### An OD Plugin Importing IDA Function Names into OD (CamelLu Importer) (orig: OD 插件将 IDA 函数名导入 OD(CamelLu Importer))

### Breaking the OD 32-Plugin Limit by Reverse Patching (orig: 逆向 patch 突破 OD 32 插件限制)
Author: imbadyc. With more than 32 plugins OD crashes, at the write into the plugin global array (exactly 32 slots): the 32nd plugin module handle overwrites the adjacent plugin-count variable `004F55B4`, and the next indexing lands on an invalid address. Set WinDbg as the default debugger to catch the first-chance AV and get the crash eip (inside OD at 004968b4 `mov [ebx],esi`) → back in OD's disassembly read the `mov ebx,[4F55B4] (index); shl/lea computes the slot; add ebx,004F0AB4 (array base)` structure; migrate the index variable and fix references to support ~100 plugins. OllyAdvanced has this built in.

### Adding LastBranchRecord to OD (Branch Tracing) (orig: 为 OD 增加 LastBranchRecord(分支追踪))
Author: softworm. ### A VT-Based OD Plugin: Ddvp (orig: 基于 VT 的 OD 插件 Ddvp)
Author: JoenChen. ## II. The OllyScript / ODbgScript Scripting System
### Lessons from Writing OllyScript Scripts (orig: 写 OllyScript 脚本的经验)
Author: Career. Variable pitfalls: `mov addr,[esp+10]` doesn't support indirect addressing — no error, but it blows up at runtime; a var declared but unassigned is 0, illegal in address accesses; to store a hex string use `mov [addr],#9876543210ABCDEF#`, not mov addr. Version-semantic drift: `find eip,#ABCDEF#` — 0.85 searches from the image start of eip's memory block, 0.92 from the address eip points to; `findop` only finds real instructions and misses things near junk code. Structure: declare variables together at the top; modularize features with `#INC` assembly (the first script's variables are global); put `pause/log/step` inside loops to watch mutations; mistyped register names (esp/ebp) go undetected.
### An ODbgScript 2.25 Brute-Force Cracking Script (CTF in Action) (orig: ODbgScript2.25 穷举破解脚本(CTF 实战))
Author: anonymous. Turning an open-ended decision branch into a closed loop: find the serial's memory address (1) and the failure jxx (2); the script rewrites (2)'s jump into a `jmp` back to the algorithm's head, writes a random 32-bit serial generated by `js` at (1), and loops until it hits; the scjs (ss) command has js randomness built in. Key: patch out the program's original character-input flow and the mid-way error popups so the loop never gets interrupted.
### ODBGScript2++ (DOJS String-Beating Commands) (orig: ODBGScript2++(DOJS 撸串命令))
Author: anonymous. ODbgScript2.03 adds DOJS/`$$` commands executing JavaScript strings with the result returned in `$RESULT`: `DOJS "3+4*5-6==17"`, `$$ "new Date().toLocaleString()"`; the variable bridge uses the eval substitution `eval "function f(c,d){return c+d};f(@x#,@y#)"` (@ and # replacing {}); switch-case (with the helper commands breaks/endsw) also goes through DOJS. ### Batch-Producing IDA Signature Files (sig) (orig: 批处理制作 IDA 签名文件(sig))
Author: manbug
```
md pat
for %%i in (*.lib) do lib /NOLOGO /list %%i >%%i.txt & md %%i.obj
for %%i in (*.txt) do (cd %%~ni.obj\ & (for /f %%j in (..\%%~nxi) do LIB ..\%%~ni /NOLOGO /EXTRACT:%%j) & pcf -g0 *.obj ..\pat\%%~ni.pat & del *.obj & cd.. & rd %%~ni.obj & del %%i)
FOR %%i in (pat\*.pat) do sigmake -n"test" %%i pat\%%~ni.sig
```

### Solutions When IDA Can't F5 (orig: IDA 不能 F5 的解决方案集)

### The x64dbg Perfect Tracing Scheme (Conditional Tracing to Locate the Key CALL) (orig: x64dbg 完美追踪方案(条件跟踪定位关键 CALL))
Author: anonymous. Finding the key CALL in a program with a nameless import table + call-esi obfuscation: use "Trace → Conditional Trace" logging only function-call arguments and returns. Log text `{modname@cip} {p:cip} {i:cip} {a:cip} {"EAX"} {a:eax} {"[ESP]"} {a:[esp]} {"[ESP+4]"} {a:[esp+4]} …`; **log condition** `dis.isbranch(cip) || dis.isret(cip)` (log only jump/ret lines); **step-over transition condition** `mod.party(dis.branchdest(cip))==1` (step over when the target is a system module, filtering system internals); to also log the instruction after call/ret: `!mod.party(cip) && (dis.isbranch(cip)||dis.isret(cip)||ReadByte(cip-1)==cc || dis.iscall(dis.prev(cip)) || dis.isret(dis.prev(cip)))`; JMP/CALL but no JCC: `dis.isbranch(cip) && !dis.iscond(cip)`; regex/substring filtering: `{dis.match(rip,"text.+,0x1")}`, `{strstr(dis.text(cip),"call esi")}`. You get a function-granularity call log for coarse locating, then generate a trace file to follow finely. Regret: constant IAT addresses in the log aren't auto-resolved to function names.

### Extracting the Source of Wireshark's Passive HTTPS Decryption (orig: Wireshark 旁路 HTTPS 解密源码提取)

### Fixing a Ghidra Decompilation Bug on Obfuscated Code (orig: 记一次修复 Ghidra 反编译混淆代码的 Bug)
Author: anonymous. An obfuscated sample (scrambled esp writes) makes Ghidra compute eax wrong. Triage: log pcode after every step inside `Action::perform`, locating the error after the oppool1 action; drill into oppool1's rules and pin `RulePropagateCopy` (CPUI_COPY propagation) substituting the constant early. Root cause: the propagation ran **before** `*(ram,esp+offset)` was recognized as a stack variable — optimization order is unguaranteed. Fix: write your own optimization rule to control ordering (or adjust that rule's condition). Methodology: Ghidra's decompilation = pcode rounds of Action optimization to fixpoint; printing pcode diffs is the fastest way to locate such bugs.
### An Introduction to the Ghidra101 Architecture (orig: Ghidra101 架构介绍)
Author: anonymous. The core three: (1) the Framework main program (Java; the Analysis analyzers handle function recognition/recursive-descent disassembly/No-Return propagation etc.); (2) the Decompiler (a fully separate process talking character streams with the Java host, runnable standalone on the command line); (3) Sleigh processor descriptions (dozens of ISAs — x86/arm/mips — plus GCC/MSVC/GO/Java compiler signatures). The narrow essence of decompilation: recognize compiler-optimization algorithm signatures and write the inverse algorithm to restore high-level abstractions. Use: when the decompiler misbehaves you know where to fix — the fundamental advantage over closed-source IDA.

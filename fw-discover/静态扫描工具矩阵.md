## BSCA 释义（二进制侧对应物）

- **cwe_checker**：BAP 后端之上的二进制 CWE 模式机检器，固件 ELF 批量出 CWE-78/120/416 等报告，binary lane 主炮；本机 docker 通道被墙，放 Linux 机跑。
- **angr**：符号执行 + CFG 恢复框架，本机已验证可啃 MIPS32；用于函数图重建、danger import 定位、路径可达性求解。
- **BAP**：卡内基梅隆/BU 系二进制分析平台（cwe_checker 的引擎），提供形式化机器语义；本轮未装——OCaml 工具链构建重且其核心价值已被 cwe_checker 封装，单独装性价比低。
- **Ghidra**：NSA 反编译器，headless+脚本做无源码固件的伪 C 恢复/跨引用/数据流；本轮未装——应用体量 + JDK 桌面栈超时间预算，angr 的反编译（`p.analyses.Decompiler`）可先顶。

## 100 CVE 电池用法（双 lane 交叉验证）

**binary lane（无源码，直接打 rootfs）**
1. `checksec` 批量扫 rootfs 全部 ELF → 弱缓解名单（bpalogin 已实证：NX-only，全裸）。
2. `firmwalker` 扫 rootfs 文件系统字符串 → passwd/凭据/隐藏路径/shadow（网络恢复后补装）。
3. `angr` 逐个高危 ELF：`CFGFast` → danger imports（system/popen/exec*/strcpy）→ 反编译确认调用上下文（本机已跑通 bpalogin：system 导入在 dynsym，150 函数图在手）。
4. `cwe_checker`（Linux 机 docker）对 rootfs 全量 ELF 出 CWE 报告，MIPS 支持，与 angr 结果互为印证。

**source lane（GPL 组件源码）**
1. 从 rootfs 的版本字符串/`/usr/share` 反查上游 GPL 源码（bpalogin 官方 GPL 包可直接拉到对应版本）。
2. `flawfinder --minlevel=3` 全树快筛 → `cppcheck`/`clang --analyze` 确认可证告警 → `semgrep`（registry 规则 + 自写 C 规则）批扫 → **CodeQL 全量污点查询**（`codeql database create` 已验证通路，补 `codeql pack download codeql/cpp-queries` 即可跑 sink=system 的污点查询）→ Joern 手写 CPG 查询攻深。

**交叉验证范式（以 bpalogin 为例）**
- 二进制侧已证：MIPS ELF 内 `system` 为 dynsym 导入、调用真流存在、缓解全关 → 「这个洞在出货固件里真实可达」。
- 源码侧：拉 bpalogin GPL 源码对应版本 → Joern `cpg.call.name("system").reachableBy(cpg.literal/env)` 或 CodeQL `system(...)` 污点查询命中 `getenv/argv→system` 链 → 「根因代码级定位」。
- 双证据闭环 = 出货固件真流 + 源码污点链，报告可直接定性命令注入并给 CVE 级论证；版本对不上时以二进制反编译传参路径为准。

# 固件提取与解包


## 1. 提取:五条路

| 路线 | 前置条件 | 成本 | 产出质量 |
|------|----------|------|----------|
| 官网/FTP 下载 | 无 | 极低 | 可能是加密包(需固件解密) |
| OTA 中间人 | 可控 App 抓包 | 中 | 拿到升级包+下载 URL 结构 |
| U-Boot console | UART 口(../无线硬件/硬件接口.md §1.2) | 中 | 真机原厂镜像(含官方未发布分区) |
| SPI/NAND 摘读 | 焊接/夹具 | 高 | 最完整(含运行时数据) |
| 后门账号/接口 | 无 | 低 | 直接 shell 后 dump |

代表帖:D-Link 固件分析记录两篇(官网路线)、智能硬件入门(OTA 路线)、用uboot"操控"某路由器(U-Boot 路线)、车机硬件分析与固件提取(SPI 路线)、无线路由器后门那些事儿 D-Link 篇(后门路线)。

## 2. U-Boot 提取与"操控"

U-Boot 是嵌入式 bootloader 事实标准。串口(UART)连上后 `Hit any key to stop autoboot` 打断进 U-Boot shell,常用命令:

```
# 看分区布局(典型 SPI NOR 布局)
=> printenv bootargs mtdparts     # 传给内核的 MTD 分区表
=> mtdparts default; mtdparts
# 内存/Flash 搬运三板斧
=> md.b 0x9F000000 0x100    # memory display(Flash 内存映射基址)
=> sf probe 0; sf read <RAM> <FL_OFF> <LEN>   # SPI NOR 读到 RAM
=> md.b <RAM> <LEN>          # 逐段倒出;或 tftp <RAM> 反向上传主机
```
(不同厂商基址/偏移不同,以 `printenv`/板图为准)

防呆点:部分设备 U-Boot 被锁(autoboot 不可打断、密码保护),退路是 `bootdelay` 竞态、Glitch 硬件攻击(../无线硬件/硬件接口.md §1.6 侧信道)或直接走 SPI 摘读。

## 3. SPI/Flash 摘读(工具面详见 ../无线硬件/硬件接口.md §1)

- **夹具法**:SOP8 测试夹 + 编程器(RTL8185/CH341A/NorWriter),免拆焊;车机帖完整演示从拆机到 `flashrom` 读出。
- **带电 in-system 读**:SOIC8 夹子夹住 Flash 芯片,主机用 `flashrom -p ch341a_spi -r dump.bin`;主板供电与编程器供电冲突时需隔离(剪 VCC 或断电阻)。
- 读出后用 `binwalk -E dump.bin` 看熵分布:高熵区=加密/压缩,低熵区=固件正文——**判断"有没有加密"的第一步**。
- 工控侧同套路:工控设备固件提取及分析。

### 3.1 U-Boot「操控」路由器实战:从打断自启到移植 telnet

中兴 ONU(ZX279127S/8S 系,360T6GV2)实战,ARM:
1. UART 打断 autoboot 进 U-Boot shell(`h` 列全命令:md/mw/cp/nand/tftp/printenv/setenv/saveenv/bootm...)。
2. `printenv` 看 bootargs 无 init → `setenv bootcmd '...init=/bin/sh;bootm 0x440001e0;'`+`saveenv` → `bootm` 报 `can't get kernel image!`:下 u-boot-2013 源码搜报错串定位 uimage 头校验(64B 头,魔数 `0x27051956`)。
3. `md.b 0x440001e0 100` 全是垃圾(内核没加载到内存)→ 按启动日志的 NAND 分区表(kernel0@0x200000)手搬:`nand read 0x44000000 0x200000 500000` → 再 `md.b 0x440001e0` 见 `27 05 19 56`+`Linux Kernel Image` → `bootm` 成功。
4. 但 `init=/bin/sh` panic(error -2)→ 改走文件系统:binwalk 解官方固件,程序里搜串 `close console` 定位 `/bin/cspd`(启动后关 console 的元凶)patch 掉;`/etc/passwd` root 密码字段置空。
5. 重打包 jffs2:`mkfs.jffs2 -d ./fs_1/ -l -e 0x20000 -o jffs2.img --no-cleanmarkers`。
6. tftp 环境:PC 装 `tftpd-hpa`,`TFTP_OPTIONS` 加 `--create`,`chmod 777 /var/lib/tftpboot`,网线直连(serverip=192.168.1.100);uboot 里 tftp 下载到 RAM,`nand write` 刷入 rootfs 分区,重启 → console 直接 root shell。
7. telnet 移植:`objdump -s --section=.comment Simulator` 判定 buildroot+glibc → buildroot 2017.05 按固件架构配 ARM/ELF32/LSB/EABI5,`make busybox-menuconfig` 勾 telnetd,产物 busybox 复制进 /bin、`/etc/rcS.d` 加 `busybox2 telnetd` 自启,重打包刷入。

坑位:修改仅在 RAM 会丢,必须 nand write 落盘;国产 ONU 可用 chinadsl 工具链直接开 telnet。

## 4. Zyxel 固件提取(实战)

Zyxel 设备固件提取(2024):应急响应 Zyxel VPN 未授权 RCE 时,官方 `.bin` 升级包是**密码保护的 ZIP 映像**,直接 `unzip` 失败。两条路:①从设备侧已解密分区直接提取;②从设备固件中定位 ZIP 密码的生成/存储逻辑(厂商常把口令硬编码在升级校验程序里)。同厂商后续:使用FirmAE对zyxel路由器固件仿真实践(固件仿真.md)。

## 6. 固件解包与静态分析

### 6.1 binwalk 一把梭之后

```
$ binwalk -Me fw.bin
├── squashfs-root/          ← 99% 的情况:完整 Linux 根文件系统
│   ├── bin/ sbin/ usr/bin  ← busybox + 厂商私有程序(httpd/goahead/cfm)
│   ├── etc/init.d/rcS      ← 自启脚本:服务怎么起来的全在这
│   ├── htdocs/web/         ← Web 前端 + .cgi 入口
│   ├── etc/passwd shadow   ← 硬编码凭据高发区
│   └── lib/                ← so 依赖(架构判定:readelf -h)
├── *_jffs2 / *_ubifs       ← JFFS2/UBI(UBI 需 ubireader_extract_image)
├── *_cramfs                ← 老设备
└── yaffs/xiaomi.etc        ← 厂商私有容器(手工解析,见华为光猫帖)
```
(ubifs 场景用 `binwalk -Me` 失败时换 `ubireader_extract_images`)

**架构判定**:`readelf -h squashfs-root/bin/busybox` → MIPS little/big-endian(路由器主流)、ARM(摄像头/手表主流)、x86(工控机)。

### 6.2 三个必翻位置

1. `/etc/init.d/rcS`:自启的服务清单 → 攻击面清单。
2. `htdocs/web/*.cgi` 或 `www/`:Web 入口 → 命令注入高发(路由器实战 §1)。
3. `strings -n 8 httpd | grep -Ei "passw|secret|key|token"` + `/etc/passwd`:硬编码凭据(DWR-932B 帖实证弱 root 密码与后门)。

### 6.3 RTOS/单片机固件(无文件系统)

无 FS 的裸固件(MCU/VxWorks/RT-Thread/RTEMS):
- **加载地址**:IDA 加载 raw bin 时 base 不对则一切引用全飞。固件安全之加载地址分析:从向量表/字符串交叉引用反推 base(STM32 帖同思路)。
- **符号恢复**:VxWorks 符号表被裁时用 `symtab` 残留结构恢复:探究vxworks文件名恢复。
- **算法还原**:固件里的私有加密/校验算法,用 Unicorn 直接把函数当黑盒跑:利用unicorn分析固件中的算法。
- 完整案例:一次嵌入式固件逆向实践、一个简单的STM32固件分析、STM32固件逆向、STM32固件Dump教程(STM32 dump 走 SWD,../无线硬件/硬件接口.md §1.3)。

### 6.4 自动化扫描器

- **EMBA**(固件安全审计全家桶,集 binwalk+CVE 匹配+NVD 比对):EMBA安装、使用与源代码分析。
- Fact/Firmwalker 等同类;结论一致:**扫描器只做线索面,漏洞定性必须回到人工读 cgi/so**(社区帖共识)。

# 固件仿真


无真机时代的标配。三层方案,由重到轻;选型口诀:**仿真起得来用 FirmAE,起不来 user 模式挂单进程,进程都跑不动就 Unicorn/Qiling 切函数**。

## 1. Firmadyne / FAT(全系统级)

```
FAT(firmware-analysis-toolkit) = Firmadyne 内核+QEMU 全系统仿真
流程:提取 FS → 识别架构 → 生成磁盘镜像 → InferNetwork 猜网卡 → qemu-system 起整机
```

痛点:非标准内核/私有驱动的设备起不来;`nvram_daemon` 等不到 pid 文件卡死(经典坑)。

## 2. FirmAE(自动绕过)

FirmAE 在 Firmadyne 基础上自动处理了大部分卡死点(nvram 劫持、块设备重定向),五种仲裁技术把仿真成功率从 Firmadyne 的 16.28% 提到 79.36%(Docker 并行逐镜像仿真)。命令面:`./init.sh` 一次性初始化;`sudo ./run.sh -c <brand> <fw>`(check 仿真)→ `-a`(FirmAE 分析器)→ `-r`(运行/测网络服务)→ `-d`(用户级调试)→ `-b`(内核级引导调试);`-c` 完成后调试模式选 2 进 shell。

代表帖:
- 使用FirmAE对zyxel路由器固件仿真实践
- Vigor3900固件仿真(CVE-2024-44844/44845)
- 小米路由器固件仿真模拟方案(小米系私有 nvram/数据中心调用的定制化仿真)
- 仿真openwrt二次开发固件的通用思路(NepCTF2024;二次开发固件内核不匹配时的「换内核保用户态」通用法)
- 小米AX9000路由器CVE-2023-26315漏洞复现(QEMU 仿真+漏洞复现串成一条线)

### 2.1 实战:FirmAE 仿真 Zyxel——自动仿真失败时的手动救活

实战案例 Zyxel NWA1100-NH 2.12(日志「成功」但 Web 没起来):
1. 根因:文件系统里有**两个** http 服务,FirmAE 起了 httpd,真身是 mini_httpd。
2. `/etc/default/mini_httpd.conf` 指向 `/tmp/mini_httpd.conf`(不存在);直接用 mini_httpd.cnf(SSL 配置)启动失败。
3. IDA 打开 mini_httpd 搜报错串 `unknown config option`,定位配置解析逻辑,试探必要字段后手写最小配置:
   ```
   dir=/usr/www
   cgipat=cgi-bin/*
   user=root
   port=8081
   ```
4. 起来后 `admin/admin` 登录报 `log_maintain: not found` → 该程序在 `/etc/scripts/`:`export PATH=/etc/scripts/:$PATH`。
5. 登录验证交给 `chkpwd`(疑似系统账密),改系统密码无效 → **patch 登录逻辑**:strncmp `"Access granted"` 判断处 `bnez`→`beqz`(IDA 直接改一条指令)即可绕过。
6. 抓到 `POST /cgi-bin/ip`(AP_IPADDR=...&EXECUTE=ip);固件里搜不到 `/cgi-bin/ip` 字符串——运行时才生成:模拟系统中 `ip` 是指向 `/sbin/cgiMain` 的链接,**真正处理请求的是 cgiMain**,逆它/gdb 调它即可继续挖洞。

坑位:仿真「流程成功≠服务起来了」,必须以端口可达为准;一个固件多个同类服务时先确认哪个是真身。

## 3. QEMU user 模式 + Qiling/Unicorn(单进程级)

- `qemu-mipsel -L squashfs-root/ ./httpd`(配 `gdbserver` 多架构,IDA 远程调试):QEMU+IDA 远程调试 mips 可执行文件、buildroot 构建 MIPS64 调试环境。
- **Qiling**:用户态模拟框架,能 hook syscall、伪造 nvram 返回,适合把单个 cgi/算法跑起来:Qiling框架模拟运行固件配合IDA动态调试、QilingLab 详解到源码分析。
- 调试环境配套:路由器固件调试方案、路由器环境基础工具安装、IoT设备获取本地shell权限并进行软件调试、靶机 DVRF(Router Pwn 靶场)。

## 4. 全系统 QEMU 整机仿真实战:思科 RV340 未授权文件上传 CVE-2023-20073

RV340/RV340W/RV345/RV345P 未授权任意文件上传至 `/tmp/upload` → upload.cgi 漏洞 → 存储型 XSS。

仿真链(Ubuntu18.04+QEMU7.2+binwalk2.3.3,ARM 小端):
1. `binwalk -Me RV34X-v1.0.03.29...img` 失败:UBI 文件系统缺工具 → `apt install liblzo2-dev && pip3 install python-lzo ubi_reader`。
2. binwalk 把指向解压目录外的软链接(var→/tmp)置 /dev/null → 后续仿真必挂。三解:改 binwalk `extractor.py` 里 `if not` 为 `if 0 and not` 重装;或直接 `ubireader_extract_files 0.ubi`;或 `python3 ubidump.py -s . 0.ubi`。
3. 网桥:`brctl addbr br0` + ens33 入桥 + `tunctl -t tap0` 入桥(br0 由 dhclient 拿 IP)。
4. `qemu-system-arm -M vexpress-a9 -kernel vmlinuz-3.2.0-4-vexpress -initrd initrd.img-... -drive if=sd,file=debian_wheezy_armhf_standard.qcow2 -append "root=/dev/mmcblk0p2" -net nic -net tap,ifname=tap0,script=no`;SD 卡报错先 `qemu-img resize ... 32G`;账密 root/root。
5. **scp 传压缩包**(tar.gz),不能传目录(会丢文件——作者在这坑耗一周);`mount --bind /proc proc; mount --bind /dev dev; chroot . /bin/sh`。
6. 服务启动序(排错后的正解):
   ```
   /etc/init.d/boot boot        # 建 /tmp 各目录,消 "uci: Entry not found"
   generate_default_cert        # 生成 /etc/ssl/private/Default.pem
   /etc/init.d/confd start      # 轻量配置管理(nginx 依赖)
   /etc/init.d/nginx start
   ```

漏洞利用(upload.cgi 关键逻辑):
- `multipart_parser_execute` 解析 POST 字段,`jsonutil_get_string(dword_2348C, &v26, "\"file.path\"", -1)` 取 file.path。
- `match_regex` 校验 file.path 必须形如 `/tmp/upload/NNNNNNNNNN`,否则走 return 分支(system 顺手 `rm /tmp/upload/*`)。
- **方法一**:卡住 upload.cgi 进程看 /tmp/upload 实际文件名,报文手写 `file.path=/tmp/upload/0000000001` 通过正则 → system 执行 `mv` 到 Portal 目录改 login.html。
- **方法二(优雅解)**:nginx 配置 `upload_set_form_field $upload_field_name.path "$upload_tmp_path"` 会**自动**生成 `<name>.path` 字段——报文 name 用 `file` 即自带正确 file.path,无需知道上传路径。

调试三板斧(fork 型 cgi 专杀):
1. 爆破:`while true; do PID=$(pidof upload.cgi); [ -n "$PID" ] && ./gdbserver 0.0.0.0:9999 --attach $PID; done`(三成概率)。
2. **死循环(最稳)**:keypatch 把 main 首个 BL 改 `B 本条地址`(如 0x10E0C 处 `BL getenv`→`B 0x10E0C`),chmod 777(www-data uid33 执行 root 文件),attach 后 `set *0x10e0c=0xebffffaa` 恢复小端机器码,`gdb-multiarch`+`set architecture arm` 远程调。
3. 父进程 `catch exec`(理论可行,实测失败)。另:uwsgi 配置有 harakiri 超时,长调会断,调大。

# IoT 协议、恶意软件与工控


## 1. MQTT 协议安全

```
Publisher ──PUBLISH(topic)──► Broker(1883/8883) ──推送──► Subscriber
                                 │
                                 ├─ 认证:匿名/弱口令/anyclean 常见默认
                                 ├─ ACL:topic 级权限,`#` 通配订阅=全量窃听
                                 └─ topic 本身即路由:无需预创建,谁都能 pub/sub
```

- 物联网的基石-mqtt协议初识(协议三角色/topic 机制)
- 西湖论剑2024 IOT赛后复盘及mqtt rce详解(Broker 实现 bug → RCE 的完整链)
- mqtt 协议pwn入门(ciscn2025 final,Broker 内存破坏方向)

审计三查:匿名可连否 / `#` 通配订阅有无 ACL / topic 里跑了什么(门锁开闭、坐标、token)。

## 3. IoT 恶意软件:Mirai 系

### 3.1 家族机制

```
扫描器(telnet 23/2323 弱口令表+CVE 表) → 感染 → 下载对应架构 payload
(busybox wget/tftp) → 运行 → 上报 C2(域名硬编码) → 加入 DDoS/挖矿/代理
架构表:x86 x64 ARM ARM5 ARM6 ARM7 MIPS MIPSel PPC SPARC SH4 M68K
反调试:watchdog 喂狗线程 + ptrace(PTRACE_TRACEME) 自挂
```

(流程还原自 Mirai 源码结构)
- 变种谱系:Satori(漏洞代替弱口令传播)/ OMG(代理变现)/ JenX / Wicked / TBOT(2024 分组运营)。
- IoT 侧防御视角:改 telnet 口令、关 WAN 侧管理、升级补 CVE(全指向 [路由器实战.md](路由器实战.md) 的漏洞矩阵)。

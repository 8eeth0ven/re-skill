# 固件解密


## 1. 为什么有加密与三条提取思路

厂商为阻止「官网直接下」路线,把升级包整体加密(AES/RC4/自定义流密码),解密逻辑放在引导程序/加密 bootloader(如 D-Link 的 `alpha/alphad` 系列、部分 DIR 系列)里,开机时才解开写 Flash。于是**密钥必然出现在设备侧**,提取思路三条:

1. **从加密 bootloader 里抠算法+密钥**:bootloader 本身不加密(U-Boot 阶段它必须可执行),binwalk/IDA 找 AES 表(S-box/Te0 表)或 TEA/Xtea 轮循环,定位 key/iv 常量。
2. **运行时 dump**:真机跑起来后从内存/解密后的 Flash 分区直接读明文(与固件提取.md 的 U-Boot/SPI 组合拳)。
3. **逐字节关系推**:对已知明文头(如 squashfs 头 `hsqs`)做 chosen-plaintext 对照,推流密码异或序列。

## 2. 判断有没有加密:熵图

`binwalk -E fw.bin` 看熵分布:恒高熵 >0.9 ≈ 加密;前低后波动 ≈ 代码+压缩混合;高熵区=加密/压缩,低熵区=固件正文——**判断「有没有加密」的第一步**。

## 3. 实战:D-Link 加密固件解密(过渡版本 diff 法)

DIR-822-US(AC1200,MIPS R3000),Payatu 原文思路:
1. **找过渡版本**:翻 FTP 发行历史,同日两包(`middle` 与正式版),`middle` 即引入加解密的过渡版(明文);此后版本 binwalk 无 squashfs 签名(全加密)。发行 notes PDF 佐证。
2. **熵图判加密**:`binwalk -E`/固件审计工具(见 §2)。
3. kdiff3 diff 旧版 vs middle 文件系统,锁定 `/etc/templates/hnap/StartFirmwareDownload.php`:
   ```php
   setattr("/runtime/tmpdevdata/image_sign","get","cat /etc/config/image_sign");
   fwrite("a",$ShellPath,"encimg -d -i ".$fw_path." -s ".$image_sign." > /dev/console\n");
   ```
4. key=`/etc/config/image_sign` 内容 `wrgac43s_dlink.2015dir822c1`;`qemu-mips -L . ./usr/sbin/encimg -d -i <fw> -s <key>` 直接解密;`-strace` 见加载 `/lib/libcrypto.so.0.9.8` → 提示对称加密。
5. IDA:main → build,导入 `AES_set_encrypt_key/AES_set_decrypt_key/AES_cbc_encrypt` = **AES-CBC,mmap 映射→设 key→CBC 加/解密→munmap 写回**。
6. 攻击面延伸:解密流程若无完整性校验→firmware-mod-kit 改固件重打包再加密上传=恶意固件更新(需签名机制防)。

方法论:加密是后期引入的 → **翻版本历史找过渡包,diff 出解密调用点与 key 存放位置**,是加密固件分析通用套路。

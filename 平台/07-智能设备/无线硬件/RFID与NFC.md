# RFID 与 NFC:M1 卡加密体系与沦陷


## 1. M1(Mifare Classic)体系

```
卡结构:16 扇区 × 4 块(每块 16B);每扇区末块 = KeyA(6B)+访问位(4B)+KeyB(6B)
认证:三次握手 → CRYPTO1 流密码(NXP 专有)
                  │
      ┌───────────┴────────────┐
  明文扇区(0钥匙默认)        加密扇区(默认钥匙改过)
  nested 攻击可恢复          需伪随机数弱点/字典/侧信道
```

## 2. 攻击谱系

| 攻击 | 条件 | 效果 |
|------|------|------|
| 默认 key 字典 | 全卡 | 60% 国内卡一把梭(FKF 等默认 key 表) |
| Nested authentication | 已知一个扇区 key | 伪随机数相关性 → 推其它扇区 key |
| Darkside/NACK | 老固件 | 错误响应泄 parity → 离线推 key |
| moebiu/校验位 | 全加密卡 | 需配合嗅探或控制器侧漏洞 |
| CPU 卡 | — | 走协议层(见 §4) |

## 4. 实战:M1 离线卡爆破——密钥之后的「数据规律逆向」全流程

水卡实战。工具链:安卓 MCT(读卡判定哪些扇区加密)→ ACR122U(~150 RMB,爆破默认 key)→ 010editor 读 dump + excel 标色比对 + CheckTool(校验位推算);再备两张 UID 白卡。

**流程**:
1. MCT 读卡:10/11 区加密(默认 key 读不出)→ 上 ACR122U 跑 key 字典 → 爆破成功导入 MCT 读全卡。
2. 定位业务块:仅 10 区 0 块随消费变化(2 块是 0 块镜像,1 块因卡而异)——**先找变化块再谈规律**。
3. 已知余额(如 4.00→49.98)转 16 进制比对:命中「余额倒置」字段;每刷一次 +1 的=刷卡次数;另有一字段=次数的加和;互相取反的一对字段;红色+暗红累加=第一个蓝色字段;**第 1~14 位异或和=第 15 位**(校验 1)、**第 2 位加到最后=0xFF**(校验 2);另有一位按「机器日历」以天为周期变化(日期位,与自然日不同步,变化节点在午后某时刻)。
4. 验证:按猜想自组一组数据写卡 → 刷卡机识别正常(未知位实测为 00-09 内变动,可当随机数)→ 破解闭环。

**坑与方法论**(帖主+评论区):
- 规律找三天、数据追踪四天,累计 100+ 组样本;**用颜色标注字段含义**再画关系图,是最快的分析姿势。
- 校验通常就是「异或和+累加和」两件套:先定原始数据位,再逆它们的运算。
- 写同 UID 到不同卡不受影响→说明业务只看 0 块数据,与 UID/1 块无关。
- 评论区:有学校的卡还有「每十个数重起一轮循环」的附加校验(数据不够会带偏);部分卡系统服务端同步(复制卡与原卡同步扣费)——克隆前先判离线/联网。

# AI 与区块链交叉安全

> 定位:「09-AI安全」与「10-区块链安全」的交叉篇。

## 1. 为什么会有这个交叉面

2024 下半年起,「链上 AI Agent」成为加密行业新叙事:AI Agent 持有钱包、自主发币/交易/打赏,代表系统(a16z eliza、Virtuals Protocol 的 GAME、ARC 等)把 LLM 的**所有已知缺陷**(提示注入、工具滥用、过度代理)直接嫁接到**能管钱的钱包**上。安全上等价于:一个可被任意网页内容注入操纵的实体,掌握着不可逆转账权限。

```
[链上 Agent 攻击面叠加图·自绘]
┌────────────── LLM 层(继承 09 篇全部) ──────────────┐
│  提示注入 / 越狱 / 记忆投毒 / 工具投毒                │
└───────────────────────┬───────────────────────────┘
                        │ Agent 框架(eliza/GAME)
┌───────────────────────▼───────────────────────────┐
│  Agent 层:Twitter/Telegram 读推文 = 间接注入入口     │
│  MCP/插件工具、sandbox、记忆库                       │
└───────────────────────┬───────────────────────────┘
┌───────────────────────▼───────────────────────────┐
│  链上层(继承 10 篇全部):私钥托管、approve 权限、     │
│  MEV、合约漏洞、rug pull                             │
└─────────────────────────────────────────────────────┘
任一层失守都直达资金;注入成本 << 合约漏洞成本
```

## 2. 已发生的事件

### 2.1 Freysa:提示注入赢得奖池(2024-11)

- Freysa.ai 是一个对抗性游戏:AI Agent Freysa 守护一个奖池,规则是「说服它转出奖池者赢得全部资金」,每次尝试付费进入奖池。参与者历经多次失败后,有人用一条消息成功——**本质是对守护提示的提示注入**:让模型进入「接下来是已批准的转账」的上下文框架,最终 Agent 调用转账函数,约 $47k 奖池被赢得(部分捐赠/部分归属获胜者)。
- 意义:第一个「公开直播、真金白银、奖金就是漏洞赏金」的提示注入实战案例——把 09 篇 §2.1 的实验室风险变成了链上资金损失。
- 后续多轮版本迭代防护、社区持续博弈(取胜手法=利用其指令/tool-call 审批逻辑框架;各版本逐轮防护差异未见系统公开复盘,以链上交易为准)。

### 2.2 Truth Terminal 与 GOAT(2024-10)

- 一个接入了加密文化的半自主 AI Agent(Truth Terminal),在与 a16z 创始人 Marc Andreessen 互动后获得 BTC 打赏,随后其关联 memecoin GOAT 市值暴涨,成为「AI Agent 百万富翁」叙事起点。
- 安全视角:① Agent 的「信仰/推荐」可被**社交工程与代币持仓利益**影响——链上 AI 的荐币行为没有信息披露边界;② 社区立刻出现仿冒 Agent 发币收割(GOAT/Fartcoin 均非 Agent 本人发行而是匿名第三方抢发;模仿盘在 Solana/Pump.fun 批量出现,pump-and-dump/rug 常态化;标志性价格事件:2024-10-25 获其背书的代币双位数暴跌)。
- 这类事件把「Agent 名誉」本身变成了攻击资产:钓鱼仿冒 Agent 账号→诱导买仿币。

### 2.3 Agent 发行的代币 = 天然 Rug 面

- AI Agent 发币(owner=Agent 钱包)时,LP 锁定、mint 权限、税费逻辑全靠部署者自觉;「Agent 自主决定砸盘/撤池」在代码上没有任何约束(个案:ai16z 2024-10 发行、市值峰值 ~$2.4B,2025-01 因 a16z 商标顾虑更名 ELIZAOS,2025-12 项目被创始人宣告死亡、币价归零级;面级统计:2025 年 rug pull 损失 ~$6B(其中 92% 系 Mantra 单案);学术侧 2024 年 rug 案损失代码级分析 ~$85.4M)。
- 与 10 篇 §4.1 貔貅检测复用:GoPlus/honeypot 检测同样适用于 AI 发的币。

## 3. 预言机信任:AI 时代的两个新问题

1. **AI 数据源预言机**:把 LLM/Agent 输出作为预言机数据(如「AI 情绪指数」上链结算)——LLM 幻觉与提示注入直接变成**链上价格操纵**;设计上必须对 AI 输出做多源共识+偏离熔断,当不可信信号处理。
2. **预言机 DON 本身的投毒面**:Chainlink 类去中心化预言机网络假设节点数据源独立;**公开可查的预言机操纵损失集中在低流动性 DEX 喂价与单一数据源依赖**(2022 年 41 起、$403.2M;Venus 协议 2024 LST 抵押品经 Curve 低流动性池扭曲喂价致 ~$110M 坏账),「Chainlink DON 节点数据源同源被操纵」未检索到已证实的个案,维持待定;AI 抓取型节点(新闻/推特情绪)继承多模态注入全部风险成立。

## 4. zkML / 链上验证推理

- 方向:用零知识证明在链上验证「某模型在给定输入下确实输出了该结果」(EZKL、Giza、Modulus Labs 等工具链),用于把 AI 决策上链结算(ex: AI 驱动的策略金库)。
- 安全要点:① 证明的是**执行正确**而非**模型正确**——被注入的模型输出照样能被「正确地证明」;② 电路 bug/量化误差是新的审计对象;③ 模型权重上链=公开(供应链 pickle 风险在电路生成环节同样存在)。
- 现状:研究/原型期,尚无重大资金事件(截至 2026-10)。

## 5. 防御与工程建议(交叉面专用)

1. **Agent 钱包限额**:链上 Agent 一律用「限额+延时+可撤销」的钱包(类似 Safe 的模块化权限/spending limit),单笔/单日上限,大额走人审多签——对应 09 篇 §6.4 权限最小化在链上的落地。
2. **社交输入当不可信数据流**:Agent 读推文/Telegram 的管道必须做注入过滤(参考 09 篇 §6.2 guardrails),不与指令上下文混流。
3. **荐币与利益冲突披露**:任何持仓 Agent 的推荐内容强制链上可验证的持仓声明(社区规范,尚无强制标准)。
4. **AI 发币走标准审计**:AI 部署的代币合约与人写的同标准——Slither/Echidna 全套+LP 锁定验证(10 篇 §3)。
5. **链上 Agent 取证**:Agent 私钥的托管方、签名的交易来源(哪个模型版本/哪个 prompt 触发)要留 trace——出事后可归因到「注入源」而非只看到一笔转账。

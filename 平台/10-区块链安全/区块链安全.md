## 2. 智能合约漏洞(原理→案例→修法)

### 2.1 重入(Reentrancy)

- 原理:外部调用(收款方 `fallback`/`receive`)在状态更新前执行,被恶意合约递归回提现函数,余额未扣即重复提取。
- 案例回放:**The DAO(2016-06)**——360 万 ETH(时值约 $60M)被盗,直接导致 ETH 硬分叉(ETC 由此而生);**Curve(2023-07)**——Vyper 编译器 0.2.15~0.3.0 重入锁失效,~$70M。
- 修法:**checks-effects-interactions(CEI)**;Solidity 0.8+ 的 `nonReentrant`;转发用 pull-payment。
- 识别特征:`call.value{...}` 后仍有 SSTORE;外部调用在状态更新前。

```solidity
// 脆弱模式(The DAO 缩写)
function withdraw() external {
    uint amount = balances[msg.sender];
    (bool ok, ) = msg.sender.call{value: amount}(""); // effects 之前 external call
    require(ok);
    balances[msg.sender] = 0;                          // ← 状态后置 = 重入窗口
}
```

### 2.2 整型溢出

- 原理:0.8 之前 Solidity 无内置溢出保护,`uint256` 环回。
- 案例:**BEC 美链(2018-04)**——`batchTransfer` 中 `amount * count` 溢出成天文数字,恶意增发,BEC 价值归零,国内影响力最大的合约案例之一;**Cetus(Sui,2025-05)**——非 EVM 链同样中招,`checked math` 缺失致整数溢出,**$223M** 被盗(部分事后冻结),证明溢出不是「EVM 老毛病」而是所有链的通用错误类别。
- 修法:Solidity ≥0.8 默认 checked;低版本用 SafeMath;Move/Rust 链显式 `checked_*`。

### 2.3 访问控制缺失

- 原理:敏感函数(owner 铸造/暂停/升级/自毁)没有修饰器或权限判断写错。
- 案例:**Parity 多签钱包(2017)**——两次事故:7 月 solidity 库漏洞被偷 15 万 ETH($31M);11 月 devops199 误调用未初始化库的 `kill`,**513,000 ETH(时值约 $150M+)永久冻结**——「一次调用冻结数亿美元」是访问控制+自毁组合的经典教材;**Multichain(2023-07)**——私钥中心化管理,被盗 $126M。
- 修法:`onlyOwner`/RBAC 库(OpenZeppelin AccessControl);初始化函数加 initializer 修饰;库合约构造后立即初始化。

### 2.4 闪电贷攻击(Flash Loan)

- 原理:同笔交易内无抵押借出巨款,操纵链上价格/治理后还款,攻击零成本撬动协议全部流动性。
- 案例:**bZx(2020-02)**——首例成名战,两起共约 $95 万;**Beanstalk(2022-04)**——闪电贷借入巨量 STASH/BEAN 投票通过恶意提案,连同闪电贷共约 $182M 被转走(**治理攻击**);**Euler Finance(2023-03)**——闪电贷配合 `donateToReserves` 自捐触发清算逻辑,**$197M**(黑客后归还,谈判案例);**Mango Markets(2022-10)**——拉升 MNGO 操纵保证金借空 $114M(操纵者被定欺诈,罕见刑事闭环)。
- 修法:链上价格只信 TWAP/预言机;治理提案生效延迟(timelock)+ 快照投票;闪电贷敏感操作检查 `tx.origin == msg.sender` 不够,必须重入/同块防护。

```
[闪电贷攻击通用流·自绘]
借贷协议A --闪电贷--> 攻击合约
攻击合约 --巨量卖压--> DEX池X (价格被打歪)
攻击合约 --用歪价格--> 受害协议B (抵押物被高估/清算获利)
受害协议B --套利吐出--> 攻击合约
攻击合约 --还贷+利息--> 借贷协议A
同一交易原子完成,失败则整体回滚 → 攻击者零风险
```

### 2.5 价格预言机操纵

- 原理:协议用「现货即时价」(DEX spot)定价,而现货价可被闪电贷瞬时操纵。
- 案例:Mango(同上);大量长尾借贷协议(2022-2024 rekt.news 上的高频死因)。
- 修法:Chainlink 等**去中心化预言机网络(DON)**;Uniswap V3 TWAP;多源聚合+偏离熔断。

### 2.6 approvals 钓鱼(授权钓鱼)

- 原理:`ERC20.approve/increaseAllowance` 授权后花的是**后续任意时刻**的额度;钓鱼站骗的不是转账而是一次 approve,过几天再 `transferFrom` 悄悄搬币。
- 变体:**permit(EIP-2612)离线签名钓鱼**——不花 gas、不产生链上交易,签个名就把币给出去了;**Permit2(Uniswap)**批量统一授权被钓鱼站滥用;2024-2025 钓鱼即服务(Drainer 家族:Inferis/Pink/Angel Drainer 等)工业化,单次活动盗百万级。
- 防护:钱包授权管理定期 revoke(revoke.cash);钱包端语义化解析交易+风险地址库(慢雾 MistTrack 标签、GoPlus);冷热分离。

### 2.7 MEV 抢跑与三明治

- 原理:交易在公开 mempool 可见,验证者/搜索者可插入排序获利——frontrunning(抢跑套利)、sandwich(前后夹击吃滑点)、liquidation MEV(清算竞速)。学术源头「Flash Boys 2.0」(Daian et al., 2019)。
- 工具链:Flashbots Protect、私有 mempool、mev-boost;观测:EigenPhi、Dune 仪表盘;libevm/flashbots-inspect 用于取证复盘。
- 防护(用户侧):滑点收紧、拆单、走私有路由(Flashbots Protect/MEV Blocker)。

### 2.8 函数选择器混淆与签名重放

- 原理:外部调用只用 4 字节选择器(`bytes4(keccak256("transfer(address,uint256)"))`),参数类型完全不管——把 `transfer(address,uint256)` 的参数换成 `(address,uint256)` 之外的语义(如把 uint256 当指针),或伪装库地址。多签/代理合约最易中招。
- 签名重放:链下签名(`ECDSA.recover`)没绑 nonce/chainId/合约地址,同一签名在别处再花一次;跨链重放(ETH 主网签名在 L2 再用)是 2021-2023 多起事故根因。
- 修法:OpenZeppelin `EIP712`(domain separator 绑 chainId+verifyingContract)+ 每用途唯一 nonce(映射 used);Solidity 0.8 的 `abi.encodeCall` 替代手拼 calldata。

### 2.9 存储碰撞与 delegatecall 陷阱

- 原理:`delegatecall` 在调用者存储上下文执行库代码——代理/可升级合约存储布局必须严格对齐,错位就是资产字段被当权限字段读写;UUPS/透明代理混用、库合约忘记初始化都会放大。
- 案例:Parity 2017-11(未初始化库 + `delegatecall` 到自杀函数)= 51.3 万 ETH 冻结(见 §2.3)。
- 修法:存储布局 gap、OpenZeppelin Upgradeable 系列合约、升级走 timelock+多签、`initialize` 加 initializer。

### 2.10 假充值(交易所记账层)

- 原理:`transfer()` 不 revert 只返回 false,交易所按事件/调用成功即记账;或 deflationary 代币实际到账少于名义值;TRON/USDT-OMNI 老链上的 false-Return 攻击。结果:没收到币却给用户上了账,被刷出提币。
- 修法:记账以**余额差核对**为准而非返回值/事件;充值地址独立监听+对账任务;新上币走完整准入测试清单。

### 3.2 审计方法论:逐函数检查清单

对每个 external/public 函数过一遍(审计公司通用做法,综合 Trail of Bits/慢雾公开 checklist):

1. **谁能调?** 鉴权修饰器、`tx.origin` 误用、任何人可触发?
2. **改了什么状态?** CEI 顺序;外部调用夹在中间?
3. **钱怎么进出?** 转账用 call/transfer?接收方可控回调?
4. **参数边界?** 0/极值/溢出/精度(除法截断、1e18 换算)?
5. **外部依赖?** 价格来源、外部 call 合约可换/可伪造?
6. **升级与所有权?** proxy admin、timelock、多签阈值、初始化可重入?
7. **签名与随机?** nonce 唯一?chainId 绑定?随机源可操纵?
8. **事件与紧急开关?** 关键操作可观测;pause 权限在谁手里?
9. **Gas 与 DoS?** 循环+外部调用、返款模式?
10. **与其他合约组合?** 组合出的闪电贷/清算路径单独 fuzz。

交付物:威胁模型 → 问题分级(Crit/High/Med/Low/Info)→ PoC(Foundry 复现)→ 修复建议 → 复审。

### 3.3 Foundry 复现 PoC 模板(重入示例)

审计交付最有力的是一键复现的 PoC,`forge test` 直接跑出资金损失数:

```solidity
// test/Reentrancy.t.sol
// forge test --match-test test_reentrancy -vvv
contract Attacker {
    IVictim public victim;
    constructor(IVictim v) { victim = v; }
    function attack() external payable {
        victim.deposit{value: 1 ether}();
        victim.withdraw();
    }
    receive() external payable {
        if (address(victim).balance >= 1 ether) {
            victim.withdraw();               // 重入:余额未清零
        }
    }
}

function test_reentrancy() public {
    vm.deal(address(this), 2 ether);
    Attacker a = new Attacker(victim);
    (bool ok,) = address(a).call{value: 1 ether}(abi.encodeWithSignature("attack()"));
    assertTrue(ok);
    assertGt(address(a).balance, 1 ether);   // 攻击者带着超额资金离场
    emit log_uint(address(victim).balance);  // 受害合约被掏空
}
```

同样模式套用到:溢出(边界值 fuzz)、越权(换 caller 调敏感函数)、预言机(打歪 mock 价再调用)。Echidna/forge 的 `invariant` 则用于「任何调用序列下总资产守恒」类性质。

## 4. 链上犯罪分析

### 4.1 钓鱼 / 貔貅盘 / Rug Pull 识别

- **貔貅盘(honeypot)**:能买不能卖。手法:卖出 100% 税、transfer 里检查 owner、黑名单动态拉黑买家。检测:TokenSniffer、GoPlus honeypot 检测、honeypot.is(模拟买卖);人工看开源合约的 `_transfer` 里有没有 owner 特权分支。
- **Rug Pull**:① 撤流动性(开发者留 LP 未锁/自锁后解锁)——查 Team Finance/Unicrypt 锁定记录;② 铸造后砸盘(owner 保留 mint 权);③ 逐步卖光持仓(看持仓集中度+持币地址行为)。经典:Squid Game Token(2021-11,$3.38M)。
- **钓鱼站/空投骗授权**:假域名+急迫话术,目标是 approve/permit 签名而非私钥;钱包插件商店山寨扩展(MetaMask 假扩展史)。

### 4.2 混币(Tornado Cash)

- 原理:固定面额存取款池,存款凭证(note)与取款零知识证明解绑地址,断开链上关联(100 ETH 存入者 A → 100 ETH 提取者 B)。
- 事件线:2022-08-08 OFAC 制裁 Tornado Cash(首次制裁智能合约,指洗钱 >$7B 含 Lazarus $455M);开发者刑事追诉(Pertsev 2024-05-14 荷兰判 64 个月;Roman Storm 2025-07 受审,三项指控中一项「共谋经营无牌资金传输」成立);**2024-11-26 第五巡回上诉法院(Van Loon v. Department of the Treasury)裁定不可变智能合约不构成 IEEPA 意义上的「财产」、OFAC 无权制裁——只能制裁滥用者**;**2025-03-21 财政部正式解除制裁**(Pertsev 案维持)。
- 追踪对抗:存款/取款时序相关、gas 来源、金额与笔数聚类、同类行为指纹——Chainalysis/慢雾均公开过方法论。

### 4.3 链上追踪(Chainalysis 类)与被盗资金追踪流程

工具谱系:Chainalysis(REACT)、TRM Labs、Elliptic、慢雾 MistTrack、OKLink 链上天眼、Arkham/Dune/Nansen(标签+可视化)、Etherscan 标签库。

**被盗资金追踪标准流程**(SRC/应急响应通用):

1. **固化证据**:交易哈希、区块高度、时间、受害地址、攻击合约地址及其创建交易;快照存档(浏览器存档+节点 RPC 导出)。
2. **归因攻击者**:创建攻击合约的交易签名者(常为龙套地址)、资金注入 gas 的上游地址、同 bytecode/同 nonce 模式的历史地址(工具:`findmyfather` 类、慢雾自动画像)。
3. **跟随资金**:多层跳转 → 归集地址 → 分类出口(交易所/混币/跨链/变现)。交易所充值=可冻结点:立刻发协查(币安/OKX/Bitget 等均有安全邮箱)+ 报警同步。
4. **跨链与混币剥离**:Bridger/stargate 跨到 Tron/BSC → 换链天眼接力;Tornado → 时序聚类等启发式(不保证成功,输出概率关联)。
5. **冻结与追偿**:稳定币发行方黑名单(Tether/Circle 链上 blacklist 直接冻结 USDT/USDC——Ronin 案后续、2022 多次实战);交易所配合冻结入金;司法扣押与返还程序。
6. **复盘报告**:时间线+资金流图+根因(合约/私钥/前端/社工)。

## 5. 交易所与钱包安全

### 5.1 热钱包管理与 Bybit 复盘

- 常规架构:冷钱包(离线/ HSM 签名)、温钱包(多签+限额)、热钱包(小额快付+自动归集);关键在**签名人终端**与**前端完整性**。
- **Bybit(2025-02-21,$1.46B≈40 万 ETH,史上最大,Chainalysis/THF 归因 Lazarus;随 ETH 波动与 Chainalysis 报告口径为 $1.5B,本文 §8 时间线统一用 $1.5B)**:攻击面不在 Bybit 代码,而在 Safe{Wallet} 前端供应链——攻击者攻陷 Safe 的 AWS/JS 分发层,签名者浏览器执行被篡改 UI:屏幕上显示正常转账,实际签的是改写 owner 的恶意 calldata(blind signing)。资金经即时兑换、跨链、P2P 分散,大部分未能追回。
- 教训:① 签名终端必须视为高价值目标(供应链/浏览器扩展/剪贴板);② 多签流程要校验**待签字节码**而非界面展示(HSM/气隙设备解码显示 raw calldata);③ 前端 SRI/子资源完整性+发布链路加固。

### 5.2 签名钓鱼(permit / increaseAllowance / 盲签)

- 见 §2.6;钱包侧演进:交易模拟(Tenderly/Blockaid 类)预演资产变化,「该签名将授权 X 全额」语义提示;对 `eth_signTypedData_v4` 的 permit 域解析展示。
- 企业侧:大宗操作走白名单地址+延时生效;财签分离。

### 5.3 假钱包 App

- 形态:高仿 imToken/TokenPocket/MetaMask 官网 SEO 劫持、应用商店山寨、客服渠道发的「修复版」;**输入助记词即上交资产**(App 把 seed 回传攻击者服务器)。
- 其他变体:剪贴板劫持(复制地址时替换收款地址,Android 无障碍权限滥用)、恶意浏览器扩展偷私钥、假客服远程指导「验资产」。
- 取证要点:假 App 的回传域名、打包证书、分发渠道溯源,常能串出黑产团伙。

## 6. 跨链桥漏洞(Wormhole / Ronin / Nomad 复盘)

跨链桥锁仓资产规模巨大,「验证消息有效性」的实现五花八门,是单案损失最高的类别(rekt.news 桥类常年霸榜)。

| 案例 | 时间 | 损失 | 根因一句话 |
|---|---|---|---|

## 7. 与 SRC/执法衔接:涉币案件取证要点

### 7.1 案件类型(国内语境)

- 侵财类:盗窃(私钥/助记词窃取、内部转账)、诈骗(貔貅盘、假 App、婚恋杀猪盘带币)。
- 洗钱类:掩隐、帮信(跑分用 USDT-TRC20)、非法经营(OTC 换汇)。
- 组织类:传销(层级计酬发币)、非法集资 ICO(924 通知定性:虚拟货币相关业务属非法金融活动)。
- 技术类:DApp 漏洞薅羊毛被定盗窃/诈骗的边界(数额+手段)。

### 7.2 取证要点清单

1. **链上数据固定**:哈希、区块、原始 calldata、事件日志,`getTransactionByHash` 原始字节导出;第三方浏览器截图需配合节点数据交叉固定。
2. **地址画像**:交易图谱聚类(共同输入启发式、找零地址、行为指纹)、标签库(交易所/混币/黑产)、与已知案地址的关联度。
3. **落地到人**:交易所调证(充值地址→KYC→IP/设备)、法币出入金通道(银行卡/第三方支付)、钱包 App 本地取证(keystore/明文助记词、剪贴板、浏览器扩展数据)。
4. **价格认定**:案发时点价格(交易所 K 线/指数),争议点——用哪个时点、哪个市场;涉案币处置(委托第三方变卖的合规程序)。
5. **赃款去向**:混币剥离分析报告(概率关联需注明方法论与置信度,供检法审查)。
6. **工具**:国产链上天眼(OKLink/慢雾 MistTrack 均有执法版)、Chainalysis、Etherscan API + 自建 ETL(Dune 复盘)。

### 7.3 SRC 视角的区块链面

- 交易所/钱包厂商 SRC:重放漏洞、假充值(地址归属校验)、API 越权(查别人订单/身份)、提币风控绕过——传统 Web 面直接迁移。
- DApp 前端 XSS/供应链 → 替换合约地址/剪贴板,危害直达资产,优先级高于普通 XSS。
- 测试环境:本地 anvil/hardhat fork 主网复现,严禁主网实战(法律红线)。

# 第7篇 语言篇 —— 各语言程序的逆向特征与工具链

> 对应树节点:Windows安全 [1000012] → 第7篇 语言篇 [1000546](32 子节点)。
> 主线:**拿到一个陌生 PE/脚本,先认语言,再选反编译器,再按该语言运行时特征定位关键代码**。

## 1. 总论:语言识别 → 工具选择(基础知识/反编译 [1000547])

逆向一个 Windows 程序,第一步不是打开 IDA,而是回答「它是什么写的」。识别四要素:

```
识别特征四象限(已文字还原)
┌───────────────┬────────────────────────────────┐
│ ① 查壳/查语言  │ PEiD / DIE(Detect It Easy)签名库 │
│ ② 导入表       │ 运行时 DLL 是最硬指纹:           │
│               │  MSVBVM60.dll → VB6             │
│               │  rtl**.bpl/Borlndmm → Delphi     │
│               │  mscoree.dll(_CorExeMain)→ .NET │
│ ③ 入口代码形态 │ 入口 stub、字符串初始化模式        │
│ ④ 字符串/资源  │ 报错文本、窗体资源、节名(.text/.rsrc)│
└───────────────┴────────────────────────────────┘
```

反编译的两个层次(反编译 [1001255]):
- **机器码 → 汇编/伪 C**:Hex-Rays(IDA)、Ghidra、Binary Ninja、RetDec。受编译器优化、内联、虚表影响,只能得到"近似源码"。
- **中间码/字节码 → 源码层**:语言自带 VM(P-Code、IL、pyc、a3x)通常可近乎完整还原——这是语言篇的核心:凡有 VM 的语言,优先打 VM 层而不是硬啃机器码。

通用决策树:

```
未知 PE
 ├─ 有壳(entropy 高/入口在最后节)→ 先脱壳(见 解密篇/脱壳技术)
 ├─ 导入 mscoree/_CorExeMain → .NET 流程(§2.4)
 ├─ 导入 MSVBVM50/60 → VB 流程(§2.2,先判 P-Code/Native)
 ├─ 导入 rtl*/BORLAND/emu → Delphi 流程(§2.1)
 ├─ 节名 UPX0/或者资源藏 a3x/pyc/asar → 解包脚本层(§2.5-2.7)
 └─ 其他 → VC/MinGW/Gcc 按 C/C++ 常规流程(32/64位逆向章节)
```

## 2. 重点语言深写

### 2.1 Delphi [1000569](基础/代码定位/Delphi逆向/Delphi破解)

**识别特征**
- 导入表:`rtl*.bpl`(静态编译时无,改为内联 RTL 代码)、`BORLANDMM`、`sysutils` 单元报错字符串("Invalid pointer operation"、`EDivByZero` 异常名)。
- 节名 Delphi 默认 `CODE/DATA/BSS/.idata/.tls/.rdata/.reloc/.rsrc`,大写 CODE 是强指纹。
- 入口:`TApplication.Initialize` → `Application.CreateForm` → `Application.Run`,main 序列高度模板化,事件处理全部挂在窗体类上。
- 字符串:Delphi 的 `string` 是 **长度前缀 + 引用计数** 结构(非零结尾),静态工具直接扫 ASCII 会错位;Unicode 后(D2009+)为 UTF-16 带长度前缀。

**工具链**
- **DeDe**(经典):解析 Delphi PE,还原窗体事件表(OnClick/OnCreate 的地址)、DFM 窗体资源、published 属性,直接给出"按钮 → 处理函数地址"映射。老版本支持到 Delphi 7 附近。
- **IDR(Interactive Delphi Reconstructor)**:IDA 上的 Delphi 专用重建器,识别 RTTI 恢复类名/方法名/事件 handler,把 `sub_4012A0` 还原成 `TForm1_Button1Click`。对 Delphi 5~2007 支持最好,新版 Delphi(FMX)支持弱。
- **DCU 反编译**:Delphi 编译单元 `.dcu` 可用 DCU32INT(kb) 等工具转回可读汇编/接口;逆向商业组件(树节点"静态库"同理)时有用。
- DFM 资源:用 Resource Hacker/IDR 直接抽出 RCDATA 里的 DFM 文本,看控件 ID → 到代码中搜 `Ctrl.Handle`/控件变量交叉引用。

**实战要点(代码定位 [1000571])**
1. 先跑 IDR/DeDe 拿事件表,80% 的注册校验就在 `btnRegClick`。
2. Delphi 按钮消息走 `TControl.WndProc` 分发,没有 IAT 密集调用;对 `MessageBox` 下断要断 `Controls.TControl` 内的 `MessageDlg`(VCL 自绘),而非 user32.MessageBox。
3. 注册码比较多用 `StrToInt/IntToStr/Length`,字符串比较 `@UStrEqual`(D2009+)/`@LStrCmp`;在 IDA 里直接找这些 RTL helper 的交叉引用比找 API 快。
4. 知识库补充:收录逆向工程笔记 [1000573](Delphi 逆向系列)。

**代表帖**:《Delphi逆向工程》、《Delphi制作注册机》、《Delphi的注册机模板》、《Delphi程序添加功能按钮①②》。

### 2.2 Visual Basic [1000588]

VB5/VB6 程序有两种编译形态,逆向路线完全不同,第一步必须判别:

| 判别点 | P-Code | Native |
|---|---|---|
| 入口附近 | `MSVBVM60!BASICrtIn` 后跟 **Opcode 解释循环**(`rtc` 前缀函数被解释执行) | 直接机器码,调用 `__vbaStrCmp` 等 `__vba*` helper |
| 导入表 | MSVBVM60.dll 少量 + 大量 `rtc*` 运行时函数 | MSVBVM60.dll + `__vba*` 大量出现 |
| 特征 | 入口后 `push ebp; ... call MSVBVM60.<rtc入口>` 且看到 opcode 表分发(跳转表巨型 switch) | 常见 `push xxx; call __vbaR8Str` 等浮点转换 |

- **P-Code**:VB 自带字节码 VM。逆向用 **VB Decompiler**(商用,直接反编译 P-Code 回近似 VB 源码)或手工解析 opcode 表;知识库专门收录 cyclotron 之 VB P-code 篇 [1000591](P-Code 指令逐一解析,经典系列)。
- **Native**:按普通机器码逆向,但所有字符串/数组操作走 `__vba*` 运行时(`__vbaStrCopy/__vbaI4Str/__vbaFreeStr`),认清 helper 语义即可还原高级逻辑;代表系列 MengLong 之 VB6 逆向工程 [1000592]。
- **SmartCheck [1000595]**:Numega 出的 VB 专用运行时追踪器,直接打印 `Form1.Command1_Click` 级别事件与字符串比较——VB(尤其 Native)样本首选动态工具,比 OD 手工跟省一半时间。
- **VB3/4 [1000598]**:更老的版本,VB3 是纯解释执行(VBXX.DLL),可用专门反编译器(VB Discompiler)直接还原源码。
- 常见坑:VB 字符串是 BSTR(UNICODE,长度前缀+\0),内存里改注册码比较时注意 `__vbaStrCmp` 参数是 BSTR 指针;OD 里下断 `rtcMsgBox` 对应 VB 的 MsgBox。

**代表帖**:P-code 系列——《VB PCODE程序破解纲要》、《P-code visual basic杂谈》、《有关VB程序P-CODE代码逆向工程入门浅说》、《如何制作VB的P-Code调试器》、《VB P-code--虚拟机的艺术》、《VB P-code--调试器的革命》、《VB P-code--伪代码的奥秘》、《VB P-CODE的一些总结》;Native/工具——《VB6反编译详解》、《几种VB6反编译器软件效果比较》、《VB Decompiler Pro 5.0 Keygen with source code》。

### 2.3 易语言 [1000613](逆向知识/实例分析)

中文低门槛开发,国内**外挂、盗号木马、打码/辅助工具大量使用**,是 Windows 恶意样本分析的必修语言。

**编译形态三档**
1. **独立编译**:带 `krnln.fnr`(核心运行库)解释执行,exe 旁边或资源里能找到 fnr/e 库文件;入口后 `eInit` 初始化。
2. **静态编译**(易语言 4.x+ / 5.x):编译成纯机器码,不再依赖 krnln.fnr 解释,但大量调用静态链接的核心库函数(字符串/窗口操作模式固定,指纹明显)。社区对「易语言 5.x 静态编译」程序的分析是经典课题(可检「易语言 5.8 静态编译」;《浅谈易语言编译方式(精华七勘误)》澄清前两档实为——**独立编译**:程序+易支持库打包单 exe,支持库以附加数据(Overlay)挂文件尾,PEID 显示 `Microsoft Visual C++ 6.0 [Overlay]`;每次启动把附加数据释放到临时目录(如 `%TEMP%\E_4`)再加载其中 krnln.fnr,加载失败即报错退出。**非独立编译**:exe 体积小,启动先找同目录 krnln.fnr,找不到则查注册表里易语言安装路径去装;[Overlay] 不是保护方式,加壳须勾"保留附加数据",手工脱壳只脱主体不带走支持库自然跑不起来——这是易语言样本分析第一坑)。
3. **编译生成**易模块/dll:导出函数表带中文函数名(静态编译时可能剥除)。

**识别特征**
- 字符串:程序里大量 **UTF-16LE/GBK 中文提示**,常直接含「易语言」运行时报错文本;
- 静态编译样本节区/入口模式统一:`eInit`/`ECode` 结构、`文本_取空白` 等核心库代码被整块复制,同版本编译器产物在 diff 工具下高度相似;
- 资源/版本信息常留「易语言」编译器痕迹,或 `krnln.fne/fnr` 文件名残留。

**工具与实战**
- 老牌工具 **E-Code Explorer(易语言反编译器)**:针对独立编译,恢复子程序名/参数/局部变量,可 dump 窗体与数据表;静态编译新版支持有限。
- 静态编译样本:IDA + 手工指纹库(把 krnln 常用函数特征做成签名,如 `MessageBoxA` 封装、文本操作 helper),识别后按易语言语义读伪 C。
- 动态:OD/x64dbg 直接下断 WinAPI(易语言最终还是要调 API),配合中文字符串引用定位按钮事件。
- 生态要点:外挂作者常用易语言+VMProtect/穿壳;脱壳后先判形态再选 E-Code Explorer 或 IDA 指纹法。

**代表帖**:《易语言3.5》、《易语言runtime的loader逆向工程》、《浅谈易语言编译方式(勘误)》、《易语言程序的结构、封装原理及安全性》、《易语言5.11缓冲区溢出漏洞》、《易语言QQ钓鱼程序简单分析》、《易语言程序分析笔记》、「易语言 5.8 静态编译」专帖站内可检。

### 2.4 .NET 平台 [1000548]

**识别**:导入表仅 `mscoree.dll` 且入口为 `jmp _CorExeMain`;`CLR Header`(COM Descriptor,数据目录第 15 项)非零;文件常为 `.exe/.dll` 混 IL。

**工具链(按层次)**
- **反编译**:dnSpy(调试+编辑二合一,可用性之王)、ILSpy(开源,插件生态)、dotPeek(JetBrains)。IL → C# 几乎无损。
- **脱壳/反混淆 [1000556-1000567]**:**de4dot** 一把梭(支持 .NET Reactor、Xenocode、MaxtoCode、DotFix、Babel 等上百种壳/混淆的特征识别与清理:重命名、控制流平坦化还原、字符串解密);ConfuserEx 系用专门的 ConfuserEx-Unpacker/deepgrep 思路(先 dump 解密后程序集再修元数据)。知识库树按壳分节点收录:NET Reactor [1000558]、MaxtoCode [1000559]、Xenocode [1000560]、CodeVeil [1000561]、流程+名称混淆 [1000562]。
- **调试**:dnSpy 附加进程断在方法;复杂反调试用 `MegaDumper/ExtremeDumper` 从内存 dump 程序集再 dnSpy 打开。
- **强名称 [1000554]**:公钥签名校验,重编译后需 sn 重新签或 NOP 校验。
- **反射 [1000555]**:代码藏在资源里运行时 `Assembly.Load` 解密加载——静态反编译看不到,要断 `Assembly::Load`/`ResolveEvent` dump 真程序集。

**实战要点**
1. 先看 `AssemblyInfo` 与入口 `Main`,再全文搜关键字符串(注册成功/失败)。
2. 加密壳(MaxtoCode/Agile)把 IL 换成 native stub + JIT hook:脱壳思路是运行后从内存重建 metadata(ExtremeDumper 自动化较好)。
3. 新形态:AOT(.NET Native/NativeAOT/R2R)没有 IL,退化为普通 native 逆向;混淆器 .NET Reactor 的 Necrobit 同理(方法体转 native),需运行时 dump。
4. **AOT/.NET Native**:混淆厂商所谓 "native 编译" 多是伪 AOT,仍留托管元数据;真 NativeAOT 用 IDA+符号还原。

**代表帖**:《.NET Reactor分析》、《如何破解.NET Reactor》、《.Net 反射脱壳机核心源代码》、《.NetReactor 3.6》、《de4dot》、《使用 Eziriz .NET Reactor 对c#程序加密》。

### 2.5 Python [1000583]

Windows 上 Python 样本三大形态:

1. **PyInstaller 打包**:
   - 识别:exe 资源/overlay 有 `MEI` 魔数(PyInstaller archive);
   - 解包:**pyinstxtractor**(按 archive TOC 抽出 pyc 与附属二进制);新版 PyInstaller(≥2.1)主脚本 pyc 无头时补 magic 修复。
   - 反编译 pyc:**uncompyle6**(≤3.8)、**decompyle3**(3.7/3.8)、**pycdc**(C++ 实现,支持新版本半还原);3.9+ 只能靠 pycdc 或读 dis 汇编。
2. **py2exe / cx_Freeze**:library.zip 直接 unzip 得 pyc,同上反编译。
3. **嵌入解释器型(C 写主程序 + python31.dll)**:找 `.pyc/.pyd` 资源或 `Py_Initialize` 后加载的字节码;**Cython 编译的 .pyd** 是真机器码,退化为普通 native 逆向(符号常带函数名)。

**实战要点**
- 反编译报 magic 错误 → 版本不匹配,先 `xxd` 看 pyc 头 4 字节 magic 对照 Python 版本表;
- 打包密码(-p):解包工具会提示,密钥常硬编码在 bootloader,可 patch 提取;
- 恶意样本常见套路:主逻辑 Python,释放 payload;解包后优先看 `main`/`__init__` 与 base64/zlib 层。

**代表帖**:《Python逆向——Pyinstaller逆向》、《逆向Pyinstaller打包的程序源码及保护》。

### 2.6 Electron 与 JavaScript [1001776 / 1001261]

**识别**:目录里有 `*.pak/resources/asar`、主 exe 是 Electron 壳(版本字符串 ELECTRON)、安装包巨大(≥150MB)。

**逆向流程**
1. 找 `resources\app.asar`(或解包后的 app/ 目录);
2. **解包 asar**:`npx asar extract app.asar out`(或 asar7zip);核心逻辑在 `out/main.js`(主进程)与渲染进程 bundle;
3. 前端 bundle 常被 webpack/terser 压缩混淆:用 sourcemap(若有 `.map`)一键还原;无 map 用 webcrack/jsbeautifier 反混淆;
4. 重点:`main.js` 里的注册验证、自动更新 URL、nodeIntegration 配置(渲染进程若开 node 集成可直接 node 命令注入);
5. **asar.integrity**(新 Electron 打包完整性头):改 js 后校验失败 → 同时改 `package.json` 关闭或重算 integrity(hexdump electron `fuses`)。
6. JS 逆向通用:eval/Function 包装的代码用断点/重写 eval dump;obfuscator.io 系用 restringer/synchrony 反混淆。

**代表帖**:《Electron编写的exe 逆向思路》、《向Typora学习electron安全攻防》、《嵌入式浏览器安全杂谈-electron框架》。

### 2.7 AutoIt [1000575]

- **识别**:`AutoIt v3` 版本资源/字符串、导入 `msvcrt` 少、节里藏 `a3x`;或加壳(AutoIt 官方 Aut2Exe 带压缩)。
- **a3x 字节码**:Aut2Exe 编译产物并非纯机器码而是 AutoIt 字节码 + 解释器 stub。反编译:
  - **MyAut2Exe**(经典,支持到 3.2.x);
  - 新版(3.3.x+)社区工具 au3-decompiler/exe2aut 变体;
  - 兜底:动态跑,monitor 脚本解释行为(Process Monitor 看文件/注册表触点),或提取 a3x 后手工解析 token 流。
- 恶意样本注意:AutoIt 恶意家族(AutoIt/CVE 利用加载器)常把核心 payload base64+二次解释,跑一层 dump 一层。
- 知识库同时在「脱壳技术 → 外壳实例 → AutoIt [1000353]」收录了 AutoIt 壳(Exe2Aut 相关)的分析节点。

**代表帖**:《Autoit3反编译引擎》、《AutoIt程序自校验》、《简析AutoIt程序脱壳后的自校验处理》、《一个AutoIt盗号木马》、《AutoIT FUD Crypter样本的分析》

## 3. IL2CPP [1001782](游戏跨平台,单列)

Unity 游戏把 C# IL 转成 C++ 再编成 native:`GameAssembly.dll` + `global-metadata.dat`。
- 工具:**Il2CppDumper**(解析 metadata 恢复类/方法名生成 IDA/Ghidra 脚本)、Il2CppInspector;
- 打法:dump 符号 → IDA 跑脚本 → 按 C# 语义读;加密 metadata(加固)需先脱壳 dump 明文;
- 知识库另有 Android 侧 U3D/IL2CPP 节点(游戏分析 → U3D [1001710]),PC 单机修改同理(CheatEngine + 符号)。
- **Android 教程级全流程**(判定 APK 形态/IDA 挂脚本/metadata 加密变体/frida-il2cpp-bridge 实战)在 `../../手法/14-手游框架/Unity与IL2CPP.md`,与本节互链。

## 4. 方法论小结

1. **先认形态再上工具**:同一语言不同编译形态(P-Code/Native、独立/静态编译、IL/AOT)工具链完全不同。
2. **运行时 helper 是路标**:VB 的 `__vba*`、Delphi 的 `@LStr*`、易语言核心库、Go 的 `runtime.*`——helper 交叉引用比 API 断点更贴近业务逻辑。
3. **脚本层优先**:凡是带 VM/打包器(P-Code/a3x/pyc/asar),先解包反编译源码层,失败才回机器码。
4. **混淆是常态**:.NET de4dot、JS synchrony、Lua unluac 之后还有一层商业壳时,先脱壳(见 解密篇)再回语言层。
5. **指纹要积累**:把常见编译器运行库做成 IDA 签名库(FLIRT/Lumina),识别率决定后续速度。

## 5. 实战串联:三类典型场景全流程

### 5.1 破解向:Delphi 共享软件注册校验

```
DIE 查壳 → 无壳/Delphi 指纹(rtl 字符串 + CODE 大写节)
→ IDR 重建(事件表直接给 btnRegClick 地址)
→ IDA 跳到 handler → 读伪 C:多半是 "机器码 → 变换 → 与序列号 StrCmp"
→ 三选一:
   a. 算法可逆 → 写注册机(解密篇 注册机编写 [1000202])
   b. 改跳转   → UE/IDA patch(重构篇 文件补丁 [1000734])
   c. 比较在 DLL → DCU32INT 反编译 DCU 单元
失败路径:加了壳 → 先走脱壳技术 [1000288];VMProtect 虚拟化关键函数
         → 见 保护篇 虚拟机 [1000711](成本超收益即止)
```

### 5.2 恶意样本向:PyInstaller 投递的 Loader

```
样本.exe(VT 免杀好)
→ DIE: PyInstaller archive(overlay MEI 魔数)
→ pyinstxtractor 解包 → 得 main.pyc + 依赖
→ magic 头对版 Python 3.9 → pycdc 反编译(或 dis 手读)
→ 主逻辑:base64(zlib(Cobalt Strike shellcode)) + VirtualAlloc/CreateThread
→ 静态还原到此为止;动态走沙箱/Unicorn 模拟解 shellcode 配置
注意:pyc 打包密码 → patch bootloader 提取;Cython .pyd 型退化为 native 逆向
```

### 5.3 游戏/商业向:.NET + ConfuserEx 加固

```
Assembly-CSharp/主程序 .NET 指纹(CLR Header)
→ ILSpy 打开 → 全是混淆名/控制流乱 → de4dot 检测识别 ConfuserEx
→ de4dot 处理:反混淆控制流+解密字符串(部分模块需带 --strtyp 参数)
→ 处理不掉的代理常量/反篡改 → dnSpy 调试:断 Assembly.Load dump 真体
→ 重签/去强名称 [1000554] → ILSpy/dnSpy 反编译读核心逻辑
→ 修改需求 → dnSpy Edit Method(C# 级重编译)或 Reflexil 插件改 IL
```

### 5.4 排错速查

| 症状 | 最可能原因 | 动作 |
|---|---|---|
| IDR/DeDe 识别失败 | 新版 Delphi(FMX)/加壳 | 先脱壳;FMX 用 RTTI 通用工具 Ghidra+C# 反射式恢复 |
| pyc 反编译全错 | 版本/无头 pyc | 补 magic;3.9+ 转 dis 阅读或 pycdc 更新版 |
| asar 解开后空白 main | 代码在 asar.unpacked/ 或字节码 pkg | 看 package.json 的 pkg/electron-builder 配置 |
| VB P-Code VB Decompiler 报错 | 非标准编译/壳 | SmartCheck 动态追 + cyclotron 篇手工 opcode |
| 易语言 E-Code Explorer 打不开 | 静态编译(5.x) | IDA + 核心库指纹;搜中文宽字符串定位 |

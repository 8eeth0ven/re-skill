# 基础知识(根分类,逆向通用底座)

> 对应目录树节点:基础知识 [1000001](24 个子节点,按层级共 25 节点)。
> 定位:逆向工程全栈的「地基」——CPU/汇编/PE/密码学/OS/编译链。所有进阶篇(病毒木马篇/调试篇/解密篇)的地基都长在这张图上。

## §1 CPU体系架构

### 1.1 x86/x64 核心模型

- **寄存器组(64 位)**:`RAX RBX RCX RDX RSI RDI RBP RSP` + `R8-R15` + `RIP`;32 位视图 `EAX/…`,16 位 `AX`,8 位 `AL/AH`。x64 新增:R8-R15、非易失寄存器集合变化(RBX/RBP/RDI/RSI/R12-R15 跨调用保留)。
- **标志寄存器 RFLAGS**:逆向只关心 `ZF`(相等/为零)、`CF`(进位/无符号小于)、`SF`(符号)、`OF`(有符号溢出)——条件跳转的判定全在这四位。
- **指令指针 RIP**:x64 下不能直接读写,只能间接控制(这也是 ROP 的基础约束)。
- **微架构常识**:分支预测、乱序执行对逆向的影响主要在时间侧信道(meltdown/spectre 家族),见「二进制漏洞」子树。

### 1.2 ARM 概览(横向对照)

固定 32 位指令长度(A64 为 32 位编码)、load-store 架构(算术不碰内存)、`PC/LR/SP` 特殊化。逆向 Windows on ARM 或移动样本时对照记忆:`x0-x7` 传参、`x29` 帧指针、`x30` 返回地址。

### 1.3 CPU 提供的三块"逆向基础设施"

1. 调试寄存器(§2)——硬件断点;
2. 单步标志 TF——调试器步进的根基;
3. 断点指令 `INT 3`(0xCC)——软件断点(调试器把目标字节换成 CC,命中后还原)。
   反调试正反过来利用:校验代码段 CC 字节、`INT 2D` 反调试、TF 检测(见《保护篇》反跟踪子树)。

## §2 调试寄存器(节点 1000003)

- **DR0-DR3**:四个硬件断点地址(线性地址);
- **DR6**:状态寄存器(哪个断点触发,B0-B3 位);
- **DR7**:控制寄存器(每断点 2 位使能 + 读/写/执行类型 + 长度 1/2/4/8 字节)。
- **DR4/DR5**:在 CR4.DE=0 时分别是 DR6/DR7 别名;置 DE=1 后访问触发 #DB——老牌反调试技巧。
- **为什么硬件断点强**:不改代码字节 → CRC 自校验壳查不出来;缺点只有 4 个。
- 调试器视角:x64dbg「硬件断点」选项本质就是 GetThreadContext 设 CONTEXT 结构的 Dr0-Dr7;壳检测硬件断点则读自身线程 CONTEXT 比对。
- 单步:RFLAGS 的 TF 位置 1,每条指令后 #DB 异常 → 调试器逐步接管;trace/动画执行全靠它。

## §3 反汇编引擎

### 3.1 两种算法路线(反汇编引擎原理 1001391)

| 路线 | 思路 | 弱点 |
|---|---|---|
| 线性扫描(linear) | 从入口顺序解码每条指令 | 数据夹在代码中会被误译码 |
| 递归下降(recursive descent) | 从入口沿控制流(call/jcc/ret)遍历可达代码 | 间接跳转(函数指针/跳表)成盲区,需启发式补充 |

IDA/ghidra 主走递归下降 + 流式补码;W32Dasm 是线性扫描时代的代表。知识库经典帖《打造自己的反汇编引擎》(1000007)与《32位反汇编引擎开发笔记》(1001473)都是手把手实现 ModRM/SIB 解码的教学。

### 3.2 x86 指令编码骨架(逆向解码必背)

```
[Prefix(66/F2/F3/REP…)] [Opcode 1-3B] [ModRM] [SIB] [Disp] [Imm]
ModRM = mod(2) | reg(3,寄存器/操作码扩展) | rm(3)
  mod=00 rm=101 → RIP相对寻址(x64 常见 lea rax,[rip+xxx])
  mod=11 → 寄存器直接操作
SIB   = scale(2)|index(3)|base(3) → [base + index*2^scale + disp]
```

变长指令(1-15 字节)是 x86 一切"花指令/重叠指令"混淆的土壤(在垃圾字节前 jmp 跳入指令中间,线性反汇编即错位)。

### 3.3 主流引擎选型

- **Capstone**:事实标准,IDA 同源轻量,Python 绑定,做脚本化分析首选;
- **Zydis**:现代 C 实现,解码信息全(含隐式读写);
- **distorm**:老牌高性能;
- 自研训练路线:按 1000007 帖,先硬译 one-byte opcode 表 → ModRM → 前缀 → 16/32/64 语境,两周可成雏形。

## §4 Intel手册翻译(节点 1000008)

Intel SDM 三卷是 x86 的"宪法",社区组织过全三卷翻译(树内三节点):

- **卷一 Basic Architecture**(1001219):数据类型、寄存器、寻址模式——入门通读;
- **卷二 Instruction Set Reference A-Z**(1000009):逐条指令编码格式与伪代码——**逆向时最常翻的一卷**,查 ModRM 语义/边界行为;
- **卷三 System Programming Guide**(1000010):分段分页、中断异常、VT-x、调试架构——内核逆向与 Rootkit 分析的地基。

## §5 虚拟机应用(节点 1001202)

### 5.0 虚拟化原理(虚拟化是如何工作的 1001203 / 深入解析虚拟化 1001263)

- 两类"虚拟机"必须分清(逆向语境下都叫 VM):
  1. **系统虚拟化**:VT-x(VMX non-root/root)+ EPT 二级地址翻译,跑整个 OS——VMware/Hyper-V/KVM;
  2. **代码虚拟化(VM 保护)**:把 x86 指令翻译为自定义字节码 + 解释器循环——VMProtect/Themida(见《保护篇》虚拟机子树)。
- 硬件虚拟化核心:敏感指令触发 VM-Exit 陷入 Hypervisor;EPT 让 Guest 物理地址再经一层翻译,影子页表已淘汰。
- 检测虚拟化(恶意样本反沙箱的原理面):CPUID 叶节点、hypervisor 位、VMware backdoor(I/O 端口 0x5658)、注册表/驱动/ACPI 字符串指纹。

### 5.1 虚拟机引擎(1000713)

树内定位偏向"VM 保护引擎"的分析与编写:handler 表结构、dispatch 循环(常见 `jmp [reg*4+table]`)、虚拟寄存器上下文。攻破思路:符号执行/trace 对比原始指令序列(VMProtect 逆向的老三样:trace 压缩、handler 识别、栈平衡校验)。

### 5.2 bochs(1001204)

纯软件全系统模拟器(每条指令都解释执行,不用硬件虚拟化)→ 唯一能做到「物理内存级透明调试」的工具:0day 漏洞利用调试(不必处理反调试)、MBR/Bootkit 分析(能断在 BIOS/引导阶段)、被 VMProtect 检测的样本在 bochs 下无感。代价:慢 10-100 倍。

### 5.3 LLVM 混淆与麒麟框架(LLVM 1001397 / LLVM混淆 1001372 / Armariris 1001373 / 麒麟框架 1001392)

- **OLLVM(Obfuscator-LLVM)**:在 LLVM IR 层做控制流平坦化(bogus-flow + dispatcher)、虚假控制流(bogus)、指令替换(sub/xor 三角交换)。编译期一次注入,抗静态分析极强。
- **Armariris**:社区开源的 LLVM 混淆框架(OLLVM 升级维护版,支持新 LLVM 版本,GitHub 开源)——树内专门节点,是国内逆向圈自研工具的代表。
- **麒麟框架(Qilin)**:基于 LLVM 的二进制分析/重写框架(树节点 1001392),做二进制插桩与符号执行辅助。
- 去混淆三板斧:符号执行(anger,树内 1001369)+ trace 修剪(IDA 插件 D810/deflat)/ 动态 trace 对比重构真实 CFG。

## §6 反编译原理(节点 1001370)

- 输入汇编 → 输出类 C 代码,流水线:反汇编(§3)→ 控制流图 CFG → 数据流分析(寄存器/栈变量传播)→ 类型恢复 → 结构化(if/while 重构,循环检测+支配树)→ 语法输出。
- **Hex-Rays 微码(microcode)**:IDA 把汇编先升为机器无关微码层再优化,这一层也开放给插件(其新 API 可写自定义优化 pass 去花/去平坦化)。
- 局限:间接调用恢复不了(需交叉信息)、C++ 虚表/异常/模板还原靠启发式、自修改代码直接失效。
- 同类:Ghidra(开源,SLEIGH 处理器描述语言)、Binary Ninja(LLVM IR 中间层,API 最顺手)、retdec(学术)。知识库树内 Ghidra 节点(1001389)含脚本与技巧两子节点。

## §7 编译原理(节点 1001614)

逆向要"认得"编译器产物,必懂编译链:

```
源码 → [词法/语法分析] AST → [语义] IR → [优化] SSA/常量传播/内联/循环优化
     → [后端] 指令选择/寄存器分配 → 汇编 → 汇编器 → 目标文件 → 链接器 → PE/ELF
```

- **优化指纹识别**(逆向定型用):`O2` 下循环被展开/合并,`Release` 无栈帧(`push ebp;mov ebp,esp` 缺失 → RBP 被当通用寄存器),内联函数无调用边界——都是判定编译器/选项/语言的旁证。
- **链接期要点**:静态链接 CRT(`__security_check_cookie`、`_main` 启动序)、延迟加载导入、重定位(ASLR 配套,见 §9 PE)。
- C++ 特有:名字修饰(name mangling,`?func@@YAXH@Z` 可直接 demangle 还原签名)、虚表结构、RTTI(`type_info` 链可半自动恢复类层次——IDA 的 RTTI 扫描)。知识库《32位软件逆向》子树的 C++ 逆向两帖(1000135/1000136)是树内原生的深读材料。

## §8 逆向通用·密码学(对应树《加密算法》子树主干的提炼)

### 8.1 对称加密

- **分组密码**:DES(64 位块/56 位密钥,已废)、3DES、**AES**(128/192/256 位,现代样本标配:勒索软件会话密钥)、Blowfish/IDEA/TEA/XTEA(游戏与壳偏爱,体积极小)。
- **模式**:ECB(同明文同密文 → 图片加密可肉眼见轮廓,判定线索)、CBC/CTR/GCM;IV 位置与是否随机是逆向重点。
- **流密码**:RC4(老 RAT/协议加密常客,识别靠 S-box 初始化 256 次交换循环)、XOR 流(黑产最爱,常见固定单字节/滚动密钥)。
- **编码非加密**:Base64(尾部 `=`、字母表变体 URL-safe/自定义表是"加密"错觉的常客)、hex。

### 8.2 非对称

- **RSA**:大数运算(n/e/d,通常 1024-4096 位);逆向识别:导入 `BCryptEncrypt`/CryptoAPI 的 CALG_RSA_KEYX,或静态出现大整数常量;勒索=RSA 公钥加密会话密钥。
- **ECC/SM2**:国密合规产品多用;SM2 为树内专门节点(1001270)。
- **DH**:密钥协商,协议类样本(C2 握手)常见。

### 8.3 哈希

- MD5(128 位,碰撞性弱但校验用途仍广)、SHA1/SHA256、CRC32(文件/网络校验,非安全哈希)。识别:魔数初始化常量——MD5 的 `0x67452301`,SHA1 的 `0x67452301 0xEFCDAB89`,SHA256 的 `0x6A09E667`,CRC32 表 `0xEDB88320`。**看到这四个常量立即知道在算什么**——这是逆向识别加密算法的第一杀招。
- 第二杀招:导入表/特征 API(`CryptAcquireContext`、`BCryptOpenAlgorithmProvider` 参数字符串 `"AES"`/`"SHA256"` 直接泄露)。
- 第三杀招:S-box 常量表(AES 的 `63 7C 77 7B F2 6B 6F C5…` 开头 256 字节表;DES 的 PC1/PC2 置换表;TEA 的 delta `0x9E3779B9`——魔数圈最著名常量)。

### 8.4 逆向工作流

1. 常量/API 定位算法(上述三杀招)→ 2. 参数与模式(密钥从哪来:硬编码/派生/上线下发)→ 3. 用 Python/C 复现对拍(拿一组样本密文验证)→ 4. 攻击弱点(ECB 重放、IV 可控、密钥可预测、随机数用了 `rand(time(0))`)。注册机与勒索"可解密"分析(如 Solar LIVE 帖)全部走这条流程。

## §9 PE 深入(对应树《系统篇-PE格式》主干)

### 9.1 整体地图

```
+---------------------+ 0x0
| DOS Header (MZ)     |  e_magic 'MZ'; e_lfanew → PE 头偏移
| DOS Stub            |  "This program cannot be run in DOS mode"
+---------------------+
| PE Signature 'PE\0\0'|
| File Header         |  Machine/NumberOfSections/TimeDateStamp/Characteristics
| Optional Header     |  AddressOfEntryPoint★/ImageBase/SectionAlignment/FileAlignment
|  (DataDirectory[16])|  EXPORT/IMPORT/RELOC/TLS/COM/RESOURCE…各目录 RVA+Size
+---------------------+
| Section Headers[]   |  Name/VirtualSize/VirtualAddress/SizeOfRawData/PointerToRawData/Entropy
+---------------------+
| Sections .text/.data/.rsrc/.reloc …
| Overlay(附加数据)  |  自解压包/恶意 payload 常藏于此,PE 装载器不加载
+---------------------+
```

### 9.2 逆向必会五件事

1. **RVA↔VA↔文件偏移**:VA = ImageBase + RVA;文件偏移 = RVA - 节 VirtualAddress + 节 PointerToRawData。所有"内存断点地址打不出文件 patch"的问题都是这三个换算没过关。
2. **导入表(IAT)**:INT/IAT 双链(Name/FirstThunk),绑定输入(节点 1001474)是启动加速优化;加壳样本 IAT 破坏 → 脱壳后要重建(Scylla/ImportREC)。
3. **TLS 目录**:反调试最爱——TLS 回调在入口点**之前**执行,`AddressOfCallBacks` 里的函数先于 EP 跑(树内 TLS 节点 1000154 为专题)。分析壳必须先看 TLS。
4. **重定位表(.reloc)**:ASLR 生效时加载器按 IMAGE_BASE_RELOCATION 块修 VA;DLL/EXE 都可能带。手工搬代码/增加节时的必修课(《重构篇》重定位节点 1000768)。
5. **资源与 Overlay**:释放器藏 payload 的两大位置;`SizeOfImage` 之外的文件尾巴即 Overlay,`pefile` 一行 `get_overlay_data` 提取。

### 9.3 恶意软件常用 PE 技巧速查

- 节名乱码/节属性可写可执行(RWX)→ 壳/注入特征;
- `AddressOfEntryPoint` 指向最后一节 → UPX 类压缩壳;
- 无导入表+高熵节 → 加密器;
- 签名目录存在但 hash 不匹配 → 签名伪造/嫁接(银狐常态);
- 富文本头(Rich Header)与声明编译器不符 → 伪造 PE 头对抗归因。
- 工具:010 Editor+PE 模板(树节点 1001524)、PE-bear、CFF Explorer、`pefile` 脚本化批量。

## §10 x86/x64 汇编要点(逆向视角)

### 10.1 调用约定(看函数先看约定)

| 约定 | 传参 | 清栈 | 场景 |
|---|---|---|---|
| cdecl | 栈右到左 | 调用方 | C 默认(32 位),参数个数可变 |
| stdcall | 栈右到左 | 被调方(ret n) | WinAPI(32 位) |
| fastcall | ECX/EDX 先,余栈 | 被调方 | MS 扩展 |
| x64 (Microsoft) | RCX/RDX/R8/R9 + 栈 | 调用方,32 字节 shadow space | Win x64 唯一主流 |
| x64 (SysV) | RDI/RSI/RDX/RCX/R8/R9 | 调用方 | Linux/跨平台 |

x64 栈对齐 16 字节、shadow space 必留——hook 和注入代码(病毒木马篇 §4)写错就对崩。

### 10.2 高级结构识别模式

- **if/else**:`cmp/test` + `jcc` 跳过一支;
- **循环**:向下计数 `dec ecx; jnz` / 向上 `cmp i,n; jl`;
- **数组访问**:`[reg + idx*4]`(SIB scale);
- **虚函数调用**:`mov rax,[rcx]`(取 vtable)→ `call [rax+offset]` —— C++ 逆向第一眼模式;
- **栈帧与局部变量**:`sub rsp,0x28` 即预留 0x28 字节局部区;RELEASE 下 RSP 相对寻址替代 RBP;
- **字符串初始化**:大片 `mov qword ptr [rsp+..], imm` 连拍即栈上构造数组/结构体。

### 10.3 熟手习惯

读不懂先跑起来:静态定位函数 → x64dbg 下断 → 看真实参数与返回值,再回头读代码;配合 IDA F5 交叉验证。深入材料:树内《深入浅出指令编码》(1000019)、《x64 汇编》(1001396)、《从汇编的角度学习C/C++》(1001716)。

## §11 操作系统概念(Underneath Windows)

### 11.1 虚拟内存与分页

- 每进程 4GB(x64 256TB)独立虚拟地址空间;`VirtualAlloc/VirtualProtect` 是注入与壳的基石 API。
- 分页:x86-64 四级页表(PML4→PDPT→PD→PT),页 4KB(+2MB/1GB 大页);CR3 指向页表根。
- 换算:`VA → (PML4, PDPT, PD, PT, Offset)` 各 9 位;读懂页表 = 读懂 PatchGuard/隐藏进程(DKOM)类 Rootkit 的前置课。
- Copy-on-Write、工作集、PFN 数据库概念层面了解即可。
- 实战关联:PE 的 SectionAlignment 决定内存对齐(§9);ASLR 由重定位表配合(§9.2-4)。

### 11.2 保护环(Ring0/Ring3)

- Ring3 用户态(应用/样本默认)、Ring0 内核态(驱动/Rootkit/杀软主防)、Ring-1 Hypervisor(VT 虚拟化,§5.0)、SMM(更深的固件层)。
- 权限边界靠 CPL+页表 U/S 位+I/O 特权级;`syscall/sysenter` 是唯一合法上行通道(x64:syscall,MSR LSTAR 指向 KiSystemCall64——syscall 直调免杀的原理位面,见病毒木马篇 §4.2)。
- SSDT(树节点 1000166):系统服务描述符表,ntoskrnl 导出 `KeServiceDescriptorTable`,内核 Hook 的经典战场;Win10+ 后 SSDT 不再导出+PatchGuard 保护,对抗转向内核回调与驱动过滤。

### 11.3 中断与异常

- **中断**(异步,硬件/软件):IDT 256 项,`int n` 直索引;时钟中断驱动调度;`int 3`(0xCC)/`int 2d` 是调试器与反调试共用阵地。
- **异常**(同步,CPU 或软件触发):#DE 除零、#PF 页错误(写时复制/换页驱动)、#BP 断点、#GP 保护违例。
- **SEH 结构化异常处理**(树节点 1000163):x86 链式 `FS:[0]` → 异常注册记录;x64 改表驱动(`RtlAddFunctionTable`+UNWIND_INFO 展开信息,栈回溯不再依赖链表)。反调试利用:SEH 反调试(故意除零,异常处理器里检测调试)、VEH 优先级抢先。壳的异常驱动解密(抛异常触发解码)必须理解这条机制。
- 与调试器的关系:调试器抢异常第一现场(first-chance/second-chance),样本借此探测调试器存在。

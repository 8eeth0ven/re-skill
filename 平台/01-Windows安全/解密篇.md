## 1. 演示版保护技术总览(树节点 1000183)

### 1.1 解密知识观(1000184)

"解密入门"始于商朝子破解教学(1000186,2000 年代启蒙帖)。方法论核心:**保护是"延迟"不是"杜绝"**——一切保护最终都要在用户机器上完成校验,逆向者的任务是找到那段"比较/跳转"逻辑并理解或绕过。流程定式:

```
定位目标(功能/提示) → 定位代码(字符串/窗口/消息/断点回溯)

   A. 爆破(patch 跳转)      B. 写注册机(求逆算法)      C. 伪造环境(keyfile/注册表/网络包)
```

## 2. 序列号保护与注册机(树节点 1000189,实例跨 2000~2024 年)

### 2.1 明码比较与暗码比较

```
明码比较: 输入串 == 内置串(或简单变换后比较)
  定位: bp GetDlgItemTextA/W / GetWindowTextA 后单步几步即见 cmp
暗码比较: f(输入) == g(机器码/内置值) —— 校验与生成分离
  关键: 找到"输入→中间值"的变换 f(常为自实现算法)
```

### 2.2 破解三路(树子节点对应)

1. **内存注册机**(1000192,原理 1000193/KeyMake 1000194/CrackCode 1000197):跟踪到"比较通过瞬间",取此时内存中的**真注册码**(程序算出的期望值),弹窗显示——不需要理解算法,只抢结果。KeyMake(按键机器)把"断点位置+取值规则"做成配置发布。
2. **WinHex 破解法**(1000200):直接在文件/内存中搜替换特征字节(爆破的原始形态)。
3. **注册机编写**(1000202,教学系列 1000203~1000206):完整理解算法后正向重实现。
   - 提取汇编法:把校验函数的汇编原样抠出,套 C 的 `__asm`/独立 .bin 加载执行——算法有混淆/依赖随机数种子时最稳。
   - **算法求逆**(1000209):f 单射则逆推输入。可逆变换(逐字节 xor/查表/移位)直接反演;不可逆(md5)则只能碰撞或换路(伪造比较结果)。

### 2.3 注册表比较/自注册(1000201/1000208)

`RegQueryValueExA` 读键校验:伪造键值;自注册=程序首运行写键,破解改写入值或绕过期判断。期限类键值注意时间戳运算(拿系统时间做差的),重点在差值比较点。

### 2.4 实战要点

1. 优先"暗码抢结果":在 `cmp/jz` 决胜点改 ZF 或直接拿期望值,比求逆快十倍。
2. 校验函数特征:字符串长度取值跳转表(switch len)+ 查表运算 + 累加器循环——识别后整体抠出。
3. 多层校验(输入格式/注册状态/功能内再验)要全找齐,只破一层会"注册成功但功能无效"。
4. 现代商业软件走 RSA/ECDSA(服务器公钥验签)——正向求逆不可行,只能 patch 验签跳转或伪造公钥(§6.3)。

## 3. 脱壳技术全流程(树节点 1000288)

### 3.1 壳的执行模型

```
加壳 PE:  [外壳节(新EP)] [压缩/加密的原始代码]
运行时:  外壳解密/解压 → 重建导入表 → 恢复重定位 → Stolen code 补齐
        → jmp 原始入口 OEP ──→ 程序正常执行(此后壳可能仍驻留:监听/二次加密)
脱壳 = 在"解压完成、OEP 未执行污染"瞬间 dump 内存映像 + 修复 PE(IAT/节表/重定位)
```

### 3.2 OEP 寻找(树节点 1000291)

| 方法 | 操作 | 适用 |
|---|---|---|
| **ESP 定律** | 壳入口 `pushad` 处下硬件访问断点于 ESP 指向地址,`popad` 恢复现场后一步即 OEP 附近 | 通用压缩壳(UPX/ASPack) |
| 内存断点(执行) | 对代码节设"执行"断点,首次命中即 OEP 方向 | 通用 |
| 单步跟踪 | F8 步过,遇跨节大跳转(jmp 远地址/ret)即 OEP | 简单壳;VM 壳不适用 |
| 断 API 法 | bp GetCommandLineA/GetModuleHandleA 等"程序第一声",返回用户代码 | 壳调用系统 API 后转交 |
| Trace 条件 | x64dbg trace 条件"地址∈代码节"批量记录后离线分析 | 乱序/混淆壳 |
| 圣杯:Stolen code | OEP 前若干条指令被壳偷走重建,需手工补回原逻辑 | ASProtect/EncryptPE 等(§5.2) |

### 3.3 抓取内存映像 Dump(树节点 1000292,《浅谈脱壳中的Dump技术》1000293)

- OEP 处(未污染瞬间)用 LordPE/x64dbg dump /`Scylla dump` 抓完整节映像。
- 修节表:按内存 SectionAlignment 重写每节 `SizeOfRawData=VirtualSize(对齐后)`、`PointerToRawData` 按文件顺序重排(基础篇 §2.10)。
- 大地址/空洞节(VirtualSize 巨大未提交)按需截断;Overlay 判断保留(树节点 1000299 附加数据)。

### 3.4 重建输入表 IAT(树节点 1000295,核心难点)

```
壳破坏 IAT 的方式:
  ① 重定向: call [IAT] 改成 call 壳内跳板 → 跳板 jmp 真函数(带解密/计数)
  ② 加密: IAT 项运行时解密; ③ 混淆 API 名(重命名/自算 hash 解析)
重建流程(ImpREC/Scylla 自动化同一原理):
  1. 在 OEP 处扫描代码中所有 call [mem] / jmp [mem] 的 mem → IAT 范围
  2. 逐项读内存中已解析的真实函数地址 → GetModuleName+GetProcName 反查名字
  3. 新建 .idata: IMAGE_IMPORT_DESCRIPTOR(按 DLL 分组)+ INT/IAT 数组
  4. 修 DataDirectory[1](IMPORT)指向新表; Size=IAT 目录同步
工具: ImpREC(经典,OD 时代)、Scylla(x64dbg 标配, x64 支持)★
  x64dbg 脚本化修复实例: thread-18042《通过x64dbg脚本功能修复IAT表》
坑: 间接调用表不连续(需手工切块)/指针被偷(Stolen)/IAT 混入非 API 数据 → 逐块修
```

### 3.5 重定位/输出表/乱序/优化(1000296~1000298/1000302)

- 重定位表:dump 后若 ImageBase 变了需重建 `.reloc`(按新基址扫描所有"原基址引用"重生成条目);PE-Armor 类壳运行中已把重定位改指向壳表,需剥壳后重算。
- 输出表(1000297):DLL 脱壳后导出目录需从内存重建(ASProtect 会加密输出表)。
- 乱序重构(1000298):壳把代码块打散重排(jump 连接),需要 trace+图算法恢复线性;现代 VM 壳则直接进入虚拟机还原领域(保护篇)。
- PE 文件优化(1000302):对齐/合并节/清壳残留节,减少特征。

### 3.6 实战要点

1. 脱壳黄金律:**停在 OEP 那一瞬**——晚一步程序自毁/二次加密,dump 即废。
2. 完整验证链:dump 后 PE 可静态解析(基础篇工具链)→ IAT 完整 → 能独立运行 → 功能正常,四关全过才算脱净。
3. 双壳/多阶段壳:外层压缩+内层加密,逐层脱,别想一步到位。
4. x64 下注意:含 `.pdata` 异常表,改代码必须同步维护 unwind,否则首异常即崩。

## 4. 脱壳机(树节点 1000303~1000309)

```
静态脱壳机(1000305): 纯算法逆解压缩流, 不运行目标 —— 快、安全(免触发反调试)
  代表: UPX(-d 自带)、AsPackDie、NsPack、PEArmor 专用(树 1000306~1000309)
  条件: 壳无多态/无密钥派生(同版本同算法), 特征定位压缩数据直接展开
动态脱壳机(1000304): 驱动/调试器仿真壳执行到 OEP 自动 dump+fix
  实现即"调试器开发"(调试篇 §4) + 脱壳流程脚本化
  对抗: 壳检测调试对象/时间差/单步陷阱 → 需无痕(虚拟化/hypervisor 级)
通用自动化: 现代 trace+模拟(Unicorn)重建, 参保护篇虚拟机节点
```

要点:静态优先(可复现可批量);动态脱壳机本质是反调试对抗工程,不是流程工程。

### 5.2 ASProtect 专题(树最细:12 个子节点)

版本演进 0.9x→2.x,已知对抗点:SEH 反调试/多线程解码/IAT 全加密重定向/Stolen code(入口指令偷走,在壳内重建执行,脱壳需手工还原被偷指令)/SDK 嵌入(高级保护加密用户函数)。SKE 版子节点(1000344~1000350):SDK、脱壳教程、Stolen Code、SDK 修复、Advanced Import protection、注册算法。知识库帖:《使用OllyDbg从零开始Cracking 第51/52章 ASProtect v2.3.04.26 脱壳 Part1/2》。

### 5.3 VMProtect 专题(壳实例+虚拟机双节点)

### 6.2 注册机中的算法求逆

```
自研变换(可逆): xor/移位/查表混合 → 从出口反演回输入(注意轮函数顺序逆推)
标准 Hash(不可逆): 只能"比较点爆破"或"内存抢期望值"(§2.2)
RSA 签名校验: 正向无解, 替换内置公钥(n,e)为自己生成的一对 → 自签"合法" (thread-12934 思路)
```

### 6.3 实战要点

1. 先扫常量定位算法(6.1 特征列),再判"魔改"(换 S-box/改轮数/插私有变换)。
2. 大数运算:抠出 asm 段直接复用(§2.2 提取汇编法),别手翻 C。
3. 明文攻击思路也适用于自定义流密码:拿已知明文 XOR 密文得密钥流,验证周期。
4. Crypto API 程序:bp CryptDeriveKey/CryptEncrypt 拿上下文与密钥句柄,`CryptGetKeyParam` 层层还原——比逆算法快。

## 7. 调试应用分支(树节点 1000250,18 子概览)

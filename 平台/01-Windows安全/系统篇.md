# 系统篇(第4篇 系统篇 1000140 + 系统程序设计系列 1000908)

> 定位:逆向工程需要的 Windows 系统机理底座——进程/线程怎么生、内存怎么管、句柄与对象怎么放、消息怎么走、文件与注册表怎么存。这是知识库「系统篇」的知识主线,也是后续保护篇/重构篇所有对抗技术的立足点。

## 1. 进程创建全链(节点 1000176,本篇核心)

### 1.1 为什么逆向要懂进程创建链

三个理由:① 壳与反调试经常 hook/检测这条链(如 hook NtCreateProcessEx 阻止调试器 attach 子进程、双进程保护靠它互守);② 注入、脱壳、Dump 都要找准"进程什么时候算真正跑起来";③ 《加密与解密》系统篇把这条链当 Windows 机理的纲。

### 1.2 用户态链路(kernel32 → ntdll)

```
CreateProcessW / CreateProcessA          (kernel32,薄封装)
        │
        ▼
CreateProcessInternalW                   (kernel32 真正干活)
  1. 解析 lpApplicationName / lpCommandLine(镜像路径搜索顺序)
  2. 打开 exe,读 DOS header/NT header,校验子系统
     (若是 DOS/OS2/POSIX 映像 → 走 VDM/POSIX 分支)
  3. 构造 RTL_USER_PROCESS_PARAMETERS
     (命令行、环境块、当前目录、窗口站/桌面、句柄继承表)
        │
        ▼
ntdll!NtCreateUserProcess                (Vista 起,一次系统调用建进程+线程)
  XP/2003 老链: NtCreateProcessEx + NtCreateThread(两次调用)
        │  syscall / KiFastSystemCall
        ▼
nt!NtCreateUserProcess(内核态)
```

要点:
- Vista 之后 CreateProcessInternalW 主走 `NtCreateUserProcess`,把进程与初始线程的创建合并为一次系统调用,参数经 `RTL_USER_PROCESS_PARAMETERS` + `PS_CREATE_INFO`/`PS_ATTRIBUTE_LIST` 传入(逆向时在 ntdll 导出表看到它是未公开形态)。
- XP 时代是 `NtCreateProcessEx`(建 EPROCESS)→ `NtCreateThread`(建初始 ETHREAD)两步;很多老帖(《加密与解密》第3版时代)按这条老链讲解,读帖时注意系统版本。
- 32 位下进入内核经 `KiFastSystemCall`(mov edx,esp / sysenter),syscall 号从 `KeServiceDescriptorTable`(见 §4.4)取;Win10 后用户态直接 `syscall` 指令。

### 1.3 内核态(NtCreateUserProcess 干了什么)

```
nt!NtCreateUserProcess
 ├─ 打开镜像文件 → IoCreateFile/解析 Section
 ├─ MmCreatePeb                    ← 建 PEB,写入参数
 ├─ PspCreateProcess               ← 建 EPROCESS/KPROCESS
 │    ├─ 对象管理器 ObCreateObject(EPROCESS)
 │    ├─ 初始进程句柄表 ObjectTable
 │    ├─ 地址空间 MmCreateAddressSpace(CR3/页表)
 │    └─ 映射 ntdll + 映像 Section
 ├─ PspCreateThread                ← 建 ETHREAD/KTHREAD + 用户栈 + TEB
 └─ 通知 CSRSS(Windows 子系统,ALPC 端口 CsrPortProcessId)
```

### 1.4 初始线程的用户态启动(逆向最关心的一段)

内核把一个用户态 APC 排入新线程,线程第一次被调度时在 ring3 从 `ntdll!LdrInitializeThunk` 起跑:

```
LdrInitializeThunk
  └─ LdrpInitializeProcess
       ├─ 初始化 PEB->LoaderData(PEB_LDR_DATA)
       ├─ 按依赖顺序加载 ntdll→kernel32→…(InLoadOrderModuleList 逐个插入三条链:
       │   InLoadOrder / InMemoryOrder / InInitializationOrder)
       ├─ 静态导入解析:遍历 Import Table,填 IAT
       ├─ TLS 回调 → DLL_PROCESS_ATTACH(按序)
       └─ 跳 OEP(Entry Point)
```

逆向落点:
- **断点时机**:附加时经常直接 `bp ntdll!LdrpInitializeProcess` 或对 `LdrLoadDll` 下断看壳又拉起了哪些 DLL。
- **TLS 回调在 OEP 之前执行**——壳与反调试爱把检测放 TLS callback,`01005000` 一带常见;脱壳找 OEP 别只盯入口。
- **双进程保护**的实现点就在这条链:父进程 CreateProcess 子进程后互相 OpenProcess+ReadProcessMemory 校验。
- 老帖主线参考:《CreateProcess函数的整体流程分析》、《NtCreateProcessEx的分析》、《进程创建与csrss的通信流程》、《挂钩Native API控制进程创建》、《拦截进程创建》、《winxp下简单实现注册表修改、进程创建监控》、《PsSetCreateProcessNotifyRoutine》。

## 2. 线程与同步(节点:进线程的结构 1000173)

### 2.1 三层结构

| 层 | 结构 | 关键字段(逆向视角) |
|---|---|---|
| 用户态 | TEB | fs:[0](x86)/gs:[0](x64) 自引用;ExceptionList(SEH 链头)、StackBase/StackLimit、PEB 指针、ClientId(UniqueProcess/UniqueThread) |
| 执行体 | ETHREAD | StartAddress、Cid、CrossThreadFlags、ThreadsProcess 回指 EPROCESS |
| 内核 | KTHREAD | 调度优先级、内核栈底、WaitBlock(等哪个分发器对象) |

- `_EPROCESS` 关键:`UniqueProcessId`、`ActiveProcessLinks`(遍历进程链,隐藏进程的战场——细节归编程篇/二进制漏洞区)、`ObjectTable`、`PEB`(位于用户态高地址,`_PEB` 在 WinDbg 用 `!peb` 看)。
- 用户栈与内核栈切换:进入内核时 CPU 自动切 TSS/`KTHREAD.KernelStack`,SSDT hook 与内核栈回溯分析的基础。

### 2.2 同步对象与逆向应用

- 临界区 `CRITICAL_SECTION`(用户态自旋+内核等待混合,死锁分析看 LockCount/OwningThread);多线程壳解压时 x64dbg 要先冻结其他线程再下断。
- Mutex/Semaphore/Event:`WaitForSingleObject` 族,内核分发器对象。
- **命名互斥体防多开**:软件起手 `CreateMutex(NULL,TRUE,"MyApp")` + `GetLastError==ERROR_ALREADY_EXISTS` 弹"程序已在运行"——爆破点是改判断跳转;反向,游戏双开就是干掉这个检测。
- 死锁/竞态逆向:两个线程对同一全局校验变量,脱壳时只跑一个线程会卡死,这就是"多线程调试"(调试篇 1001374)要解决的问题。

## 3. 内存管理(节点 1000911/1000912)

### 3.1 VirtualAlloc 全链

```
VirtualAlloc/VirtualAllocEx   (kernel32)
   │
   ▼
ntdll!NtAllocateVirtualMemory  (syscall)
   │
   ▼
nt!NtAllocateVirtualMemory
   ├─ 找一段空闲 VA(从 Zone/自顶向下)
   ├─ 建/合并 VAD 节点(进程的 VAD 树,描述"哪段虚拟地址、什么属性、对应哪份 Section/页面文件")
   └─ 返回基址(此时物理页还没分配!)
        │
        ▼ 首次访问该页 → #PF 页错误
nt!MmAccessFault → 按 VAD 描述补物理页(按需调页 demand paging)
```

要点:
- VirtualAlloc 的 MEM_COMMIT 只提交不触碰;物理页在第一次访问缺页时才给。**脱壳 Dump 出来某些页是稀疏的**与此有关。
- `VirtualProtect`→`NtProtectVirtualMemory`:壳把 .text 改可写→解密→改回可执行,挂 `NtProtectVirtualMemory` 断点可抓壳的自解密节奏。
- VAD 树是内存 forensic 的核心:即使 PEB 被摘,VAD 仍记录该进程所有映射(反隐藏的关键)。

### 3.2 堆

- 默认堆:`GetProcessHeap`,即 PEB->ProcessHeap;`HeapCreate` 私有堆。
- RtlAllocateHeap:后端空表/快查表,Win Vista+ 默认 LFH(Low Fragmentation Heap)。
- 逆向价值:PEB->ProcessHeap 的 Flags/ForceFlags 堆标志被调试器改动 → 反调试检测点(见保护篇 §1.1);字符串在堆上 U 解密后 Dump 要等解密完成。

### 3.3 内存布局(x86 用户空间)

```
0x7FFFFFFF ┌──────────────┐
           │ 0x7FFDF000 TEB │ ← fs:[0] 指向
           │ 0x7FFDB000 PEB? (XP 位置; 版本不同浮动)
           │ KUSER_SHARED_DATA 0x7FFE0000(只读系统区)
           │ ntdll.dll / kernel32.dll 等系统映射
           │ ↓ 动态 DLL/堆/栈
           │ 进程 exe 镜像
0x00010000 └──────────────┘ (64KB 以下保留,NULL 指针保护)
```
x64:用户区到 0x00007FF_FFFFFFFF,TEB/PEB 由 gs:[0x30]/gs:[0x60] 取。

### 3.4 内存映射文件(节点 1000912)

- 链:`CreateFile`→`CreateFileMapping`(内核 Section 对象)→`MapViewOfFile`→`NtMapViewOfSection`,把文件/页面文件-backed 区域映射进 VA。
- 用途:大文件分析不整体读入、进程间共享内存(IPC 首选,§9.2)、加载器本身就用 Section 映射 PE。
- 逆向应用:多进程壳用共享段共享解密密钥;改写映射即改文件(写时复制除外)。

## 4. 句柄与对象管理、核心数据结构(节点 1000164)

### 4.1 对象与句柄

```
用户拿到 HANDLE = (句柄表索引 << 4) | 属性位
   │
   ▼ 查 EPROCESS->ObjectTable(多级句柄表,x86 最多三层,类似页表)
OBJECT_HEADER → OBJECT_TYPE(Process/File/Key/Section/Mutant…)
   → 对象体(EPROCESS / FILE_OBJECT / …)
```

- 常见属性位:0x1 继承标志(PROCESS_FLAG…),低位在 DuplicateHandle/句柄传递时起作用。
- 逆向意义:调试器 attach 的本质是拿到 PROCESS_ALL_ACCESS 句柄;`CloseHandle` 传非法句柄会抛异常——被用作反调试(见保护篇);Handle 权限降级(PROCESS_VM_READ 摘除)是对抗 Dump 的手段。
- 对象目录 `\??`、`\BaseNamedObjects`(命名互斥体/信号量所在地,WinObj 可看)。

### 4.2 TEB(节点 1000168)

x86 通过 `mov eax, fs:[0x18]` 得 TEB 自引用再取其他字段;`fs:[0x30]` 即 PEB。关键偏移(随版本微调):`+0x00 ExceptionList`、`+0x18 Self`、`+0x30 ProcessEnvironmentBlock`。调试器切线程上下文时 TEB 跟着换——多线程反调试会给不同线程的 TEB 涂标志。

### 4.3 PEB(节点 1000169)

```c
PEB(x86 偏移): +0x02 BeingDebugged   // IsDebuggerPresent 的源头(x64 同偏移)
     +0x0C Ldr → PEB_LDR_DATA // 三条模块链(找 kernel32 的正路;x64 +0x18)
     +0x18 ProcessHeap        // 其 Flags/ForceFlags 被 LFH 改动(x64 +0x30)
     +0x68 NtGlobalFlag       // 调试器启动时被置 FLG_HEAP_*(x64 +0xBC)
```
PEB 是用户态可写的——所以反调试检测 PEB,反反调试就改回 PEB(ScyllaHide 原理,保护篇展开)。

### 4.4 SSDT(节点 1000066→1000166)

- `KeServiceDescriptorTable` → 服务函数表,`ntdll.dll` 的 syscall 号查这张表进内核;Win32K 另有 `KeServiceDescriptorTableShadow`(GUI 服务)。
- 逆向意义:系统调用是绕不开的最后一层——壳最终都要 VirtualAlloc/WriteProcess/Protect,在 SSDT 层下钩看得见一切;反之 SSDT Hook 也是 Anti-Debug 的内核层手段。附:知识库附录有 Windows System Call Table(节点 1001141)。

### 4.5 GDT/保护模式(节点 1000167/1000162)

- 段寄存器在 Windows 下基本平坦(fs/gs 特殊),GDT 内是 TSS/段描述符;VT 相关检测(如 sidt 读 IDT 基址探测 hypervisor)属保护篇 Anti-VM。
- 分页:CR3→PDT→PT→PFN,2MB/4MB 大页;`MmGetPhysicalAddress` 与物理内存搜索(游戏修改器原理)。

### 4.6 API 绝密档案(节点 1000175)

社区整理的未公开/少文档 API 资料(NT 层函数原型、未文档化结构),做工具级补丁、迷你调试器、自实现 API 时查这里。现代等价物:符号库(winternl.h、phnt 头文件)。(内容随系统版本,使用前验证)

### 4.7 NTFS / HIVE / 缓存结构(节点 1000170/1000171/1000172)

- **NTFS**:MFT 主文件表,每记录 1KB,属性流(0x10 STANDARD_INFORMATION、0x30 FILE_NAME、0x80 DATA);常驻/非常驻。附录5 也有 NTFS 格式(1001143)。取证与"文件伪装/数据隐藏"分析的基础。
- **HIVE**:注册表落盘格式,`CM_KEY_NODE`/`CM_KEY_VALUE`,根键文件(SYSTEM、SOFTWARE…位于 config 目录);注册表读取器/口令提取类工具直接解析 HIVE。注册表五棵树 HKLM/HKCU/HKCR/HKU/HKCC;RegOpenKeyEx→NtOpenKey 链路,自启动(Run 键/服务)是安全排查第一站。
- **缓存结构**:Cache Manager 延迟写、系统缓存视图;内存取证时"文件在缓存里改了但还没落盘"的窗口。

## 5. 消息机制(Windows GUI 的骨架)

```
硬件输入 → 系统原始输入线程(RIT) → 线程消息队列(attach 到创建窗口的线程)
                                          │
   GetMessage/PeekMessage ← ──────────────┘
        │ TranslateMessage(键盘虚拟键→字符消息 WM_CHAR)
        ▼ DispatchMessage → USER32 找到 hwnd 的 WndProc
        ▼
   窗口过程 switch(msg){ WM_COMMAND / WM_TIMER / … }
```

- 每个建窗口的线程有自己的队列;`PostMessage` 异步入队,`SendMessage` 跨线程同步(接收方要进 GetMessage 才返回)——死锁与"消息断点"都源于此。
- **逆向应用**:
  - 警告框/NAG 窗口爆破:对 `WM_CLOSE`/按钮 `WM_COMMAND` 下消息断点定位处理逻辑;
  - Spy++ / 消息 Hook(SetWindowsHookEx WH_CALLWNDPROC)抓通信;
  - 网络验证客户端常把逻辑放 WM_TIMER,断 WndProc 比断 API 高效。
- 消息循环是二次开发"增加按钮/菜单"的理论基础(§9.5、重构篇)。

## 6. 文件系统与注册表 API 链(逆向常用断点层)

### 6.1 文件

```
CreateFileW → ntdll!NtCreateFile → I/O 管理器构造 IRP(MJ_CREATE) → FSD(ntfs.sys)
            → 缓存管理器/卷管理器 → 磁盘
```
- CD-check/keyfile 保护都落在这条链上:`CreateFile`+`SetFilePointer`+`ReadFile` 序列,断 NtReadFile 拿缓冲区。
- 文件过滤驱动(minifilter)在 IRP 路径上挂钩——文件监视工具与主动防御的原理(细节归编程篇驱动开发)。

### 6.2 注册表

- 配置管理器解析 HIVE 成内存树;`NtQueryValueKey` 返回 KEY_VALUE_BASIC_INFORMATION 等结构。
- 序列号保护"注册表比较法"(解密篇节点 1000201):快照运行前后差异定位持久化键。

### 6.3 DLL 基础与加载器(节点 1000916)

- 加载顺序(静态导入):见 §1.4;动态:`LoadLibrary`→`LdrLoadDll`;卸载与引用计数。
- DLL_THREAD_ATTACH/DETACH:多线程壳利用线程 attach 做反调试(线程回调里检测)。
- **DLL 搜索顺序**(劫持的基础,重构篇 §4 展开):应用目录→系统目录→Windows 目录→当前目录→PATH;KnownDLLs 免搜索直接映射。

## 7. 结构化异常处理 SEH(节点 1000163/1000915)

### 7.1 x86 SEH 链

```
异常发生(如 #UD/#PF)
  → 内核 KiUserExceptionDispatcher(回到用户态)
  → RtlDispatchException:
      ① 先 VEH(AddVectoredExceptionHandler,XP+)
      ② 遍历 fs:[0] 链上每个 EXCEPTION_REGISTRATION_RECORD
         (node->handler(ExceptionRecord, EstablisherFrame, ContextRecord))
      ③ 都不处理 → 默认处理器(UEF / UnhandledExceptionFilter)
```

- 栈上每个节点 8 字节:`[next][handler]`;编译器放 `__except_handler4`(带 scope table,校验 cookie)。
- **逆向落点**:① 异常反调试(故意触发异常,调试器若抢了异常就露馅,保护篇 §1.4);② OEP 捕获(壳用 SEH 跳转);③ 恶意代码用 SEH 链隐藏真实流程。

### 7.2 x64 表驱动展开

x64 SEH 与栈解耦:`.pdata`(RUNTIME_FUNCTION:函数范围)+`.xdata`(UNWIND_INFO),`RtlAddFunctionTable`;异常时按表展开恢复。逆向影响:不能再像 x86 那样往 fs:[0] 链上塞节点伪造 handler,反调试手法随之变形(改用 VEH)。

## 8. 中断与系统调用(节点 1000161)

- 中断向量表 IDT:0x2E 是 XP 时代系统调用门(int 2Eh),后被 sysenter/syscall 取代;调试器单步用 0x1,断点 0x3。
- IDT/GDT/调试寄存器都是 ring0 资源——"Ring0 权限"节点(1000180)讲怎么从 ring3 到 ring0(驱动加载、物理内存漏洞),提权漏洞利用本身归二进制漏洞区,不在此展开。
- WoW64(1001482):32 位进程经 wow64cpu 转发到 64 位 ntdll,系统调用号映射两套——脱壳老程序在新系统上行为差异的来源之一。

## 9. Windows 系统程序设计系列(节点 1000908,九章合并)

### 9.1 进程管理(1000909)
CreateProcess 族/CreateToolhelp32Snapshot 枚举/ExitProcess 终止;作业对象 Job 控制子进程。逆向对应:进程监视、防多开、父子互守。

### 9.2 进程间通信(1000910)
全谱:匿名管道(父子)、命名管道(跨机)、邮槽 Mailslot(单向广播)、共享内存(§3.4 + 信号量同步)、剪贴板、`WM_COPYDATA`(SendMessage 携带数据,跨进程只读)、RPC/COM。逆向对应:客户端-验证端(本地验证服务)抓 WM_COPYDATA/命名管道流量即抓注册通信。

### 9.3 系统服务(1000913)
SCM:OpenSCManager/CreateService/StartService;服务程序入口 ServiceMain + 控制分发器。逆向对应:保护驱动/反盗版服务以 SERVICE 自启动,摘除即停服务改启动项。

### 9.4 异步 I/O 与完成端口(1000914)
OVERLAPPED 重叠 IO→IOCP(GetQueuedCompletionStatus);高性能网络验证服务器、游戏服务器骨架;抓包分析时的线程模型参照。

### 9.5 插入 DLL 和挂接 API(1000917)
- 注入三式:远程线程 CreateRemoteThread+LoadLibrary、Windows Hook(WH_CBT/WH_GETMESSAGE 跨进程)、APC 注入。
- 挂接 API:IAT Hook(改导入表项)与 Inline Hook(改函数头 5 字节)——系统机制层到此,工程细节归编程篇 Hook 节点(1000837)。

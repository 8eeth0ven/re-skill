# 知识库 · Windows 安全 · 第1篇 基础篇

> 主线源自《加密与解密》体系。本篇覆盖逆向 Windows 平台所需的全部地基:汇编、PE 结构、Windows 核心数据结构、API 体系、反汇编引擎与静态分析技术。

## 1. 汇编基础(树节点 1000014~1000024)

### 1.1 概念

x86/x64 汇编是 Windows 逆向的"母语"。知识库将汇编基础拆为:汇编知识、汇编指令、汇编专题、汇编教学、深入浅出指令编码、内联汇编六个子节点。逆向视角的汇编学习与正向开发不同:重点在**认出高级语言结构在指令层的形状**(调用约定、栈帧、循环模式、虚函数表调用),而不是会写。

### 1.2 关键寄存器与常用指令

```
通用寄存器(x86): EAX EBX ECX EDX ESI EDI EBP ESP
特殊寄存器: EIP(指令指针) EFLAGS(标志)
段寄存器: CS DS ES FS GS        ; x86 下 FS=[TEB], x64 下 GS=[TEB]
调试寄存器: DR0~DR3(断点地址) DR6(状态) DR7(控制)  ; 见调试篇
控制寄存器: CR0(PE位/PG位) CR2 CR3(页目录) CR4
```

| 指令 | 逆向含义 |
|---|---|
| `mov/cmovcc/xchg` | 数据搬运;`cmov` 是无分支优化痕迹 |
| `lea` | 取地址,常用于"乘法/加法"优化(lea eax,[eax+eax*4]) |
| `push/call/ret/add esp,N` | 调用约定识别的钥匙 |
| `test/jz`, `cmp/jcc` | 分支与校验逻辑 |
| `imul/idiv` | 乘除;除常数会变成 magic number 乘法 |
| `rep stosd/movsd` | 结构体/缓冲区初始化与拷贝 |
| `cdq+idiv` | 有符号除法标配 |

### 1.3 调用约定(识别编译器与恢复函数签名的核心)

| 约定 | 参数位置 | 清栈者 | 典型场景 |
|---|---|---|---|
| __cdecl | 栈,右到左 | 调用者(`add esp,N`) | VC/C 运行库默认 |
| __stdcall | 栈,右到左 | 被调者(`ret N`) | Win32 API 绝大多数 |
| __fastcall | ECX/EDX 先两个,余栈 | 被调者 | Borland/部分驱动 |
| thiscall | ECX=this,余栈 | 被调者 | VC 成员函数 |
| x64 System V / Win64 | RCX/RDX/R8/R9(Win64) + 栈 | 调用者(影子空间 0x20) | x64 全部 |

逆向要点:`call` 后有没有 `add esp`、`ret` 带不带立即数、ECX 是否装对象指针——三者组合即可定调用约定,进而推参数个数。

### 1.4 栈帧结构(汇编教学主线)

```
高地址
  ┌──────────────┐
  │ 调用者局部变量  │
  │ 实参(逆序压栈) │
  ├──────────────┤
  │ CALL 压入返回址│ ← ESP 指向处(进入函数瞬间)
  ├──────────────┤
  │ PUSH EBP      │
  │ MOV EBP,ESP   │ ← EBP 成为帧基
  ├──────────────┤
  │ 局部变量       │ EBP-4, EBP-8 ...
  │ 保存的 EBX/ESI/EDI │
  ├──────────────┤
  │ CALL 前临时参数│ EBP+C 开始是入参
低地址
```

函数识别经验:`push ebp; mov ebp,esp` 是标准序;VC6 常见 `sub esp,N; push ebx; push esi; push edi; lea edi,[ebp-xxx]; mov ecx,N/4; mov eax,0xCCCCCCCC; rep stosd`(Debug 版 int3 填充)。

### 1.5 指令编码(深入浅出指令编码 1000019)

x86 变长指令 1~15 字节,格式:

```
[Legacy prefixes][REX(x64)][Opcode 1~3B][ModRM][SIB][Disp 0/1/2/4][Imm 0/1/2/4]
ModRM = Mod(2) | Reg(3) | R/M(3);  SIB = Scale(2) | Index(3) | Base(3)
```

逆向价值:手改机器码(补丁/爆破)、识别花指令(插入等价前缀制造错位)、手写反汇编引擎(§5)。例:`EB 05`(jmp +5)与花指令 `E8` 后接垃圾字节是壳的常见干扰;`0x0F 0x8x` 两字节 jcc near。

### 1.6 x64 汇编差异(IA-64 体系 1000022 → x64汇编 1001396)

- 通用寄存器 RAX~R15 共 16 个,默认操作 32 位(EAX 写入自动零扩展)。
- 传参改寄存器(RCX/RDX/R8/R9),调用者预留 32 字节影子空间。
- 绝大多数 `push/pop` 栈传递消失;栈对齐 16 字节。
- 寻址 `RIP-relative`:`lea rax,[rip+0x1234]` 取代绝对地址,配合 ASLR。
- x86 程序跑在 x64 系统经 WoW64(树节点 1001482,见系统篇)。

### 1.7 数据对齐(1000020)

结构体成员按自身大小对齐(`#pragma pack` 改变);x86 允许非对齐访问(慢),校验指令(如 `movdqa`)强制对齐会异常。逆向时用于:**还原结构体布局**、判断"指针 4 字节/8 字节"截断错误、分析对齐填充里的残留数据。

### 1.8 浮点格式(1000021)

x87 FPU 栈(ST0~ST7,80 位扩展精度)已让位 SSE(XMM0~XMM7,128 位)。IEEE754 单/双精度布局:`[符号1][指数8/11][尾数23/52]`。识别浮点比较:`ucomiss/ucomisd + seta/setb` 系列;`fld qword ptr [x]` 是老编译器浮点常载入。游戏/图形逆向必会。

### 1.9 实战要点

1. 拿到陌生代码段先看"序言+清栈"定调用约定与参数个数。
2. `rep stosd` 批量 0xCC/0x0 清填充 → Debug 版,符号友好,优先静态读。
3. 大除法被换成 magic number 乘法(如 `imul` + `shr` 组合),还原时用 `/magic` 反推除数。
4. 控制流还原:小循环体先数 `jcc` 回跳边。

### 1.10 代表帖

- 《深入浅出指令编码》系列 —— 知识库节点 1000019;《x86指令编码格式解析》、《Intel32位指令编码学习笔记》、《浮点处理和指令编码》
- 《汇编专题》—— 知识库节点 1000017
- 《从逆向工程的角度来看C++》(1000136)—— 汇编层识别 C++ 结构经典
- 实现一个基于LLIL的x86/x64的静态分析框架(2025 年前后新帖,x86/x64 指令层分析工程参考)
- 现代补充:知识库检索词「指令编码」「调用约定」,chm-search 页可直接定位

## 2. PE 结构(树节点 1000141,原挂第4篇)

### 2.1 概念

PE(Portable Executable)是 Windows 可执行文件(EXE/DLL/SYS/OCX)的统一格式,源自 COFF。逆向四大刚需:脱壳后修复 PE、手工构造 PE(补丁/加节)、识别加壳变形、写解析工具。知识库 PE 格式节点含:Iczelion's PE 教程(1000143)、基本概念(COFF/PE对齐/PE校验和/RVA-VA 1000144~1000148)、区块、输入表、输出表、重定位表(ASLR)、资源、TLS、附加数据、PE文件的加载、编写PE分析工具、手工构造PE。

### 2.2 整体布局(ASCII 还原)

```
+------------------------+  偏移0
| MS-DOS Header (0x40B)  |  e_magic 'MZ'; e_lfanew → NT 头偏移
+------------------------+
| DOS Stub ("This prog..")|
+------------------------+  e_lfanew 处
| Signature 'PE\0\0'     |
| IMAGE_FILE_HEADER      |  Machine/NumberOfSections/TimeDateStamp/
|   (20B)                |  PointerToSymbolTable/SizeOfOptionalHeader/Characteristics
| IMAGE_OPTIONAL_HEADER  |  Magic(0x10B=PE32/0x20B=PE32+)
|   PE32: 0xE0 B         |  AddressOfEntryPoint★/ImageBase★/SectionAlignment/
|                        |  FileAlignment/SizeOfImage/Subsystem/DllCharacteristics/
|                        |  NumberOfRvaAndSizes(16) + DataDirectory[16]★
+------------------------+
| Section Headers ×N     |  IMAGE_SECTION_HEADER(40B each):
|  .text .data .rsrc ... |  VirtualSize/VirtualAddress★/SizeOfRawData/
|                        |  PointerToRawData★/Characteristics(RWX)
+------------------------+
| Sections 原始数据(.text)|  File Offset ↔ RVA 换算:
|  .data .rdata .rsrc    |  RVA = VA - ImageBase
|  .reloc ...            |  同一节内: Offset = RVA - SectionVA + SectionRaw
+------------------------+
| Overlay(附加数据 1000155)|  文件尾附加,如自解压包/签名,加载器不映射
+------------------------+
```

RVA→文件偏移换算是手工修复壳 dumped PE 的第一道坎:节表对齐(FileAlignment 通常 0x200,内存 SectionAlignment 通常 0x1000)不一致,壳常故意改坏 SizeOfRawData 造成 dump 后无法直接运行。

### 2.3 数据目录表(1001252)

```
IMAGE_DATA_DIRECTORY[16]: {VirtualAddress, Size} 对
 0 EXPORT   导出表(.edata)      1 IMPORT  输入表★
 2 RESOURCE 资源(.rsrc)          3 EXCEPTION 异常(.pdata, x64 SEH 表)
 4 SECURITY 证书(文件偏移!)      5 BASERELOC 重定位★
 6 DEBUG    调试目录(pdb 路径!)  7 ARCHITECTURE 8 GLOBALPTR
 9 TLS★     TLS 目录            10 LOAD_CONFIG(CFG/安全_cookie)
11 BOUND_IMPORT 绑定输入(1001474) 12 IAT★(输入地址表本体)
13 DELAY_IMPORT 延迟载入         14 CLR(.NET 元数据)
15 保留
```

逆向要点:DEBUG 目录直接暴露编译机 pdb 路径与 GUID——配符号用;IAT 目录 Size 是 IAT 修复(解密篇)的核对基准;壳常清零输入表目录隐藏依赖。

### 2.4 输入表/输入地址表(1000150,逆向最核心的表)

```
加载前(文件中):                          加载后(内存中):
IMAGE_IMPORT_DESCRIPTOR 数组              IAT 项被加载器覆写:
  OriginalFirstThunk(INT/RVA)→   INT/IAT 数组            IAT 数组
  TimeDateStamp                   [0x77xxxxxx]→user32.MsgBox  [MessageBoxW 真实地址]
  ForwarderChain                  [0x77yyyyyy]→kernel32.  [LoadLibraryA 真实地址]
  Name(RVA)→"USER32.dll"          ...
  FirstThunk(IAT/RVA)★            最后一项 0 结尾
以全 0 的 Descriptor 结尾
```

- 双桥:OriginalFirstThunk(INT,保留名字)与 FirstThunk(IAT,加载后被写成真实函数地址)。老链接器可能只有 FirstThunk。
- IMAGE_IMPORT_BY_NAME:{Hint(2B), Name(ASCIIZ)}。
- **绑定输入(1001474)**:预先写好地址+时间戳校验,加载器跳过解析提速——脱壳时是干扰项。
- 延迟导入(DELAY_IMPORT):首次调用时经 `__delayLoadHelper` 解析。
- 修复 IAT(脱壳必备):见解密篇 §3.5。

### 2.5 输出表(1000151)

```
IMAGE_EXPORT_DIRECTORY:
  Characteristics / TimeDateStamp / Name(RVA→"MyLib.dll")
  Base(序号基数) ★NumberOfFunctions / NumberOfNames
  AddressOfFunctions(RVA 数组,按序号-Base 索引)
  AddressOfNameOrdinals(序号数组) / AddressOfNames(名字 RVA 数组)
按名找址: 二分/遍历 Names → index → Ordinals[index] → Functions[ord]
```

逆向价值:写 DLL 劫持/转发时构造输出表;壳的输出表转发(ASProtect SDK);补间转发器(Forwarder RVA 指向 "dll.func" 字符串)。

### 2.6 重定位表(1000152,ASLR 1001425)

```
IMAGE_BASE_RELOCATION: {VirtualAddress(页基), SizeOfBlock}
后跟若干 WORD 项: 高4位=类型(3=HIGHLOW, 10=DIR64), 低12位=页内偏移
加载时若实际基址≠ImageBase: *target += delta
```

- EXE 通常是首选基址无需重定位;DLL/SYS 必有 `.reloc`。
- ASLR(Vista+,DllCharacteristics DYNAMIC_BASE)使每次加载基址随机。
- 脱壳 dump 后若直接按新基址 dump,`.reloc` 失效或需重算——手工修复条目。

### 2.7 TLS(1000154)

线程局部存储回调:目录 TLS 目录的 AddressOfCallBacks 数组在**主入口点之前**被调用(每个线程启动/退出各一次)。经典反调试位置(比 EP 更早断下);也是壳二段解密的钩子。`#pragma data_seg`/`__declspec(thread)` 静态 TLS 与 `TlsAlloc` 动态 TLS 两条线。

### 2.8 PE 文件的加载(1000156)与手工构造(1000158)

加载器(ntdll `LdrpInitializeProcess` 线):建 Section 映射(VA/对齐)→ 处理重定位 → 解析输入表递归加载依赖 → 写 IAT → TLS 回调 → 跳 AddressOfEntryPoint。手工构造:改节表加节(Characteristics|RWX)、移动 EP、追加 Shellcode——补丁与壳的共同雏形。校验和(1000147,IMAGE_OPTIONAL_HEADER.CheckSum)仅内核驱动强校验。

### 2.9 工具

- PE 工具:LordPE(经典,dump/重建)、PEditor、CFF Explorer、PE-bear、010 Editor(PE 模板,树节点 1001524)、StudyPE、`dumpbin /all`
- 自写解析:Python `pefile`(现事实标准)、知识库《编写PE分析工具》系列

### 2.10 实战要点

1. 壳识别第一步看:EP 是否指向最后一个节/节名异常/输入表只剩 Kernel32.GetProcAddress+LoadLibraryA 两项。
2. dump 后程序跑不起来,90% 是节表 SizeOfRawData/PointerToRawData 与内存映像不一致,按内存 SectionAlignment 重建节表。
3. Overlay 不能丢:自解压/安装包类程序把数据放在文件尾。
4. x64 `.pdata`(EXCEPTION 目录)是异常 unwind 表,爆破时改代码需同步,否则异常遍历崩溃。

## 3. Windows 数据结构(树节点 1000164,原挂第4篇)

### 3.1 概念

逆向从"看代码"升级到"看系统",分水岭就是掌握进程/线程/对象三张图:用户态 TEB/PEB(每线程/每进程,fs/gs 段直达),内核态 EPROCESS/KPROCESS(ntoskrnl 全局链表),以及贯穿两态的句柄机制。知识库节点还含 NTFS(1000170)、HIVE(1000171,注册表储巢)、缓存结构(1000172)、对象数据结构(1000174)、GDT(1000167)、SSDT(1000166)。

### 3.2 TEB(1000168,Thread Environment Block)

```
定位: x86  mov eax, fs:[0x18]   ; x64  mov rax, gs:[0x30]
TEB(节选,逆向高频字段):
  +0x00 NT_TIB.NtTib.ExceptionList  ; 当前 SEH 链头(x86)★
  +0x08 NT_TIB.StackBase / +0x0C StackLimit  ; 栈界
  +0x18 NT_TIB.Self                 ; 自指针(fs:[0x18])
  +0x30 ProcessEnvironmentBlock     ; → PEB★
  +0x34 LastErrorValue
  +0xF18 (x86) / 动态(x64) GDI/用户回调区
```

异常分发(x86)第一步就是 `fs:[0]` 拿 SEH 链——这使它成为壳/反调试对抗最密集的内存位置(伪造 SEH 链检测调试器)。x64 后 SEH 改表驱动(`.pdata`+`UNWIND_INFO`),`gs:[0]` 不再挂链。

### 3.3 PEB(1000169,Process Environment Block)

```
定位: x86 fs:[0x30] / x64 gs:[0x60]
PEB(节选,偏移 x86/x64 分列):
  +0x02 BeingDebugged ★          ; IsDebuggerPresent 的全部真相(x86/x64 同)
  +0x0C(x64+0x18) Ldr ★         ; → PEB_LDR_DATA:三条 InLoadOrder/
  ;    InMemoryOrder/InInitializationOrderModuleList 模块链(遍历找 kernel32 基址)
  +0x10(x64+0x20) ProcessParameters ; → RTL_USER_PROCESS_PARAMETERS(命令行/ImagePathName)
  +0x18(x64+0x30) ProcessHeap    ; 头部含 Flags/ForceFlags 调试痕迹
  +0x68(x64+0xBC) NtGlobalFlag ★ ; 调试器堆标志(FLG_HEAP_ENABLE_TAIL_CHECK 等)
  ;    其余字段(OSBuildNumber 等)偏移随版本浮动,dt nt!_PEB 现场核对
```

反调试与反反调试的主战场(详见保护篇);`PEB.Ldr` 三链是 Shellcode 无导入表定位 API 的标准姿势(树节点:API自实现 1000620)。

### 3.4 EPROCESS/KPROCESS(1000173 进线程的结构)

```
KPROCESS(EPROC 前缀,调度器可见):
  +0x00 DispatcherHeader / +0x18 DirectoryTableBase(CR3)★
  +0x5A~ ThreadListHead / ...
EPROCESS(节选;偏移随 Windows 版本剧烈浮动,禁止硬编码,`dt nt!_EPROCESS` 现场核对):
  UniqueProcessId / InheritedFromUniqueProcessId ; 进程标识
  ActiveProcessLinks ★            ; 双链遍历全系统进程(隐藏进程的摘链点)
  ImageFileName[15]               ; 任务管理器里的进程名
  Token(EX_FAST_REF) ★            ; 提权目标(树节点 1001479)
  VadRoot                         ; 虚拟地址描述符(内存遍历/dump 用)
  Peb / ObjectTable / ProcessLock 等
```

要点:偏移随系统版本变化,硬编码必挂;知识库《win10 1909 逆向》系列(1001705)即以现代系统结构演化为线索。ETHREAD 同理(ThreadListEntry、StartAddress、Win32StartAddress——脱壳时定位真实 OEP 线程入口的旁路)。

### 3.5 句柄(1000165)

```
_OBJECT_HEADER: PointerCount/HandleCount/TypeIndex/SecurityDescriptor/Body...
句柄表 EPROCESS.ObjectTable → _HANDLE_TABLE:
  TableCode 低2位=层级(0/1/2 级表),每项 8B HANDLE_TABLE_ENTRY:
  低 32位(内核) &~7 = 对象体指针 | 高位 flags(锁定/保护)
Handle = 句柄表索引 << 4(进程内句柄值,跨进程无效 → DuplicateHandle 跨进程复制)
```

逆向场景:游戏多开检测常遍历句柄表找互斥体;安全软件摘句柄杀保护进程;句柄调试器(handle.exe/Process Hacker/Process Explorer)。

### 3.6 SSDT/GDT/保护模式(1000166/1000167/1000023/1000162)

```
SSDT(System Service Descriptor Table):
  KeServiceDescriptorTable → ServiceTable(RVA 数组)/ServiceLimit/ParameterTable
  Ring3 API → ntdll!Zw* (mov eax, 服务号; sysenter/syscall)
           → KiSystemService → SSDT[服务号] → nt!Nt* 真身
  Hook SSDT = 改表项 → Rootkit/安全软件必争之地(树:Hook技术 SSDT Hook 1000843)
GDT/保护模式: 段选择子 CS=0x1B DS=0x23 等查 GDT → 段描述符;
  Windows 平坦模型,段偏移=线性地址;分页 CR3 → PDE→PTE(大页 2MB/4MB)
  → 物理页;Windbg `!process`/`!pte` 走这条链
```

### 3.7 NTFS/HIVE/缓存(1000170~1000172)

- NTFS:MFT 记录/属性(B+ 目录)——取证与文件隐藏(ADS 流)逆向。
- HIVE:注册表储巢(`WINDOWS\system32\config\*`),区块(Cell)结构;`regedit` 只是壳,离线解析 HIVE 是取证基本功。
- 缓存管理:系统缓存视图/共享视界,与《软件调试》内存篇交叉。

### 3.8 实战要点

1. 用户态拿 PEB/TEB 永远用 fs/gs,别信固定地址。

## 4. API 体系(树节点 1000175 API绝密档案 / 1000176 进程创建分析)

### 4.1 三层 API 图

```
应用层                Win32 API(KERNEL32/USER32/GDI32/ADVAPI32/COMCTL...)
                       │  (大部分简单转发)
                      ▼
系统服务层             Native API(ntdll.dll):Zw*/Nt* 前缀
                       │  mov eax,服务号; mov edx,7FFE0300(KUSER_SHARED_DATA)
                       ▼                    ; sysenter / syscall
内核层                nt!Nt*(ntoskrnl.exe/win32k.sys)
  环境子系统: POSIX/OS2(Win10 已移除POSIX)、WoW64(1001482)
  KUSER_SHARED_DATA(0x7FFE0000,用户态只读映射):TickCount/SystemRoot/
    SystemCallStub — 双机调试与无导入 Shellcode 的常客
```

逆向视角:只盯 Win32 层会被 API Hook 欺骗(安全软件 hook kernel32!CreateFileW),要下到 ntdll Zw 层甚至内核 Nt 层。`PEB.Ldr` 遍历 + 暴力搜 `mov eax,idx; syscall` 获取 syscall 号是现代免导入标准技(树:API自实现)。

### 4.2 常用调试断点 API 速查(API 绝密档案主线)

| 目的 | API |
|---|---|
| 文件操作 | CreateFileA/W、ReadFile、WriteFile、SetFilePointer |
| 注册表 | RegOpenKeyExA/W、RegQueryValueExA/W |
| 网络 | WSAStartup、socket、connect、send、InternetOpenA |
| 窗口/消息 | FindWindowA/W、GetWindowTextA/W、MessageBoxA/W |
| 时间限制 | GetSystemTime、GetLocalTime、GetTickCount、SetTimer |
| 进程/线程 | CreateProcessA/W、CreateRemoteThread、OpenProcess、VirtualAlloc(注入) |
| 反调试常客 | IsDebuggerPresent、CheckRemoteDebuggerPresent、NtQueryInformationProcess |

### 4.3 进程创建链(1000176,《加密与解密》第4篇重点)

```
CreateProcessW(kernel32)
  → CreateProcessInternalW
    → ntdll!NtCreateUserProcess(一次调用同时建进程+主线程)
      Vista 前: NtCreateProcessEx → NtCreateThread(两步)
    内核: KiInitializeProcess/EPROCESS 建档 → PEB 初始化
  → ntdll!LdrInitializeThunk(APC 注入到新进程主线程用户态起点)
    → LdrpInitializeProcess:
       映射 EXE → ntdll → 清单(manifest/SxS)→ 输入表递归加载 DLL(按初始化链)
       → TLS 回调 → 跳 OEP(EXE 入口)
```

逆向价值:API 限级(Hook CreateProcess 抓子进程)、DLL 劫持时机、壳在 Ldr 之后的二段入口;配合 `gflags + loader snaps` 可让加载器自述全过程。

### 4.4 实战要点

1. 断点策略:字符串来源不明先 `bp CreateFileW`/`RegQueryValueExW` 观察回溯栈。
2. 检测"API 被偷":比对 ntdll Zw* 前几字节(inline hook 检测,树节点 1000849)。
3. KUSER_SHARED_DATA 0x7FFE0000 用户态可读:反调试读 SystemRoot 拼路径、读 TickCount 反虚拟机。

## 5. 反汇编引擎(树节点 1000005,基础知识篇)

### 5.1 概念

知识库两个招牌系列:《打造自己的反汇编引擎》(1000007)、《32位反汇编引擎开发笔记》(1001473)。自写反汇编引擎是"指令编码→指令语义"的完整训练,也是自动化逆向(脱壳机、代码比对、VM 还原工具)的地基。

### 5.2 两种扫描策略

```
线性扫描(Linear Sweep):  从入口顺序逐条解码,快;遇数据/花指令即漂移
                          (OllyDbg/W32Dasm 主用)
递归下降(Recursive Descent): 跟随控制流(jcc/call/jmp)标记可达代码,
                          抗数据混排;遇间接跳转需启发(IDA 主用)
最佳实践 = 两者结合 + 交叉验证(capstone 支持 start/address 逐条模式)
```

### 5.3 引擎分层(32 位反汇编引擎开发笔记主线)

```
① 前缀解析(66/67/F2/F3/REX)
② 操作码表驱动(单/双字节 0F xx,三字节 0F 38 xx / 0F 3A xx)
③ ModRM/SIB 解出操作数形态(寄存器/内存基地址+变址+位移)
④ 输出格式化(AT&T vs Intel 语法;AT&T: 源在左,寄存器加%,立即数加$)
⑤ 指令长度计算(用于线性扫描步进/Stealth 断点对齐)
```

### 5.4 工具

- **Capstone**(现事实标准,IDA 同源引擎,多架构,X86/X64/ARM/MIPS)
- udis86/distorm(x86 系);Zydis(x64 现代引擎,REX/AVX 处理最完整)
- 老一代:PEiD 作者团队系列工具内置自制引擎

### 5.5 实战要点

1. 写脱壳机/指令追踪器,首选 capstone `cs_disasm` 逐条 + 长度推进,别手写全表。
2. 检测花指令:反汇编结果中"指令边界异常 + 无效操作码(UD2/垃圾前缀)"聚类处即花区。
3. x64 引擎重点处理 REX 前缀与 RIP 相对寻址的地址计算(目标 = 下条指令地址 + disp32)。

# 保护篇(第5篇 保护篇 1000616)

> 定位:软件作者视角的"防逆向"全景——反调试、反跟踪、花指令、壳、虚拟机保护,以及研究者视角的"反反跟踪"。知识主线:每种保护 = 检测原理 → 关键 API/结构 → 对抗手法 → 代表帖。

## 1. 反调试全景(Anti-Debug,节点 1000672)

### 1.1 PEB / 进程信息类(最常用一梯队)

| 手法 | 原理 | 绕过 |
|---|---|---|
| `IsDebuggerPresent` | 读 PEB!BeingDebugged(fs:[30]+2) | 改 PEB 字节为 0;ScyllaHide |
| `CheckRemoteDebuggerPresent` | 内部即 NtQueryInformationProcess(ProcessDebugPort) | 同下 |
| `NtQueryInformationProcess(ProcessDebugPort=7)` | 被调试时返回调试端口(非 0/-1) | 改返回值/参数;x64dbg 插件改参数 7 |
| `NtQueryInformationProcess(ProcessDebugObjectHandle=0x1E)` | 查调试对象句柄,被调试返回有效句柄 | hook 后清返回值 |
| `NtQueryInformationProcess(ProcessDebugFlags=0x1F)` | 返回 NoDebugInherit,被调试时为 0(注意反逻辑) | 改返回 1 |
| PEB!NtGlobalFlag(fs:[30]+0x68) | 调试器创建进程时置 FLG_HEAP_ENABLE_TAIL_CHECK 等位 | 清零 |
| PEB!ProcessHeap 堆标志 | Flags/ForceFlags 因调试堆而变大 | 恢复正常值(0x02/…) |
| `NtSetInformationThread(ThreadHideFromDebugger=0x11)` | 线程对调试器隐藏(异常不再通知) | hook 该调用 NOP 掉 |
| `NtQueryObject` 枚举对象 | 进程内出现 DebugObject 类型句柄 | 隐藏句柄/改类型名 |
| `NtQuerySystemInformation(SystemKernelDebuggerInformation)` | 查内核调试器(KdEnabled) | 双机调试才会中 |

代表帖:Windows平台反调试技术学习、windows反调试技术、Windows软件反调试简单总结、反调试技术总结、windows调试体系初探。

### 1.2 断点/上下文类

- **INT3 检测**:关键函数头/代码段自校验,发现 0xCC 即退;CRC/逐字节扫(见 §5.2)。绕过:硬件断点 DRx 代替 INT3;或先 patch 校验。
- **硬件断点检测**:`GetThreadContext` 读 DR0-DR7,非零即有断点。绕过:ScyllaHide 清 DRx/用一次性单步恢复。
- **单步检测**:检查 EFLAGS.TF;或 Trap Flag 自查( pushf 后改 TF 再 popf 触发自异常)。
- 线程上下文不一:对每个线程 GetThreadContext,DebugReg 只在断点线程非零。

### 1.3 时间检测(节点:时间限制 1000231 同源)

```
t1 = rdtsc / GetTickCount / QueryPerformanceCounter / timeGetTime
  …一段密集运算…
t2 = 同上
if (t2 - t1 > 阈值) → 判定被单步/断点拖慢 → 自毁
```
- `rdtsc`(特权级 3 可用,纳秒级)最常见;注意多核 TSC 漂移问题。
- 绕过:hook rdtsc 返回伪差值(ScyllaHide 的 Fake rdtsc:回放"合理差值");或把比较跳转 patch。

### 1.4 异常类反调试

- **Int 3 / Int 2D**:Int 2D 在被调试时使调试器"吃掉"一条指令(导致后续错位);程序自挂 SEH/VEH,无调试器时异常回自己 handler——执行路径分叉即检测。
- **无效句柄**:`CloseHandle(0x1234)`/`RaiseException(STATUS_INVALID_HANDLE)`——仅当存在调试对象时进程收到该异常通知,程序据此分支。
- **INT 1 单步链**:连续 push 单步标志跑一段,任何外部接管即中断。
- 对抗:调试器"异常全部回传给程序"(x64dbg:异常选项全 pass;OD:忽略范围),或 ScyllaHide 异常伪装。

### 1.5 OllyDbg 漏洞利用(Anti-OD 节点 1000673)

- 窗口检测:`FindWindowA(NULL,"OLLYDBG")`/按类名 `OLLYDBG`;枚举进程名 ollydbg.exe/x32dbg.exe/idag.exe/WinDbg…(窗口方法检测节点 1000681)。
- OD 1.x 历史漏洞被程序利用:格式化字符串崩溃(如对 OD 的命令栏/加载 DLL 名处理)、LoadDll 插件越界、Ctrl+F2 重载后堆残留、路径含特殊字符崩溃等——"构造让调试器崩的输入"即 Anti-OD。
- 对抗:改窗口标题/进程名;用 phantOm/StrongOD/ScyllaHide;换 x64dbg。

### 1.6 反反调试工具一览

ScyllaHide(x64dbg/OD 插件级)、phantOm、SharpOD、TitanEngine 隐藏层;内核级:TNB(老)、Hypervisor 层隐藏(VT,呼应系统篇 VT 节点)。原理=在检测点"伪造正常值":PEB 字段、NtQIP 返回、rdtsc、句柄枚举、GetThreadContext 的 DRx。

## 2. 反跟踪与反环境(Anti-Trace/VM/沙箱,节点 1000676-1000865)

- **Anti-Trace**:TF 标志检测、SEH 反单步(在 handler 里校验返回地址)、代码校验(见 §5.2)。
- **Anti-ICE**(SoftICE):`CreateFileA("\\\\.\\SICE")`(Win9x)/`"\\\\.\\NTICE"`(NT/2000) 打开成功(`<>INVALID_HANDLE_VALUE`)即判定挂载,关句柄置标志——Delphi 完整代码见《检测softice(delphi版)》:`hFile:=CreateFileA('\\.\SICE',GENERIC_READ or GENERIC_WRITE,FILE_SHARE_READ or FILE_SHARE_WRITE,nil,OPEN_EXISTING,FILE_ATTRIBUTE_NORMAL,0)`;另有《DS2.x检测SoftICE》、《SoftICE Internals(1)》。经典 `int 68h`(SoftICE 占用 INT 68h 向量)与 int 1 单步陷阱法为社区口传手法;对应隐藏驱动名改名的对抗见 §8 hidetoolz。
- **Anti-Loader**:检测加载方式(挂 loader 起的进程句柄/父进程非 explorer.exe/启动目录异常);对付"Loader 型"破解(自解密后由 Loader 拉起)。
- **Anti-ImpREC/Anti-W32dasm**:ImpREC 修复 IAT 时重建导入表——程序检测导入表被修复(函数地址不在壳代理区)/利用 W32dasm 的反汇编 bug 崩溃(如畸形指令)。
- **Anti-VMware**:注册表键(`HKLM\HARDWARE\DESCRIPTION\System\BIOS` 含 VMware)、`CPUID` 叶、I/O 端口 `in eax,dx`(0x5658 "VMXh")、sidt 读 IDT 基址探测(red pill)、MAC 前缀 00:0C:29、svga/ioregistry 文件。
- **Anti-VirtualPC**:类似,端口/指令时延(VPC 的 CPUID 慢)、注册表 Virtual Machine 服务。
- **Anti-沙箱**(1001489):检测内存小/CPU 核少、`IsDebuggerPresent`+父进程名、鼠标未移动(`GetCursorPos` 采样)、`Sleep` 大循环熬过沙箱超时、沙箱内时间加速检测(两次 GetTickCount 差值不合理)、稀少 API 命中(虚拟执行不落地的 API)。
- 对抗通则:环境伪装工具(VBox/VMware 修改补丁)、或在检测分支处直接 patch 跳转;动态分析先做"检测点摸排"再谈逻辑。

## 3. 花指令(节点 1000666)

### 3.1 原理

利用**线性扫描反汇编器**逐字节解码的弱点,在指令流中塞垃圾字节使其错位;真实执行时这些字节要么被跳过、要么被当作指令的一部分消费。

```
        call  $+5                 ; E8 00 00 00 00  → 下一条地址入栈
        pop   eax                 ; eax = 当前地址(取 EIP)
        add   eax, 0x0C           ; 计算目标
        jmp   eax                 ; 跳走
        db    0xE8                ; ← 垃圾:线性反汇编会当成 call 的操作数开头
        ...                        ;   真实控制流永不执行到,但反汇编器错位整段
```
经典款:`jmp $+2` 后接垃圾字节;`push 立即数 + ret`(跳到立即数);重叠指令(同一字节既是上一条结尾又是下一条开头);等价指令替换(xchg 替换 mov 等)打乱特征码。

### 3.2 对抗

1. 手工:IDA 中把垃圾字节 patch 成 NOP(0x90)或 U(undefine)再 C(重新代码化);
2. 脚本:IDAPython/x64dbg 脚本按特征码(`E8 00000000 58 83 C0 xx FF E0` 等)批量 patch;
3. 递归下降反汇编器(IDA 默认从入口跟控制流)对"跳转可达"代码天然免疫部分花指令,但间接跳(eax)仍迷路 → 动态跟踪补路径;
4. 用执行 trace(Unicorn/UnicornFlux 类)取真实路径再回填。

代表帖:《手动清除花指令》、《SVKP中的一些花指令》、《花指令小研究》、《清除花指令的脚本》、《去除花指令的代码》、《使用数学运算式随机生成花指令》、《分享几个C语言花指令宏》、《识别花指令》、《抗去除花指令》、《TSSafeEdit中的花指令研究》、《指令的膨胀和花指令的插入》。

## 4. 抵御静态分析(节点 1000664 其余)

- **SMC 自修改代码**(1000665):代码运行时解密/加密自身(xor/流密码,分段解密执行后即毁);分析必须动态或先 dump 解密段。
- **信息隐藏**(1000667):字符串不上字符串表——栈构造(`push 'x';push 'y'…`)、运行时解密(注册机作者的 API 名/提示语常这样藏)、资源加密。
- **代码变形**(1000668):同一功能每次生成不同指令序列(变形引擎,源自病毒多态),配合 garbage instruction。
- **代码混淆**(1000669):控制流扁平化(switch 调度器包住全部基本块)、虚假控制流、bogus 跳转;现代代表 OLLVM(1001421)及其中国分支 Armariris——**Android so 混淆同样用 OLLVM,但那部分归 Android 篇**,此处只收录 Windows/通用原理。
- **多态引擎**(1000670):解密头每代变异(病毒技术交叉引用,详见病毒篇)。

## 5. 软件保护技术(节点 1000617)

### 5.1 API 自实现(1000620)

- 自写 `GetProcAddress`:遍历 kernel32 导出表(PEB_Ldr 找基址→PE 头→导出 RVA→按名二分/顺序_hint)或按 hash 比较,躲 IAT 断点与字符串引用;
- 自写 `LoadLibrary`/`GetModuleHandle`(1000622/1000623):直接 LdrLoadDll 转发或 PEB_LDR_DATA 链上找模块;
- 反向对抗:研究者用更底层断点(NtMapViewOfSection/LdrLoadDll)或内存搜索。

### 5.2 文件完整性校验(1000626)

- 自校验:运行时读自身文件/代码段算 CRC32/MD5,比对内嵌值;防补丁(文件补丁/内存补丁都会破坏)。
- **反内存校验**(1000628):校验内存代码段(抓内存 patch/inline hook);配合反内存监视(1000629:检测 OpenProcess 句柄/调试器读内存痕迹)。
- 破解:先定位校验函数 patch 成恒真;或用 DRx 补丁不落字节(见重构篇 §2.3);高阶对抗是"校验函数本身套花指令+VM"。

### 5.3 双进程保护(1000630)

```
主进程 ←OpenProcess/共享内存/管道→ 守护进程
   相互校验代码段 CRC、互发心跳
```
破解:同杀两个(断点挂在 IPC 上)、摘除通信(堵命名管道/事件)、或 LD_PRELOAD 式 DLL 劫持两边。游戏保护(TP/HS/GPK)是其工程化加强版(§6.5)。

## 6. 壳保护:原理、脱壳与写壳(节点 1000697 + 解密篇脱壳树)

### 6.1 壳的分类与运行流程

```
加壳后文件:  [壳代码段(新入口)] [压缩/加密的原程序] [原资源/重定位…]
运行:
 OEP' = 壳入口
  ① 反调试/反虚拟机自检
  ② VirtualAlloc 申请内存 → 解压解密原程序各节
  ③ 处理重定位(若基址变化)
  ④ 重建/解析 IAT(逐个 LoadLibrary+GetProcAddress 或 IAT 重定向到壳代理)
  ⑤ 恢复 TLS/资源/偷代码回填(stolen bytes)
  ⑥ jmp OEP(原程序真实入口)  ← 脱壳者要的时刻
```

- 压缩壳(UPX/ASPack/PECompact/nSpack):目标省体积,弱保护;加密壳(ASProtect/ACProtect/Armadillo/Enigma/Safengine):反调试全家桶+stolen code+IAT 混淆;虚拟机壳(Themida/VMProtect/Code Virtualizer):关键函数 bytecode 化(§6.6)。
- **驱动壳**(1000709):ring0 段参与(驱动加载、SSDT/保护进程),对抗需内核调试。
- **欺骗查壳**(1000699):伪造区块名/入口特征/EP 区假字节,让 PEiD/DIE 识别错。

### 6.2 通用脱壳流程(对抗主线)

1. **OEP 寻找**(1000291):内存访问断点(对 .text 区下"写入后访问")、ESP 定律(壳入口 `pushad`/`popad` 配对)、Run trace、`bp GetVersion/GetCommandLine` 常见 OEP 前哨、Stolen code 时 OEP 本身被偷需人工恢复;
2. **Dump**(1000292-1000294):OEP 处用工具(PETools/Scylla)抓内存映像,注意 SizeOfImage/对齐;
3. **重建输入表**(1000295):ImpREC/Scylla 找真 IAT(区分壳代理转发)、裁剪无效项、生成新导入表;
4. **修重定位/输出表/附加数据**(1000296-1000299);PE 优化(1000302)。
5. **Anti-Dump 对抗**:壳抹 PE 头(DOS/NT 头清零)→ 手工回填头;改小 PEB 中 ImageSize → 修回;壳把节属性改怪 → 恢复。反反跟踪节点(1000684)即此。
- 脱壳机(1000303-1000305):静态(UPX 官方 -d 类)/动态(脚本化跑流程)。

### 6.3 写壳路线(外壳编写节点)

普通壳(1000707):区块合并/压缩引擎(aPLib/LZMA)→壳入口汇编→加载还原逻辑;进阶:stolen code 生成(1000700)、IAT 保护(1000702)、资源处理(1000704)、PE 加载器(1000705)、驱动壳(1000709)。"软件保护壳专题"(1000710)/"学写压缩壳心得"(1000708)为入门主线。

### 6.6 VMProtect 专节(节点 1000716)

**原理**:把被保护函数的原生指令编译为自定义 bytecode,外层 handler 循环解释执行:

```
       VMEntry:保存原生上下文(通用寄存器/标志)到 VM Context(VBKI/VFrame)
          │
          ▼
   ┌─────────────────────────────┐
   │ VMLoop:  fetch bytecode     │
   │   decode(乱序操作数/rolling key/指令别名)
   │   dispatch → handler N      │  ← 每代编译 handler 顺序都变
   │   handler 执行一条"虚拟指令" │     (push/pop/算术/内存/流控)
   │   更新 VIP(虚拟 IP)        │
   └─────────────────────────────┘
          │
          ▼
       VMExit:恢复上下文,回原生代码
```

- 保护等级:Virtualization(纯 VM)/Mutation(变形但原生)/Ultra(两者叠);SDK 用 `VMProtectBegin/End` 标记区段(或 Ultra marker); licensing SDK 绑机器。
- **分析思路**(知识库 VMProtect 逆向节点 1000718 的主线):
  1. 从 VMEntry 下手,识别 Context 布局与 bytecode 指针;
  2. 提取 handler 表(常经跳转表/计算索引),对每 handler 归类语义;
  3. 写 trace:记录 (VIP, handler, 栈效果) 序列 → 还原虚拟指令 → 回原生逻辑;可借 Unicorn 模拟执行自动化;
  4. 对 Mutation 部分先去花(§3)再看;
  5. 实战常不强拆:定位关键比较点(如 license 判断)后 patch 决策处/绕过 VM 调用边界。
- 同类:Code Virtualizer(Oreans,与 Themida 同家)、Themida VM(1000723 节点有 1.8 Demo VM 分析帖)、Safengine VM。
- 检索:VMProtect——《VMProtect 虚拟机小窥》、《再次小窥 VMProtect 虚拟机》、《VMProtect使用技巧》、《VMProtect 的简单分析》、《VMProtect进入虚拟机时》、《另辟蹊径,VMProtect分析》、《Vmprotect1.2x诡计收集》、《VMProtect 1.20伪指令总结》;Themida——《Themida V1.1.1.0》、《Themida Kernel Reverse-Engineering》、《Themida VM解码器》、《Themida虚拟机简单介绍》、《Themida的VM分析--变形代码清理》、《Themida 初步研究(ANTI篇)》。

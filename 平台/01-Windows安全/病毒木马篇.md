# 第9篇 病毒木马篇

> 对应目录树节点:Windows安全 [1000012] → 第9篇 病毒木马篇 [1000928]

## §1 病毒分析方法论

### 1.0 病毒/木马/蠕虫概念分野(病毒知识)

- **病毒**:寄生宿主文件,感染后随宿主传播(DOS 时代 COM/EXE 感染型,如 CIH 感染 PE 空洞节)。
- **蠕虫**:无需宿主、利用漏洞/弱口令自我复制横向传播(srv32.exe、SQL Slammer、WannaCry 的永恒之蓝模块)。
- **木马(RAT)**:伪装成正常程序,核心是 C2 远控通道(Gh0st 家族及其海量变种是国内黑产的主流形态)。
- **勒索软件**:加密+勒索双阶段,现代勒索=数据窃取(Exfiltration)+加密(Encrypt)+双重勒索。
- 经典学习材料:知识库收录的《Billy Belceb 病毒教程 DOS 篇/Win32 篇》(节点 1000931/1000932)是 Win9x/2000 时代感染型病毒原理的奠基文,讲解 EPO、入口点隐藏、Cavity(空洞)感染等技术,至今仍是理解 PE 感染原理的最佳入口。

### 1.1 样本获取与安全环境(环境配置 1001472)

**样本源**(原则:只取 hash 可交叉验证的样本):

| 渠道 | 用途 |
|---|---|
| MalwareBazaar (bazaar.abuse.ch) | 按 tag/family 检索,配套 YARA 规则 |
| VirusShare / VX-Underground | 大批量样本集合 |
| VirusTotal(需账号) | hash 查询、行为报告、关系图 |
| 微步在线云沙箱 / 奇安信病毒响应中心 / 360 威胁情报中心 | 国内家族(银狐/Steloj/BabyK 等)报告+样本 hash |
| 蜜罐(自建 RDP/SSH 弱口令蜜罐) | 采集真实投递链,获取一阶段加载器 |

**安全环境铁律**(树节点「环境配置」核心考点):

1. 物理隔离网段或 Host-Only + INetSim/FakeNet-NG 模拟 C2 域名解析与服务,既能看行为又不外联。
2. 快照三连:干净快照 → 联网前快照 → 感染后可回滚;勒索样本必须在 disposable VM 中跑,禁用共享文件夹。
3. 管理工具放宿主,样本放 guest;禁用剪贴板双向共享。
4. 高危样本(RaaS 勒索、APT)建议两层嵌套虚拟化或专用物理机(部分样本检测 VMware/Hyper-V 指纹逃逸,见 §4.6)。

**网络行为模拟工具**:INetSim(全协议假响应)、FakeNet-NG(重定向所有流量到本机)、Wireshark+Fiddler 抓包。分析银狐这类强 C2 依赖样本时,FakeNet-NG 能诱导其提前吐出配置。

### 1.2 静态分析(先看而不跑)

流程与工具链:

```
hash 计算(imphash)  → 查 VT/微步
   → 查壳(DIE/PEiD) → 判断是否需要脱壳
   → strings(ASCII+Unicode) → 提取 C2 域名/IP/PDB 路径/勒索信
   → 导入表分析(Import表缺失=加壳;看 VirtualAlloc/CreateRemoteThread/SetWindowsHookEx 判注入类)
   → PE 结构细看(节名、熵值>7.2 疑似加密节、overlay 附加数据、数字签名有效性 sigcheck)
   → YARA 匹配家族特征
```

- **熵值分析**:PE 节熵 > 7.2 基本可断定加密/压缩壳(UPX 壳节名 UPX0/UPX1 直接识别)。
- **imphash**:导入表哈希,同源样本家族聚类第一手段。
- **数字签名**:银狐大量样本盗用真实签名或携带过期签名,sigcheck -i 检查签名是否有效、签名者是谁。
- **资源/富文本头**:释放器常把 payload 藏 RCDATA 资源;Rich 头可推断编译器版本与链接时间(溯源线索)。

### 1.3 动态行为监控(核心三板斧)

| 工具 | 监控面 | 典型用法 |
|---|---|---|
| **Process Monitor (Procmon)** | 文件/注册表/进程线程/网络 | 过滤 `Result is NAME NOT FOUND`、`Process Name is xxx.exe`;看释放文件路径、Run 键写入 |
| **Process Explorer / Process Hacker** | 进程树、句柄、DLL、字符串 | 找可疑父子关系(Word→cmd→powershell)、验证签名、看注入 DLL |
| **API Monitor (rohitab)** | Ring3 API 参数级记录 | 按 Category 选中 Process/Thread/Network/Crypto,直击行为链;注意会被反调试检测 |
| **火绒剑** | 文件/注册表/进程/网络/驱动加载五合一 | 国产样本分析标配,日志可导出回放,对驱动加载(Rootkit)监控友好 |
| **Wireshark / Fiddler / mitmproxy** | 网络流量 | C2 协议还原、证书指纹、DGA 特征 |
| **Sysinternals: Autoruns** | 持久化点全集 | 感染后一键 diff 全部自启动项(比手工翻注册表高效十倍) |

**Procmon 实战要领**(调试篇 Process Monitor 节点 1000088 的经验总结):

- 用 `Filter → Result is NAME NOT FOUND` 快速定位样本「探测」行为(反沙箱探针文件)。
- `Tools → Process Tree` 看派生链;配合 `Ctrl+L` 收紧过滤,否则勒索样本百万级事件会淹没关键行。
- 恶意行为链典型事件序列:

```
[样本.exe 启动]
   │ CreateFile (NAME NOT FOUND: %APPDATA%\xxx\  探测沙箱标记)
   ├─ WriteFile   释放 payload.dll / 加密器本体
   ├─ RegSetValue HKCU\...\Run\<随机名>          ← 持久化
   ├─ CreateProcess cmd /c ... / powershell -enc ← 逃逸检测视线
   ├─ Process Create SUSPENDED + WriteProcessMemory + ResumeThread ← 进程注入
   ├─ vssadmin delete shadows / bcdedit recoveryenabled no ← 勒索预清理
   └─ DNS + TCP 连接 C2 → 加密文件(海量 WriteFile+RenameFile *.lock 后缀)
```

### 1.4 沙箱与自动化

- **公共沙箱**:Any.Run(交互式,可拖拽触发 UI 类样本)、VirusTotal 行为页、微步云沙箱(国内家族识别强)。
- **自建沙箱**:Cuckoo(经典,已停更)/ **CAPE**(Cuckoo 分支,内置 CAPE 检测模块与配置提取,支持大量家族自动脱配置)、Speakeasy。
- 沙箱盲区:反沙箱技术(§4.6)导致大量国内黑产样本在沙箱内空转,必须人工+交互式分析兜底。

### 1.5 逆向深挖

1. x64dbg 动态跟 OEP(壳样本):ESP 定律/内存断点/Run trace,配合 Scylla(PE-bear 时代工具)dump+修复导入表。知识库《脱壳技术》子树有完整方法论,本篇不展开。
2. IDA 静态:定位 main(WinMain)、识别加密算法常量(见基础知识篇 §密码学)、还原 C2 配置结构。
3. 配置提取示例:银狐/Gh0st 系配置通常在 `.data` 段以明文或 XOR 弱加密存放,strings 直接可读「上线地址|分组|版本」字段;Phobos 系把公钥/受害者 ID 写入勒索信与注册表 `HKCU\SOFTWARE\<随机键>`(以样本实际为准;分析帖确认勒索信含联系方式+ID 结构)。

### 1.6 分析报告产出

最小完备要素:hash(imphash)→ 文件类型/壳 → 行为链(时间线)→ 持久化位置 → C2(域名/IP/协议)→ 加密算法 → MITRE ATT&CK 技术编号 → IoC 清单 → 检测建议(YARA + 行为规则)。病毒分析帖基本都按此骨架成文。

## §2 恶意行为链与 ATT&CK 映射(ATT&CK相关 1001352)

把 §1 观察到的行为挂到 MITRE ATT&CK 矩阵上,是现代病毒分析的通用语言:

| 阶段 | 常见技术 | ATT&CK 编号(典型) |
|---|---|---|
| 初始访问 | 钓鱼附件/链接、RDP 爆破、1day 漏洞、SEO 投毒、软件供应链 | T1566 / T1110 / T1190 / T1195 |
| 执行 | 宏、PowerShell、LOLBins(mshta/rundll32/regsvr32)、恶意脚本 | T1059 / T1218 |
| 持久化 | Run 键、计划任务、服务、WMI 事件订阅、映像劫持 IFEO、启动文件夹、COM 劫持 | T1547 / T1053 / T1546 |
| 提权 | UAC 绕过(§8)、令牌操纵、内核漏洞 | T1548 / T1134 |
| 防御规避 | 加壳、混淆、进程注入、反沙箱、卸载安全软件、卷影删除 | T1027 / T1055 / T1562 |
| 凭据访问 | LSASS dump(mimikatz)、浏览器密码、键盘记录 | T1003 |
| 横向移动 | 永恒之蓝、PsExec/WMI、RDP、共享文件夹投毒 | T1210 / T1021 |
| C2 通信 | HTTP(S) 信标、自定义 TCP、DNS 隧道、域前置、加密信道 | T1071 / T1090 |
| 渗出 | 打包压缩上云盘、C2 直传、WebDAV | T1567 |
| 影响(勒索) | 文件加密、勒索信、磁盘 MBR 改写、DoS | T1486 / T1491 |

### 2.1 注入技术全家桶(木马核心技术)

- **远程线程注入**:`OpenProcess → VirtualAllocEx → WriteProcessMemory → CreateRemoteThread`(导入表见这四件套基本实锤)。注入目标首选 explorer.exe / svchost.exe / rundll32.exe。
- **APC 注入**(树节点 1000855):把 payload 地址挂入目标线程 APC 队列,等线程 `SleepEx/WaitForSingleObjectEx` 时触发,需遍历线程挂遍提高命中率。
- **SetWindowsHookEx 注入**(树节点 1000841):键盘记录器经典,把 DLL 强制载入同桌面所有 GUI 进程。
- **进程空洞化(Process Hollowing)**:挂起创建合法 svchost.exe → 卸载其镜像 → 写入恶意 PE → 修 EP → Resume。外观是合法进程,内存是恶意代码。
- **反射式 DLL 注入(Reflective DLL Injection)**:不走 LoadLibrary,自带 loader 在目标进程内存中手工重定位+解析导入+调用 DllMain,磁盘无落地、无加载器痕迹——Cobalt Strike 默认注入方式,知识库注入技术子树(1000852)有多篇源码实现帖。
- **DLL 侧载(白加黑)**:与签名白程序同目录放置同名恶意 DLL,利用其导入表顺序加载。银狐最爱的姿势:主程序用微软/腾讯签名的白 EXE,旁边一个恶意 DLL(详见 §3.1 与 §4.3)。

### 2.2 C2 协议形态

1. HTTP 信标型(多数 Gh0st 系):GET 请求回传「上线包」(机器名/系统版本/摄像头标志),POST 接收指令,流量特征是自定义 Base64/XOR 变体。
2. 原始 TCP 长连接:心跳+指令分发,协议头常见魔数(如 Gh0st 头 `Gh0st` 字样——大量变种改头字符串,但结构同源,这是家族同源性判断的黄金证据)。
3. DNS 隧道/DoH:强封锁环境。
4. 加密升级:现役样本普遍 RSA 换密钥+AES 会话加密,抓包只见密文;逆向必须回二进制里抠密钥交换流程。

### 2.3 勒索软件行为标准剧本

```
[投递] RDP爆破/钓鱼/漏洞 → [驻留] 关闭防护(Windows Defender/杀软进程) 
→ [预清理] vssadmin delete shadows / wbadmin delete catalog / bcdedit /recoveryenabled no
   / netsh advfirewall set allprofiles state off / 跳过特定目录与系统目录保机器可开机
→ [密钥] 随机 AES-256 会话密钥加密文件,再以硬编码或拉取的 RSA 公钥加密会话密钥
→ [加密] 多线程遍历盘符+网络共享,改后缀(.locked/.mallox/.steloj/.babyk...)
→ [勒索信] info.txt / info.hta / HOW_TO_RESTORE_FILES.txt
→ [可选] 窃取数据先行 → 双重勒索
```

卷影删除与防火墙关闭这两条在 Procmon/火绒剑里一眼可辨,是动态判定勒索的最快指纹。

### 2.4 蠕虫传播模块

树节点 1000940《蠕虫 srv32.exe 逆向分析》是经典帖:解剖 Win32 蠕虫如何枚举网络共享、弱口令字典 IPC$ 横向、感染 PE 与注册表持久化三线并进。现代对应物:WannaCry 的 DoublePulsar/永恒之蓝 SMB 横向(2017 年有多篇复现分析帖,可检索「永恒之蓝」)。

### 2.5 Rootkit/Bootkit 防御面(树节点 1000860-1000875 概述)

内核态隐藏(SSDT Hook/IRP Hook/DKOM 摘链)+ MBR/VBR 改写。分析工具:PCHunter/火绒剑驱动监控、WinDbg 内核调试、Volatility 内存取证。移动端对应 Android 篇,此处不展开。

### 2.6 病毒预防(节点 1000934)

最小防线:补丁(RDP 永远放公网=邀请勒索)、最小权限+MFA、RDP 只走 VPN、离线备份 3-2-1、宏默认禁用、应用允许清单(AppLocker/WDAC)。个人端:官方渠道下载(银狐 SEO 投毒的直接反制)、UAC 不盲点允许。

## §3 家族案例(近年热门)

> 本节家族特征为公开威胁报告结论;细节按家族名检索最新报告。

### 3.1 银狐(Gh0st 系远控/加载器集群)

- **定位**:2023 年至今国内感染量第一的黑产集群,非单一家族而是 Gh0st/Valyria/大灰狼等 RAT 变种+流氓加载器的集合;CNCERT 与各厂多年通报。
- **投递**:SEO 投毒/竞价广告(搜「wps/excel/向日葵/cad 破解」点进假站)、QQ/微信群文件、伪装成「发票、税务局、驾照新规」等公文类文件名。
- **技术链(分析时按图索骥)**:
  1. 白加黑:签名白 EXE + 恶意同名 DLL(msedge.dll、version.dll、dbghelp.dll 等常见侧载名);
  2. 多级加载器(NTFS 数据流、注册表 blob、图片隐写藏 stage);
  3. 远程注入到系统进程,落地 Gh0st 变种;
  4. C2 心跳后按指令推送二次载荷(挖矿/引流/窃密)。
- **识别指纹**:导入表 `WriteProcessMemory+CreateRemoteThread`、加密配置串(XOR 后可读「Gh0st」风格上线结构)、伪装资源图标(Office/PDF 图标但文件是 EXE)。
- 检索词:「银狐」「白加黑」「DLL 侧载」;代表:《极致反沙箱(银狐样本分析)》(2024-08,见 §汇总表)。

### 3.2 LIVE 勒索病毒家族(Solar 安全系列)

- 要点:国内勒索进入 2.0 时代——从弱口令/1day 入侵进化为定向攻击;【病毒分析】系列(银狐/LockBit/DragonForce/LIVE 等)以「可解密」为特色,给出密钥生成缺陷的完整推导,逆向含金量高。

### 3.3 Mallox / TargetCompany(.mallox)

- 概况:2021 年中出现的家族,别名 TargetCompany/Fargo/Tohnichi/Elbie;以 `.mallox` 后缀著称,主要经 MSSQL 弱口令+暴露的 1433 端口入侵。
- 与 LiveLock 的关系:Mallox 即 TargetCompany 2021 年株的迭代品牌,别名 Fargo/LiveLock/Tohnichi/Elbie——Symantec(2023-03)确认「Mallox 是 TargetCompany 勒索菌株的更新变种」;Kaspersky Securelist《Evolution of Mallox: From Private Ransomware to RaaS》(2024-09,securelist.com/mallox-ransomware/113529)梳理了从私有勒索到 RaaS 的演化;Unit42(2023-07)与 Avast/GenDigital(2024-10,发现 2023 年株加密缺陷可解密)均有专项评估。
- 技术要点:纯 C/C++ 加密器;AES+RSA 混合;上线 Tor .onion 勒索页;国内安全论坛有多篇 `.mallox` 样本逆向分析(可检索「mallox」)。

### 3.4 Phobos / Dharma(老牌 RaaS)

- 2019 年至今长期活跃;RDP 爆破+钓鱼入侵为主;RSA+AES;勒索信 `info.txt`+`info.hta`;后缀随 affiliate 变化(.faust/.devos/.eight/.steloj/.babyk…)。
- 安天 2019 报告《Phobos 勒索软件变种分析》(antiy.com/response/20191016.html)为权威中文材料;2024-10-18 有《【病毒分析】Phobos家族新变种深度分析》(Solar 团队;Phobos 经 RDP 暴破+钓鱼邮件传播,常被认为与 Dharma 同源,AES+RSA 双重加密每文件生成唯一密钥;多论坛同步转载)。
- 行为指纹:提权后模拟 explorer.exe 令牌、删除卷影、加密后留双勒索信。

### 3.5 Steloj / BabyK(Phobos 系国内流行变种)

- **Steloj**:2023 年底起在国内政企侧高发,`.steloj` 后缀,info.txt/info.hta 勒索信;国内厂商(微步/奇安信/360)均有专报;语料帖:《【病毒分析】Steloj勒索病毒分析》  (2024-07-09,Solar 团队,汽车制造企业受害案例;入侵面 MSSQL 弱口令爆破,加密前删除卷影/关闭网络共享/停止服务——与 Mallox 的 MSSQL 入侵面重合)。
- **BabyK**:Phobos RaaS 化后的 affiliate 品牌,`.babyk` 后缀,RDP+钓鱼投递;与 Steloj 同源不同壳,分析流程可直接复用 Phobos 模板。
- **实战建议**:Phobos 系样本分析重点在「公钥来源」(硬编码 vs 上线拉取)与「密钥落盘/注册表残留」,这决定恢复可能性;参考 FBI 2025 年对 Phobos/8Base 的执法解密通报(360 月报转述)。

### 3.6 蠕虫 srv32.exe 逆向(树内经典帖)

知识库原生节点 1000940,完整的 Win32 蠕虫解剖:进程互斥量防重复感染、注册表 Run 持久化、IPC$ 弱口令横向、感染 PE。作为教学样本比现代家族干净(无反调试无混淆),适合作为第一个完整逆向的恶意样本。

### 3.7 经典坐标(病毒知识)

CIH(PE 空洞感染+破坏 BIOS,1998)、熊猫烧香(感染型蠕虫+下载者,2006,当年爆款分析帖)、Stuxnet(LNK 漏洞+PLC,2010)、WannaCry(永恒之蓝+勒索,2017)。了解这四个坐标即覆盖病毒技术四十年主干。

## §4 免杀技术(攻防双视角)

> 树节点 1000936/1000942 查杀与恶意软件的对抗面。免杀=绕过「特征码/行为/信誉」三类检测的组合拳。

### 4.1 加壳与混淆

- 通用壳(UPX/ASPack)只是压缩,杀软通杀;恶意样本用 VMProtect/Themida 防静态特征+防模拟器,代价是行为检测更扎眼。
- 自写加密器+SMC 自解密:每次生成密钥不同 → 每个样本 hash 唯一(自动化对抗特征库);知识库《保护篇》外壳编写子树(1000697+)与《脱壳技术》互为镜像,读懂壳才知道怎么杀。

### 4.2 syscall 直调(Direct Syscall)

- 原理:EDR 在 ntdll 的 Zw* 导出函数头部插 hook(inline hook / detour)捕获调用;样本绕过 ntdll,自己实现 `mov eax, <syscall#>; syscall` 汇编桩,从内核返回直达,EDR 用户态 hook 全数失效。
- 对抗升级:EDR 退守内核回调(ObRegisterCallbacks/Process Notify)与 ETW;样本进而 patch ETW(§4.5)。
- 识别:出现裸 `syscall` 指令、`mov eax, 0x36`(NtAllocateVirtualMemory 号)等模式,几乎必为直调;Win11 syscall 号随版本变化,样本内常带系统版本号映射表。

### 4.3 白加黑 / DLL 侧载

- 选签名白 EXE(微软自带工具、知名软件启动器)+ 利用其 DLL 搜索顺序劫持。链条:白 EXE 启动 → 加载同目录恶意 DLL → 恶意 DLL 转发原始导出(保证宿主正常)→ 拉起真身。
- 落地三大件:SideLoad DLL(带转发导出表)、加密 payload(资源/数据流)、注入目标。银狐(§3.1)、Emmenhtal 类 LOLBin 加载器(§9)都是此范式。
- 检测侧对策:监控「签名 EXE 从用户可写目录启动」+ DLL 数字签名不一致告警。

### 4.4 反射注入与无文件落地

见 §2.1。配合 PowerShell `-enc`/`FromBase64String` 一条命令内存展开 shellcode(`VirtualAlloc+memcpy+函数指针调用`),磁盘全程无文件;防御靠脚本块日志(ScriptBlock Logging)+ AMSI(于是有 §4.7 的对抗)。

### 4.5 ETW Patch

- ETW(Event Tracing for Windows)是 .NET/PowerShell/EDR 的遥测主干。样本在进程内定位 `ntdll!EtwEventWrite`,把入口 patch 为 `ret`(0xC3),遥测静默——「事件消失但进程还在」。
- 变体:patch `EtwNotificationRegister`、篡改 ProviderHandle、直接篡改注册表 EnableLevel。检测:完整性校验 ntdll 代码段、对比 hook 前后字节。

### 4.6 反沙箱 / 反虚拟机(树节点 1001489 Anti-沙箱)

- 时间炸弹:`GetTickCount`/`rdtsc` 检测单步时差、`Sleep` 长延时(沙箱通常只跟 3-5 分钟)。
- 环境指纹:CPUID hypervisor bit、注册表 VMware 键(`Hardware\Description\System\BIOS`)、MAC 前缀 `00:0C:29`、磁盘大小、最近文档数、鼠标移动轨迹。
- 交互检测:等待用户点击/窗口失焦才执行(Any.Run 交互式沙箱的由来)。
- 《极致反沙箱-银狐样本分析》(2024-08):银狐样本反杀软/反沙箱实录——patch ETW/AMSI、检测 Defender 模拟执行特征;hook 免杀总结见 §4.9。

### 4.7 AMSI Bypass

- AMSI(Anti-Malware Scan Interface)让脚本内容在执行前送杀软扫描。经典 bypass:在 .NET 进程内定位 `amsi.dll!AmsiScanBuffer`,把首个参数或返回标志 patch 失败(`mov eax, 0x80070032` / 修改 `amsiInitFailed` 字段),扫描器拿到「失败」就放行。
- 识别:内存搜索 `AMSI` 字符串+对 `amsi.dll` 的 `GetProcAddress`。
- 检测对策:amsiInitFailed 监控、脚本块日志在 patch 前已经记录。

### 4.8 组合范式(2024-2026 现役)

```
签名白EXE(信誉绿) → 侧载DLL(无特征) → syscall直调(绕hook)
   → ETW patch(致盲遥测) → 反射注入系统进程(无文件) → C2走域前置/DoH
```
每一环都对应杀软一个检测维度;单点突破易,全链绿才上量——这也是 YARA/行为规则要按「链」而不是按「点」写的原因。

### 4.9 实战代表帖

- **《极致反沙箱-银狐样本分析》**  (2024-08):银狐一线对抗实录——样本先探测 Defender 模拟执行特征,再 patch ETW/AMSI 致盲遥测,完整演示 §4.5-§4.7 的现实组合;分析这类样本要在虚拟机里先摘掉杀软 hook 或用 bochs(§10)透明调试。
- **《hook免杀总结》**  (2024-08,茶余饭后版):系统梳理 hook 体系在免杀中的攻用——从用户态 inline hook 到杀软扫描通道的干扰思路,与《编程篇·Hook技术》子树(1000837-1000851)互为攻防两面对照阅读。

## §5 恶意软件查杀(病毒查杀 1000936)

- **特征码**:精确 hash 与模糊特征(字节模式);对多态样本失效率高。
- **YARA 编写实战**:先从 2-3 个同族样本提取稳定代码段(避开会变的 C2 串),配 `$config = "上线" wide ascii` 类字符串规则 + 熵条件;规则要拿干净软件集回测误报。
- **行为引擎**:HIPS(火绒/360 的主防思路)拦截 CreateRemoteThread 目标为系统进程、Run 键写入+删除卷影组合等;误报靠云判白。
- **内存查杀**:扫描进程内存中 payload 特征(解决无文件落地),银狐 Gh0st 配置串常靠内存 dump 才拿到。
- **云查杀+信誉**:文件哈希云查询、签名信誉(催生白签名滥用)。
- **事件响应**:Autoruns 清持久化 + Volatility 内存取证 + 网络侧封 IoC;勒索场景优先镜像留存再处置(解密研究依赖现场密钥残留)。

## §6 木马查杀与蠕虫 srv32 案例(木马技术 1000937)

- Gh0st 系木马落地后标准排查路径:Autoruns 全持久化点 → 火绒剑看注入 → 找配置串定位 C2 → 断网封 C2 → 清理+改密(重点:被键盘记录的凭据全部作废)。
- srv32.exe 教学流程:静态看导入(网络+注册表+文件 API)→ OD/x64dbg 跟感染例程 → 还原弱口令字典与传播逻辑 → 手工写专杀(互斥量+文件清理+注册表恢复)。
- 专杀编写要点:先 CreateMutex 抢占互斥量阻止再感染,再清理;处理文件感染型需备份剥离。

## §7 APT 攻击(节点 1001218)

- 定义性特征:定向(spear phishing 精准投递)+ 长期潜伏 + 定制工具链(非商品木马)+ 0day 储备。
- 双阶段加载器范式:一阶段极简(HTML smuggling / LNK / 宏)落地二阶段 shellcode 加载器,三阶段才见 RAT(Cobalt Strike/自研)。
- 知识库视角重点:漏洞利用链复现(LNK/CVE-2017-11882 公式编辑器等文档漏洞归「二进制漏洞-文档型漏洞」子树)、攻击工具逆向(如 Equation/C&C 协议还原)。
- APT 与黑产的分水岭:目标价值 vs 广撒网;分析时先看投递精准度与 0day 使用即可初判。

## §8 UAC 绕过(节点 1001220)

- 原理面:UAC 虚拟化与自动提升(auto-elevate)清单内的进程可静默提权;绕过=欺骗 auto-elevate 程序执行我们的命令。
- 经典三式(逆向时按 COM CLSID 搜代码):
  1. **fodhelper.exe**:写 `HKCU\Software\Classes\ms-settings\Shell\Open\command` 指向 payload,fodhelper 自动提升读取时执行(注册表劫持);
  2. **事件查看器 eventvwr.exe**:同类 `mscfile` 注册表劫持;
  3. **COM 提权(IFileOperation)**:劫持 CLSID 让高完整性进程替我们 CopyFile 释放 payload 到受保护目录。
- 检测:监控对上述注册表键的写入;UAC 等级调最高(Always notify)可全灭此路。

## §9 恶意脚本(节点 1001351)

- 宏(Office VBA)、VBS/JS(WSH)、PowerShell 是三大件;恶意 LNK 也归此(图标伪装文档)。
- 现役范式参考:2024-2025 流行的 Emmenhtal 类加载器——VBS/JS 一段脚本解码内嵌数据,经 `forfiles.exe/pcalua.exe` 等 LOLBin 执行,再侧载二进制阶段(与 §4.3 联动);国内银狐投递链前段同构。
- 分析工具:文本直接读 + ` powershell -enc` Base64 解码链(多次嵌套逐层剥);调试用 x64dbg 附加 wscript/powershell。
- 防御基线:禁宏、ASR 规则阻断 LOLBin 子进程派生、PowerShell Constrained Language Mode + 脚本块日志。

## §10 环境配置与学习路径(节点 1001472)

新人到熟练的最短路径(按知识库结构):

3. 脱壳基本功(《脱壳技术》子树)+ PE 格式(见同目录《基础知识》篇);
4. 家族实战:银狐白加黑(§3.1)→ Phobos 系(§3.4)→ Solar 系列 LIVE 帖(§3.2);

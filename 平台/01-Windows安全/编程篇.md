# 第8篇 编程篇 —— 安全攻防底层编程技术全景

> 对应树节点:Windows安全 [1000012] → 第8篇 编程篇 [1000785](18 子节点)。
> 主线:**注入与 Hook 是横切技术,驱动是 Ring0 门票,Rootkit/Bootkit 是恶意软件形态,系统编程是地基**。本篇按 18 节点组织,重点深写:注入全类、Inline Hook 自实现、驱动 IRP/IOCTL、Windows 恶意软件开发基础。

## 1. 基础知识 [1000786]

安全方向底层编程的四块地基:

- **硬件相关 [1000822]**:端口 IO(x86 `in/out` 特权指令,Ring3 不可直接用)、U盘(枚举 `WM_DEVICECHANGE`/SetupDi,恶意样本靠此摆渡)、键盘鼠标(全局钩子见 §3;驱动级 kbdclass 过滤)、磁盘(ATA Pass Through、`\\.\PhysicalDrive` 直接读写扇区——MBR/Bootkit 落盘必经)、BIOS(实模式入口、UEFI 之前的知识)、SMM(系统管理模式,比 Ring0 更高)。
- **安全编程 [1000833]**:自保护(文件/注册表/进程防删)、反调试反注入(与第5篇保护篇呼应)。
- **x86-64 编程 [1000834]**:64 位下 `__fastcall` 前 4 参走 RCX/RDX/R8/R9;hook 桩、shellcode 都要按新 ABI 写。
- **算法相关/开发技巧/C++编程建议 [1000835/1000836/1001198]**:RAII 管句柄、SEH 安全使用、编译原理 [1001245](语言篇/编译器选择的理论背景)。

## 2. 环境与语言 [1000787]

- **汇编系**:MASM(罗云彬《Windows环境下32位汇编语言》即本知识库 Win32 asm 学习主教材 [1000805-1000808])、TASM(16 位时代遗产)、NASM、RadASM IDE。Win32 汇编路线:窗口创建 → 消息循环 → 控件 → DLL → 事件 hook。
- **C/C++ [1000809]**:安全开发主力;`从汇编的角度学习C/C++` [1001716] 是本库推荐逆向视角学习法。
- **MIX 语言 [1000811]**:C++ 内嵌汇编(`__asm`)/Delphi 混 C,写 shellcode/hook 桩必备技能(内嵌汇编 [1000820])。
- **框架 [1001784]**:**LLVM** [1001779](写混淆 pass,呼应保护篇 OLLVM)、**Frida** [1001785](现代 hook/注入首选框架,跨语言;重构篇亦有 Frida 补丁 [1001743])。
- 环境选型结论:写注入器/hook 用 C(体积小可控);写分析自动化用 Python(Frida binding);写壳/加密用 C+汇编。

## 3. 注入技术 [1000852](重点)

**注入知识总览**:把代码/模块送进目标进程地址空间执行。按执行载体分类:

```
注入技术树(已文字还原)
DLL 注入路线
 ├─ ① 远程线程 CreateRemoteThread+LoadLibrary(经典)
 ├─ ② NtCreateThreadEx/RtlCreateUserThread(绕过 CreateRemoteThread 监控)
 ├─ ③ APC 注入 QueueUserAPC(目标线程 alertable 时触发)
 ├─ ④ SetWindowsHookEx(WH_GETMESSAGE/WH_CBT,系统按需加载 DLL)
 ├─ ⑤ 输入法注入 IME(imm32 加载自定义 IME 到 GUI 进程)
 ├─ ⑥ COM 劫持(注册表 CLSID/InprocServer32 指向恶意 dll)
 ├─ ⑦ AppInit_DLLs / Image File Execution Options Debugger
 ├─ ⑧ DLL 劫持/代理(放恶意 dll 在搜索路径前部,转发导出)
 └─ ⑨ 进程空洞 Process Hollowing(挂起创建→卸镜像→写入→改上下文→恢复)
Shellcode 路线
 ├─ ⑩ WriteProcessMemory + SetThreadContext(改 EIP/RIP)
 ├─ ⑪ 线程上下文注入/幽灵线程(Thread Hijacking)
 ├─ ⑫ 反射式注入 Reflective DLL Injection(自实现 loader,不落 LoadLibrary)
 └─ ⑬ 傀儡进程/AtomBombing/PROPagate 等窗口对象滥用
```

### 3.1 远程线程注入(经典四步)

```c
// 最小实现(教学)
HANDLE h  = OpenProcess(PROCESS_ALL_ACCESS, FALSE, pid);
LPVOID m = VirtualAllocEx(h, NULL, len, MEM_COMMIT, PAGE_READWRITE);
WriteProcessMemory(h, m, dllPath, len, NULL);
CreateRemoteThread(h, NULL, 0,
    (LPTHREAD_START_ROUTINE)GetProcAddress(GetModuleHandleA("kernel32"), "LoadLibraryA"),
    m, 0, NULL);
```
要点:ASLR 下 kernel32 基址在同会话进程间一致(Win7 前;之后会话隔离,但多数场景仍可用,稳妥做法 `Toolhelp32Snapshot` 取目标 kernel32 基址);被 EDR 盯得最死的一条路。

### 3.2 SetWindowsHookEx 注入

`SetWindowsHookEx(WH_GETMESSAGE, proc, hDll, threadId)`:目标是 GUI 线程时,系统把 hDll 映射进目标进程处理消息。优点:不需要 OpenProcess;缺点:必须 DLL+目标有消息循环。常被键盘记录器与输入法滥用场景使用。

### 3.3 APC 注入 [1000855]

把例程挂到目标线程 APC 队列,线程进入 alertable 状态(`SleepEx/WaitForSingleObjectEx`)时执行。遍历目标进程全部线程各挂一次提高命中率;恶意软件爱注入常做异步 IO 的浏览器/杀软进程。

### 3.4 输入法注入与 COM 劫持

- **输入法**:imm32 在 GUI 进程加载 IME(本质是个 dll),老外挂/窃密样本把它当"合法加载通道";对抗点:IME 签名校验(现代 Windows 已收紧)。
- **COM 劫持 [1000754 相邻知识点在重构篇 DLL 劫持]**:改 `HKCU\Software\Classes\CLSID\{...}\InprocServer32` 指向自己 dll,explorer 等 COM 消费者加载时即注入;无需进程操作,持久化常用(与注册表处理 §10.3 联动)。

### 3.5 进程空洞(Process Hollowing)

`CreateProcess(SUSPENDED)` → `NtUnmapViewOfSection` 清原镜像 → `VirtualAllocEx` + 写入恶意 PE → `SetThreadContext`(EBX/RDX 指向新 PEB ImageBase)→ `ResumeThread`。合法外壳+恶意内容,是免杀与木马生成器标配;检测点:映像与磁盘文件 hash 不一致。

### 3.6 反射式 DLL 注入

注入器只负责把 DLL 字节写进目标内存,DLL 自带 `ReflectiveLoader` 导出:自重定位、自解析导入、调用 DllMain——全程不出现 `LoadLibrary`,不进模块链(默认),绕过模块枚举类检测。Metasploit/CS 上线即此技术。现代对抗:内存扫描、ETW、回调监控(`PsSetLoadImageNotifyRoutine`)。

**注入技术的应用/工具** [1000857/1000854]:经典注入器(ProcMemCopier、ExtInject)、游戏修改器、HIPS 测试;知识库树单独有「注入相关 [1000858]」收集变体(如 Early Bird——进程创建早期挂 APC)。

**代表帖**:《Dll注入NetTransport 2.25.337》、《QueueUserApc实现DLL注入》、《最简单的DLL注入》、《无DLL远程线程注入》、《N种内核注入DLL的思路及实现》、《Win32汇编实现DLL的远程注入及卸载》、《内核中注入dll的一种流氓方法》。

## 4. Hook 技术 [1000837](重点)

**Hook 概念 [1000838]**:截获调用/消息并改道。按层分类(树节点即覆盖全部):

| 类型 | 节点 | 原理一句话 | 环节 |
|---|---|---|---|
| IAT Hook | 1000847 | 改导入表函数指针 | PE 加载后 |
| InLine Hook | 1000844 | 函数头写 jmp 跳桩 | 任意时机 |
| API Hook | 1000840 | 上两者统称,Ring3 | — |
| 消息 Hook | 1000841 | SetWindowsHookEx 消息链 | USER 层 |
| SSDT Hook | 1000843 | 改 ntoskrnl SSDT 表项 Ring0 | 内核 |
| IDT Hook | 1000845 | 改中断描述符表入口 | 内核 |
| IRP Hook | 1000846 | 挂 IRP 派发队列(文件/键盘驱动栈) | 内核 |
| Object Hook | 1000842 | 改内核对象内函数指针(如 OBJECT_TYPE->TypeInfo) | 内核 |
| SEH Hook | 1000848 | 向量化异常 VEH 挂 INT3/非法访问 | Ring3 |
| InfinityHook | 1001704 | 挂 WMI 的 ETW 通知回调绕 PatchGuard | 内核(Win10) |
| 检测/恢复/对抗 | 1000849 | 校验字节/表项,还原被 hook 区域 | — |

### 4.1 Inline Hook 自实现(核心代码)

```c
// 32 位最小 jmp 桩(5 字节),64 位用寄存器桩或 trampoline
// 1) 长度反汇编:确定被 hook 函数头部 >=5 字节的完整指令边界
size_t stolen_len = disasm_at(target, 5);   // 用 HDE/BeaEngine/Capstone
// 2) 备份 stolen bytes 建 trampoline:stolen + jmp target+len
 BYTE* tramp = alloc_near(target);
 memcpy(tramp, target, stolen_len);
 patch_jmp(tramp + stolen_len, (BYTE*)target + stolen_len);
// 3) 头部写 E9 detour
 patch_jmp(target, my_hook);
// 4) my_hook 里做完事后 call tramp 回原流程
```

要点与坑:
- **长度反汇编是灵魂**:不按指令边界覆盖半条指令必崩;用 Capstone/HDE 而不是手数字节。
- **短跳转范围**:`E9` 相对跳 ±2GB,detour 函数要 `VirtualAlloc` 在附近,或用 `mov eax, addr; jmp eax` 7 字节绝对跳桩;64 位必须 12 字节桩(`mov rax, imm64; jmp rax`)或 14 字节桩。
- **多线程竞争**:写桩期间其他线程执行到头部 → 先 `SuspendThread` 全线程或用原子 8 字节写(先写后 5 字节);
- **重入与递归**:hook 里调原 API 要走 trampoline,否则死循环;
- **x64 热补丁**:多数系统 API 头部预留 `mov edi,edi`(2 字节)+ 前 5 字节 nop 空间,可直接利用(微软官方 hotpatch 设计)。
- 现成库:Detours(微软)、MinHook(长度反汇编+trampoline 完整实现,推荐读源码)、Funchook;树「Hook 库 [1000839]」即收录这类。
- **Hook 检测对抗 [1000849]**:校验 `.text` CRC/字节快照、从磁盘重读干净副本对比、内核侧 PatchGuard;对抗方用 "hook 页做只读+VEH 修复" 等手段。对应保护篇反调试/第6篇内存补丁 [1000738-1000742](Debug API、调试寄存器 DR0-DR3 硬件断点 hook)。

**代表帖**:inline hook——《放个inline Hook的工程》、《菜鸟理解的inlineHook的要点》、《绕过函数头INLINE HOOK》、《inline hook NtQueryDirectoryFile》;SSDT——《SSDT Hook的妙用》、《城里城外看SSDT》、《shadow ssdt学习笔记》、《寻找原始表,恢复ssdt表》、《修改SSDT表HOOK NTDebugActiveProcess函数》、《The Age-Old Art of SSDT Hooking》。

### 4.2 Frida 对照:脚本化 Hook 与注入

同一件事的 2020s 答案(框架节点 [1001785]),与手写对照学习效率最高:

```js
// frida -p <pid> 或 frida -f target.exe
Interceptor.attach(Module.getExportByName(null, "MessageBoxW"), {
  onEnter(args) { console.log("[+] title=", args[1].readUtf16String()); },
  onLeave(retval) { retval.replace(0); }              // 改返回值=内存补丁
});
// = 手写:长度反汇编 + trampoline + detour,Frida 全部自动做掉
Java.perform(() => {                                   // Java/托管层同理
  let Activity = Java.use("android.app.Activity");    // (Android 侧呼应)
});
```

- `Interceptor.replace` = 整函数替换(手写 detour 直接不回原函数);
- `frida-trace -i "CreateFile*"` = 批量 hook 生成模板,十分钟出样本行为画像;
- 与手写的关系:Frida 底层就是 §4.1 的 Inline Hook(gum 引擎含全套长度反汇编),被 EDR 盯 frida-agent 特征时仍需回手写/驱动方案。
- 树内呼应:重构篇「Frida 补丁 [1001743]」把 Frida 当补丁器用(SMC 替代品)。

## 5. 驱动开发 [1000887](重点)

### 5.1 驱动入门 [1000888]

- 环境:WDK + VS;KMDF/WDM/UMDF 选型(安全场景多用 WDM 裸驱动,控制力强)。
- 骨架:

```c
NTSTATUS DriverEntry(PDRIVER_OBJECT drv, PUNICODE_STRING reg) {
    DbgPrint("[drv] loaded\n");
    for (int i=0;i<IRP_MJ_MAXIMUM_FUNCTION;i++)
        drv->MajorFunction[i] = DefaultDispatch;
    drv->MajorFunction[IRP_MJ_DEVICE_CONTROL] = IoctlDispatch; // 应用层通信入口
    drv->DriverUnload = DriverUnload;
    IoCreateDevice(drv, 0, &devName, FILE_DEVICE_UNKNOWN, 0, FALSE, &dev);
    IoCreateSymbolicLink(&symLink, &devName);
    return STATUS_SUCCESS;
}
```

### 5.2 IRP/IOCTL:Ring3↔Ring0 通信 [1000894/1000895]

- 应用层 `CreateFile("\\\\.\\MyDev")` → `DeviceIoControl(h, CTL_CODE(...), in, out)` → 内核 `IoctlDispatch` 收 IRP:
  - `irpStack = IoGetCurrentIrpStackLocation(Irp)`;
  - `CTL_CODE(DeviceType, Function, METHOD_xxx, FILE_ANY_ACCESS)`;`METHOD_NEITHER` 直接用户指针(要 `ProbeForRead/Write` + SEH 包裹,否则任意地址提权漏洞);
  - 缓冲区三种方式:BUFFERED(安全默认)/IN_DIRECT/OUT_DIRECT/NEITHER;
- **安全红线**(也是历史漏洞模式):IOCTL 未校验输入长度、`METHOD_NEITHER` 不探针、任意用户可打开设备 ACL —— 驱动提权漏洞三大来源。
- IRP 概念扩展:同步 IRP 自己完成(`IoCompleteRequest`);异步下发到下层驱动(文件过滤必会);`IoBuildSynchronousFsdRequest` 主动发 IRP(驱动间通信)。

### 5.3 驱动加载 [1000889/1000890]

## 7. Rootkit 与 Bootkit [1000861/1000860]

### 7.1 Rootkit 技术 [1000861]

目标:驻留+隐藏(文件/进程/网络/注册表/驱动自身)。知识库「Rootkit 的学习与研究 [1000863]」九节即经典学习路径:
1. 内核 hook(SSDT/IRP);2. Ring3→Ring0 之门(调用门/漏洞提权);3. Windows 分页机制(PDE/PTE,直接改页属性藏代码);4. 直接访问硬件(绕 OS);5. detour 修改函数执行路径;6. 隐身术(DKOM——直接内核对象操纵:把 EPROCESS 从 ActiveProcessLinks 摘链隐藏进程);7. Ring0 调 Ring3(APC 注入用户负载);8. 进程线程监控(PSNotify 回调);9. 其他。

- **DKOM 隐藏进程**:遍历 `PsActiveProcessHead` 链表,目标 EPROCESS 的 `ActiveProcessLinks` BLINK/FLINK 自链摘除——任务管理器/内核枚举全瞎;检测:交叉比对(线程数/句柄表/CSRSS)。
- **BIOS Rootkit [1000862]**:写 SPI Flash/EFI 变量持久化,先于 OS 启动(现代 SecureBoot/CapsuleUpdate 对抗)。
- 隐藏技术 [1000874]:文件过滤隐藏(§10.2)、端口隐藏(netstat 挂 TDI/_INDICATE)。

### 7.2 Bootkit [1000860]

改 MBR/VBR 引导链,在 OS 前接管执行:MBR 改写(TDL4/Gapz 思路)→ Bootmgr 校验绕过(早期)/UEFI Bootkit(LoJax 思路)→ 无驱动文件加载内核态代码。与 Rootkit 的分界:Bootkit 负责起跳(Ring-1/引导期),Rootkit 负责落地后隐身。

## 8. 优化技术 [1000859]

逆向侧相关:体积优化(shellcode 压缩、指令最短化)、执行优化(inline 汇编热点)、混淆与优化的边界——优化的代码最难读(O2 内联+循环展开)。

## 9. 主动防御技术 [1000876]

HIPS 视角双面:

## 10. 内核对象处理四件套

### 10.1 进程处理 [1000897]
保护:句柄权限 stripping(`ObRegisterCallbacks` 剥 PROCESS_VM_WRITE/TERMINATE)、EPROCESS 标志;隐藏 [1001457]:DKOM(§7.1)、线程挂靠遍历。
### 10.2 文件处理 [1000900]
文件过滤 [1000902]:**minifilter**(FltRegisterFilter,IRP_MJ_CREATE/READ 前后回调)是现代标准;老 sfilter/IFS 路线已淘汰但思想一致;文件删除 [1000901]:强制删(重命名+重启删 `MoveFileEx MOVEFILE_DELAY_UNTIL_REBOOT`)、占用解除(枚举句柄 DuplicateHandle 关闭)。
### 10.3 注册表处理 [1000904]
`CmRegisterCallbackEx` 监控/过滤注册表操作——COM 劫持类持久化的检测位。
### 10.4 网络层处理 [1000905]
TDI(旧)→ **WFP**(Win Vista+ 标准过滤平台,callout 驱动拦 connect/recv)→ NDIS(网卡层,最底层);抓包 hook `NdisSend`、防火墙类软件内核栈。

## 11. 应用开发 [1000879]

## 13. Windows 恶意软件开发基础(横向小结)

以上技术的恶意组合套路(防御视角同步):
1. **投递**:漏洞文档/宏(VBA)→ PowerShell 无文件落地;
2. **驻留**:服务/计划任务/注册表 Run/COM 劫持/WMI 事件订阅;
3. **注入**:自注入或迁 explorer.exe/svchost.exe 等可信进程(§3);
4. **隐藏**:Rootkit/Bootkit(§7)、进程空洞换皮;
5. **C2**:自定义协议 over HTTP/DNS,IOCP 服务端;
6. **横向**:凭据 dump(mimikatz 类:LSASS 进程注入+minidump)。
对抗基线:ETW+内核回调+内存扫描+签名强制;对应知识库第9篇病毒木马篇(另有专题)。

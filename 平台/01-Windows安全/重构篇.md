# 重构篇(第6篇 重构篇 1000732)

> 定位:逆向工程的"再加工"——不改需求、改行为:补丁(文件/内存/SMC/DLL劫持/Inline)与二次开发(给别人的程序加功能)。知识主线:每个手法 = 理论基础 → 机制(落在哪些系统机制上) → 实例 → 反向对抗(软件方如何防)。

## 1. 文件补丁(节点 1000734)

- **原理**:定位文件中关键字节(jz→jmp、比较数、跳转目标),直接改写,重算 PE 校验和(如有)。
- **定位法**:① 地址法(版本强绑定);② **特征码搜索法**:取指令上下文若干通配字节(如 `74 1A 68 ?? ?? ?? ?? E8` )跨版本"通杀";③ 字符串/常量引用回溯。
- **形态**:单文件补丁器(读→匹配→写→备份)、多语言/多版本补丁配置(KeyMake、PatchMaker 类"补丁制作"工具,基础知识节点 1000735)。
- **反制(软件方)**:文件完整性校验 CRC(见保护篇 §5.2)、数字签名、启动时自我还原(从资源里回写)——因此衍生出内存补丁(§2)。
- 实例:知识库 1000736 汇聚各软件文件补丁实战帖;《如何编写文件补丁》、《详解定位特征码方法》、《用特征码定位按钮事件》、《特征码便捷搜索工具》、《写文件补丁和内存补丁LPK》、《超简单的特征码搜索算法以及DEMO》、《内存特征码搜索_Boyer-Moore思想实现》。

## 2. 内存补丁(节点 1000738,本篇核心)

### 2.1 内存存取机制(节点 1000739)

```
补丁进程                          目标进程
OpenProcess(PROCESS_VM_WRITE|VM_OPERATION|VM_READ, pid)
WriteProcessMemory(hProc, VA, newBytes, len)   ──►  目标 VA 生效
(可选) CreateRemoteThread 远程调 Call/恢复
```
- 前提:拿到目标 VA(模块基址+RVA;ASLR 下用 CreateToolhelp32Snapshot/Module32First 拿运行基址)。
- 短板:时机难控(写早了被初始化覆盖)、跨权限(UAC/服务进程)、自校验会抓到字节变化。
- 这也是"补丁工具"(如早期内存补丁器/UDP)的底层;老帖《如何破解内存补丁数据内容》《关于内存补丁的讨论》讨论了对抗与抓取。

### 2.2 Debug API 机制(节点 1000741)——"迷你调试器"式补丁

```
CreateProcess(DEBUG_ONLY_THIS_PROCESS) / DebugActiveProcess
循环 WaitForDebugEvent:
  CREATE_PROCESS_DEBUG_EVENT → 从 lpImageName/文件头算基址
  EXE/LOAD_DLL 事件        → 记录模块基址表
  断在目标时机(入口断点/EXCEPTION_BREAKPOINT)
     WriteProcessMemory 打补丁
     ContinueDebugEvent(DBG_CONTINUE)
```
- 价值:时机可控(等壳解密完、等 DLL 加载完);不落盘;天然与"断点计数/条件"结合。
- 系统底座:调试事件靠 DebugObject 传递(见系统篇/保护篇调试体系),`EXCEPTION_DEBUG_EVENT`、`OUTPUT_DEBUG_STRING_EVENT` 都可当同步点。
- 成品参照:各种"调试器框架补丁器"(x64dbg 脚本本质同构)。

### 2.3 调试寄存器机制(节点 1000742)——硬件断点补丁(对付自校验的杀器)

```
DR0~DR3:断点线性地址   DR6:状态(哪条命中)   DR7:使能/长度(b00-b03,LEN,RW)/类型
命中 → 处理器抛 #DB → EXCEPTION_SINGLE_STEP 到调试器(或程序 SEH/VEH)
```
- **DRx 补丁流程**(一次执行,零字节修改):
```
1. 设 DR0=目标VA, DR7 使能 RW=00(执行) LEN=1
2. 命中执行断点(指令尚未执行)
3. 保存原指令 → 临时写入补丁指令
4. 清 DR0 使能,置 EFLAGS.TF 单步
5. 单步执行完补丁指令 → 恢复原指令、重设 DR0
   (循环往复:每次执行到该处都换装补丁)
```
- 优点:**原代码字节始终不变**,CRC/自校验失效;无限多个"逻辑补丁点";权限要求低(仅需 SetThreadContext)。
- 限制:每线程仅 4 个 DRx(实际 3 个可用,DR7 校验/DR3 备用策略),多线程要对每线程设上下文;程序可检测 DRx(保护篇 §1.2)。
- 代表帖:调试寄存器原理与使用 DR0-DR7;成品工具 Baymax Patch Tools v2.1——"硬件断点优先,占满 3 个降级 INT3"的补丁器(帖内注明修复了 DRx 超 3 崩溃 bug)。

### 2.4 Frida 补丁(节点 1001743,现代形态)

- `Memory.patchCode(addr, size, cb)`(自动处理只读代码页 mprotect+缓存刷新 icache)、`Interceptor.attach/replace` 逻辑级补丁、`Module.findBaseAddress` 对付 ASLR;
- JS 脚本热加载,等价"运行时补丁语言",跨 Windows/macOS/Linux;反制也变成 Frida 检测(端口/线程名 gum-js-loop、map 里的 frida-agent)。
- 与 §2.1-2.3 的关系:Frida 在目标进程内做 gum 层修改,不依赖外部 OpenProcess 权限,但注入本身可被防。

## 3. SMC 补丁(节点 1000744)——对付加壳程序

- **问题**:直接文件补丁改的是密文,运行解密后你的修改消失;直接内存补丁写早了,解密覆盖你的字节。
- **思路 A(时机法)**:等壳解压解密完成(OEP 断点,见保护篇 §6.2)再打内存补丁 → 本质=§2.2/2.3 的时机特例;配套把补丁逻辑做成"补丁加载器"(Loader 起目标进程+等待+写入)。
- **思路 B(自修改注入)**:把补丁逻辑编译成一段 SMC 代码注入目标(代码洞/新增节),由目标进程自己在解密后执行替换。
- 知识库实例节点(1000746-1000753):**UPX / ASPack / ASProtect / PECompact / 幻影 / MoleBox** 各壳的 SMC 补丁实战——共同骨架:断壳尾事件(如 `VirtualProtect` 回调/OEP)→ dump 校验 → 回填补丁;ASProtect 还要过 stolen code 与 IAT 代理,MoleBox(多文件打包)需先释放资源再补。
- 检索:《smc教程》、《一个SMC补丁》、《几个SMC代码》、《SMC破解DLL时基址的问题》、《upx脱壳及附加数据处理》。

## 4. DLL 劫持技术(节点 1000754)

- **理论基础**(1000755)——加载器搜索顺序(系统篇 §6.3):

```
应用目录 → 系统目录 System32 → 16位系统目录 → Windows 目录 → 当前目录 → %PATH%
(KnownDLLs 清单内的 DLL 直接按已知路径映射,不参与搜索劫持)
```
- **手法三型**:
  1. **缺失 DLL 型**:绿色/老程序引用了系统不存在的 DLL(或版本清单未声明),把同名恶意 DLL 丢应用目录即被加载——补丁/注入的入口;
  2. **代理 DLL 型**:重命名真 DLL,劫持 DLL 转发所有导出(裸 jmp 到真 DLL)+ 入口(DllMain)插自己的补丁/钩子代码——`#pragma comment(linker, "/export:foo=real.foo")` 或 `.def` 别名;
  3. **加载顺序型**:应用目录放同名字 DLL(需目标不在 KnownDLLs、无 SxS manifest 强绑定)。
- **应用**:内存补丁载体(见帖《如何对dll文件打内存补丁》——正是 LPK 劫持在 DllMain 里写内存补丁)、反调试注入、功能扩展(§6)。
- **防御视角**(软件方):manifest/`AddDllDirectory` 显式全路径加载、KnownDLLs、签名校验——所以新软件越来越难劫持,老软件/工控/内网仍是主场。
- x64 注意:劫持 DLL 位数必须与目标一致;WOW64 下 System32/SysWOW64 目录镜像坑。

## 5. InLine Patching(节点 1000757)

- **理论基础**(1000758):在目标函数头部/热点路径写 `jmp rel32`(5 字节)改道到自己的函数(或直接内联改逻辑),与 Inline Hook 同构——区别是 Hook 强调"截获转发",Inline Patch 强调"就地永久改行为"。
- 与文件补丁的区别:改的是内存镜像(可等解密后),不必落盘;与 IAT Patch 的区别:IAT 只拦"经导入表的调用",Inline 拦所有路径(GetProcAddress 动态取的也拦)。
- **实例应用**(1000759):改 API 行为(如让 `CreateFile` 对特定名永远成功)、破解网络验证客户端(改 `send/recv` 处理)、配合代码洞放补丁函数。
- 反制:完整性校验+反内存校验 → 用 §2.3 DRx 法免字节修改。

## 6. 二次开发(节点 1000760)——重构的正统形态:给程序加功能

### 6.1 理论底座(pediy 教学,节点 1000763)

逆向者给第三方程序"加料"的工程体系——不改原代码逻辑,在旁路加自己的空间与入口。

### 6.2 增加代码空间(节点 1000764)

- **代码洞 code cave**:PE 各节对齐产生的尾部缝隙(`.text` 末尾 0x00 填充区)找一段放代码;
- **新增节**:文件尾加 section(改 NumberOfSections/SizeOfImage,对齐 FileAlignment/SectionAlignment),空间充裕,首选;
- 对齐、文件偏移↔RVA 换算是基本功(系统篇 PE 加载)。

### 6.3 函数调用与自定位(节点 1000765/1000769)

- 新代码调用系统 API:不能依赖原 IAT——运行时动态解析:**代码自定位**(`call $+5/pop eax` 取 EIP)→ 从 PEB->Ldr 找 kernel32 基址 → 遍历导出表按名/hash 取地址(与保护篇"API 自实现"同源,一攻一用);
- 重定位(节点 1000768):新增节里若有绝对地址,随 ASLR 需要自重定位或纯 RIP/相对寻址(x64 天然 rip-relative 友好)。

### 6.4 消息循环与增加接口/按钮(节点 1000767/1000766/1000770)

- **Win32**(1000771):找目标窗口过程(系统篇 §5 消息机制)→ hook/子类化(subclass)WndProc 拦新菜单命令;或 `CreateWindowEx` 在其窗口加按钮 + `InsertMenuItem` 加菜单,靠拦截 `WM_COMMAND` 响应;
- **Delphi**(1000772):运行时用 VCL(TForm.FindComponent/动态 Create)注入控件与事件——Delphi RTTI 丰富,二开最容易;
- **MFC**(1000773):消息映射表 ON_COMMAND 追加/改资源脚本加菜单。
- 增加接口(1000766):给目标加导出函数/IPC 端点,让外部脚本驱动目标。

### 6.5 注入入口(配合编程篇注入节点)

DLL 劫持(§4)二开型:代理 DLL 的 DllMain 里 CreateThread 起自己的功能线程——与补丁型劫持同一机制、不同 payload。

### 6.6~6.7 流程(略表)

定位资源/字符串表 → 改图标文案(汉化交叉)→ 加保存/导出/自动化功能。

### 6.8 功能增强经典实例(节点 100074-100096 体系,1000774)

- **Windows 自带程序**(1000775):**扫雷**(1000776,读棋盘矩阵+自动标雷,入门第一课)、**记事本**(1000777,加标签页/去字数限制)、**计算器**(1000778,按键自动化/精度魔改)、**任务管理器**(1000779,显示隐藏进程/路径列——顺带就是"检测隐藏进程"的正向利用)、**注册表编辑器增强**(1000780,收藏/权限页);
- **QQ**(1000782,去广告/多开/消息钩子)、**微信**(1001366)、**企业微信**(1001423)、豪杰解霸(1000781,老帖经典)、其他应用程序(1000783)。
- 共性套路:定位 UI 框架 → 消息/控件注入(§6.4)→ 反制点(完整性、反注入)。

### 6.9 功能的移植和提取(节点 1000784)

从 A 程序"抠"出算法/模块用到 B:静态重定位提取(带走依赖的表)、或 DLL 化包装(把 exe 的导出函数包成 DLL,见 loaddll 思路,调试篇节点)。提取注册算法做注册机、提取解码器做通用播放器皆此流。

# Windows 漏洞挖掘工具链搭建（AI 自动执行手册）

> 架构：**目标机 = Windows 10/11 虚机**（VMware Fusion / Parallels / Hyper-V 皆可，建议 VMware：串口/网络调试配置最顺）；**本机 macOS 只做编排与静态分析**（Ghidra/radare2/符号下载），一切动态（WinDbg 内核调试、x64dbg、fuzz）都在虚机内跑。
> AI 读本手册后应**自动完成目标机全部安装与验证**，无需人工；失败按降级路径走，最后按 §7 自检输出表格。
> 地址核对日期：2026-10-16。所有「版本」均以对应 releases 页为准，本文写的是当日核对值。

## 0. 执行纪律

- 逐节做，每节**先检测再安装**（已装跳过）；单命令超时 5 分钟；全程记录到 `工具链报告-<日期>.md`
- 目标机一律用**管理员 PowerShell**（`Win+X → 终端(管理员)`）；包管理顺序：winget → scoop（`irm get.scoop.sh | iex`）→ GitHub releases 手动 zip 解压到 `C:\tools\` 并加 PATH
- 需重启的步骤（§1.2 bcdedit、VS Build Tools 装完）统一**攒到最后一次重启**，重启后继续跑 §7 自检
- 虚机快照纪律：装任何内核相关组件（驱动调试、测试签名模式）前先打 VMware 快照，回滚成本为零

## 1. 基础环境（PowerShell 自动化，winget 优先）

### 1.1 winget 基线

```powershell
winget --version          # Win10 21H1+ / Win11 自带；无则装 App Installer:
# winget 来源 Microsoft Store「应用安装程序」，或 https://github.com/microsoft/winget-cli/releases
winget source update
winget install --id Microsoft.WinDbg -e --accept-source-agreements --accept-package-agreements
```

- WinDbg Preview（新版 WinDbg，商店版）：包 id `Microsoft.WinDbg`（当日核对存在，manifest 最新 1.2610.1001.0；winget 装的就是商店版 WinDbg，含 TTD/时间旅行调试）
- 老式 `windbg.exe`（经典版）随 Windows SDK 调试器目录分发，本手册不依赖它，可跳过

### 1.2 双机内核调试配置（VM 内目标机 + 第二台 Windows 当主机）

调内核必须有「主机侧 WinDbg」。macOS 跑不了 WinDbg，所以：

- **方案 A（推荐）**：VMware 里**两台虚机**——`win-target`（被调）+ `win-host`（调试器），放同一 host-only/vmnet 网络，`win-host` 也装 `Microsoft.WinDbg`
- **方案 B（轻量替代）**：单机本地内核模式 `windbgx -kl`（能看内核内存/驱动列表，不能下断点），适合快速看池/对象，不适合挖驱动洞
- **方案 C**：VMware 串口管道直连宿主进程，仅当网络调试不通时用（见下方串口配置）

目标机（`win-target`，管理员 CMD/PS）——**网络内核调试（推荐，快）**：

```bat
bcdedit /debug on
:: hostip = win-host 的 IP；key 可省略让系统自动生成，之后用 bcdedit /dbgsettings 查
bcdedit /dbgsettings net hostip:192.168.x.x port:50000 key:1.2.3.4.5.6.7.8.9.0.1.2.3.4.5
bcdedit /enum              :: 记下自动生成的 key（若上面没指定）
shutdown /r /t 0           :: ← 需重启才生效
```

主机侧（`win-host`）连接语法：

```powershell
# GUI: File → Attach to kernel → NET → 填 port=50000 与目标机 key
# 命令行：
windbgx -k net:port=50000,key=1.2.3.4.5.6.7.8.9.0.1.2.3.4.5 -y srv*C:\Symbols*https://msdl.microsoft.com/download/symbols -loga c:\kd.log
```

VMware 串口方案（方案 C）：VM 设置 → 串行端口 → 使用命名管道 `\\.\pipe\com_1`，「此端是服务器/另一端是应用程序」；目标机 `bcdedit /dbgsettings serial debugport:1 baudrate:115200`；主机侧 `windbgx -k com:pipe,port=\\.\pipe\com_1,baud=115200,pipe,reconnect`（管道建在跑 WinDbg 的那台虚机/系统上）。

### 1.3 符号服务器（系统级，一次配好）

```powershell
New-Item -ItemType Directory -Force -Path C:\Symbols | Out-Null
[Environment]::SetEnvironmentVariable('_NT_SYMBOL_PATH',
```

## 3. Fuzz 环境

### 3.1 WinAFL（用户态覆盖引导主力）

仓库：https://github.com/googleprojectzero/winafl ；依赖 **DynamoRIO**（插桩后端）：https://github.com/DynamoRIO/dynamorio/releases （滚动 cronbuild，当日 11.91.20735，文件形如 `DynamoRIO-Windows-11.91.x.zip`，**以 releases 页为准**；下 Windows x64 + x86 两个 zip 各解一份）。

构建（VS 开发者命令行，需 §1.4 的 Build Tools + CMake；官方 readme 以 VS2019 生成器为例，VS2022 生成器 `"Visual Studio 17 2022"` 同样可用）：

```bat
git clone https://github.com/googleprojectzero/winafl C:\tools\winafl
cd C:\tools\winafl
:: 32 位（32 位目标必需; 64 位换 build64 + -A x64 + bin64）
mkdir build32 && cd build32
cmake -G "Visual Studio 16 2019" -A Win32 .. -DDynamoRIO_DIR=C:\tools\DynamoRIO\cmake
cmake --build . --config Release
:: 可加速项: -DTINYINST=1（TinyInst 后端）; -DINTELPT=1（Intel PT 模式，先 git submodule update --init --recursive）
```

跑通官方示例（源码自带测试目标 `test.exe`，导出被调函数 `fuzz`，两种输入参数）：

```bat
cd C:\tools\winafl\build32\bin\Release
mkdir in && echo hello > in\test.txt
afl-fuzz.exe -i in -o out -t 20000 -D C:\tools\DynamoRIO\bin32 ^
  -- -coverage_module test.exe -target_module test.exe -target_method fuzz -nargs 2 -fuzz_iterations 1000 ^
  -- test.exe @@
:: 10 分钟内 coverage path 数在涨、无 DLL 注入报错 = 跑通
```

要点：**目标位数必须匹配 winafl.dll 位数**（64 位程序用 build64 + bin64）；语料最小化 `winafl-cmin.py -D C:\tools\DynamoRIO\bin32 -t 100000 -i in -o minset -covtype edge -coverage_module m.dll -target_module test.exe -target_method fuzz -nargs 2 -- test.exe @@`；DLL 目标（如图片解码库、LMDB 类嵌入式库）用 `-target_module <dll> -target_method <导出函数>`，先写个宿主 exe 加载 DLL 再把方法挂进去。

### 3.2 kAFL（Intel PT 内核快照 fuzz——高门槛，标注后再决定投入）

- 仓库：https://github.com/IntelLabs/kAFL （**2026 年已归档停维护**，Phoronix 报道 Intel 已结束投入；纯研究向）
- 门槛（全中才玩）：**Linux 裸机宿主**（Ubuntu 20.04+/Debian，需打补丁内核、重启生效）+ **Intel CPU Skylake 及以后**（要 Intel PT + PML + VT-x，AMD 不行）+ QEMU/KVM + 每 vCPU ~2GB。**macOS 与 Windows 宿主均不可用**；要玩需单独 Linux 裸机或 IceLake+ 嵌套虚拟化（不保证）
- 「rgpd」这一 kAFL 衍生名 2026-10 联网已查不到可核实仓库，**别按旧文部署**。现役替代思路：0dayResearchLab/msFuzz（Intel PT 覆盖引导驱动 fuzz）、google/syzkaller（官方支持 Windows 目标 syscall/driver 面：https://github.com/google/syzkaller ）
- 结论：常规 Windows 内核挖洞按 §3.3 IOCTL fuzz + 静态审 IOCTL handler 走，kAFL 仅在专攻内核面且硬件达标时投入

### 3.3 IOCTL fuzz（内核驱动面主力，现役开源选型）

- **koutto/ioctlbf**：https://github.com/koutto/ioctlbf —— 现役小工具，扫驱动合法 IOCTL 码（`-d` 设备名探测 IOCTL range）再逐个 fuzz，适合第三方驱动快速过面；老版基于 antinucleus 思路，编译需 VS
- 经典 **ioctlfuzzer**（Google Code 已归档，只作思路参考）：拦截 DeviceIoControl 记录合法 IRP 再重放变异
- 微软官方 **IoSpy/IoAttack**（WDK 自带，需测试签名）：https://learn.microsoft.com/en-us/windows-hardware/drivers/devtest/iospy-and-ioattack
- 定制思路（AI 可自动写）：静态（Ghidra headless 找 `IRP_MJ_DEVICE_CONTROL` handler 里的 `METHOD_NEITHER/INLINE` 分支 + CTL_CODE 宏还原）→ 用户态 C 小 harness 用 `DeviceIoControl` 发变异 buffer，配内核调试器看崩；对 METHOD_NEITHER/缓冲区长度未校验类命中率高
- 辅助：先跑 `driverquery /v` + `pnputil /enum-drivers` 列攻击面，非微软签名驱动优先

### 3.4 honggfuzz（Windows 支持标注）

- https://github.com/google/honggfuzz ；Windows 支持经 **Cygwin/MinGW 编译**，最后正式版 **v2.6**（之后 master 滚动更新，以仓库为准）；Windows 侧无 perf 硬件覆盖，反馈能力弱于 Linux/mac
- 实战定位：Windows 上有 WinAFL（§3.1）覆盖引导已够用；honggfuzz 仅当目标程序在 WinAFL 插桩不稳（强反调试/DynamoRIO 冲突）时做备选；VLC PE 目标实战案例可参考（pentestpartners 博客，双洞案例）
- macOS 侧可直接 `brew install honggfuzz`，但那是给 mac 目标用的，与虚机无关

## 5. setup.ps1 一键脚本（骨架，存为 `C:\tools\setup.ps1` 管理员执行）

```powershell
# Windows 漏洞挖掘工具链一键安装 · 2026-10-16 · 需管理员 PowerShell
# 用法: powershell -ExecutionPolicy Bypass -File setup.ps1
$ErrorActionPreference = 'Continue'
$results = @()
function Step($name, $check, $install) {
    if (& $check) { $script:results += [pscustomobject]@{Item=$name;Status='已装'}; return }
    try { & $install
        if (& $check) { $script:results += [pscustomobject]@{Item=$name;Status='新装'} }
        else          { $script:results += [pscustomobject]@{Item=$name;Status='装后检测失败'} } }
    catch { $script:results += [pscustomobject]@{Item=$name;Status="失败:$($_.Exception.Message)"} }
}
# 0) 前提: winget + 管理员
if (-not (Get-Command winget -EA SilentlyContinue)) { Write-Error '无 winget: 装 App Installer(商店) 后重跑'; exit 1 }
if (-not ([Security.Principal.WindowsPrincipal][Security.Principal.WindowsIdentity]::GetCurrent()
      ).IsInRole('Administrators')) { Write-Error '需管理员 PowerShell'; exit 1 }
# 1) 基础(全走 winget; 版本以 winget 源为准)
$pkgs = @(
  @{n='WinDbg';      id='Microsoft.WinDbg'},
  @{n='Python3.12';  id='Python.Python.3.12'},
  @{n='git';         id='Git.Git'},
  @{n='7zip';        id='7zip.7zip'},
  @{n='CMake';       id='Kitware.CMake'},
  @{n='radare2';     id='radare2.radare2'},
  @{n='x64dbg';      id='x64dbg.x64dbg'},
  @{n='Sysinternals';id='Microsoft.Sysinternals'},
  @{n='JDK25(Temurin)';id='EclipseAdoptium.Temurin.25.JDK'} )   # id 不确定时先 winget search temurin
foreach ($p in $pkgs) {
  Step $p.n { winget list --id $p.id -e | Select-String $p.id } `
       { winget install --id $p.id -e --silent --accept-source-agreements --accept-package-agreements }
}
# 2) 符号路径(系统级)
New-Item -ItemType Directory -Force -Path C:\Symbols | Out-Null
[Environment]::SetEnvironmentVariable('_NT_SYMBOL_PATH',
  'srv*C:\Symbols*https://msdl.microsoft.com/download/symbols','Machine')
$results += [pscustomobject]@{Item='_NT_SYMBOL_PATH';Status=[Environment]::GetEnvironmentVariable('_NT_SYMBOL_PATH','Machine')}
# 3) VS Build Tools(winafl 前置; 大, 装完建议重启)
Step 'VS2022BuildTools' { winget list Microsoft.VisualStudio.2022.BuildTools | Select-String BuildTools } `
  { winget install Microsoft.VisualStudio.2022.BuildTools --silent --override
    "--add Microsoft.VisualStudio.Workload.VCTools --includeRecommended" }
# 4) Ghidra zip(github releases, 版本取 latest)
$rel = Invoke-RestMethod 'https://api.github.com/repos/NationalSecurityAgency/ghidra/releases/latest'
$zip = $rel.assets | Where-Object name -Match '\.zip$' | Select-Object -First 1
Step 'Ghidra' { Test-Path C:\tools\ghidra\ghidraRun.bat } {
  New-Item -ItemType Directory -Force -Path C:\tools | Out-Null
  Invoke-WebRequest $zip.browser_download_url -OutFile "$env:TEMP\ghidra.zip"
  7z x "$env:TEMP\ghidra.zip" -oC:\tools | Out-Null
  Rename-Item (Get-ChildItem C:\tools -Directory -Filter 'ghidra_*' | Select-Object -First 1).FullName C:\tools\ghidra }
# 5) DynamoRIO + winafl 源码(编译仍需手动开 VS 命令行, 见手册 §3.1)
Step 'winafl-src' { Test-Path C:\tools\winafl } { git clone https://github.com/googleprojectzero/winafl C:\tools\winafl }
$dr = (Invoke-RestMethod 'https://api.github.com/repos/DynamoRIO/dynamorio/releases/latest').assets |
      Where-Object name -Match 'Windows.*x86_64|Windows-.*64' | Select-Object -First 1
if ($dr) { Invoke-WebRequest $dr.browser_download_url -OutFile "$env:TEMP\drio.zip"
           7z x "$env:TEMP\drio.zip" -oC:\tools | Out-Null }   # 解压目录名即版本号, 记录到报告
# 6) 汇总(需要 reboot / 手动的项在这里标出)
$results += [pscustomobject]@{Item='bcdedit内核调试';Status='手动: 见 §1.2, 配完需重启'}
$results += [pscustomobject]@{Item='winafl编译';      Status='手动: VS开发者命令行 cmake, 见 §3.1'}
$results | Format-Table -AutoSize
$results | Export-Csv C:\tools\setup-report.csv -NoTypeInformation
Write-Host "`n== 装完先重启一次(BuildTools/bcdedit), 再按手册 §7 自检 =="
```

## 6. macOS 本机侧说明

**能做（不用虚机）**：
- Ghidra 静态：手动 zip 装（§2.1；brew 无 cask，实测确认），headless 批量反编译驱动/内核模块，产出伪 C 与调用图
- radare2：`brew install radare2`，配合 Ghidra 互补
- **PDB 符号下载（替代 symchk）**：macOS 无 symchk，直接按 msdl URL 规律取——`https://msdl.microsoft.com/download/symbols/{PDB名}/{GUID去连字符大写+AGE十六进制}/{PDB名}`。GUID/AGE 从 PE 的 debug 目录（CodeView RSDS 记录）解析：

```python
import pefile, re, sys, urllib.request
pe = pefile.PE(sys.argv[1], fast_load=True)
pe.parse_data_directories([pefile.DIRECTORY_ENTRY['IMAGE_DIRECTORY_ENTRY_DEBUG']])
for d in pe.DIRECTORY_ENTRY_DEBUG:
    data = pe.get_data(d.struct.AddressOfRawData, d.struct.SizeOfData)
    if data[:4] == b'RSDS':
        pdb = data[24:].split(b'\x00')[0].decode()
        guid = data[4:20]; age = int.from_bytes(data[20:24],'little')
        g = ''.join(f'{b:02X}' for b in guid[:4][::-1]) + ''.join(f'{b:02X}' for b in guid[4:6][::-1]) \
            + ''.join(f'{b:02X}' for b in guid[6:8][::-1]) + ''.join(f'{b:02X}' for b in guid[8:])
        url = f'https://msdl.microsoft.com/download/symbols/{pdb}/{g}{age:X}/{pdb}'
        print(url); urllib.request.urlretrieve(url, pdb)   # 装好可进 Ghidra 的 PDB 符号路径
```

- 覆盖引导 fuzz 源码审（读 winafl/syzkaller 源码）、报告写作、AI 编排（虚机里的一切由主线程下发命令执行）

**不能做（必须 Windows 虚机）**：WinDbg 内核/用户调试、x64dbg、WinAFL/DynamoRIO 实跑、ProcMon、PoolMon、驱动加载与蓝屏复现。macOS（arm64）上更不可能跑 x86 Windows 二进制。编排方式：主线程通过 VMware 虚机的共享目录（`\\vmware-host\Shared Folders\`）或 `scp`/ssh（虚机开 OpenSSH：`Add-WindowsCapability -Online -Name OpenSSH.Server`）下发脚本与回收 crash dump。

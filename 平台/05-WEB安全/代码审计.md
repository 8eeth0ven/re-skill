## 1. 白盒审计方法论:入口 → sink → 污点

### 1.1 三段模型(自绘)

```
[source 入口]  ──传播(propagation)──▶  [净化器 sanitizer?]  ──▶  [sink 危险点]
 request.getParam      赋值/拼接/容器           escapeSql/参数绑定         Runtime.exec
 getHeader/Cookie      方法间传递               白名单校验                OGNL/SpEL/MVEL
 JSON/XML body         反射/反序列化            (断链=安全)               SQL拼接/JNDI lookup
 文件上传名/内容                                                          模板render/文件写
```

- **入口定位**:WEB 容器映射(web.xml 的 servlet/filter/struts.xml)→ 注解路由(Spring `@RequestMapping`)→ 框架拦截器链;入口集合=攻击面清单。
- **污点传播**:变量跨方法/跨类传递,审计工具(CodeQL/Tabby/fortify)做自动化;人工审计靠 IDE 调用链回溯(IntelliJ Analyze Dataflow)。
- **净化器判定**:参数绑定(PreparedStatement)断链;`StringEscapeUtils` 只对对应上下文有效;白名单强于黑名单;常见假净化(只 strip 引号、只 URL decode 一次)是绕过点。
- 流程/报告/判定标准正本 → `~/.zcode/skills/secure-code-audit/知识库/审计流程与报告.md`;sink 全表 → `sink速查-Java.md` / `sink速查-PHP.md` / `sink速查-Go-Node.md`。

### 1.2 审计切入顺序(经验优先级)

1. 依赖清单( pom.xml/composer.json/requirements.txt )打已知 CVE(1day 密度最高)— snyk/dependency-check。
2. 全局搜 sink(反序列化/模板/命令/反射)再回溯 source。
3. 鉴权链(filter/interceptor/中间件)找白名单路径遗漏 → 未授权面。
4. 配置文件(application.yml/production 密钥)。
5. 业务流对照(订单/支付/找回)→ 逻辑洞,归 `../08-业务安全/业务安全.md`。

## 2. PHP 审计(ThinkPHP / Laravel)

### 2.1 框架洞模式

- **ThinkPHP 3.x**:`preg_replace /e` 执行、`assign` 变量覆盖、I 函数 filter 注入、where 注入。
- **ThinkPHP 5.x** 经典 RCE:5.0.x 核心 `invokeFunction`(cache 文件名/语言包路由触发,2018-12 漏洞爆发);5.0.23 captcha 路由 RCE;模式=框架反射调用用户输入进方法名/参数。
- **Laravel**:`.env` 泄露 APP_KEY → 老版本 X-CSRF-TOKEN 签名反序列化 RCE(CVE-2018-15133);Ignition 组件 RCE(CVE-2021-3129,log 文件 phar/file 双写);debug 页(Debug=True)信息泄露。
- **CMS 系**:DedeCMS 变量覆盖系列、phpunit CVE-2017-9841(eval-stdin)。

### 2.2 PHP 通用 sink 与 POP 链构造法

- 高危函数速记(参数可控即致命):`eval/assert/preg_replace(/e)/call_user_func/array_map($cb)` / `system/exec/shell_exec/passthru/popen/backtick` / `include/require(+URL 含数据流)` / `unserialize/phar://`。
- POP 链挖掘法(反向构图):全局搜魔术方法 `__destruct/__wakeup`(入口触发)→ 派生类里找 `__toString/__call/__get`(中继)→ 终点 `eval`/`call_user_func`/文件写。工具:PHPStan+自写规则、phpggc(现成链库:Laravel/Monolog/Smarty/Guzzle)。
- phar 反序列化:`file_exists/unlink/file_get_contents` 等文件函数接受 `phar://` 流时触发元数据反序列化 — 绕过「没有 unserialize 点」的死局。
- 特性坑:`==` 松散比较(MD5 0e 开头科学计数法绕过)、`in_array` 松散模式、intval 截断、`$_REQUEST` 优先级、开启 `register_argc_argv` 的 CLI 入口。

## 4. Java 生态审计(重点深挖)

### 4.1 反序列化全景(自绘)

```
入口: ObjectInputStream.readObject / JSON.parseObject(autoType) /
      XMLDecoder / Shiro rememberMe AES(CBC)解密后readObject / RMI·JNDI
        │
        ▼  [gadget 链]
 URLDNS: HashMap→hashCode→URL.hashCode→DNS查询(无害探测,判反序列化点存活)
 CC1: LazyMap→AnnotationInvocationHandler.invoke→ChainedTransformer→InvokerTransformer
      (依赖 JDK≤8u71 前 AnnotationInvocationHandler 实现)
 CC3: TrAXFilter+TemplatesImpl 避开 Runtime 特征(加载字节码)
 CC6: TiedMapEntry→LazyMap(HashSet 路径,不挑 JDK 版本,实战首选)
 CB:  Commons-Beanutils 依赖链(Shiro 环境自带,配合无依赖回显)
        │
        ▼  [终点 sink]
 Runtime.exec / TemplatesImpl 字节码加载 / JNDI lookup→LDAP/RMI 远程类加载
```

- URLDNS/CC1:CC1 全链笔记(ConstantTransformer 固定返回→ChainedTransformer 链式传递→InvokerTransformer 反射调用;LazyMap 触发面);CC3/CC6 属同系列进阶,JSON 反序列化系列覆盖;URLDNS 作为无依赖探测链散见各复现帖。通用正本:`~/.zcode/skills/skill/知识库/deserialization-gadgets.md` + `deserialization-test.md`。
- 利用链终点转 JNDI → `jndi-injection-test.md`(JNDIExploit/LDAP 返回体分流)。

### 4.3 Fastjson 演进线(社区实证)

- 1.2.24:autoType 默认开,`@type` 任意类加载→JNDI(经典 JdbcRowSetImpl)。
- 1.2.25-1.2.47:开 checkAutoType 黑白名单;1.2.47 利用 `java.lang.Class` 缓存绕过(**不需要 autoType 开启**,危害最大一波)。
- 1.2.48:修缓存绕过。
- 1.2.68:引入 expectClass 期望类机制又开新面(safeMode 未开时)。
- 1.2.80:expectClass 判断缺陷(Throwable 子类链)。
- 1.2.83+ / fastjson2:autoType 收敛,safeMode 全局禁。
- 审计动作:版本号定位→autoType/safeMode 配置→出网面(JNDI 需出网或本地链)→WAF 对 `@type` 特征的变形(`\x74` 等编码绕过,见该帖 WAF bypass 节)。

### 4.5 Java 审计实操路线(代码到洞)

1. **建工程视图**:IDEA 导入(maven 依赖解析)+ 反编译依赖 jar;先看 web.xml/SpringBoot 启动类、Filter/Interceptor 注册链。
2. **鉴权矩阵先画**:哪些 path 白名单、哪些注解自定义鉴权(`@RequiresPermission` 类)→ 差集即未授权面(高频出洞位)。
3. **sink 反向 grep**:`readObject|parseObject|XMLDecoder|getMethod.invoke|Runtime|ProcessBuilder|SpelExpressionParser|ScriptEngine|MVEL|new File(|FileOutputStream` → 逐个回溯 source。
4. **SQL 面**:`${}`(MyBatis)全文搜 → 判断是否 order by/limit 等无法参数绑定处(常见真洞)→ `injection-test.md`。
5. **二次渲染面**:freemarker/velocity 模板内容是否可被用户写入(模板编辑功能=潜在 SSTI RCE)。
6. **密钥面**:`application.yml` 中 secret/token 加密密钥 → 判断可伪造什么(JWT 签名/接口签名)→ `oauth-jwt-test.md`。
7. 工具加速:CodeQL(本地数据库+谓词查询)、Tabby(Java 3-min SCG,适合大项目可达性判断)、Semgrep(轻规则批量)。

## 8. 代码 diff 审计(Patch diff 找 0day)

### 8.1 流程(自绘)

```
盯源(安全公告/CVE-NVD/GitHub watch/厂商公告)
  → 取 diff(git log -p / commit compare: 修复 commit vs 父)
  → 定位修复点: 改了哪个判断/加了什么校验
  → 三问: ①修复是否完整(边界/编码/长度) ②同模式代码点还有几处(复制粘贴洞)
          ③能否构造绕过修复的新输入(0day 变体)
  → 产物: 绕过 PoC + nuclei 模板(批量验证资产)
```

- 要点:修复 commit 常带测试用例(直接抄用例改边界);`git log --grep="CVE\|security\|inject"` 快筛历史修复;跨版本 diff(相邻 minor)比单 commit 更能看出模式。
- 经典案例型:补丁只加黑名单→编码/大小写绕过(多数 CMS);补丁改正则→回溯未覆盖路径。
- 1day/nday 打法(补丁出了、资产没更)是 SRC 高产面,配合 FOFA 指纹批量 → `~/.zcode/skills/skill/知识库/rce-面定位.md`。
- MCMS 0day:指向 ve1kcon 米酷 MCMS 审计系列(前台注入+后台 getshell)。CMS 审计代表帖:BlueCMS 源代码审计、addslashes 绕过×苹果CMS、DedeCMS 任意改前台用户密码、某 CMS 漏洞挖掘实录。

### 9.1 CodeQL 污点查询骨架(Java SSRF 示例)

```ql
class SsrfConfig extends TaintTracking::Config {
  SsrfConfig() { this = "SSRF" }
  override predicate isSource(DataFlow::Node src) {
    src instanceof RemoteFlowSource   // 全部 HTTP 入口参数
  }
  override predicate isSink(DataFlow::Node sink) {
    sink.asExpr() = any(URL u | u = openURL(_))  // URL 打开点
  }
}
from SsrfConfig cfg, DataFlow::PathNode source, DataFlow::PathNode sink
where any(TaintTracking::Path p).hasFlowPath(source, sink)
select sink.getNode(), source, sink, "SSRF: $@ → URL 打开", source, "用户输入"
```

要点:先跑框架内置查询集(security-extended),再按业务改 source/sink;Tabby 对超大型项目先算可达性再精读,省时间一个量级。

# Android 文件格式详解 — dex / elf(so) / oat / vdex / cdex / arsc / AXML

> 对应树节点:文件格式[1001533] 全子树(DEX/ODEX[1001305]/OAT[1001307]/ELF与so[1001341]/AXML[1001303]/ARSC[1001304]/apk文件[1001539]/class字节码[1001301]/库文件[1001536])
> 手法库(同 skill re/手法)只散点讲了「so 修复 dump」「dex dump 修复」两处;本篇是**字节级格式底座**,是脱壳修复/重打包/解析器开发的公共地基。

## 0. APK 是什么(zip 容器)

```
app.apk (ZIP)
├── AndroidManifest.xml      ← 二进制 AXML(§6)
├── classes.dex [classes2.dex ...]   ← 代码(§1/§2)
├── res/                     ← 编译后资源(二进制 AXML + arsc 索引,§7)
├── resources.arsc           ← 资源表(§7)
├── assets/                  ← 原样打包文件(壳的第二 dex / so / 配置常藏此)
├── lib/<abi>/libxxx.so      ← native 库(§3 ELF)
├── META-INF/                ← MANIFEST.MF / *.SF / *.RSA(DSA/EC) 签名文件
└── (V2+ 签名块:ZIP 中央目录前的 APK Signing Block,	key-value:0x7109871a=V2)
```

- ZIP 细节:entries 可 STORED(不压缩,dex 在 API27+ 可页对齐 `zipalign -p 4` 直载)或 DEFLATED;**ZIP 重打包坑**:中央目录 offset 重算、注释字段藏 payload 的壳(如某些整体壳把原 dex 放 zip comment)。
- 签名演进:V1=JAR 逐条 SHA1+PKCS7;V2=APK Signing Block 全 zip 校验(1-3 段);V3=密钥轮换证明;V4=fs-verity。`apksigner verify --verbose` 看;**V2 的 existence 意味着重打包必须整块重签**(zipalign 在 signing block 前,顺序:zip 数据→signing block→中央目录)。

## 1. DEX 格式(树 DEX/ODEX/1001305 核心)

### 1.1 header(112 字节,偏移逐字段)

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0x00 | 8 | magic | `dex\n035\0`(035=格式版本,037/038/039 递进:min-api/隐藏 api/动态调试位);**cdex 为 `cdex001`** |
| 0x08 | 4 | checksum | **Adler-32**,覆盖偏移 12 起全部 |
| 0x0C | 20 | signature | **SHA-1**,覆盖偏移 32 起全部 |
| 0x20 | 4 | file_size | 整个 dex 大小 |
| 0x24 | 4 | header_size | 0x70 |
| 0x28 | 4 | endian_tag | 0x12345678 |
| 0x2C/0x30 | 4+4 | link_size / link_off | link 段(动态链接用,常 0) |
| 0x34 | 4 | map_off | map_list 偏移 |
| 0x38.. | — | string_ids_size/off | 后续 7 组 size+offset 成对:strings→types→protos→fields→methods→class_defs→data |

**修复铁律**(dump 脱壳后必做,手法库 已实证):任何字节改动→重算 `signature=SHA-1(dex[32..])`→再重算 `checksum=Adler-32(dex[12..])`,否则 jadx/baksmali 拒收。

### 1.2 map_list

header 尾部 map_off 指向;`map_item{uint16 type;uint16 unused;uint32 size;uint32 offset}` 数组+结尾 0。type 常量即全 dex 段落清单(0x0001 header/0x0002 string_id/0x0003 type_id/0x0005 proto_id/0x0006 field_id/0x0007 method_id/0x0008 class_def/0x1002 string_data/0x2000 map_list/0x2001 type_list/0x2002 annotation_set/0x2003 class_data/0x2004 code/0x2005 static values…/0x2006 debug_info)。**写 dex 解析器以 map 为准,别按 header 线性推**——加固常对 header 表项做手脚而 map 是自洽的。

### 1.3 索引五连(以 id → data 两级结构)

- **string_id_item**:`uint32 string_data_off` → MUTF-8 编码(`uleb128 utf16_size + bytes + \0`);MUTF-8=变体 UTF-8(\0 编码为 0xC0 0x80,增补字符走代理对)。字符串池有序(按 MUTF8 码点),被 string_id 索引。
- **type_id_item**:`uint32 descriptor_idx`(指向 string)→ 类描述符 `Ljava/lang/String;`、`[I`。
- **proto_id_item**:`shorty_idx + return_type_idx + parameters_off(type_list)`——方法原型(不含类与名字)。
- **field_id_item**:`class_idx(u16) + type_idx(u16) + name_idx(u32)`。
- **method_id_item**:`class_idx + proto_idx + name_idx`。**method_id 是 hook/混淆的常用锚点**(frida `Java.use` 走到这里)。

### 1.4 class_def 与 class_data_item

- **class_def_item**(32 字节):`class_idx / access_flags / superclass_idx / interfaces_off(type_list) / source_file_idx / annotations_off / class_data_off / static_values_off`。
- **class_data_item**(uleb128 全变长,无对齐):`static_fields_size/instance_fields_size/direct_methods_size/virtual_methods_size` + 四组 **encoded_field/encoded_method**——**field_idx_diff / method_idx_diff 是差分编码**(相对前一个的增量),解析器必须累加。
- **encoded_method**:`method_idx_diff + access_flags + code_off` → 指向 code_item。

### 1.5 code_item(方法体)

```
code_item {
  u16 registers_size;   // 本方法 v 寄存器总数
  u16 ins_size;         // 传入参数占的寄存器(含 this)
  u16 outs_size;        // 调用别人时要借的寄存器
  u16 tries_size;
  uleb128 debug_info_off;  // 常为 0(壳抹掉)
  uleb128 insns_size;      // 16-bit 代码单元数
  u16 insns[insns_size];   // 指令流(switch 表按 4 字节对齐,nop 填充)
  [padding]
  try_item tries[tries_size];   // {start_addr(u4) insn_count(u2) handler_off(u2)}
  encoded_catch_handler_list handlers;
}
```
(依据 AOSP `libdexfile/DexFile.proto` 结构)

- **抽取壳的落点**:insns 全 NOP/置空 + access_flags 加 native——检测「方法空但有注册」即抽取壳特征(还原方案互链 手法库 `03-脱壳dump/dex脱壳.md` 的主动调用系)。
- **debug_info 抹除**:加固常抹行号,`jadx` 显示 `/* compiled code */`。

### 1.6 ODEX(旧 Dalvik 优化格式)

4.4 时代 `dexopt` 产物:ODEX 头 + 依赖列表 + optimized dex(quickened 指令);5.0+ 被 ART 的 oat/vdex 取代,仅考古。树把 DEX/ODEX 合并一节,现役只看 dex 与 §5 的 vdex 内 dex。

### 1.7 解析与修改工具(树 DEX解析工具[1001670]/修改DEX[1001599])

- **baksmali/smali**(树 Smail/Baksmail[1001598]):dex↔smali 往返的事实标准;`baksmali d x.dex`/`smali b out/ -o x.dex`(3.x 由 baksmali 组织维护(原 google/smali),发 Google Maven `com.android.tools.smali:smali-baksmali` 至 3.0.10+,Android 13 期 odex/vdex 由 OatHeader key-value 解析等修复覆盖;Android 10+ 的 odex 常不含 dex 正文,需 vdexExtractor 先提 vdex)。
- **dexlib2**(baksmali 的库)是程序化改 dex 的底座;**redex**(Facebook)做 dex 级优化/重排。
- 010 Editor 有 dex 模板;Androguard(py3)脚本化解析(axml/dex 双能)。
- 代表帖:《DexFile文件格式分析》(boyliang,2014-09)、《分析一个简单的 .dex 文件》、《Dex分析Demo》、《DEX文件内存加载实现中的数据构造(C部分)》、《Android DEX安全攻防战》、《Dexguard分析&钛备份破解》;「手写 dex 解析器」方向另见 IDC 脚本族《IDC脚本,elf,vdex,cdex格式解析》(X.D,2021)。

## 2. class 字节码(树 class字节码[1001301])

- JVM 栈式:.class 结构(magic 0xCAFEBABE/常量池/access/fields/methods/attributes);与 dex 的映射:常量池→字符串池,method→method_id+code,attribute Code→code_item。
- 子树含 AOP 工具族:**Javassist[1001575]**(源码层字节码编辑,运行时 `CtClass`)/ **ASM[1001576]**(visitor 模式,最底层最快,Android 端改 dex 前的 class 期注入主流)/ Javasnoop(考古)。
- 逆向视角:看 APK 里塞了 ASM/Javassist=运行时自生成代码(风控 SDK 常见,frida `Java.enumerateClassLoaders` 找动态定义的类)。

## 3. ELF 与 so(树 ELF与so文件[1001341])

### 3.1 ELF 基本盘

- 头:`\x7fELF` + class(1=32/2=64)+ data(LSByte)+ e_type(ET_DYN,so 无固定基址)+ e_machine(EM_ARM=40/EM_AARCH64=183)+ Program Headers(`p_type=PT_LOAD` 段映射)。
- **段 vs 节**:加载视角用 Program Header(LOAD/_DYNAMIC/GNU_RELRO);静态分析视角用 Section Header(`.text/.rodata/.data/.bss/.got/.got.plt/.plt/.init_array/.fini_array/.dynsym/.dynstr/.rela.dyn/.rela.plt`)——**so 可以把 Section Header Table 抹掉/搞乱(加载器不依赖),IDA 仍靠它**;加固常破坏节表反静态。

### 3.2 动态链接三件套(逆向核心)

- **`.dynamic`(PT_DYNAMIC 指向)**:d_tag/d_val 数组;关键 tag:`DT_STRTAB/DT_SYMTAB/DT_STRSZ/DT_SYMENT`(符号表)、`DT_PLTGOT`(GOT 地址)、`DT_JMPREL/DT_PLTRELSZ`(.rela.plt)、`DT_RELA/DT_RELASZ`(.rela.dyn)、`DT_INIT_ARRAY/DT_INIT_ARRAYSZ`、`DT_NEEDED`(依赖)、`DT_SONAME`;Android 特有:`DT_ANDROID_REL(A)`(压缩重定位,packed)。
- **重定位条目** `Elf64_Rela{r_offset(目标写哪)/r_info(sym<<32|type)/r_addend}`:
  | 类型(arm64) | 含义 | 时机 |
|---|---|---|
  | R_AARCH64_RELATIVE (1027) | base+offset 写入(GOT 内部指针) | relocation 早期 |
  | R_AARCH64_GLOB_DAT (1025) | 符号地址→GOT 数据槽 | 符号解析 |
  | R_AARCH64_JUMP_SLOT (1026) | 符号地址→PLT 跳转槽 | **懒绑定**(Android 上 linker 实际多用 BIND_NOW,GOT hook 要点) |
  | R_AARCH64_ABS64 (257) | 符号+addend 写任意位置 | 嵌入指针 |
- **GOT/PLT**:PLT 桩 `adrp x16, GOT; ldr x17,[x16,off]; br x17`;外部调用走 `.plt`→查 `.got` 槽。**GOT hook=改槽不动代码**,对壳保护的函数比 inline hook 稳——两条完整实现(纯 JS 解析 ELF dynamic→找 JUMP_SLOT 项 / linker soinfo 走 `plt_rela/symtab/strtab`)互链 手法库 `02-frida/高级/gothook.md`,不重复。
- **init_array/fini_array**:加载完重定位后 linker 逆序/顺序调用的构造函数数组——**壳/反调试的自启点**;so 加载完整时序(dlopen→linker→重定位→init_array)与「抢注入时机」互链 手法库 `11-链路内核级/进程时序与内存链路.md`。

### 3.3 Android linker 要点(树 Linker分析[1001566])

- `/system/bin/linker64`(用户态动态加载器,非 glibc ld.so 谱系):`dlopen`→`find_library`→soinfo 链(solist/somain)→`linker_sonames`/`linker_namespace`(类加载器命名空间:app 的 `classloader-namespace` 限制可见 so——**unidbg 补环境的坑来源**)。
- `android_dlopen_ext`(带 `android_dlextinfo`:可指定 fd/memp_fd 加载,壳用来内存加载 so)。
- soinfo 结构偏移与遍历(dump 加固 so 的底座)互链 手法库 `03-脱壳dump/so修复dump.md`(494 行,含段回填修复)。
- 工具:readelf/objdump、LIEF(py)、pyelftools、010 模板、IDA ELF 处理器。
- 代表帖:《SO文件格式及linker机制学习总结(1)(2)》、《Android Linker详解》、《android linker 解读2----find_library》、《android linker 编译替换》、《自定义linker跑android_server》、《基于Bionic/linker修改,实现无痕so_loader》、《基于linker实现so加壳技术基础》;init_array 断点实操见《JNI_OnLoad与init_array下断方法整理》。

## 4. OAT 格式(树 OAT文件格式[1001307])

- ELF 容器:OAT header(magic `oat\n`+版本+checksum+key-value 存 dex 文件摘要)+ OAT dex files(每 dex:位置/类偏移表)+quickened/AOT 机器码段。
- 与 vdex 共生:`base.odex` + `base.vdex` 同目录;**A10+ 机器码可移入 vdex 的 quickening 信息**,odex 渐薄。
- 提取 dex:vdex 里的才是原文(见 §5);`oatdump --export-dex-to=dir`(老版本 flag;A10+ 后 oatdump 逐步退化,dex 提取主走 vdexExtractor/dexdump 路线——新版 AOSP 已移除 --export-dex-to,以当版 `oatdump --help` 为准);树「smali转换[1001683]」= oat/vdex 取出 dex 后走 baksmali。OAT 结构参考:《Android oat文件格式分析笔记》、《Android4.4.2系统的OAT文件解析》、《oat_file_manager与oat_file_assistant》、《OatFile::Open流程与OatDexFile的获得》。

## 5. VDEX 与 cdex(手法库 已实证,此处给结构)

- **vdex**:header(magic `vdex`+version,校验器版本/特性 flag)+ dex section(原文或 compact dex)+ quickening info;A8.0 引入、逐版演进(019/021/025/027…版本差异大,解析器要按 version 分支)。本地参考:《IDC脚本,elf,vdex,cdex格式解析》(X.D,2021,含三类格式 IDC 解析实现);版本-Android 对应仍以 AOSP `art/runtime/vdex_file.h` 各 tag 为准。
- **cdex(compact dex)**:dexlayout 按 profile 重排的紧凑形态——magic `cdex001`,header 多 `container_size_`,**多个 dex 共享 data section,索引表可变长(u4→uleb)**;ART 内存里直接跑 compact 形态不还原。
- **cdex→dex 修复链**:vdexExtractor 转换,或 dump 后最低限度重算 SHA-1(signature)/Adler-32(checksum)——完整管线(手法库 `03-脱壳dump/eBPF脱壳深挖.md` §5.2)不重复。

## 6. AXML — AndroidManifest 二进制(树 AXML文件格式[1001303])

- 原理:打包时 aapt2 把 XML 编译成二进制:chunk 化(`ResChunk_header{uint16 type;uint16 headerSize;uint32 size}`)+ **字符串池**(全局字符串去重索引)+ 命名空间映射 + 属性引用资源 ID。
- 顶层结构:STRING_POOL(0x0001)→(可选 RESOURCE_MAP 0x0180)→ START_NAMESPACE(0x0100)→ START_ELEMENT(0x0102,含 attribute 数组:ns/name/typedValue)→ …→ END_ELEMENT(0x0103)。
- **typedValue 三态坑**:属性值可为字符串引用(rawValue 指池)或编译值(Res_value:data+dataType,如 `0x12`=int、`0x01`=reference→资源 ID);布尔 `true` 存 int 0xffffffff。手写解析器最常见的错=漏 dataType 分支。
- 逆向用法:①看组件导出(`exported`/intent-filter)、②权限面(`uses-permission`/自定义 permission protectionLevel)、③壳特征(`android:name` 指向壳 Application、meta-data 藏 key);④ **AXML 是资源混淆(aab/arsc 混淆)的对齐对象**——资源 ID 与字符串池联动改。
- 工具:apktool(axml→文本)、androguard `AXMLPrinter`、jadx 自动还原;纯库:**pyaxmlparser**(0.3.31,不依赖 androguard)与 **androguard/axml**(独立无依赖库)。

## 7. resources.arsc(树 ARSC文件格式[1001304]/apk文件[1001539])

- 作用:资源全局索引表——资源 ID(0xPPTTEEEE:package+type+entry)→ 类型/名称/配置/值。
- 结构:RES_TABLE_TYPE 头+全局字符串池(资源名)+ package chunk(RES_TABLE_PACKAGE_TYPE:id/名称+类型字符串池+key 字符串池)+ typeSpec(RES_TABLE_TYPE_SPEC_TYPE,标可变配置)+ type(RES_TABLE_TYPE_TYPE:配置如 zh/hdpi,entry→ Res_value 或偏移到字符串池/复杂类型)。
- **逆向高频点**:①字符串在哪:`public.xml`(apktool 还原)/按资源 ID 反查(type×entry);②**资源混淆/加固**:重排 ID+清字符串池让 apktool/jadx 报错——修复思路=按引用图重建(手法库 `05-工具矩阵/静态分析工具.md` 的 ROSAL 锚点思路);③改资源名/删资源重打包后必须重编 arsc(aapt2 或 apktool 内建)。
- 树 res 目录[1001541]/assets[1001540]:res=编译后资源+索引进 arsc;assets=原样不进索引(壳的隐藏通道)。
- 工具:aapt2 dump(`aapt2 dump resources`)、apktool、androguard、arsc 分解脚本。

## 8. 库文件(树 库文件[1001536])

- **jar[1001537]**:zip 容器装 .class(桌面 JVM);Android 侧 = `libs/*.jar` 进 dex 编译源。
- **aar[1001538]**:Android 库包 = classes.jar + res/ + R.txt + AndroidManifest.xml + libs/;解包看依赖 SDK 的真实类是逆向第三方 SDK 的第一步(`unzip sdk.aar`)。

## 9. 六格式对比表

| 格式 | magic | 容器 | 逆向关注点 | 解析工具 |
|---|---|---|---|---|
| dex | `dex\n035` | 自有 | header 8 表/map/class_data 差分/code_item;cdex 变体 | baksmali/androguard/010 |
| odex | ELF(oat) | ELF | A10+ 渐废,考古 | oatdump |
| oat | ELF `oat\n` | ELF | 机器码段与 dex 摘要 | oatdump |
| vdex | `vdex` | 自有 | **dex 原文/压缩原文在此** | vdexExtractor |
| so | `\x7fELF` | ELF | dynamic/GOT-PLT/init_array/节表破坏 | IDA/LIEF/readelf |
| arsc | `0x02 0x00 0x0C 0x00` | chunk | ID→值映射、资源混淆修复 | aapt2/androguard |
| AXML | `0x03 0x00 0x08 0x00` | chunk | 字符串池/typedValue/组件面 | apktool/androguard |

> 注:arsc/axml 的 type 值以 chunk 头第一个 u16 计(RES_TABLE_TYPE=0x0002/RES_XML_TYPE=0x0003),表中为首 chunk 原始字节(小端),已按 AOSP `ResourceTypes.h` 还原;具体数值随版本演进需比对源码。

## 1. glibc 堆基础:ptmalloc 内存模型

### 1.1 堆从哪来:brk 与 mmap

《dlmalloc、ptmalloc与glibc堆漏洞利用》(evilpan):malloc 的空间通过 **brk/mmap** 系统调用向内核申请。brk 修改 program break(数据段末尾)扩展堆,以页(0x1000)为单位;首次 `sbrk(0)`返回 .data 段末尾,再 sbrk 后 maps 出现 `[heap]`区。用户态的事用户态解决——分配器在已申请的大片空间上自己管理切分。

### 1.2 chunk 结构(64 位,16 字节头)

《Glibc Heap 利用之初识 Unlink》含堆布局图与 unlink 前后链表图:

```
chunk->  +-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
         | prev_size | 上一个chunk空闲时=其大小;否则被上一chunk的用户数据占用
         +-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
   head: | size       |A|M|P|   A=NON_MAIN_ARENA M=IS_MMAPPED P=PREV_INUSE
         +-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
   mem-> | fd         | 空闲时:双向链表前驱;已分配:用户数据
         +-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
         | bk         | 空闲时:双向链表后继
         +-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
         | fd_nextsize| 仅 largebin 空闲块:指向下一个更小尺寸
         +-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
         | bk_nextsize| 仅 largebin 空闲块:指向上一个更大尺寸
         +-+-+-+-+-+-+-+-+-+-+-+-+-+-+-+
```

要点(原文):
- 64 位最小 32 字节(MINSIZE)、16 字节对齐;32 位最小 16 字节、8 对齐
- 已分配 chunk 的 fd/bk/nextsize 区域都给用户数据用——**堆溢出改的就是这些复用字段**
- dlmalloc 的 Boundary Tag(边界标签)设计:头尾都带大小标签,便于相邻空闲块合并;现代实现砍掉了使用中 chunk 的尾部标签

### 1.3 bin 谱系

```
_int_malloc(av, nb) 分配优先级:
 fastbin(≤global_max_fast,单链LIFO)
   → smallbin(<0x400,64条双向链,精确尺寸)
   → unsorted bin(回收站,双向循环,先进先出)
   → largebin(64组,按大小范围,含nextsize双链)
   → top chunk(最后一块,不够则 sysmalloc 向系统要)
```

`glibc2.23 ptmalloc 原理概述`逐行拆 `_int_malloc`:①查 `__malloc_hook`②fastbin 命中即摘链 ③smallbin 摘 bk 端 ④遍历 unsorted(期间做 unlink/smallbin 归位/largebin 插入) ⑤binmap 扫更大 bin 切割 ⑥top 切割。每步的检查字符串(`malloc: memory corruption (fast)`等)就是利用时要绕过的关卡。

free 侧:`glibc的free函数笔记`补 _int_free 流程(fastbin 头插、非 fast 合并前后邻居、邻 top 则并 top)。

## 2. tcache:2.26 引入的快车道及其攻击面

### 2.1 结构与演进

《Tcache安全机制及赛题详细解析(gundam && House of Atum)》:

```c
typedef struct tcache_entry {
  struct tcache_entry *next;   // 指向用户区(mem),注意与 fastbin fd 指向 chunk 头不同
  struct tcache_perthread_struct *key; // 2.29+: double-free 检测
} tcache_entry;
typedef struct tcache_perthread_struct {
  char counts[64];             // 每链计数
  tcache_entry *entries[64];   // 64 条单链
} ;  // 位于堆开头的 0x290(旧0x250) 结构,thread-local
```

- 2.26 引入:每链最多 7 个,无锁、无 size 校验、**tcache_put/take 早期完全无检查**
- 2.29:加 `key`字段防 double free(同 chunk 二次 free 时 key 相等则 abort);加 count 检查
- 2.32:`next`指针加密(异或 `chunk>>12`后存贮),需先泄露堆地址才能伪造链
- free 时 tcache 满才走 fastbin/unsorted;malloc 优先 tcache——**大量老攻击的"第一站"变成了 tcache poisoning:改 next 任意分配**

### 2.2 攻击模式

- **tcache poisoning**:`Tcache Attack原理学习`——UAF/double free 改 entries 链头 next → malloc 两次拿到目标地址(2.32 前无任何校验)
- **tcache stashing unlink attack**:`house of pig详解`前置节——smallbin 中 5 个 chunk 被 calloc 搬进 tcache 时,`bck->fd`写入发生在校验前,可越界写一个堆地址到 `target-0x10`
- **count 篡改**:改 `tcache->counts`让 `tcache_get`在空链也"取到"东西
- 赛题样例: gundam(UAF 进 tcache 改指针)+ House of Atum(double free 反复吃 tcache 名额);《【NKCTF】babyHeap-Off by one&Tcache Attack》

《Tcache利用总结》(V1NKe):LCTF2018 easy_heap 用 off-by-null + unsorted 合并构造 chunk overlap(堆固定 0x100 无法常规 overlapping 时,交错 delete 制造 unsorted 邻接、null 字节截断 size 再合并)。

## 3. 经典 bin 攻击(2.23 时代四大件)

### 3.1 unlink

《Linux堆溢出漏洞利用之unlink》+《Pwn堆利用学习——Unlink——2014_hitcon_stkof》:

```
unlink(P): FD = P->fd; BK = P->bk;
  检查: FD->bk == P && BK->fd == P   ← 绕过法:让 FD/BK 都指回受控地址
  通过后: FD->bk = BK; BK->fd = FD    ← 效果 = 两个指针互写
```

绕过范式:在可控 chunk 内伪 P 使 `P->fd = &ptr-0x18, P->bk = &ptr-0x10`(ptr 是指向该 chunk 的全局指针),则 `FD->bk=*&ptr-0x18+0x18=ptr`与 `BK->fd`均通过检查,unlink 后 `ptr = ptr-0x18`——指针变矮,再 edit 即任意写。largebin unlink 还需满足 nextsize 检查(伪造 `fd_nextsize->bk_nextsize == P`)。

### 3.2 fastbin attack 族

- **double free**:`Fastbin-Double-Free——ACTF_2019_message`——A→B→A 绕过"相邻同 chunk"检查;在 A 的 fd 写 hook 地址-0x23 对齐伪造 size(0x7f),第三次 malloc 拿到 `__malloc_hook`;经典组合 `malloc_hook = one_gadget`
- **house of spirit**:`Fastbin-House of Spirit——LCTF_2016_pwn200`——在目标区域(栈/BSS)伪造 fake chunk(size 匹配 fastbin、IS_MMAPPED=0、next chunk size 合理),free 指向它的指针,再 malloc 即拿到该区域 → 覆盖返回地址/函数指针
- fastbin 检查仅两点:取出时 `fastbin_index(chunksize(victim))==idx`;`free`时 chunk 与 top 不相邻

### 3.3 unsorted bin attack

《PWN:Unsortedbin Attack学习》:free 的非 fast chunk 进 unsorted(fd/bk 指向 bin 头=libc 地址,可泄露 libc 基址)。改 `bk = target-0x10`,下一次 malloc 从 unsorted 取出该 chunk 时执行 `bck->fd = unsorted_chunks(av)`→ **target 被写入一个 libc 大地址**(不是任意值)。经典用途:改 `global_max_fast`、`magic`后门变量(HITCON training magicheap)。

### 3.4 largebin attack

《ctf中的large bins attack及lctf2017 2ez4u writeup》(sakura零):largebin 按 size 降序、同 size chunk 组成一组,nextsize 链连接不同 size 组:

```
bk_nextsize: 首chunk(最大)指向末端(最小),否则指向更大者
fd_nextsize: 末chunk指向首部,否则指向更小者
```

改 `bk_nextsize = target-0x20`,插入更大 chunk 时 `victim->bk_nextsize->fd_nextsize = victim`把堆地址写进 target。2.30 起插入路径加了双向链表完整性检查, 指出 2.31 下"插入更小 chunk"分支未检查,仍是利用点——**largebin attack = 任意地址写一个堆地址**,是高版本 hook 移除后接 IO 攻击(house of apple/cat/pig)的标准前菜。

### 3.5 House of Storm

《CTFHUB-LargeBin Attack|House of Storm》:largebin attack(写堆地址到目标)+ unsorted bin 的 bk 指向同一目标 → 在目标处拼出合法 fake chunk 头,`_int_malloc`取 unsorted 时把它当 victim 返回——**一次拿到任意地址的 malloc**,glibc-2.27 下验证。要求 `freeChunkU.size > freeChunkL.size`。

## 4. House of 全家谱

源自 2004 年 Malloc Maleficarum(《The House of Prime》):Prime/Mind/Force/Lore/Spirit/Chaos 六式;后社区扩展出 Orange/Einherjar/Rabbit/Storm/Botcake/Pig/Apple/Cat/Emma/Kiwi/Banana/Water 等。共性 = **利用 ptmalloc 特定代码路径,把"堆元数据写"升级成"任意地址写或执行流劫持"**。

| House | 核心路径 | 版本 |
|---|---|---|
| Prime | 覆写 top size 使 free 写 global_max_fast | 古老,2.3x|
| Mind | 伪造非主 arena 指针(heap_info)使 free 写任意 | phrack66|
| Force | top size=-1,malloc 任意大小 | 2.23 前|
| Spirit | 伪造 fake chunk free 进 fastbin | 通用|
| Lore | 篡改 smallbin/largebin 链 | 较少用|
| Orange | top 缩水进 unsorted→FSOP | ≤2.23 经典|
| Einherjar | off-by-null 清 P 位反向合并进 fake chunk | ≤2.29 通用|
| Storm | largebin+unsorted 拼 fake chunk | 2.27|
| Botcake | double free + tcache 满时合并再切 | 2.29+|
| Pig | largebin+tcache stashing→_IO_str_overflow | 2.31|
| Apple | 一次 largebin attack 打 wfile 虚表 | 2.35 通用|
| Cat | wfile_seekoff 链,免 pointer_guard | 2.35+|

### 4.1 House of Orange(无 free 函数时的开局)

《PWN堆利用:House Of Orange》(how2heap 翻译):
1. malloc(0x400) 后溢出改 top size 为 0xc01(需通过 `top size & 0xff...`页对齐检查)
2. 再 malloc 大块 → 旧 top 进 unsorted(fd/bk=unsorted 地址)→ 泄露 libc
3. unsorted bin attack 改 `_IO_list_all`
4. 伪造 `_IO_FILE`:`_mode=0,_IO_write_base<_IO_write_ptr`,vtable→fake jump_table,`jump_table[3](_IO_OVERFLOW)=system`,chunk 开头放 "/bin/sh"
5. malloc 触发 → `exit→_IO_flush_all_lockp→_IO_OVERFLOW(fp)`→ system("/bin/sh")

`学习House of Orange`/ `堆溢出-House of orange 学习笔记`互为补充。

### 4.2 House of Einherjar(off-by-null 拉链合并)

①栈/可控区伪造 fake chunk(fd=bk=fd_nextsize=bk_nextsize=&fake 自指,过 unlink 检查)②a 溢出 null 清 b 的 P 位③a 尾部写 `fake_prev_size = b头-fake`④free(b) → `chunk_at_offset(b, -prev_size)`回溯到 fake,unlink 后与 fake 合并成横跨栈-堆的大块 → malloc 落在可控区。配套赛题 Tinypad(Seccon CTF 2016)。

### 4.3 House of Force(top 任意定位)

溢出改 top size=-1(防 mmap)→ `malloc(evil_size)`其中 `evil_size = target - 0x20 - old_top`(整数回绕可打到低地址/BSS)→ 再 malloc 即从 target 起切。2.29 起 sysmalloc 对 top size 做了页对齐断言,已死。

### 4.4 高版本 IO 流派(Apple/Cat)

- 《House of apple》(roderick01):**只需一次 largebin attack**。exit→fcloseall→_IO_cleanup→遍历 _IO_list_all→`_IO_OVERFLOW`。伪造 wide_data(宽字符域),改 `_wide_data->_IO_write_base==0 && _IO_write_ptr>0`走 `_IO_wfile_overflow→_IO_wdoallocbuf→_wide_data->_wide_vtable->__doallocate`,该 wide_vtable **不在 __libc_IO_vtables 段内不受 2.24 vtable 检查**。四条思路:改 tcache 线程变量/改 mp_/改 pointer_guard(即 house of emma)/改 global_max_fast
- 《House of cat》(CatF1y,2022 强网杯):虚表偏移改到 `_IO_wfile_jumps+0x10`调 `_IO_wfile_seekoff`→`_IO_switch_to_wget_mode`→`_IO_WDOALLOCATE`,**绕开 TLS pointer_guard 校验**,比 emma 条件更宽。触发方式:FSOP(main 返回/exit)或 `__malloc_assert`(堆错误路径)
- 《深入理解Pwn_IO_FILE及相关赛题》:_IO_FILE_plus = _IO_FILE + vtable;stdin/stdout/stderr 在 libc,fopen 的在堆;2.24+ `IO_validate_vtable`检查 vtable 落在 `__start___libc_IO_vtables`~`__stop`段内——所以打法转向"合法 vtable 内偏移"或 wide_vtable

### 4.5 House of Botcake(2.29+ 对抗 tcache)

《2020祥云杯garden》:填满 tcache(7 个)→ 再 free 的 chunk 走正常合并 → double free 同一块使其既在 unsorted 合并块里又被放进清空后的 tcache → 拿 overlap。原文给 glibc2.31 全流程 exp(uaf 泄露 libc → 合并切割 → counts 对齐)。

## 5. 堆漏洞原语:溢出/Off-by-null/extend/UAF

- **off-by-null(2.29 对抗)**:`glibc2.29下的off-by-null`——2.23 公式(chunk 排布让 null 清 P 位触发后向合并 unlink)在 2.29 遇到 double-linked list 校验+nextsize 检查,需让 fake 前再放一个 real free chunk 满足 `next chunk prev_size`一致性;原文给出 2.23→2.29 的构造差异流程图
- **chunk extend/overlapping**:《HITCON Training lab13》——改 size 字段扩大 chunk,free 后吃掉邻居,产生两个指针指同一区域 → 任意读写。**这是所有堆题的"万能中间态"**
- **UAF**:《pwnable_hacknote》/《PWN学习笔记【堆】【UAF】》:free 后指针未清零,fd 位置被函数指针占用时直接劫持(打印/调用均触发)
- **fastbin dup into stack**、**poison null byte** 等 how2heap 手法在 how2heap 仓库有完整实现

## 8. 栈溢出体系(ROP 全家)

### 8.1 基础 ROP 与 ret2libc

《rop链攻击原理与思路(x86/x64)》:
- x86:栈传参,payload = `padding + p32(system) + p32(fake_ret) + p32(binsh)`;无 libc 时 DynELF/ret2dlresolve
- x64:前 6 参走 rdi/rsi/rdx/rcx/r8/r9,需 `pop rdi; ret`类 gadget(ROPgadget/ropper 找);`小白学pwn——ret2libc`
- `蒸米的一步一步学ROP之linux_x64篇`是社区标准入门
- ret2csu:用 `__libc_csu_init`尾部 gadget 控制 rdx/rsi/rdi 三参,解决 x64 找不到 pop rdx

### 8.2 SROP

《SROP分析及例题》(plkk)+`srop基本利用教程`+`/[23-271200] linux中的信号处理与SROP`:
- 内核对 signal frame 无审计 → 栈溢出伪造 SigreturnFrame(全部寄存器+rip)
- 64 位 `rax=15; syscall`触发 sigreturn;rax 常借 read 返回值控制
- frame 中设 rip=syscall、rdi=binsh、rax=59 → 一次 execve;**空间要求:溢出需容纳 ~0xf8 字节 frame**
- 例:ciscn_s_3(gadget `mov rax,0fh`现成给)

### 8.3 BROP(盲打)

《【KCTF-pwn】2022 春第六题 BROP》:
1. 爆破返回地址低字节判断 crash/正常 → 推断 main/基址(base=0x400000 无 PIE)
2. 逐地址试 `ret`、`pop x N; ret`(挂 main 判活)→ 摸出 stop gadget 与 pop 链
3. 用 write/puts 类 plt 泄露 ELF → dump 全文件 → 后续常规 ret2libc
4. 该题最终 SROP getshell

### 8.4 ret2dlresolve(无 libc 泄露的 x86 神器)

《高级栈溢出之ret2dlresolve详解(x86&x64)》(77pray):伪造 `.rel.plt`偏移 + 假 Elf_Sym/Elf_Rel/string,让 `_dl_runtime_resolve(link_map, reloc_arg)`把 "system" 解析进伪造 GOT。x64 需处理 `link_map`里 DL_RTLD_DEBUG 绑定与 0x8000000 偏移;pwntools `Ret2dlresolvePayload`一键。另见 《ret2dl-resolve详解》:《ROP高级用法之ret2_dl_runtime_resolve》:`CTFHUB-ret2dl_resolve`。

### 8.5 栈迁移(stack pivot)

(本地散见各 WP)`leave; ret`或 `pop rsp`把栈搬到 BSS/堆:《ROP Tricks - Stack smash》(canary 报错打印泄露的附加技巧)、《CTFHUB-ret2VDSO》(vdso 中找 syscall gadget)。

### 8.6 JOP/其他

《ROPMEMU 代码重用攻击分析框架》:《ROPGuard 检测技术》(防御视角);iOS ROP(见 04 区);kernel ROP → `漏洞类型与利用.md`§3。

### 8.7 Shellcode(历史线)

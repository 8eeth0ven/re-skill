# 打穿短表-固件(IoT/嵌入式刷 CVE 主力)

> 主表见 `打穿短表-CVE.md`(索引);本表是固件面扩容,格式同主表:对得上再开「见 xxx」深挖(短篇整开,长篇点名节)。够 CVE 的发现=安全策略违反+可利用证明+影响面(三问见 `漏洞披露与CVE申请.md`)。固件面规律:**提取→解密→解包→翻三处(shadow/cgi/upnp)→注入或溢出一枪→仿真或真机复现→按厂商选渠道**。

| 认什么 | 打哪 | 出什么算成 | 假点 |
| --- | --- | --- | --- |
| 任何 `.bin/.img/.trx/.chk` 固件,`binwalk -Me` 出 squashfs | 认 magic:厂商魔改头(TP-Link/华硕等)常让 `unsquashfs` 报 unknown magic——换 `sasquatch` 解;dd 出来 `file` 看大小端再选工具。提取链全貌见 `平台/07-智能设备/iot/固件提取.md` §6.1 | 解出完整 rootfs(有 etc/ usr/ www/)才算拿到攻击面;只出裸内核继续往下翻分区 | binwalk 幻签名:把内核/随机数据误报成 squashfs,目录里没有文件系统的空壳不算 |
| binwalk 识别 lzma/erofs/ubi/cramfs 但解不开 | lzma 用 `xz --format=lzma -d` 手工试;ubi/ubifs 换 `ubireader_extract_files`;erofs 要新版 erofs-utils(老 binwalk 不认);cramfs 分大小端两套工具,解错端=乱码不报错 | 换对工具后解出可浏览目录 | 解出乱码目录就当成功;magic 对但中间还有一层自定义头(十六进制翻头几个字节比对标准格式) |
| `binwalk -E` 整包熵 >7.5 且只有裸数据块 | 先画熵图区分:全段高熵=加密,局部高熵+可读区=正常压缩。判加密后走三条思路(见 `平台/07-智能设备/iot/固件解密.md` §2 起步) | 确认加密+定位到加密区起止偏移 | 高熵段是内核压缩镜像(正常);密钥来源没找到就死磕解密,不如转硬件路 |
| 加密固件的密钥三板斧 | ①老过渡版本未加密 diff(下载同型号老固件,加密段出现前的版本里有解密程序——D-Link 实战见 `平台/07-智能设备/iot/固件解密.md` §3);②bootloader 分区 strings 抠 AES key + openssl 试解;③UART/SPI 接线 dump,见 `平台/07-智能设备/无线硬件/硬件接口.md` §2/§3 | 任一条路解出明文 rootfs | 过渡版本也加密(再往前找初代);bootloader 里的 key 字符串是别的用途(交叉验证:解密头 16 字节对上才算) |
| binwalk 只出内核不出 rootfs | `binwalk -vv` 看完整签名表;`strings 固件 | grep -i "rootfs\|mtd"` 找分区名;U-Boot 环境变量(`fw_printenv` 布局)里有分区表,按偏移 `dd` 手切。布局套路见 `平台/07-智能设备/iot/固件提取.md` §1/§2 | 手动切出 rootfs 镜像再二次 binwalk | 把 kernel 里的 initramfs 当成完整 rootfs(initramfs 是早期用户态,web 面常在另一个分区) |
| 厂商 SDK 包里 kernel.bin 和 rootfs.bin 分离 | 直接对 rootfs.bin 再 binwalk;web/服务全在 rootfs,kernel 只用来认驱动漏洞面和版本 | rootfs 解出 www/cgi-bin 目录树 | 只分析 kernel 里的 initramfs 就开打(web 二进制根本不在这里) |
| 解包后第一件事:翻三个必查位置 | `cat etc/shadow`(root 有无哈希)、`grep -rn "telnet\|backdoor" etc/ bin/ --include="*"`、`strings -n 8` 全盘过一遍默认账密。三位置清单见 `平台/07-智能设备/iot/固件提取.md` §6.2 | 硬编码 root 密码哈希(可跑 john 破)/telnet 常开后门账号/调试账号 | shadow 里是 `x`(真密码在别处或 pam 对接);后门账号只允许 console 登录(物理面,网络不可达要写清) |
| web 目录有 goahead | `www/cgi-bin/` 逐个 C 程序:`websGetVar`/`cgiMain` 取参数处追到 `system/popen/execve`;别忘了 handler 注册面(`websUrlHandlerDefine` 注册的非 cgi-bin 路径)。矩阵见 `平台/07-智能设备/iot/路由器实战.md` §1 | 参数到 sink 无过滤(过滤表只拦分号不拦 `%0a`/`$()`/反引号) | 参数只写日志/_nvram;过滤函数藏在库里(grep libgoahead 的 wrapper) |
| web 目录有 boa / lighttpd / mini_httpd | boa:lua/cgi 混合,formDefine 注册的 lua handler 一样追参数;lighttpd:`grep -n "mod_auth\|auth.require" conf` 看哪些路径注释掉认证、`cgi.assign` 列的扩展名对应 binary;mini_httpd:裸 cgi-bin 全 C,逐个 main→argv 追 | 任一 cgi 参数未认证可达 sink | conf 里认证开着但 cgi 自己不查 session(反过来:cgi 查了 session,未认证面在别的 handler) |
| 诊断类接口(ping/ntp/traceroute) | 字段名认 `ping_ipaddr`/`ntp_server`/`host`/`dst`,打 `;id`、`%0a id`、`` `id` ``、`$(id)` 四套;判据=回显或带外 DNS(可控域名解析记录)。命令注入第一高发见 `平台/07-智能设备/iot/路由器实战.md` §1 | 未认证或低权命令注入(有回显/带外证据) | 参数进 `ping` 的 `-I` 之类安全位置;回显的是转义后命令本身(看输出格式是不是 shell 输出) |
| 固件里有 upnp 目录或 49152-49154 端口特征 | `grep -rn "AddPortMapping\|NewInternalPort\|NewExternalPort" upnp/` SOAP action 字段直接拼命令(HG532 模式);upnp 的 xml 描述文件里 service 列表全过。完整链路见 `平台/07-智能设备/iot/路由器实战.md` §5 | 未认证 SOAP 请求直接命令注入/upnp 栈溢出 | UPnP 只绑 LAN 口(LAN 侧可报但降级);SOAP 参数过 schema 类型校验(试协议允许的畸值) |
| 1883 端口(mqtt) | 匿名 connect 后:订阅 `#` 拿全 topic 面,往 cmd/set 类 topic 发畸形 payload 看设备端解析;无认证 broker 本身就是洞。协议面见 `平台/07-智能设备/iot/协议与服务.md` §1 | 未认证控制指令 topic(改配置/重启/开锁类) | topic 只读不落执行;broker 需 TLS 证书(先看 8883) |
| 5683/udp(coap) | `GET coap://ip/.well-known/core` 枚举资源树,对 PUT/POST 资源未认证打;资源名里 config/update 类逐个试。见 `平台/07-智能设备/iot/协议与服务.md` §2 | 未认证写资源(配网/指令下发) | 资源只绑本地回环;CoAP over DTLS(5684)先过握手 |
| 云对接固件(strings 出 api.域名/iot-域名) | `strings -n 12 | grep -iE "api\.|token|access.{0,3}key|secret"` 抠硬编码 cloud 凭证;AK 类认长度特征(阿里 16/30 位);拿到后试云 API 设备列表/批量下发 | 硬编码凭证可操作同厂商设备云(影响面=全厂设备) | 凭证是单设备级且只能读自身状态;token 已过期(拿新固件再验一次) |
| 固件里有更新/升级逻辑(upgrade/update 文件) | 追签名校验:`grep -rn "verify\|rsa\|ecdsa\|signature" 升级程序`;只有 md5/sha256 校验=无签名,OTA 流程可 MITM 换包;抓 OTA 请求看 URL 是不是 http | 篡改固件包+设备接受并刷入=RCE | bootloader 启动时二次验签(刷得进起不来);OTA 走 https 且证书校验严格(降级到 http 试) |
| 新版修了洞但更新机制不拦旧版本 | 拿含已知 CVE 的旧固件走正常更新流程刷回(看升级请求有没有最低版本检查);刷回成功+旧洞复现=降级保护缺失 | 降级保护缺失单独可报(常配已知 CVE 成链) | 服务器侧校验版本拒绝下发;签名校验挡住旧包(那就要先破签名) |
| 设备到手/有开发板:先接 UART | 接线四线见 `平台/07-智能设备/无线硬件/硬件接口.md` §2;拿 shell 后看:要不要密码、是不是 root、`ps` 里哪些服务 root 跑 | 无认证 root shell(UART 或 telnet);root 跑的 web 服务给网络洞垫影响面 | UART 有密码/锁丝(物理面单报价值低,写成攻击链前置条件);shell 是restricted busybox(翻可逃逸命令) |
| JS/前端里有隐藏路由 | 翻 web 目录 js:`grep -rn "hidden\|debug\|engineering\|factory" www/`;隐藏页常挂 diag/syscmd/restore 类接口,参数直通 shell | 隐藏页接口未认证命令注入 | 隐藏页只是 UI 隐藏,后端有独立鉴权;路由残留但 handler 已删(404) |
| 二进制网络服务(非 http 端口) | IDA/Ghidra 找 `bind`/`recvfrom` 的私有协议解析函数,专打 `strcpy/sprintf/vsprintf/memcpy` 到栈 buffer;MIPS/ARM 栈布局见 `平台/07-智能设备/iot/路由器实战.md` §2 | 远程栈溢出可控制 pc(ra/lr) | 服务只绑 127.0.0.1;解析前有长度字段校验(看校验是 `<` 还是 `<=`) |
| 固件组件带版本号(busybox/openssl/lighttpd) | `strings busybox | grep "BusyBox v"` 等拿版本,对已知 CVE 列表;老版本 busybox netcat/telnetd/dnsmasq 常有历史洞直接可用 | 组件已知 CVE 在该厂商固件可复现=报厂商(修复迟缓+设备暴露量);新版本引入的组件 bug 才是新号 | 只有组件版本老但洞触发条件不满足(功能没编进 busybox:`--list` 看编了哪些 applet) |
| 同平台 OEM 多型号 | 下载同平台 2-3 型号固件 `diff -r` 两个 rootfs;公共组件(web 核心/upnp 栈/minig)相同=一处洞全型号命中;NAS/摄像头/电力猫同样适用 | 一洞挂多型号(影响面写全型号列表) | 型号各自魔改了公共组件(diff 后函数级比对确认);不同硬件平台共用 UI 皮但二进制不同 |
| 厂商已 EOL 的型号 | 照报(报告标 EOL+在网设备数);海外 PSIRT 回「不再支持」转 CNVD/证书渠道;国内直接 CNVD 收 | EOL 型号照样给号(CNVD 侧常见) | 僵尸品牌无人认领(查母公司/代理/收购方再定投递对象);别因 EOL 跳过厂商直接公开(embargo 规则不变) |
| 报告要写影响面 | 用固件特征串(http.title/banner/特定页面字符串)到测绘平台搜设备数,数量写进报告提评级;设备搜索面见 `平台/07-智能设备/iot/攻击面与信息收集.md` | 影响面有设备数佐证(评级/收录更快) | 特征串太宽(搜出别的厂商);只写「大量设备」不贴数 |
| 打穿前要复现:先试仿真 | FirmAE 一键跑(见 `平台/07-智能设备/iot/固件仿真.md` §2,失败救活套路 §2.1);整机起不来降级 QEMU user 跑单个 binary(§3)或远程真机打。**起不起来都报**:CVE 要的是可复现,不要求仿真成功 | 仿真或真机任一稳定复现+截图/录屏 | 仿真打穿≠真机通(NVRAM/外设差异),有条件真机验一次再发报告 |
| 报送选型 | 海外厂商走 PSIRT/安全邮箱、小米/华为/TP-Link 有自家 SRC、国内通用走 CNVD;渠道选择与模板见 `漏洞披露与CVE申请.md` §1/§4 | 编号到手(设备类 CNVD 周期常快于 MITRE) | 同一洞多头投递被撞号(一家为主,重复投写明);PoC 里带真实设备 IP 未脱敏被退回 |
| binwalk 解不出文件系统(RTOS/单片机固件) | strings 找 RTOS 特征(FreeRTOS `pxCurrentTCB`/ThreadX 特有错误串);符号剥离的用函数表恢复(见 `平台/07-智能设备/iot/固件提取.md` §6.3);主打网络栈和私有协议解析 | RTOS 网络面溢出(常无 MMU,一枪即控制) | 把数据段字符串当函数名;偏移算错基址(用已知字符串交叉定位) |

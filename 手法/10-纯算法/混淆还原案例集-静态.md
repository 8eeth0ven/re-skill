# 混淆还原案例集(静态):OLLVM/花指令可照抄流程

> 定位:`去混淆实战.md` 是方法论总述,本文件是 8 篇实战案例的可照抄流程——步骤/脚本/反汇编特征。六节:花指令识别去除 / IDA+Hex-Rays / Binary Ninja / ARM64 专项 / 字符串混淆修复 / IDA&FRIDA 联调。案例以 ARM/ARM64/Thumb 移动端 native 为主,x86 花指令识别特征通用。

## 1. 花指令识别与去除

### 识别和避免反汇编中遇到的花指令
作者:skeep

核心前提:x86 指令密集编码,16KB 随机数据 98% 能反汇编成有效指令——**能被反汇编成功 ≠ 真实代码**。判「这区域是不是垃圾」的特征清单(仅分析 bootloader/内核/驱动时 Ring0 指令才合法):
```
Ring0 特权指令(用户态出现即垃圾): IN/INS/INSB/INSW/INSD  OUT/OUTS/OUTSB/OUTSW/OUTSD  IRET/IRETD  ARPL  ICEBP/INT 1  CLI/STI  HLT
便利指令(编译器不生成、手写才用;占 opcode 空间近 1%,花指令高频):
  ENTER/LEAVE(编译器用 PUSH/MOV/SUB)  LOOP/LOOPE/LOOPZ/LOOPNE/LOOPNZ  PUSHA/POPA(会存 SP 自身)
不太可能的数学指令:
  F*/WAIT/FWAIT(浮点;例外:shellcode 用 FPU 取自身指针、3D 程序正常)  SAHF/LAHF(高级语言不会产生)  AAA/AAS/AAM/AAD(BCD 远古单字节)
  SBB(与 SUB 似占 3.5%;合法场景 32 位下做 64 位数学)  XLAT(单字节查表)  CLC/STC/CLD/STD(合法场景在 REP 串操作附近)
远指针指令(16 位产物,32 位代码出现即垃圾): LDS/LSS/LES/LFS/LGS
```
**指令前缀信号**:32 位代码大量 16 位寄存器(AX 而非 EAX——前缀字节落 ASCII 字母区,反汇编文本高发);助记符前频繁 `LOCK/BOUND/WAIT`;段前缀 `FS:/GS:/SS:/ES:` 出现在**不寻址内存**的指令上、`POP SS`、写 segr7 → 花指令(合法 32 位只在特定场景用 FS/GS)。用法:上述特征高频成片出现 → 整段判垃圾,不当代码读。

### Android记去花指令还原算法
作者:neilwu

**样本**:强网杯 flower.apk(ARM32 Thumb),JNI `MainActivity.check` → `sub_F34`(输入校验),其内 `sub_F8E`/`sub_FD0` 无法 F5。**流程一:JUMPOUT 修复(Thumb)**——F5 出 `JUMPOUT(...)` = 函数被切成碎片函数;按 IDA 提示找真实落点(如 `sub_F8E` 应跳 `0xFA4 = 0xF98+0xC`),在 0xF98 patch 无条件 B:
```python
def put_unconditional_branch(source, destination):
    offset = (destination - source - 4) >> 1
    if not (-2097152 <= offset <= 2097151): raise RuntimeError("Invalid offset")
    if offset > 1023 or offset < -1024:    # 超 B 条件码 11 位范围,patch 4 字节 B.W(0xF000/0xB800 前后缀对)
        PatchWord(source, 0xf000 | ((offset >> 11) & 0x7ff)); PatchWord(source+2, 0xb800 | (offset & 0x7ff))
    else: PatchWord(source, 0xe000 | (offset & 0x7ff))
```
patch 完对函数区域 **U 取消再 P 重建**即可 F5;`sub_FD0` 同法。

**流程二:花指令字节模式去除**——形态(反汇编成 `MOV R3, PC` 类:把 PC 写寄存器制造错位,紧跟垃圾数据被切成指令),26 字节:
```
8F 46 [r] 46 00 DF 8F BD BF 46 70 47 [n] BC 8E BC 08 46 11 46 1A 46 3B 46 80 BC  → 00 × 26
```
特征:首两字节 `8F 46` 固定、第 3 字节寄存器号变化、`00 DF`/`8F BD` 等骨架固定、`70 47` 后跟 `xx BC` 变化;同函数多组只有寄存器字节和小常量不同。动态确认不执行(不可执行花)或无效果(可执行花)后整体替换为 0,P 重建函数 F5。

**流程三:算法还原**(去花后伪代码仍混淆:大量 `(&dword_0+3)` 花算术 + JUMPOUT 混合,动态调试验证):
1. CRC16(多项式 0x1021)算输入校验值 `v5`;
2. `v12=v5&0xF`、`v13=(v5>>8)&0x3F` 决定填充参数;首字符填充+明文+尾字符填充到 128 字节;
3. 16 轮×8 字节分组加密:每轮与 key1 `{0x11,0x22,0x33,0x44,0x55,0x66,0x77,0x88}` 和 key2 `{0x77,0x23,0x9D,0xAC,0x13,0x27,0xCF,0xFE}` 异或,再做 28×(v5&0xF+16) 次 4bit 半字节轮转(高/低半字节交换组合),最后整体异或 0x88;
4. 与 128 字节目标密文比较。
要点:**花指令只挡静态,算法本身往往是对称轻量自定义分组**,去花后按「校验→填充→轮函数→比较」四段拆(key 与中间值断点打 `loc_11B0`/`loc_10AA` 动态取)。

## 2. IDA+Hex-Rays 路线

### Hex-Rays: 十步杀一人,两步秒OLLVM-BCF
作者:葫芦娃

BCF 原理:用**只初始化、不写入的全局变量**构造不透明谓词,结果恒定 → 永远只走真实分支。F5 典型:`while(1){ do{ ...一堆 if(dword_XXX & 1) 恒定判断... }while(v10^1); }`,谓词变量在 .data 段(`dword_B004 DCD 0xD14E403C` 起连续 dword 表)。
**两步去除**:Hex-Rays 自带 DCE 本可消永假分支,不消的原因是谓词用的全局变量段**可写**(优化器不能假设恒定)。操作:`Edit Segment` → 选中 `.data` → **去掉 Write 勾** → 重新 F5,谓词被当常量折叠,虚假分支全消。边界:.data 里只有 BCF 谓词变量时最干净;IDA 6.9 起有效;只改分析视图不影响文件。

## 3. Binary Ninja 路线

### 使用Binary Ninja去除ollvm流程平坦混淆
作者:krash

**样本**:libvdog.so(娜迦)+ 自编译 cff(均 ARM64 fla)。工具链:Binary Ninja(HLIL)分析 + Keystone 汇编 + IDA 新建段放 patch。**分析阶段**提取三样:各 case 入口块、出口块、出口跳转目标 case(条件跳转还要真假分支与 case 对应):
- **case 入口识别**:LLVM 生成 switch 代码不能用跳转表时退化为**二分查找**,查到最后必有一条对 case 编号的精确测试:`bool cond = x9.w9 != 0x76579ace; if (cond) then 0x704f0 else 47@0x70688` → 假分支 0x70688 是 case 入口;`if (x8 == 0xdcf244e1) then 439@0x71080` → 真分支是入口;
- **case 出口识别**:包含「对状态变量赋值」的基本块:`aop_init(); uint64_t x8_1 = 0xc88d21cd; goto 0x704f0`(写新 state 回分发器);
- **条件真假对应**:case 尾部两个 state 赋值块,查目标块入边类型:
```python
def resolve_branch_condition(state):
    il_bb = state.il_basic_block
    assert len(il_bb.incoming_edges) <= 1
    return il_bb.incoming_edges[0].type == BranchType.TrueBranch if len(il_bb.incoming_edges) == 1 else True
```
边界(不处理也可保守跳过):一块**同时是 case 入口、出口、分发器一部分**;分发器内变量对变量比较需回溯;处理不了不 patch 保留原分发器——**保守修复**,只影响还原完整度不影响正确性。

**修复阶段**:难点是 patch 空洞难找、编译器优化移动过代码。策略:**不在原地址挤空间,IDA 新建段(0x4000000)放全部 patch 代码,原分发器有意保留**——未识别后继的 case 仍走原分发器;全部 state 后继 patch 完,分发器变不可达被自动优化掉。

**坑:编译器合并块**(其他文章都没讲):两个 case 的公共头/尾被编译器合并进一个块:
```c
case 1: case 2: {
  puts("enter case 1 or 2");          // 合并的头(不属于任何单 case)
  if (state_var == 1) { puts("case 1"); state_var = 2; }
  else               { puts("case 2"); state_var = 3; }
  puts("exit case 1 or 2");           // 合并的尾
}
```
解法 = **代码拷贝**:把「分发器入口→case 入口」与「case 出口→分发器入口」路径上的所有指令拷进 patch 区,patch 后执行序列 = 原 case 指令 + 拷贝指令,语义等价拆回独立 case;漏识别的 case 走回分发器再进,结果仍对。

**多出口 case**:一个 case 可多个出口(TBNZ/CBZ/CSEL+B 并存),必须**所有出口逐一 patch**。单出口模板(出口1 改跳 patch,出口2 保持):
```
b    patch_code                      ; 出口1 改跳 patch(原:tbnz w8,#0,to_dispatcher)
cont: ...                           ; 出口2 保持原样(cbz w0,to_dispatcher)
patch_code:
tbnz w8, #0, to_case_entry          ; 复制原出口指令语义
b cont
to_case_entry:
  [patch 时覆盖掉的指令]
  [离开当前块到分发器入口的所有指令]        ; 代码拷贝
  [分发器入口到目标 case 入口的所有指令]    ; 代码拷贝
  b 目标case
```
双出口(CSEL 型)——**不能在 CSET 后直接跳走,后面的 MOV 是活跃指令**:
```
cset w7, eq                   ; !!! 保留,不可提前跳转(原:csel w7,w15,w14,eq)
mov  w20, w0
b    patch_code
patch_code:
cbnz w7, true_branch
cbz  w7, false_branch
true_branch:  [覆盖指令][到分发器][分发器到真分支]  b 真分支
false_branch: [覆盖指令][到分发器][分发器到假分支]  b 假分支
```
实例(vdog 0x704dc,前驱 loc_704CC 的 `LDR W9,[X19,#0x18]` 会被覆盖):patch 区先补 `LDR W9,[X19,#0x18]`,再原块指令 `STR W9,[X19,#0x1C]`,再拷贝整条分发器二分 CMP 链,最后 `B loc_70778`(0x6fa40fc9 的后继)。工程数据:vdog JNI_OnLoad 修复 21KB patch/15 分钟;拷贝指令要**过滤死代码**否则函数过大 IDA 拒绝反编译;拷贝 PC 相关指令(调用/全局引用)需做**重定位修复**;vdog JNI_OnLoad 有 **6 个分发器**(魔改 ollvm 或 inline),状态变量与分发器自动识别是待办;验证:fla 四分支函数还原后 F5 与源码语义一致,JNI_OnLoad 反调试/签名校验/包名检查全可读。

## 4. ARM64 专项

### ARM64 OLLVM反混淆
作者:无名侠

纯 Unicorn+Capstone 模拟执行(不用 angr/miasm,arm64 支持不佳)。块二分:**虚假块只含流程控制指令,真实块含任何真实指令**;关键是找真实块间顺序/分支(csel)关系,Keystone patch 直跳。

**第一步:Capstone 反汇编切块 + 引用计数**(`md = Cs(CS_ARCH_ARM64, CS_MODE_ARM); md.detail = True`):
```python
# 遍历 md.disasm(bin1[offset:end], offset):跳转/ret 指令(i.groups 非空)结束一块,记 saddress/eaddress/ins;
# IMM 操作数记 naddress(跳转目标);自跳(imm==address)= 死循环入 dead_loop;每个跳转目标计数 processors[imm] += 1
for dead in dead_loop: processors.pop(dead, None)   # 娜迦样本有死循环路径,必须剔除
```
**第二步:识别真实块**——初筛:被 >1 块引用的目标即分发器,引用分发器的块是候选(`naddress in processors and processors[n]>1`);复筛(特征码):虚假块也可能引用分发器,按「指令助记符+操作数类型」拼特征码匹配(与寄存器/常量无关):
```python
def get_code_sign(block):      # 'movz'+'12'(imm+reg) 这类助记符+操作数类型串接
    sign = ''
    for i in block['capstone']:
        sign += i.mnemonic
        for op in i.operands: sign += str(op.type)
    return sign
# ollvm 虚假块特征码库(按样本积累):
ssign = {'b2','cmp11b.ne2','cmp11mov11b.ne2','movz12movk12b2','movz12movk12cmp11b.ne2',
         'movz12movk12cmp11mov11b.ne2','movz12movk12movz12movk12b2','movz12movk12cmp11movz12movk12b.eq2',
         'movz12movk12cmp11movz12movk12b.ne2','ldr13b2','...'}
def is_real_block(item):
    sign = get_code_sign(item)
    if sign in ssign or sign.endswith('movk12movz12movk12b.ne2'): return False
    return any(insn.mnemonic not in ['movz','movk','cmp','b.eq','b.ne'] for insn in item['capstone'])
# ↑ 含任何非流程控制指令 = 真实块;剔除 fake 后,ret 块不引用任何块,单独补入 real_blocks
```
**第三步:Unicorn 模拟执行找后继**:
```python
mu = Uc(UC_ARCH_ARM64, UC_MODE_ARM)
mu.mem_map(0x80000000, 0x10000*8); mu.reg_write(UC_ARM64_REG_SP, 0x80000000+0x10000*6)   # 栈
mu.mem_map(0, 4*1024*1024); mu.mem_write(0, bin1)       # 代码,so 按基址 0 映射
mu.hook_add(UC_HOOK_CODE, hook_code); mu.hook_add(UC_HOOK_MEM_UNMAPPED, hook_mem_access)
```
hook_code 五个核心技巧(全在指令级回调):
- ① 跳过一条指令(禁用 bl/非栈内存访问,屏蔽真实代码副作用):`mu.reg_write(UC_ARM64_REG_PC, address+4)`;
- ② 内存访问白名单:操作数含 `[` 且目标不在栈区 0x80000000~+0x80000 → 跳过该条;bl/blx 一律跳过(只要 ollvm 路径,不要真实执行结果);
- ③ 命中下一个真实块:`isSucess=True; distAddr=address; mu.emu_stop()`;
- ④ csel 分支人工控制(ollvm 条件分发靠 csel 选 state):读 v1/v2,按 `branch_control` 写 `regs[0]=v1/v2` 再 PC+size;
- ⑤ 简易断点调试:address 命中进单步,'>' 空回车步过 / 's' 停 / 'r' 退出 / '!x0' 打印寄存器。

寄存器名转换 + 上下文保存恢复 + 路径搜索:
```python
def reg_ctou(regname):   # capstone 名 → unicorn 常量:w0-w28→W0+idx;x29→1,x30→2,其余 x→X0+idx;sp→4

    flow[pc] = []

```
结果:graphviz 画 flow 流程图;Keystone 按 flow 回写——顺序块尾 `ks.asm("b #%x" % dist)`;csel 块 `ks.asm("b%s #%x;b #%x" % (cond, d1, d2))`(cond 取自 csel 条件码)。
要点归纳:引用计数找分发器 → 特征码筛虚假块 → Unicorn 单向搜每真实块后继(csel 双向)→ flow 字典 → Keystone 回写;真实块内指令不模拟副作用(bl/访存全跳过),只让 state 流转。

### ARM64 OLLVM反混淆(续)
作者:FraMeQ

对上篇的补丁(总思路不变:识别真实块/序言/retn/垃圾块 → 模拟或符号执行定前后关系 → 修复):

**坑 1:教程 CFG 与实战不符**——教程样本 Debug 编译保留「预分发器」(可用《利用符号执行去除控制流平坦化》经典定位法);实战 Release 把预分发器优化掉,CFG 形态完全不同,经典方法失效。**先确认目标 so 编译优化程度再选定位法**。
**坑 2:引用计数法两缺陷**——分发器后跟子分发器时子分发器也被误判真实块(原方案靠特征码补丁);且会**漏掉**部分真实块。

**找真实块三次迭代**(angr CFG 的 supergraph 上):
- 思路一(失败):被引用最多的块=主分发器,引用它的=真实块——Release 下部分真实块引用**次分发器**,出现漏识别(非误识别);
- 思路二(补漏):主分发器起 DFS 遍历后继记录访问列表,当前块后继已在列表(成环回分发器)→ 上一个遍历到的块是真实块:
```python
def get_relevant_nodes(supergraph, node, founded_node):
    founded_node.append(node)
    for i in supergraph.successors(node):
        if i not in founded_node: get_relevant_nodes(supergraph, i, founded_node)
```
- 思路三(处理合并块):Release 合并相邻真实块公共代码(两个 puts 优化成一个)→ 真实块的前继还是真实块。规则:**前驱若唯一后继已是已识别真实块,则它也是真实块**(在上函数中加单后继判断,把 `supergraph.predecessors(node)` 追加进 relevant_nodes)。
仍未解决(人工兜底):叠加 -bcf 出现死循环块,真实块被打散成两个,前半识别不出 → 手动补进列表;patch 条件跳转个别块条件完全相反(真假日标互换)需人工核对。参考:GitHub cq674350529/deflat(angr 系符号执行去平坦化,基于 supergraph 的块分类思路)。

## 5. 字符串混淆修复

### ollvm字符混淆修复
作者:einsteinzl

场景:孤挺花(上交 GoSSIP,基于 ollvm)字符串加密。特点:**解密函数在 initArray 里,等长加密、原地解回 .data 原位置**——so 加载完字符串已在内存恢复,可一次性 dump 回静态文件。步骤:
1. IDA 看 initArray:一批 `.datadiv_decodexxx` 命名函数即孤挺花解密函数(每个对应一批加密串);
2. `readelf -S libxxxxx.so` 找加密字符表 section 的文件偏移与大小(实测 0x7f0000/0x1ca8,.data 尾部区域);
3. gdb attach 运行中进程(so 已加载、initArray 已执行),dump 该内存区间——即解密后明文表;
4. 0x1ca8 字节直接**回填 so 文件 .data 同偏移**,IDA 重载:字符串全可读,交叉引用正常解析;
5. 表上方紧邻还有**偏移表**(加载时初始化为实际虚拟地址,非密文),回填后要 beyond compare 类工具对照修正;
6. 修复后的 so 要正常运行,需**去掉 initArray 里的解密函数注册**(字符串已明文,重复解密会破坏数据)。
本质:利用「等长+原地解密」把运行时状态一次性静态化。适用判断:`.datadiv_decode` 体内是对固定区间的循环 XOR/查表,且写入目标与密文区间重合。

## 6. IDA&FRIDA 联调

### 初试IDA&FRIDA联合调试简单ollvm保护的加密函数源码
作者:无造

场景:轻 fla 混淆的加密函数,IDA Trace 拿到日志但难定位计算点 → 「IDA 静态读结构 + Frida hook 对拍数据流」还原完整 C 源码。轻混淆 F5 仍可读,比啃 trace 汇编快一个量级。
1. **入口定位**:函数 e 内直接调 `sub_1500C(v42, v41)`(v42=输入 bytes,v41=输出 key),hook 验参数与返回值:
```javascript
Interceptor.attach(base_native.add(0x1500C), {
  onEnter: function (args) {
    this.args0 = args[0];   console.log("args0:", hexdump(this.args0));
    var args1addr = ptr(args[1]).add(Process.pointerSize*2).readPointer();   // args[1] 二级结构:+2*8 处才是字符串本体
    console.log("args1:", args1addr.readCString());
  },
  onLeave: function (retval) {   // 返回值不在 retval,存在 args0+5*8 处指针指向的缓冲区——嵌套结构返回值位置要试探
    console.log("onLeave:", hexdump(ptr(this.args0).add(Process.pointerSize*5).readPointer()));
  }
});
```
2. **逐层下钻**(IDA 静态)+ 寄存器约定:`sub_1500C` 算加密后总长(lenStr+6 头+padding),引入写死串 `"www.pediy.com&kanxue"`,转调 `sub_13CE4`(x0=输入串/x1=长度/x2=固定串/x3=固定串长/x4=输出 buff);`sub_13CE4` 核心:6 字节头(固定 `79 79`(yy)+`03`+lenPadding+`00 01`)→ 拷明文 → 查表 `byte_42108`(0x63,0x7C,0x77,0x7B…即 AES S 盒)逐字节替换 → `sub_13808` 用固定串生成 0x10 字节轮密钥(固定串先过 S 盒,再按 4 字节组 bswap32)→ `sub_172D0` 做 3 种模式字节轮转(AABBCCDD→BBCCDDAA 类)→ 轮转结果与轮密钥 `key[i%4]` 异或,含 `part>>(32-i%4*8) ^ part<<(i%4*8)` 移位混合;
3. **还原验证**:按结构写 C 复刻(myenc),同输入比对输出 hex 一致即成功。
可复用要点:hook 参数是嵌套对象时用 `ptr(args[n]).add(k*8).readPointer()` 逐槽试探;返回值藏入参缓冲结构时 onLeave 从 `this.args0+k*8` 回读;轻混淆下「静态分层看结构 + 动态只验数据流」比纯动态 trace 快一个量级;加速识别:0x63,0x7C,0x77,0x7B 开头的 256 字节表直接按 AES S 盒处理,bswap32+分组移位异或是轮密钥调度常见长相。

## 1. Unicorn 反平坦化(arm32 TBB/TBH)

### Unicorn反ollvm控制流平坦化之bb
作者:欧阳峰峰

**样本**:arm32 so,fla 后 F5 大 while+switch;目标函数选 app 日志输出函数(劫持 `__android_log_write`/`__android_log_buf_write`)与字符串解密函数——混淆 so 里这两类是天然还原靶标。
**fla 的 IR 生成规则**(写识别器依据):① 首块 AllocaInst(switchVar)+StoreInst(随机初值)+br loopEntry;② loopEntry:LoadInst+SwitchInst 查表跳;③ loopEnd:br 回 loopEntry;④ 真实块:无条件分支→去原 br 加 StoreInst(后继 switchNum)+br loopEnd,条件分支→SelectInst 选 switchNum 再 store;⑤ switchDefault:br 回 loopEnd。调试期 `Function.viewCFG()` 在 `runOnFunction` 前后 dump 对照。**注意:IR 层是 switch,但 arm32 最终机器码没有 switch 指令**——落地成多块 cmp 比较链,静态识别按汇编形态,不能按 IR 形态。

**unicorn 还原四步**(TBB/TBH 分发):
1. **找分发指令**:Capstone 遍历函数匹配 `TBB`/`TBH`,取一组 cmp:第一个 cmp 操作数=函数 `pop` 块入口号;第二个 cmp 操作数+1=switch 表项数;
2. **算 case 地址**:`case_addr = pc+4+4*table[i]`(TBB 每项 1 字节,TBH 2 字节)→ **switchVar↔真实块入口映射**;
3. **模拟所有路径**:从 tbb/tbh 起 unicorn 模拟,退出时机=执行到 `pop`(函数退出)或回到分发块;退出读 **R3**(switchVar 所在寄存器)查映射 → 下一真实块地址 + patch 位置;
4. **keystone patch**:按映射把分发块尾跳转改成真实块直跳。

**坑**(无法全自动,按函数适配):switch 特征可能是 `cmp/bhi/tbb` 组合;case 链嵌套 switch 表(嵌套平坦化);switchVar 非 mov 立即数而是寄存器运算生成;一个真实块按内部结果跳不同后继,通过 `ITE/MOVELT/MOVEGE` 条件执行给 R3 赋值——单次模拟只走一条路,未覆盖分支要改条件/NZCV 后重跑补齐。

## 2. Unicorn trace 算法还原(arm64)

### 使用unicorn来trace还原ollvm混淆的非标准算法
作者:misskings

**适用判据**:算法纯净(不依赖 JNI/系统调用上下文),F5 分支爆炸但输入输出简单 → unicorn 整段模拟 + 全指令 trace。**样本**:ollvm9.apk `UUIDCheckSum(input,len,output)`,IDA 定边界 `start=0xfcb4 end=0xff2c`。
**铁律:别用 apk 解包的 so,必须真机运行时内存 dump**(frida_dump `dump_so`),dump 带完整重定位可直接执行;文件名里的基址(如 `0x7eae047000`)即模拟基址。

**unicorn 环境搭建**(完整可跑):
```python
uc = unicorn.Uc(unicorn.UC_ARCH_ARM64, unicorn.UC_MODE_ARM)
code_addr = 0x7eae047000                    # dump 时 so 真实基址,与文件名一致
uc.mem_map(code_addr, 8*0x1000*0x1000)      # 代码区给大,内存不值钱
stack_addr = code_addr + code_size          # 紧挨代码区划栈;stack_top = stack_addr+0x1000-0x8(64 位偏 8 字节)
uc.mem_map(stack_addr, 0x1000)
args_addr = stack_addr + 0x1000; uc.mem_map(args_addr, 0x1000)   # 再划一块放参数
uc.hook_add(unicorn.UC_HOOK_CODE, hook_code)                      # 逐指令回调
uc.mem_write(code_addr, open(dump_path,'rb').read())
uc.mem_write(args_addr, input_str.encode()) # 随机入参,便于区分常量与输入相关值
uc.reg_write(UC_ARM64_REG_X0, args_addr); uc.reg_write(UC_ARM64_REG_X1, len(input_str))
uc.reg_write(UC_ARM64_REG_SP, stack_top)
uc.emu_start(code_addr+0xFCB4, code_addr+0xFF2C)   # IDA 偏移 + 基址;出参写在入参缓冲区,mem_read(args_addr) 读回
```

**定制 trace 回调**(比裸打汇编强一个量级的三件事):① 每行汇编后打印该行用到的所有寄存器当前值;② **延迟一行打印目标寄存器新值**——下一指令 hook 里读上一条第一个寄存器=执行后值(`pre_codestr`/`pre_regname` 全局暂存);③ **内存监控**:watch 列表地址每 0x10 字节 hex 快照,变化即打印:
```python
cs = capstone.Cs(capstone.CS_ARCH_ARM64, capstone.CS_MODE_ARM); cs.detail = True
reg_names = {"X0": UC_ARM64_REG_X0, ..., "W28": UC_ARM64_REG_W28, "SP": UC_ARM64_REG_SP}  # 完整表见 unicorn.arm64_const
def hook_code(uc, address, size, user_data):
    for inst in cs.disasm(uc.mem_read(address, size), size):
        # 1) 先补打上一条执行后寄存器值(pre_codestr += "\t//%s=0x%x" 后 print)
        # 2) watch_addrs 逐地址 b2a_hex 快照,变了就 print 并更新
        # 3) 当前行:re.findall(r'[^0]([wx][0-9]+)', op_str, re.I|re.M) 抓寄存器名;第一个=被写寄存器存 pre_regname
        #    拼行存 pre_codestr,has_pre=True
```
输出效果(执行前值在前,`//` 后是执行后值):
```
0x7eae056cc8: ldrb w22,[x0,#0x18] ------x0=0x7eb6048000 w22=0x0 //w22=0x46
0x7eae056f0c: sub w9,w10,w9       ------w9=0x9d0 w10=0x9db //w9=0xb
```
**反向数据流推理链**(UUID 末两字节例):① 搜出参地址,`strb w8,[x0,#0x22]` → w8 从哪来;② 上溯 `ldrb w8,[x11,w9,uxtw]`,x11 watch 打出表内容 `30313233343536373839616263646566` = **"0123456789abcdef"**(hex 转 ascii 查找表);③ w9=0xb 是下标,上溯 `sub w9,w10,w9`(w10=0x9db、w9=0x9d0),再上溯 `and w9,w9,#0xfffffff0`;④ 0x9db 上溯到 `add w20,w23,w20`——按地址 grep 同一指令执行 29 次,每轮 w20=输入一字节 → **0x9db=输入部分字节累加和**(边界看 trace)。
关键技巧:**同一地址反复出现(循环体),按地址 grep 全部出现行,串起寄存器变化=该循环语义**。

**还原结果**(C 复刻对拍一致):
```c
char getAscii(int num) { char tmp[3]; snprintf(tmp,3,"%x",num); return tmp[0]; }  // 半字节转 hex ascii
int sum = 0, eorsum = 0xff;
for (int i = 0; i < strlen(input); i++) {
    output[i] = input[i] ^ 0x1;                                             // 主体:逐字节异或 1
    if (i==0x8||i==0xd||i==0x12||i==0x18) { output[i]=0x2d; continue; }    // UUID 分隔位 '-'
    // 特例位:i==0xe→0x34;i==0x23→input[0x22];i==0x22→input[0x9];i==0x17→input[0x18]^0x1
    if (i < 0x22) { int v = input[i]; if (i==0x17) v = input[0x18];        // 校验和只累加前 0x22 字节
                    sum += v; eorsum ^= v; }
}
output[0x22] = getAscii(sum - (sum & 0xfffffff0));   // 累加和低 4 位转 ascii
output[0x23] = getAscii(eorsum & 0xf);               // 异或和低 4 位转 ascii
```

## 3. Trace + frida hook 链还原

### 记使用Trace还原ollvm混淆的函数
作者:neilwu

**IDA trace 三模式**:Instruction tracing(每指令存被修改寄存器,主力)/ Basic block tracing(到达块地址)/ Function tracing(调用/返回)。trace 后回 CFG 看图,**变黄指令=真实执行路径**——一眼剥离 bcf 永假分支。
**frida 主动调用构造已知输入**(先拿黑盒对照再 trace):
```javascript
var sub_13CE4 = new NativeFunction(Module.findBaseAddress("libnative-lib.so").add(0x13CE4),
    "void", ["pointer","int","pointer","int","pointer"]);
sub_13CE4(Memory.allocUtf8String("pediy_imyang_lXcaTALmow"), 23,
          Memory.allocUtf8String("www.pediy.com&kanxue"), 20, Memory.alloc(0x26));
// 输出: 79 79 03 09 00 01 a4 b8 b6 c8 9e b4 7f 4f 29 b4 ...
```
**轮函数推理链**:
1. 参数1(23 字节)逐字节查表变换(0x70→0x51)得 `514d43f9 b6cff93c b6ef9f85 cf506afb ef208329 3ca8f563 63636363 63636363`(后两 dword 是 padding 固定值);
2. 参数3 只有**前 16 字节**参与后续(尾部截断看 trace 别看 F5);
3. 两组字节循环 8 次两两运算,**参数1 按循环次数变形**:`0次 514d43f9→514d43f9;1次 b6cff93c→cff93cb6;2次 b6ef9f85→9f85b6ef;3次 cf506afb→fbcf506a`(逐次字节循环移位,单独函数 sub_172D0 完成);
4. **第 1/5 次循环参数1 只变形不参与加密,由参数3 与常量 `0x68DE32AA` 运算**——「隔轮跳过一路输入」静态看不出,只有 trace 对拍能发现;
5. 轮函数核心(trace 寄存器直读):`X8=0xf5f5f531(参数3 变换值) X9=0x514d43f9(参数1 变换值); W11=X8&(X8^X9); W8=X9&(X9^X8)→0xa4b8b6c8`——`(a&~b)|(b&~a)=a^b` 的 MBA 展开;
6. 头 6 字节 `797903090001` 固定:动态看 x4 指向内存前 6 字节(多次确认)或 trace 搜赋值。
**坑**:连续内存赋值拼装在 trace 里对齐费眼,按「先搜出参地址被谁写→再看写入值来自哪条指令」倒着追,别顺着读 15 万条。

### ollvm算法还原案例分享
作者:咸鱼炒白菜

**定位链(纯 frida)**:① jadx 看 `MainActivity.e(byte[])` 为 native 结果函数;② hook `RandomStringUtils.randomAlphabetic` **固定随机后缀 "lXcaTALmow"** → 黑盒输入输出可复现;③ hook Java 层 `e` 打入出参 hex 拿基准对;④ hook `sub_184EC`(被调三次第三次 arg1 是结果)→ 引用回溯到 `sub_13CE4(input, inputlen, tb, tblen, output)` 关键算法。
**hook 组合拳**:
```javascript
RandomStringUtils.randomAlphabetic.overload('int').implementation = function (a) { return "lXcaTALmow"; };  // 固定随机串
Java.choose("com.kanxue.ollvm5.MainActivity", { onMatch: function (inst) {    // Java 主动调 native
    console.log(ByteString.of(inst.e(Java.array('byte',[0x70,0x65,0x64,...]))).hex()); }, onComplete: function () {} });
Interceptor.attach(base.add(0x13CE4), {   // native 层确认签名;output 延迟到 onLeave 读
  onEnter: function (args) { console.log(hexdump(args[0]), args[1]); arg4 = args[4]; },
  onLeave: function (r) { console.log(hexdump(arg4)); } });
```
**字节变形确认**(hook 一把):`172D0 onEnter 0xb6cff93c → onLeave 0xcff93cb6;0xb6ef9f85→0x9f85b6ef` 对拍 → `sub_172D0(v) = v 循环右移 8×轮次位`。
**识别 AES S-box**:查表 `byte_42108` 开头 `63 7c 77 7b f2 6b 6f c5 30 01 67 2b fe d7 ab 76` = 标准 S-box。**IDA 静态搜不到 MD5/S-box 特征的原因:OLLVM 指令替换把常量打散进运算**——必须 hook/trace 动态确认表内容。
**还原算法**(对拍通过):
```c
static char keytb[] = "www.pediy.com&kanxue";                 // 参数3
static char keytbde[] = {0x31,0xf5,0xf5,0xf5, 0xf9,0x43,0x4d,0x51, 0xa8,0xfb,0x31,0xb6, ...};  // sub_13808 从 keytb 派生
int REV(int v) { return ((v<<24)&0xFF000000)|((v<<8)&0xFF0000)|((v>>8)&0xFF00)|((v>>24)&0xFF); }
int keygen_13CE4(input, inputlen, tb, tblen, output) {
    sub_13808(tb, tblen, o13808);    // key 派生表;头 6 字节 = 79 79 03 [长度混淆式 (-len^0xFFFFFFF0)&-len] 00 01
    for (int i=6; i<=0x25; i++)                               // input 逐字节过 S-box,越界补 0x63
        output[i] = (i-6 >= inputlen) ? 0x63 : byte_42108[input[i-6]];
    for (int i=0; i<tblen; i++) tb[i] = byte_42108[(uchar)tb[i]];   // key 也过 S-box
    for (int i=0; i<=(0x25-0x6)/4; i++) {                     // 8 轮,每轮一个 dword
        uint tmp1; memcpy(&tmp1, keytbde+4*(i%4), 4);         // key 流,4 dword 循环
        uint tmp2; memcpy(&tmp2, output+i*4+6, 4);
        tmp2 = REV((tmp2 >> 8*(i%4)) | (tmp2 << 32-8*(i%4))); // 按轮次循环移位再字节反转
        int out = REV(tmp1 & ~tmp2 | tmp2 & ~tmp1);           // MBA 异或
        memcpy(output+(6+i*4), &out, 4);
    }
}
```
套路:**版本头(定值)+ 长度混淆字节 + S-box 查表 + key 流循环取 dword + 移位变形 + MBA 异或**——风控 so 高度复用,先按模子对再抠细节。

### ollvm后的算法还原案例分享
作者:咸鱼炒白菜

**hook 链从 JNI 入口打到 MD5**(每 hook 一个函数修正一次签名,纯黑盒):
1. `RegisterNatives` hook 拿 `sign1→0x10BE8`(动态注册,导表没有);
2. F5 见 `sprintf` 连打 16 次(二进制转 hex 典型形态)→ 其上 `sub_1494C4(&in,16,&out)` 即关键算法,hook 确认 `(input,inputlen,output)`;
3. hook `sub_14141C(input,len,output)` → 16 字节摘要;hook `sub_1390B8(ctx,data,len)` 被调 4 次,调用形态直接是 **MD5Update 序列**:`(ctx,"421d38d9...",0x20)` salt(32 字符)/ `(ctx,input,0x10)` / `(ctx,bits,8)` 内部长度填充 / 第 4 次在 Final 内;
5. **CyberChef 对拍 `MD5(salt+input)` 一致坐实**;IDA 搜不到 MD5 常量(IV `01234567 89abcdef fedcba98 76543210` 反而在 hook 的 ctx 里看到)——**「hook 到 ctx 看 0x30 处 IV」比 IDA 搜常量靠谱**;
6. salt 来源:`.init_array` 三个函数中**第二个**完成字符串解密(静态密文与运行时不一致先查 init_array)。
**trace 设置**(IDA 动态调试器):`idc.SetReg(ea,"T",0)`(ARM64 必须把 T 切 0 否则断点打不上)+ `MakeCode`+`add_bpt`,函数头+结束处下断,trace 约 15 万条;**结合 F5 定位基本块范围**(trace 命中地址 ↔ F5 块互查)分段读。
**两个密码表动态定位**:表一:153F24 疑似 → hook 153F28 读 `this.context.x11` 对拍 → `v2015={0x3a,0x33,0x9b,0x79,0x61,0xf3,0x27,0x96,0xbe,0x5b,0x84,0xd2,0x6c,0xf5,0xb9,0x15}`;表二:`LDUR W16,[X29,#var_80]` 感觉是表 → 追写入找到 `ADRL X10, xmmword_1FF160`,frida `print_string` dump → `"151caed3cfc7e999ebf6b66d3e8e96cc"`(取 `i%8` 参与)。
**算法骨架**(两层大循环 MBA):
```c
for (int i = 0; i < 16; i++) {          // 第一轮:MD5 结果 → v2020[16];第二轮 v2020 与两表再混合出 16 字节
    int v1433 = md5_out[i];             // = MD5(salt + input)
    int v1434 = v2015[i];               // 密码表一
    int v47   = v2018[i % 8];           // 密码表二(字符串取模)
    // ……几十层 (~a & c | a & d) ^ e 形态 MBA 混合,输入只有 v1433/v1434/v47
    v2020[i] = result & 0xFF;
}
```
**MBA 化简套路**(OLLVM 花式全建立在恒等式上):`(~x&c | x&d)`=按位选择器(x 的位选 c/d),c/d 互补即 `x^c`;`(~0xa3&A|0xa3&B) ^ (~0x33&A|0x33&B)` = `A^B`(两组选择器异或,掩码抵消);`x&~x=0`、`x|~x=0xFF..`、`x^x=0` 全是死运算。多层取反混合**先按选择器恒等式逐层折叠再读**。

### ollvm CrackMe算法分析
作者:ddsf

核心一条:**取反混淆等价化简**:
```c
v = (~0xa3 & 0x5E58FB3C | 0xa3 & 0xA1A704C3) ^ (~0x33 & 0x5E58FB3C | 0x33 & 0xA1A704C3);
// 化简:v = 0x5E58FB3C ^ 0xA1A704C3(掩码抵消,纯常量)
```
方法:定位关键加密段→分段→每段对出参数与结果→对照 trace 寄存器值验证化简。trace 里大量「取反运算+固定数值」组合基本都能用选择器恒等式压回一条异或/与或。

## 4. Xposed 主动调用爆破(不还原算法)

### 利用Xposed对ollvm后的so中flag爆破
作者:PTRer

**判据**:算法懒得还原但**答案空间可枚举**(test(str) 3 字符大小写,52^3=14 万)→ 真机批量主动调用。三步:
1. **找关键函数**:jadx 看 `jnitest`,so 里嵌套 while+状态机即 fla;**从后往前分析**(从 sprintf/返回值处理倒推)更快锁定 `test`(0xF9A0),`test(sub_103C0(s))!=0` 即命中;
2. **等 so 加载完再注入**:hook `Runtime.loadLibrary0`(Android 8.1 里 System.loadLibrary 最终走它;**不同 Android 版本函数名/参数顺序不同,先看对应版本源码**),命中包名后 JNI_OnLoad 里加载自制 hookso:
```java
XposedHelpers.findAndHookMethod(Runtime.class, "loadLibrary0",
    Class.class, ClassLoader.class, String.class, new XC_MethodHook() {
  @Override protected void afterHookedMethod(MethodHookParam param) throws Throwable {
    if (param.args[1].toString().contains("com.kanxue.test2"))
        System.load("/data/data/com.kanxue.test2/files/hookso.so"); } });
```
3. **sandhook 主动调用爆破**:选 sandhook 因能直接拿 so 内函数地址调用(arm32/64 都行);**init 必须先完成才能 hook,封装的调用函数放 JNI_OnLoad 里触发**;so 推 `/data/data/<pkg>/files/`,关 SELinux,枚举 3 字母组合调 test 返回非 0 即 flag。
**取舍**:要 flag 不要算法且空间小 → 爆破快几个数量级;空间上亿(长 token)不通,回 §2/§3 还原。

## 5. 横向经验汇总

**定位关键函数固定套路**:① hook `RegisterNatives` 拿动态注册 JNI 地址(导表搜不到时);② F5 找 `sprintf`×N/`__android_log_*`/返回值组装点**从后往前**倒推;③ 逐函数 hook 修正签名 `(input,len,output)`,onEnter 存指针、onLeave 再读=黑盒输入输出对;④ 固定随机源(RandomStringUtils hook 返回定值)让样本可复现——对拍前提。
**动态工具选择**:算法纯净无 JNI → **unicorn+内存 dump 的 so**(离线快可控);依赖上下文/嫌搭环境 → **IDA 指令 trace**(真机准确,15 万条量级);只要黑盒复算/枚举 → **frida NativeFunction / Xposed+sandhook**(零还原成本)。
**高频坑**:apk 里的 so 直接喂 unicorn 会跑飞——必须 frida dump 内存态(带重定位);ARM64 下 IDA 下断要 `SetReg(ea,"T",0)`;静态搜不到算法常量(MD5 IV/AES S-box)≠ 非标准算法,指令替换打散常量,以 hook 到的内存为准;salt/密钥常在 `.init_array` 解密,静态密文与运行时不一致先查它;字符串表参与 `i%8` 取模这类细节,表内容用 frida print_string 拉运行时值;trace 读法永远**倒着追**(先搜出参被哪条 str 写→追写入值来自哪→循环体按地址 grep 聚合语义);`(a&~b)|(b&~a)`、`(~x&c|x&d)^e` 先 MBA 折叠再读,九成「复杂算法」折叠完就一层异或。

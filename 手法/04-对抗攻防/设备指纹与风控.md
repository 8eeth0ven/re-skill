# 设备指纹与风控

> 定位:按「风控采集与伪造」组织——风控 SDK 采什么、怎么采、服务端怎么交叉核验、黑产怎么分层伪造。
> 检测原理(frida/root/模拟器/无障碍怎么检)不重复,见《[检测原理全景.md](检测原理全景.md)》;
> 标识域函数五层链(Java→binder→libc→svc→kernel)见《[../09-函数全景/安卓函数分层全景.md](../09-函数全景/安卓函数分层全景.md)》§12。

## 1. 风控体系分层

```
┌─ 客户端采集 SDK ──┐   ┌─ 传输 ──┐   ┌─ 服务端 ─────────────────┐   ┌─ 处置 ────────┐
│ Java 层:系统 API  │   │ 加密上报 │→ │ 解密→特征提取→设备库归一   │→ │ 验证码挑战      │
│ Native 层:props/  │   │ (AES+   │   │ 规则引擎+模型打分         │   │ 降权/限流       │
│ 文件/传感器/binder│   │ protobuf│   │ 团伙图谱(设备-账号-IP)     │   │ 账号封禁        │
│ 环境检测(注入/root)│   │ 自定义) │   │ 黑名单/信任分             │   │ 设备拉黑        │
└───────────────────┘   └─────────┘   └───────────────────────────┘   └────────────────┘
```
- **采集 SDK**:大厂自研(阿里 mtop/mtgsig、小红书 shield、腾讯 vkey)或采购(数美/同盾/网易易盾/顶象)。形态是一个混淆 so + 少量 Java 壳,启动时初始化,业务请求前生成 token/签名+设备指纹串。
- **上报**:采集项序列化(protobuf/自定义)后 AES 加密,随机 key 混淆,部分字段在 native 完成拼接(例:网易易盾 libNetHTProtect.so 一次上报 350+ 条字段,protobuf 序列化+AES)。
- **服务端设备库**:把多源标识归一成一个稳定 device_id(单标识被改不塌),维护设备-账号-IP 图谱。
- **处置**:渐进式——先验证码挑战(滑块/点选),再限流降权,最后封号封设备。
**黑产对抗点全在「采集」与「一致性」**:
1. 改采集结果(L1~L2 hook)或改数据源头(L3~L4 改机);
2. 跳过客户端直接伪造协议(脱机挂)——此时行为/传感器/环境特征全缺,靠纯伪造补;
3. 服务端唯一可靠的抓手是**交叉一致性**与**硬件级证明**(Key Attestation,§8)。
移动端同构的 PC 案例:网吧计费/管理系统用「硬件序列号(CPU/主板/内存/硬盘)+会员卡」做身份,对抗思路同为改硬件序列号层(PC 侧走 WMI/注册表/SMBIOS 层修改)。

## 2. 设备指纹采集面全景表(核心)

组织方式:按采集信道分 6 组,共 66 项(64 行,其中 2 行各含 2 个标识)。列:标识 | Java 入口 | Native 入口 | 稳定性 | 伪造难度(骗过本地采集的成本,不含服务端交叉)。
函数分层(L1~L5)详见 09 区《安卓函数分层全景.md》。

### 2.1 系统属性类

| 标识 | Java 入口 | Native 入口 | 稳定性 | 伪造难度 |

**采表心法**(对抗时按此逐项过):
1. 同一标识**至少两处产生源**(Java 缓存/属性区/binder 服务端/vendor 进程),只改一处必穿帮(09 区§13 规律 7);
2. 稳定性越高(不可变+硬件固有)的标识,服务端权重越高,改它性价比最低;
3. 行为类无法「改」只能「造」——这是脱机挂与改机党的分水岭;
4. 采集 SDK 自己就是检测器:环境检测字段与指纹字段同包上报。

## 3. 一致性校验(风控怎么抓伪造)

风控服务端不指望单点,靠**交叉**。抓伪造的七类手段:
1. **多源交叉**:
 - IMEI 与厂商云端记录(换机不换卡/卡机绑定图谱);
 - ANDROID_ID 与 SettingsProvider 数据库(改内存返回值没改库,二次查询穿帮);
 - Build 属性与属性区双读不一致(09 区§10);
 - 传感器列表/GPU 扩展与机型库(千元机报骁龙 8 系 GPU = 实锤;安全客《设备指纹指南》);
 - CPU/内存/屏幕与 Build.MODEL 白名单比对。
2. **时间线**:新设备+老账号+首次下单优惠;boot_id 会话时长 vs claimed 开机时长;SD 卡种子文件 mtime 早于「恢复出厂时间」的矛盾(反用:种子文件 mtime 是「真实设备年龄」证据);firstInstallTime 与账号注册时间。
3. **传感器静默**:自动化没有加速度计波动;人手触屏必带微抖(陀螺仪 8-12Hz)、压力值随滑动渐变;脚本触控压力恒定+传感器静止(建议检测方按 1/9 比例抽样上报环境事件)。
4. **GPU/驱动指纹**:GLES 扩展顺序、着色器精度、EGL 版本串、渲染结果哈希(canvas hash)——与机型库比对,云真机/改机最容易在这一项漏馅(Web 侧 canvas 指纹同构技术)。
5. **协议侧**:请求时序等间隔、无人类思考停顿;心跳缺失;TLS/HTTP 指纹非官方客户端(§9 JA3)。
6. **挑战响应**:风控怀疑时下发验证码(§6)或 attestation 挑战(§8),答不出=设备拉黑。
7. **图团伙**:同 IP 段/同 WiFi BSSID/同充电模式/行为序列相似度聚类——单设备伪装再好,农场设备批量同构仍被图算法圈出。

## 4. 伪造策略分层(L1~L4)

| 层 | 手段 | 成本 | 存活率 | 典型检测手段 |
|------|------|------|------|------|
| L1 改数据源 | Xposed/frida hook Java API 返回假值 | 极低(脚本级) | 低 | native 层交叉(属性区直读/raw binder/自解析 apk);hook 痕迹检测(检测原理§2/§5.2) |
| L2 改 native 层 | hook libc/__system_property_get/改属性共享内存/GOT hook/注入 so | 中(需懂逆向) | 中 | 函数头 CRC、maps 扫描、svc 直调读文件、字符串扫描(检测原理§2.6/§2.9;降级链见 09 区《hook降级实战.md》) |
| L3 真实多开/改机工具 | AWZ/ALS、RshMod(Magisk+LSPosed 模块)、沙箱多开、群控、比特指纹手机 | 中(工具采购) | 中 | 改机软件包名/私有设备节点(如 /dev/wgzs);沙箱文件系统差异;框架 jar 与机型不符;传感器一致性 |
| L4 定制 ROM/内核注入 | 自编 ROM 改 property;APatch KPM 内核 hook sysctl_bootid;init/vendor 进程 ptrace 注入改 DRM ID;mount --bind IO 重定向一机多号;「不在客户端留任何痕迹,在产生地修改」 | 高(内核级工程) | 高 | 服务端硬件证明(Key Attestation §8);厂商云端交叉;时间线统计 |
L4 是 社区帖的核心论点:
- 五大产生地:system_server(hook SettingsProvider.call 改 android_id、hook PackageManager 隐藏包)、**其他 Apk**(小米 OAID 在 com.miui.idprovider 等 app 内)、内核 ID(boot_id,APatch KPM)、init 进程(DRM ID 产生于 android.hardware.drm@1.3-service.widevine,ptrace 注入 vendor 进程)、属性区;
- 客户端零注入:不 hook 目标 app 任何代码,痕迹自然消失;
- 一机多号:`mount --bind` 对 /data/data/包名 与 SD 卡目录做 IO 重定向,每个「号」一套数据视图;
- 现实约束:小米等新内核闭源驱动使自编内核是死路,APatch/KPM 是当前可行内核路径(07 区《内核Hook与无痕对抗.md》承接);
- 反向建议(检测方视角):自带静态 libc、避免 std::string(strlen hook 通杀)、单字段多形式获取、1/9 比例环境检测、logcat 异常上报。
物理层:双卡双待真机矩阵/设备农场/人工(打码)——协议特征与真机无异,靠图谱+行为聚类(§3.7)。

## 5. 风控 SDK 案例索引

### 5.1 阿里 mtop / mtgsig / 无线保镖

- mtop 是阿里无线网关协议,签名头 x-sign(x-mini-wua/x-sgext/x-umt 等)由 SDK native(so)计算;umidtt(设备指纹串)由无线保镖 libsgmain 体系生成。
- 美团 mtgsig(同为 mtop 系家族名):libmtguard 为重混淆 so(见 大厂抓包对抗档案 §6)。
- 相关:阿里云 Anti-Bot SDK SGAVMP——把签名逻辑编译为自定义字节码跑在自带 VM 里。
- 对抗要点:x-sign 生成在 so,unidbg/模拟执行是主流还原路径;设备侧改机必须同时骗过 umid 采集。

### 5.2 网易易盾 NetHTProtect(分析对象,厂商归属:推断)

350+ 字段 protobuf+AES(随机 key)加密上报(`/v4/c` 初始化、`/v4/a/up` 上传);采集含:SD 卡 statfs、DRM ID(dlsym libmediandrm)、70+ 条厂商 props、文件 stat(atime/mtime/ctime/inode)、6 目录文件树 hash、/proc/bus/input/devices、电池、GL_VENDOR/GL_RENDERER、emmc/soc serial、boot_id、微信 apk 路径、输入法列表;检测含:frida(linjector/re.frida.server 特征)、Xposed、libc .text/.rodata/.eh_frame CRC 校验、lineageOS/OpenHarmony、品牌框架 jar 对应机型、bootloader 解锁 6 props、群控(minicap/minitouch/stf)、模拟器(VMOS/X8/51/虚拟精灵)、改机软件(包名+/dev/wgzs)、/memfd:/jit-cache(检测 LSPosed)、getevent 序列上传后端 AI 分类模拟点击(CSDN 转载 u012971339/article/details/139120729)。

### 5.3 数美(smid / 天网)

- 设备指纹生成 smid 类唯一 ID,识别模拟器/改机/设备农场;「天网」体系融合设备风险+黑产情报图谱。
- 滑块验证码:缺口识别+轨迹模拟,见 §6。
- 攻击者视角评测:腾讯云开发者社区《以攻击者角度学习某风控设备指纹产品》(2020)——结论「设备指纹不是银弹」,交叉校验依赖多源。
- 注:smid 生成算法细节公开深析少,多见于付费圈。

### 5.4 同盾科技(Fingerprint)

公开深度逆向分析少;产品形态为数美同类:设备指纹+规则引擎+名单。**结论留白,遇实战再补。**

### 5.5 小红书 shield

- 签名头 shield(旧 x-s/shield);分析路径:jadx 定位 JNI_Load→IDA 分析 native 函数(签名校验函数如 sub_2e1f4 可 nop)→unidbg 模拟调用。
- 开源拼接规则:GitHub RedNote/Xiaohongshu-Shield-Algorithm(基于 v9.19.2 逆向,注明随版本变化)。
- 服务侧为「阿瑞斯」风控:IP 频控+设备指纹。
- 版本对抗:App 端 shield / Web 端 x-s 双轨。

### 5.6 腾讯 vkey / R 协议系

腾讯系风控 SDK(如 QIM/net 系):Java+Native 双层采集(电池/硬件/网络/位置),含 Xposed 检测与虚拟机识别;vkey 为其终端安全凭证头。

### 5.7 Google Play Integrity(海外基线)

取代 SafetyNet API:设备完整性(verdict: MEETS_DEVICE_INTEGRITY / STRONG)+应用完整性+许可;信号源含 verified boot 状态(ro.boot.verifiedbootstate,与检测原理§3.3 同源)。国内 app 不用,但出海产品以此为准。

## 6. 验证码对抗

风控处置链第一环。四类:
1. **滑块**:
 - 缺口识别:OpenCV `cv2.matchTemplate`/Canny 边缘检测定位缺口 x 坐标(2024 实战)。
 - 轨迹模拟:先快后慢(ease-out)+随机抖动+末端回弹,模拟人手加速度曲线;等速直线=必死。
 - 服务端反制:轨迹熵、起始 x 抖动、设备指纹联动(同 smid 高频挑战)。
2. **点选(点击式)**:目标检测(YOLO 系)+OCR 识别提示字序;OpenCV 模板匹配做初筛。
3. **九宫格/图标式**:
 - CNN 图像分类识别目标类;
 - 弱实现可用 md5 图像比对/切割定位(CSDN 20 种验证码识别思路,2024)。
4. **语音/短信**:打码平台与接码平台覆盖(边界:仅技术概述——人工/AI 打码平台市价分到毛级,合规红线,不展开操作)。
**成本公式**:识别成本(一次 CNN 推理/打码费)+轨迹库成本 < 一次挑战收益,黑产才打;风控故把挑战频率调到「真人无感、机器亏本」。验证码只是拖延,设备指纹标记才是处置本体。

## 7. autojs / RPA 检测与对抗

**原理**:Auto.js 基于 AccessibilityService——`onAccessibilityEvent` 事件回调里 `rootInActiveWindow` 拿控件树,`performAction` 模拟点击。
**检测面**(详细见检测原理§5.3,此处只列风控侧用法):
1. 无障碍开启状态+服务名列表(`Settings.Secure.ENABLED_ACCESSIBILITY_SERVICES` 含 autojs/airtest 等);
2. autojs 包名/类名/脚本文件特征(如 /sdcard/脚本、.js 工程结构);
3. 控件树遍历行为异常:高频 `rootInActiveWindow` 查询、AccessibilityNodeInfo 请求频率超人类;
4. 事件层:模拟点击 MotionEvent 缺压力/面积变化;getevent 序列 AI 分类。
5. 对照:检测/对抗两端系统梳理见本节与《检测原理全景.md》§5.3。
**对抗演进**:
- 黑产:改包名/混淆脚本存放路径 → 转协议直连(跳过 UI)→ root 注入 `/dev/input/eventX`(sendevent/uinput);
- 检测方:微信 8.0.52+ 控件混淆(节点 id 混乱化)使 AutoJs6 无法布局分析(GitHub SuperMonster003/AutoJs6 issue #463)——业务方主动把 UI「降权」对抗无障碍,攻防双向上移到协议层。

## 8. Key Attestation(硬件级证明)

**原理**(developer.android.com 官方文档):
1. app 在 Keystore 生成密钥时指定 `setAttestationChallenge(随机数)`;
2. TEE/StrongBox(KeyMint)为该密钥签发 **X.509 attestation 证书链**:根证书(Google 硬件根)→中间→叶证书;
3. 叶证书 extension 携带:verified boot 状态、bootloader 锁、ROM 补丁级别、屏幕锁、**Android 8.0+ 可严格认证硬件标识符(序列号/产品名/IMEI/MEID,受限需特权)**核心:Android 8.0 为此更新了 ASN.1 结构);
4. 服务端验证证书链到 Google 根 + 校验 challenge 回显 + 读 extension 里的设备状态。
**为什么难伪造**:
- 私钥在 TEE 内生成不可导出,attestation 只能由真硬件签;
- 证书链锚定 Google 硬件根 CA,自签链验不过;
- challenge 绑定会话,重放无效;
- 与「出厂时已录入厂商库的 IMEI」联动=设备身份终极背书。
**出口(黑产空间)**:
1. 旧设备:Android <7 无 attestation、大量存量设备只有软件 keymaster——检测方强制硬件级则误伤,只能分级;
2. 降级检测:伪造「设备不支持」走软件密钥路径,hook `KeyGenParameterSpec`/`KeyStoreGeneratorCallback` 移除 attestation 标志,骗 app 放弃硬件 attestation——开源实现 vvb2060/bypassKeyAttestation;
3. 反制:服务端比对「claimed 机型应有 attestation 能力」与「实际证书链」——旗舰机突然「不支持」即穿帮;Play Integrity verdict 做同样的事(§5.7)。
4. 全新硬件信任链(StrongBox/像素级防降级)逐步压缩出口,但在中低端机存量清空前,attestation 只能做「高价值操作强校验」而非全量门槛。

## 9. 脱机挂的风控自检清单

脱机挂(协议直连,无真 UI/传感器)上线前逐项自检:

### 9.1 协议与流量特征

- [ ] 请求时序:去等间隔——加思考延迟(对数正态分布)、会话间隔遵循人类作息;
- [ ] 心跳/长连接保活与官方 app 一致(官方有心跳而脚本没有=实锤);
- [ ] TLS 指纹:JA3/JA4 与官方客户端一致?
 - JA3=MD5(SSL 版本,密码套件列表,扩展列表,椭圆曲线,椭圆曲线点格式);JA4=2023 格式化串(更抗混淆),均已进 Cloudflare/AWS 等商用 bot 管理;
 - **移动端现状**:python requests/go 客户端的 BoringSSL/OpenSSL 栈与 app 的 OkHttp(Conscrypt/BoringSSL,cipher suite 顺序+ALPN+扩展)指纹不同;**frida 抓包分析后直接用脚本重放=TLS 指纹直接换族**;抓包代理(mitmproxy/Burp)介入时出口指纹是代理的(公开资料均为 Web 侧,移动端为同构推论);
 - 对策:请求经真机 OkHttp 栈发起(rpc 转发)或精确复刻 Conscrypt 握手参数(含扩展顺序),HTTP/2 还要比 SETTINGS 帧序/窗口;
- [ ] Header 顺序、User-Agent 与设备声明一致(申明小米却带华为 UA=低级穿帮)。

### 9.2 设备指纹一致性

- [ ] 单标识双读一致:本地返回值 == 属性区 == binder 服务端可见值(09 区§13 规律 7);
- [ ] 机型白名单自洽:MODEL↔CPU↔GPU 扩展↔屏幕↔传感器列表↔基带版本全对齐(§3.1);
- [ ] 时间线自洽:boot_id 会话时长、firstInstallTime、SD 卡种子文件 mtime、账号注册时间无矛盾(§3.2);
- [ ] 「正确的默认值」:Android 10+ 该拿不到 IMEI 就别报,报了反而异常;MAC 随机化值 02:00:00:00:00:00 要有(§2.1)。

### 9.3 行为模拟缺失(最大破绽)

- [ ] 触控:压力渐变+轨迹抖动+起始/终止速度曲线(不能等速直线);
- [ ] 传感器:操作前后加速度/陀螺仪有波动;跨天步数累积连续;
- [ ] getevent 层序列(若被采集)有真实多指/边缘事件—— 社区帖证明该序列会被上传做 AI 分类;
- [ ] 页面行为:滑动/滚动/停留时间分布与真人分布(非固定值)。

### 9.4 环境痕迹

- [ ] 注入痕迹:frida/xposed/root 隐藏链过一遍(《frida反检测对抗.md》《root与环境隐藏.md》);
- [ ] 时区语言与 IP 归属地一致;VPN/代理 tun0 按需隐藏;
- [ ] 不在同一 IP 段/BSSID 批量出现(图谱聚类,§3.7)。

## 一、jadx CLI 深度

### 1.1 全量反编译（标准姿势）

```bash
jadx -d jadx_full --show-bad-code --deobf -j 4 app.apk > jadx_full.log 2>&1
```

```text
实测输出（macOS 本机，F-Droid.apk 12.5MB）：
ERROR - finished with errors, count: 147      ← 正常！12MB 级 APK 几乎必有 error
产物：sources/ 11949 个 .java + resources/，共 132M
耗时：约 90s（-j 4）
```

要点：
- `--show-bad-code`：失败方法也吐出来（标注释），比空文件强。
- `-j 4`：处理线程数，默认 5；大 APK 调到物理核一半，IO 瓶颈时再加无益。
- **error 不是失败**：判定成功看 `sources/` 有没有产出 java，别看退出码（见坑 3）。

### 1.2 坑与降级（实测踩过）

**坑 1：`--deobf` 在非混淆包上帮倒忙。** 实测 JustTrustMe.apk（未混淆）：

```text
raw:     just/trust/me/Main.java   just/trust/me/R.java
--deobf: just/trust/p000me/Main.java   C0019R.java
```

`me` 只有 2 字符 < `--deobf-min`（默认 3），被强制改名 `p000me`；`R` 同理变 `C0019R`。**规则：确认包是 ProGuard/DexGuard 混淆才开 --deobf；正常包名里常见短段（me/io/ui/xx）会被毁掉。** 缓解：`--deobf-whitelist "just.trust.me.*"` 排除。混淆包二次跑时配 `--deobf-cfg-file app.jobf` 复用首跑映射保持一致。

**坑 2：`--fallback` 已废弃且语义变了（1.5.6）。** 实测输出仍是 `.java` 而非 smali，但方法体被清空（Main.java 只剩字段+空行）。**要 smali 一律 apktool（见第二节）。** 降级链：`--no-inline-anonymous`（匿名类不内联，修 Kotlin/回调反编译乱套）→ `--no-inline-methods` → 真不行 apktool 看 smali。

**坑 3：jadx 退出码语义。** `--no-res` 跑完 exit=3 但产物完好（还是那 147 个反编译 error）。**批量脚本必须以"sources/ 有 java"判活，别 `set -e`。**

### 1.3 --no-res 分离资源（快扫代码专用）

```bash
jadx -d jadx_nores -j 4 --no-res app.apk
```

```text
实测：123M→代码几乎同体积；resources/ 目录仍会创建但是空壳（find 无文件）
用途：只看代码逻辑、跳过资源解码提速；配合 grep 扫接口字符串
```

### 1.4 单类导出（秒级，定位后精读）

```bash
jadx --single-class org.fdroid.fdroid.FDroidApp --single-class-output FDroidApp.java app.apk
```

```text
实测输出：
INFO  - Saving class 'org.fdroid.fdroid.FDroidApp' to file '.../FDroidApp.java'
INFO  - done                       ← 秒级完成，适合反复迭代读一个类
```

1.5.6 里 `--single-class`（全名/raw/alias 均可）+ `--single-class-output` 均在。类名不确定先 `find jadx_full/sources -name "*.java" | grep -i keyword` 再导。

### 1.5 批量反编译脚本（实测可用）

```bash
#!/bin/bash
# batch_jadx.sh <apk目录> <输出根目录>：逐个 jadx，exit!=0 不中断
IN=${1:-.}; OUT=${2:-./batch_out}; mkdir -p "$OUT"; ok=0; bad=0
for apk in "$IN"/*.apk; do
  name=$(basename "$apk" .apk); echo "[*] jadx: $name"
  jadx -d "$OUT/$name" --show-bad-code -j 4 --no-res "$apk" > "$OUT/$name.log" 2>&1
  if [ -d "$OUT/$name/sources" ] && [ -n "$(find "$OUT/$name/sources" -name '*.java' | head -1)" ]; then
    echo "    ok -> $(find "$OUT/$name/sources" -name '*.java' | wc -l | tr -d ' ') java"
    ok=$((ok+1)); else echo "    FAIL"; bad=$((bad+1));
  fi
done; echo "[=] done ok=$ok fail=$bad"
```

```text
实测输出（macOS 本机）：
[*] jadx: FrecencyLauncher-debug
    ok(rc=3, err_lines=0) -> 5743 java   ← rc=3 但产物完好，正是坑3活例
[*] jadx: JustTrustMe
    ok(rc=0, err_lines=0) -> 3 java
[=] done ok=2 fail=0
```

## 三、radare2 工作流（Mach-O 与 ELF so 通吃）

### 3.1 Mach-O 实战（/bin/ls，macOS 自带样本）

```bash
r2 -q -c 'aaa; afl~main' /bin/ls          # 列 main
r2 -q -c 'aaa; pdf @ main' /bin/ls        # 反汇编 main
r2 -q -c 'aaa; axt @ sym.imp.printf' /bin/ls   # 谁 call 了 printf（xref）
r2 -q -c 'izz~usage' /bin/ls              # 字符串搜
r2 -q -c 'iS' /bin/ls                     # 段表
```

```text
实测输出（macOS 本机）：
0x100000960  153   3072 main                          ← afl~main
┌ 3072: int main (int argc, char **argv, char **envp); // noreturn
│  0x100000960  pacibsp ...                           ← arm64e PAC 指令可识别
axt printf → sym.func.100002328 0x1000023b4 [CALL:--x] bl sym.imp.printf（+4处）
izz~usage → ascii 'usage: ls [-@ABCFGHILOPRSTUWXabc...]'
iS → 0.__TEXT.__text / __auth_stubs / __cstring / __DATA_CONST.__auth_got ...
```

### 3.2 APK 抽 so：JNI 导出判定（重要实战结论）

```bash
unzip -o -q app.apk "lib/arm64-v8a/*" -d apk_libs
r2 -q -c 'iE' apk_libs/lib/arm64-v8a/libandroidx.graphics.path.so   # 导出表
r2 -q -c 'aaa; afl' .../libandroidx.graphics.path.so                # 全函数
```

```text
实测输出：
iE → 8  GLOBAL FUNC 448  JNI_OnLoad        ← 唯一导出
afl → 19 funcs（10KB 小 so）；ii~JNI 无（不导 JNIEnv 透传）
HINT: Relocs not applied, some references may not resolve: use -e bin.relocs.apply=true
```

**实战结论：`is~Java_` 搜不到 ≠ 没有 JNI。** 本 so 只有 `JNI_OnLoad` = **动态注册**（RegisterNatives 在 OnLoad 里跑）。追法：`pdf @ sym.JNI_OnLoad` 找 `RegisterNatives` 调用点，第二参数表即 Java 方法↔native 函数映射。静态注册（Java_xxx_yyy 命名）才直接 `is~Java_`。
**坑**：r2 提示 relocs 未应用时加 `-e bin.relocs.apply=true`，否则交叉引用漏报。

### 3.3 -B 基址：APK 里的 so 不需要

实测 `iS`：`.text` 段 paddr==vaddr（0xd2c==0xd2c），ELF 共享库按 program header 自动映射，**`-B` 留给内存 dump 修复基址的场景**（脱壳 dump 出来的 so 需要，见《03-脱壳dump》）。

### 3.4 r2pipe 脚本化（批扫函数+敏感字符串）

```python
# r2pipe_list.py <binary>  （$VENV/pip 无 pip！装法见坑）
import r2pipe, sys
r2 = r2pipe.open(sys.argv[1], flags=["-2"])   # -2 屏蔽 stderr 噪音
r2.cmd("aaa")
funcs = r2.cmdj("aflj") or []
print(f"[*] {sys.argv[1]}: {len(funcs)} funcs")
for f in funcs[:8]: print(f"    {hex(f.get('offset', f.get('addr')))}  {f['name']}")
strs = r2.cmdj("izzj") or []
pw = [s for s in strs if any(k in s.get("string","").lower() for k in ("key","token","secret"))]
for s in pw[:5]: print("    ", s["string"][:60])
r2.quit()
```

```text
实测输出（macOS 本机）：
[*] /bin/ls: 135 funcs
    0x1000042a4  sym.imp.__assert_rtn ...（8行）
    敏感字符串 1 条
so 版：[*] libandroidx.graphics.path.so: 19 funcs（sym.imp.__system_property_get 等）
```

**坑：r2 6.x 的 `aflj` 键名是 `addr` 不是 `offset`**（旧教程脚本直接 KeyError）。
**坑：venv 是 uv 建的没有 pip**，装包：`XDG_CACHE_HOME=/tmp/frida_cache uv pip install --python $VENV/python r2pipe`。

## 五、frida 17.x 本机实操（macOS 自测）

### 5.1 坑 1：~/.cache 属主 root → 全家桶瘫痪

```text
实测报错：frida.PermissionDeniedError: error creating directory ~/.cache/frida/...
根因：~/.cache 为 root:staff drwx------（历史遗留），frida/uv 全写不进
```

**每次开工 `export XDG_CACHE_HOME=/tmp/frida_cache`（写进 §〇 三件套）即解。**

### 5.2 坑 2：attach 他人进程被拒 → spawn 模式通

```text
实测报错：PermissionDeniedError: unable to access process with pid 15520 from the current user account
（macOS 无 sudo、终端无 Debugging 权限时，attach 已有进程一律被拒）
```

**降级：spawn 自己的子进程再 attach（macOS 允许，frida-helper 完成）：**

```python
# hook_spawn.py（$VENV/python hook_spawn.py）
import frida, time
dev = frida.get_local_device()
pid = dev.spawn(["$VENV/python", "-c", "import time;time.sleep(15)"])
session = dev.attach(pid)                    # 子进程可 attach
script = session.create_script('''
  var f = Module.getGlobalExportByName("getpid");   // 17.x 用 getGlobalExportByName
  Interceptor.attach(f, { onEnter: function(a){ send("getpid hit"); }});
  console.log("[*] pid="+Process.id+" arch="+Process.arch+" frida="+Frida.version);''')
script.on('message', lambda m,d: print("[msg]", m.get("payload")))
script.load(); dev.resume(pid); time.sleep(5); session.detach()
```

```text
实测输出（macOS 本机）：
[*] spawned pid 17414
[*] hooked getpid in pid=17414 arch=arm64 os=darwin frida=17.23.3
[msg] getpid hit  ×2
[*] detached ok
```

**坑 3：spawn 目标必须纯 CLI 二进制。** `/usr/bin/python3` 是 CommandLineTools 的 Python.app（GUI bundle），spawn 它直接卡死在 helper。用 venv/homebrew 的纯 CLI python。真要给 GUI app 注入，走 frida-server + Android 设备，本机 GUI 用 sudo。

### 5.3 frida CLI（参数顺序陷阱）

```bash
# 正确：-e 在 target 前，-- 后才是被注入程序的参数
(sleep 5; echo exit) | $VENV/frida \
  -e 'console.log("[+] "+Process.arch+" pid="+Process.id+" mods="+Process.enumerateModules().length)' \
  -f $VENV/python -- -c "import time;time.sleep(4)"
```

```text
实测输出：
Spawned `/…/python -c import time;time.sleep(4)`. Resuming main thread!
[+] injected arch=arm64 pid=18449 mods=349
[Local::python ]-> Process terminated
```

**坑 4：`--no-pause` 在 17.x 已删（unrecognized arguments）；`-e` 放到 `--` 之后会被当 app 参数吞掉**（实测：spawn 出的 python 把 `-e` 当自己的 argv，注入代码根本没跑）。非交互自动化优先 python API（5.2），CLI 留交互调试。

## 六、工具间流水（静态→动态的目录/命名约定）

单个目标一条流水线，**按包名建目录、产物固定名**，任何一步可增量重跑：

```text
work/org.fdroid.fdroid/           ← 一目标一目录，用包名（AG 4.2 的 a.get_package()）
├── app.apk                       ← 原始样本只此一份，哈希记录在 notes.md
├── jadx/                         ← jadx -d jadx（--deobf 仅混淆包加）
│   └── sources/...               ← 定位类后 --single-class 导出到单文件精读
├── apktool/                      ← apktool d；要 smali/回编才建
├── libs/arm64-v8a/*.so           ← unzip "lib/arm64-v8a/*" 抽出，保留 abi 层级
├── r2/                           ← r2pipe 扫描结果 afl/izz 落 .txt；命名 so名.afl.txt
├── ag/                           ← androguard 脚本输出：perms.md / xref_<API>.md
├── scripts/                      ← hook_spawn.py / r2pipe_list.py 按 §4.3/§3.4 模板改
└── notes.md                      ← 命令历史+结论（jadx 定位的类名→so 导出→r2 偏移→frida hook 点）
```

流水四步衔接（实战顺序）：

1. **jadx 定位**：`find jadx/sources -name "*.java" | grep -i <关键词>` → `--single-class` 导出精读 → 记下 `System.loadLibrary("xxx")` 的类与 native 方法声明。
2. **抽 so 进 r2**：`unzip lib/arm64-v8a/libxxx.so` → `r2 -q -c 'iE'` 先看导出（只有 JNI_OnLoad = 动态注册，`pdf @ JNI_OnLoad` 解 RegisterNatives 表拿函数映射）→ `aflj`/`izzj` 落盘。
3. **androguard 补面**：权限/组件/deeplink 攻击面 + 敏感 API xref（4.3 模板）反向圈定重点类，喂回第 1 步。
4. **frida 动态验证**：静态拿到的偏移/方法名写进 scripts/hook_spawn.py（本机合法自测 spawn CLI 程序；真机 Android 走 frida-server）。so 偏移在 hook 里用 `Module.getBaseAddress("libxxx.so").add(0x偏移)` 定位。

回编/改包：apktool b 出 patched.apk → apksigner 重签（不在本流水默认步骤）。

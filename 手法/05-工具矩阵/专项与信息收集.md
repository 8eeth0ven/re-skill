# 专项与信息收集工具（接手陌生 APK 的第一分钟）

> 定位：不做完整反编译，先在几分钟内回答四个问题——**装了什么壳/混淆、泄露了什么密钥/URL、是谁编译的、资源里藏了什么**。
> 专项信息收集类完整工具链与《静态分析工具.md》互补。

## 零、第一分钟工作流（总览）

```
拿到 APK
 1. APKiD app.apk        → 壳/混淆器/编译器一键画像（认壳决定后续路线）
 2. apkleaks app.apk     → 密钥/隐藏 URL/内网地址泄露
 3. DIE lib*.so          → so 架构/编译器/打包器（native 层画像）
 4. DroidLysis --verbose → 属性提取报告（权限/组件/可疑特征打点）
 5. 按需深挖:010/imHex 解私有格式;LIEF/pyelftools 脚本化解析 ELF
 6. 秘密环境(无 PC): UltraSina/androidReverse 直接在手机上完成全部
```

## 一、APKiD —— 壳/混淆/编译器识别

- 识别面：packer（梆梆/爱加密/360/腾讯等数十种）、protector、obfuscator（ProGuard/dexguard 等）、compiler（javac/r8/d8/kotlinc）、anti-vm/anti-disassembly 痕迹。
- **第一分钟用法**：
  ```bash
  pip install apkid
  apkid app.apk          # 单文件
  apkid samples/         # 目录批扫
  apkid app.apk -j       # JSON 输出接脚本
  ```
- 读法：`packer →` 命中即走脱壳路线（见《03-脱壳dump》）；`obfuscator → dexguard` 意味着准备上 ROSAL/DexKit 对抗；miss 时回人工四板斧（so 名/Stub Application/strings 扫描）。

## 二、apkleaks —— 密钥与隐藏 URL 挖掘

- 状态：可用，非活跃迭代。
- 原理：内部调用 jadx 反编译全量源码，再跑正则规则库（URI/API key/IP/Email/secrets）找硬编码泄露。
- **第一分钟用法**：
  ```bash
  pip install apkleaks
  apkleaks -f app.apk                       # 出报告到默认输出
  apkleaks -f app.apk -o report.txt         # 指定输出
  apkleaks -f app.apk --pattern "AWS_KEY,firebase"   # 只跑指定规则组
  ```
- 实战要点：输出里的**隐藏后台 URL/调试接口/S3 bucket** 是黑盒测试资产面第一步；key 命中要验证有效性（多数是第三方 SDK 公共 key，误报常见）。深度 secrets 扫描配合 TruffleHog（见第八节）做熵+字典双确认。

## 三、DIE（Detect It Easy）—— so/二进制画像

- 多引擎（签名+熵+启发式）识别 PE/ELF/Mach-O 的**编译器、链接器、打包器、保护器**。
- **第一分钟用法**：
  ```bash
  # GUI: die.app 拖入 lib/arm64-v8a/*.so
  diec libmsaoaidsec.so        # CLI 单文件
  diec -d -e libfoo.so         # 深扫 + 熵分析
  ```
- Android 场景读法：`clang/LLVM` 版本线索→NDK 代际；`UPX`→先脱壳再看；高熵 section→加密数据/壳；与 APKiD 的 native 维度互补（APKiD 看 APK 整体，DIE 看单个 so）。

## 四、DroidLysis —— 属性提取/预分析

- 无正式 release，`pip install` 或源码跑。
- 定位：**Android App 属性提取器**——解包 + 一堆"特性探测"（root 检测/反模拟器/加密特征/可疑权限组合），输出可 diff 的属性报告，为深度分析缩小范围。
- **第一分钟用法**：
  ```bash
  python3 droidlysis.py -s samples/ --verbose     # 批处理目录,verbose 打印发现
  python3 droidlysis.py app.apk -o outdir         # 输出报告 + 解包产物
  ```
- 亮点：report 里 `suspicious.` 前缀的属性（如 `suspicious.isdebuggerdetected`）直接给逆向"对抗点清单"；批处理几十个样本时比手工 apktool 快。

## 五、UltraSina/androidReverse —— 纯 Android 设备端逆向套件

- 定位：**完全在 Android 设备上跑的逆向套件——无 PC、无 ADB、无桌面工具**，从 APK 解包到 native 分析、编辑、重建签名全部 on-device。
- 能力清单：
  - **native 分析**：内嵌 Radare2 引擎（JNI 绑定），CFG 交互画布、调用图/xref、Pseudo-C 反编译、函数重命名/注释。
  - **8 个 Java 反编译引擎按类切换**：CFR / Procyon / JD-Core / Krakatau / Vineflower / Jadx / Jadx Fallback / Jadx IR。
  - **APK/资源处理**：apk/xapk/split apks 通用解包；抗混淆 AXML 解码（反射版 AXMLPrinter 绕现代 manifest 混淆）；深度 ARSC 解析；导出/替换单文件。
  - **编辑与重建**：AXML/manifest/smali/资源就地编辑 + APK 重建签名（作者另有 DexAndJar-Converter 做 dex/jar/smali 互转）。
  - **内置 MCP server**：MCP 客户端（AI agent）可直连编辑资源/AXML/manifest/smali；编译/重建保持手动触发。
  - 支持 Flutter 与 Unity il2cpp。
- **第一分钟用法**：装到有 Termux 环境的手机/平板 → 打开目标（存储里的 apk 或已装 App）→ Summary 看 manifest/权限/组件 → 挑类切 8 引擎反编译 → native 页看 so。适合：出差/现场无电脑、云手机内闭环、需要"设备上直接改了就装"的场景。

## 六、hookerView → 最接近：CreditTone/hooker

> 全网无 `hookerview` 同名独立项目；最接近的是 **CreditTone/hooker**：**基于 Frida 的 Android 逆向工具包**，友好 CLI + 通用 hook 脚本集，支持在目标 App 进程内注入轻量 webserver（默认 8080，暴露内置调试接口），自动部署 patch.jar→dex，周更频率高（`python3 hooker.py upgrade` 同步）。若所指另有其物，使用前自行确认。

- CreditTone/hooker 第一分钟用法：
  ```bash
  python3 hooker.py            # 列出设备进程,选中注入
  # 注入后:hooker 自动 attach 并展开常用脚本(SSL/加密/加固dump)
  # webserver: 目标 App 内 http://localhost:8080 暴露调试接口
  ```

## 七、LIEF / pyelftools —— so 脚本化解析

| 工具 | 定位 |
|---|---|
| LIEF | 跨格式（ELF/PE/Mach-O/DEX 等）解析+**修改**库，C++ 核心 Python 绑定 |
| pyelftools | 纯 Python 只读 ELF 解析，轻量零依赖 |

- **第一分钟用法（LIEF）**：
  ```python
  import lief
  b = lief.parse("libfoo.so")
  print(b.header.machine_type, b.entrypoint)
  for s in b.sections: print(s.name, s.size, hex(s.virtual_address))
  print([f.name for f in b.exported_functions])        # 导出表=JNI 入口候选
  # 修改场景(反检测):改导出符号/字符串/加段
  b.patch_hook(...)  # 例:改 gum-js-loop 线程名特征对抗 frida 检测
  b.write("libfoo_patched.so")
  ```
- **pyelftools** 适合批量只读分析（dump .rodata、遍历重定位表找 GOT hook 点）；要**改写** so（frida 特征抹除、patch ELF）用 LIEF。
- 常见用途：静态过检测（LIEF 抹 so 层 frida 特征）；解析加固 so 的自定义段（壳常把加密 dex 藏在自有 section/末尾 overlay，脚本算 offset 提取）。

## 八、TruffleHog —— secrets 深扫（通用，配 apkleaks）

- 定位：通用密钥扫描（800+ detector 验证器，能**在线验证 key 有效性**，不只正则命中）。
- Android 场景：反编译导出源码后扫目录；或直接对解包目录跑：
  ```bash
  trufflehog filesystem --no-verification out/sources/   # 只报不验证(无外联时)
  trufflehog filesystem out/                             # 默认验证(会打外部API,注意授权)
  ```
- 与 apkleaks 分工：apkleaks 快、专、面向 APK 正则（URL/隐藏端点）；TruffleHog 深、带 key 有效性验证（AWS/GCP/SLACK…）。SRC 场景先 apkleaks 找资产面，命中疑似云 key 再 TruffleHog 验证。

## 九、010 Editor / imHex —— 私有格式与二进制模板

| 工具 | 说明 |
|---|---|
| 010 Editor | 商业（$149.95/家庭学术 $59.95）；Binary Templates 解析 300+ 格式；Tree-sitter 语法 45+；内建 x86/ARM/MIPS 反汇编；50GB 大文件 |
| imHex | 免费开源替代，Pattern Language 模板，社区模板仓库 |

- **第一分钟用法**：解不出结构的文件（自定义加密容器、dex 变体、protobuf wire format、壳的私有 dat）拖进 010 → 找现成模板（官方仓库有 dex/elf/dex 变体模板）或现写：
  ```c
  // 010 模板示例:壳的私有 header
  typedef struct {
      uint32 magic;      // 0xDEX 或自定义魔数
      uint32 version;
      uint32 dataOffset; // 数据偏移;之后可 while(!FEof()) 逐段声明解析
  } PACKER_HEADER;
  ```
- 实战技巧：魔数定位（`dex\n035` / `PK` / 自定义）→ 用模板把 offset/size 字段结构化 → 直接在 hex 里改字段（去加密标志位/改长度骗解析器）。imHex 免费场景同思路（Pattern Language 语法略异）。

## 十、选型速查

| 问题 | 工具 |
|---|---|
| 这 APK 有没有壳/什么混淆? | APKiD（首选）→ 人工四板斧 |
| 有没有硬编码 key/隐藏 URL? | apkleaks → TruffleHog 验证 |
| 这 so 是谁编的/加壳没? | DIE（diec） |
| 批量样本快速属性报告? | DroidLysis |
| 手边只有手机? | UltraSina/androidReverse |
| frida 特征要抹/so 要 patch? | LIEF（改写）、pyelftools（只读分析） |
| 私有二进制格式看不懂? | 010 Editor（商业/模板多）、imHex（免费） |
| 需要 AI agent 参与设备端编辑? | androidReverse 内置 MCP / dexllm MCP（见《静态分析工具.md》） |

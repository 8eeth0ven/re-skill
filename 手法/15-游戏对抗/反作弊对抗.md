# 反作弊对抗(手法/15-游戏对抗/反作弊对抗)

> **边界声明(先读)**:本篇覆盖**授权语境下的技术分析**——CTF 游戏题、自家游戏的安全测试、反作弊引擎的逆向研究、防守方(游戏厂商)了解攻击面。**在线游戏实战对抗 = 封号风险 + 违反服务条款**;制作/销售/分发外挂在多地涉刑(国内:破坏计算机信息系统罪/侵犯著作权罪判例多起)。本库不提供在野游戏的绕过成品,只讲原理与研究对象。驱动级对抗与 BYOVD 背景 → `../07-内核级/跨平台内核速查.md` §4。

## §0 全景:反作弊的三层架构

```
┌──────────────────────────────────────────────┐
│ 云端:行为模型/AI 判定/信誉库/封号决策           │ ← 检测证据汇总,最难绕(不可见)
├──────────────────────────────────────────────┤
│ 用户态模块:游戏内嵌 SDK/完整性校验/取证接口      │ ← 最先接触到,第一道对抗线
├──────────────────────────────────────────────┤
│ 内核态驱动:内存扫描/句柄清查/环境检测           │ ← ACE-Guard/EAC/BE 主战场
└──────────────────────────────────────────────┘
```

三层职责:内核驱动拿"上帝视角"(读写谁、谁在读写游戏),用户态做完整性自证,云端做最终裁决(单点证据不足时累积行为置信度)。**判定越靠云端越难对抗**——这是现代反作弊的演进方向。

## §1 ACE(Anti-Cheat Expert,腾讯)

### 1.1 架构与产品线

- 腾讯游戏安全体系:PC 端 TP(TenProtect,老)→ ACE(现);手游端 ACE 手游版(反外挂 SDK+加固+模拟器检测);云端 Anti-Cheat AI(行为分析)。
- PC 端形态:**内核驱动 + 游戏进程内用户态模块 + 云端分析**;部分游戏启用"预启动模式"——开机即加载驱动(早于外挂启动,堵"外挂先行"路线)。
- 手游形态:无内核权限(无 root 检测为主),重心在模拟器检测/破解包检测/变速检测/云手机识别,与 Android 手法库的对抗线直接衔接(→ `../04-对抗攻防/root与环境隐藏.md`)。

### 1.2 检测面(PC 内核侧)

| 检测面 | 原理 | 对分析者的含义 |
|---|---|---|
| 内存扫描 | 驱动遍历游戏进程内存,比对已知外挂特征码/校验关键数据结构(坐标/血量)一致性;对关键数据设**蜜罐**(伪造指针/坐标,读蜜罐=实锤 DMA) | 分析机不能直接 CE 搜值——碰蜜罐即标记 |
| 句柄检测 | 枚举所有进程对游戏进程的句柄(OpenProcess 痕迹),非白名单进程持有读写句柄=可疑 | 调试器/frida 注入天然暴露句柄 |
| DMA 检测 | 对抗外接 DMA 卡( PCIe 采集卡+第二台机读内存):蜜罐数据+千人千面加密(关键数据每用户/每局不同加密形态)+硬件行为侧信道 | DMA 不是法外之地:读到的可能是密文或诱饵 |
| 外设指纹 | 键鼠注入路径合法性(驱动签名/厂商 ID)、输入时序分布 | 模拟输入(压枪脚本)从时序熵被识别 |
| 环境检测 | 调试器/虚拟机/注入库白名单 | 研究环境必须与玩家环境解耦(§4.3) |

### 1.3 ACE 手游版检测面补充(与 Android 库衔接)

| 检测面 | 手游侧形态 | 库内对应 |
|---|---|---|
| 模拟器检测 | 特征文件/传感器/帧率指纹,云手机识别(帧率熵) | 检测原理全景.md 模拟器节 |
| 破解包检测 | 签名校验+资源完整性(客户端自检+服务端下发 challenge) | 工具检测与魔改.md 重打包链 |
| 变速检测 | 时间基准多源比对(系统时钟/单调钟/网络钟) | 本篇 §3.3 时序 |
| 注入/hook 检测 | frida 特征全栈+inline hook 扫描+so 完整性 | frida反检测对抗.md |
| 外设指纹(压枪/连点) | 触控事件时序分布(微秒级),外接设备枚举 | 本篇 §1.2 同型 |

### 1.4 对分析者工具的检测

- **frida**:端口/线程名(gum-js-loop)/映射名特征;ACE 手游版有完整 frida 检测栈 → 对抗全链见 `../04-对抗攻防/frida反检测对抗.md`(改特征/藏 gadget);
- **调试器**:句柄+调试对象标志(P_TRACED 同型)+断点字节扫描(0xCC/BRK 指令自检);
- **CheatEngine**:内存扫描行为本身被检测(枚举/读写模式),与扫描到的值无关——"还没改值就封"即此;
- **IDA/静态**:不检测(离线行为),但样本(驱动文件)带完整性上报——云端可关联"这台机 dump 过我"。

## §2 EAC(Easy Anti-Cheat)与 BattlEye

### 2.1 形态对比

| 维度 | EAC(Epic) | BattlEye |
|---|---|---|
| 内核驱动 | 有,开机预启动(BE_Service/EAC 服务化) | 有,同预启动模式 |
| 证书与加载链 | 微软认证的 EV 签名驱动,随游戏启动经服务加载;跨平台(EAC 也做 mac/Linux/PS/Xbox) | 同级签名,Boot 启动服务(BEService) |
| 检测路数 | 驱动扫描+句柄清查+签名库+云端统计(社区反馈其"证据收集后延迟封禁"策略明显) | 同级;以激进封禁策略著称 |
| 绕过研究边界 | 二进制+驱动可静态分析(签名合法但代码可逆);**公开绕过=快速过时**,官方热更特征 | 同 |

共同点:驱动本身**合法签名**(厂商证书,微软驱动黑名单之外),加载链无可攻击的"伪造签名"环节——与 Windows BYOVD(自带漏洞驱动)是两条路:反作弊驱动没有已知"漏洞"可用,对抗点全在**检测规则的发现与规避**,不在打穿驱动本身。

### 2.2 加载链细节(研究环境要知道的时序)

```
开机/登录 → EAC/BE 服务进程(BEService.exe / EasyAntiCheat.exe)
  → 游戏启动时服务加载内核驱动(Signed driver,PNP/服务控制管理器路径)
  → 驱动 attach:枚举进程/建立游戏进程保护(句柄剥离 ObRegisterCallbacks)
  → 游戏内用户态模块起 TLS 心跳+取证上报
```

- **ObRegisterCallbacks 句柄剥离**:驱动注册回调,把第三方进程对游戏进程句柄的权限位剥掉(读/写/VM_READ 等被清)——分析机上的常规注入(OpenProcess 全权)在源头被阉割;
- **预启动的意义**:外挂驱动先于反作弊驱动加载抢占优势位 → 反作弊开机即驻留,封死"起外挂再开游戏"路线;
- 服务卸载面:服务进程被停(游戏关闭后驱动卸载与否随产品策略),**研究窗口=驱动加载期间的游戏运行时**,离线 dump 驱动文件不受限。

### 2.3 研究对象获取

- 驱动文件:EAC/BattlEye 随游戏安装落地(游戏目录/DriverStore),可直接拷贝做静态分析(签名合法,不拦文件复制);
- 用户态模块:游戏进程内 dll/so,带 VMProtect 级壳,脱壳思路 → `../../平台/01-Windows安全/解密篇.md`;
- 通信协议:用户态↔驱动(IOCTL/FilterCommunicationPort)与↔云端(TLS),前者是检测指令的主要载体(§3.2)。

### 2.4 其他引擎速览(对照定位)

| 引擎 | 归属/代表游戏 | 形态特点 |
|---|---|---|
| Vanguard | Riot(Valorant) | 最激进:开机驱动常驻(TDK 系列),先于 Windows 登录加载;固件级(TPM/Secure Boot 链)参与校验 |
| FairFight | 纯服务端 | 只做行为统计判定,客户端不落驱动——对抗面=行为分布本身 |
| nProtect/GameGuard | 韩系老牌 | 用户态为主+驱动,混淆重;老游戏遗产多 |
| 网易易盾/自研 | 国产手游/端游 | 手游侧与 ACE 同型;端游自研驱动走 BYOVD 式签名链 |
| Denuvo(Irdeto) | 反篡改(非反作弊但常共存) | VM 级保护游戏本体,逆向成本抬高第一手分析 |

判型口诀:**看驱动加载时机(登录前/游戏时)+看判定在哪层(客户端证据/服务端统计)**——两者决定对抗重心在环境对抗还是行为拟合。

## §3 反作弊通用原理(分析视角)

### 3.1 内核态读写

- 合法驱动(包括反作弊自身与签名工具驱动)可 `MmCopyVirtualMemory`/APC 注入式读写任意进程——**外挂的"驱动读写"用的也是签名驱动**(自有 EV 证书或滥用正规驱动,后者即 BYOVD 思路,清单见跨平台内核速查 §4.3);
- 检测侧对抗手段:**句柄清查**(直接 OpenProcess 路线死)+ **驱动黑名单**(已知作弊驱动哈希)+ **内核完整性**(PatchGuard 时代改内核收窄);
- 读写的数据面被"千人千面加密"后,拿到读写原语≠拿到有效数据——现代对抗重心从"能不能读"移到"读到的是不是真的"。

### 3.2 混淆通信

- 用户态 SDK ↔ 驱动:IOCTL 命令号+输入输出缓冲加密(会话密钥/白盒),静态看驱动只见解密后的分发逻辑,规则本身云端下发;
- **trace 法定位检测规则**(互链 `../13-trace/trace实战.md`):运行时跟 IOCTL 流/驱动分发函数,比对"做动作 A(开 CE)"前后指令差集——检测规则触发路径就暴露了;同理跟 frida 特征扫描函数的调用来源;
- 云端协议:TLS+证书校验(抓包对抗全套适用 → `../04-对抗攻防/抓包全场景.md`),但抓到也只是证据上报通道,不是判定逻辑。

### 3.3 云端行为模型

- 输入特征:鼠标轨迹频率/微秒级时序偏差、射击间隔分布、帧率熵值(云手机脚本帧率异常稳定是强特征);
- 对抗含义:**行为模拟要过统计检验**——随机抖动不够,要拟合人类分布(研究向:检测论文与开源数据集是理解判定边界的入口);
- 信誉系统:设备指纹+账号关联图谱,封号跨游戏联动(同一引擎生态内)。

### 3.4 一局对局的检测时间线(分析者视角)

```
t0 开机:预启动驱动驻留(ACE 预启动/Vanguard/BE 服务)
t1 游戏启动:完整性校验(游戏文件哈希/签名/内存映像)→ 环境快照(进程/驱动/句柄基线)
t2 对局中:实时扫描(内存特征/关键数据结构一致性)+ 输入流时序采集 + 蜜罐数据监测
t3 对局后:证据打包上报(加密)→ 云端判定(即时封/延迟批量封)
t4 关联:同设备/同 IP/同硬件指纹的历史证据合并 → 信誉分坍缩=连坐封禁
```

每一段都有对应研究切口:t1 的环境快照可差分(干净机 vs 研究机快照 diff);t2 的扫描节奏可计时(扫全内存一遍的周期=绕过窗口);t3 的上报通道可抓包(证据形态=它怕什么);t4 说明**单点绕过≠安全**,证据链在云端闭环。

## §4 分析对抗视角(授权语境实操)

### 4.1 驱动逆向(IDA+符号)

- 反作弊驱动多数**未 strip 或带 PDB 泄漏**:先查符号(windows 驱动符号服务器+本地分析,流程 → `../../平台/01-Windows安全/win-vuln/PE逆向与符号分析.md`);
- 静态主线:DriverEntry → MajorFunction[IRP_MJ_DEVICE_CONTROL] 分发函数 → 命令号 switch 表 = 检测能力清单;字符串/日志标签("\[EAC\]"/"\[ACE\]" 前缀)快速锚定功能域;
- 动态:双机 WinDbg 内核调试(搭法 → 跨平台内核速查 §5),研究机(离线)上断 IOCTL 分发,回溯用户态指令构造。

### 4.2 检测规则定位(trace 法)

1. 干净环境跑基线:全量 trace 驱动 IOCTL/游戏模块调用(工具选择 → `../13-trace/trace实战.md` 的 11 工具矩阵);
2. 单变量注入动作(开一次 CE/插一次 frida)再 trace;
3. 差集=检测触发路径;顺藤定位规则函数(扫描特征/句柄枚举/时序统计);
4. 防守视角反向使用:自家游戏的检测覆盖率评估(哪些动作没触发任何上报=检测盲区)。

### 4.3 测试机隔离

虚拟机被检测的三重物理根源(不是特征问题,是"虚拟不出真硬件"问题):

| 根源 | 检测表现 | 能否伪装 |
|---|---|---|
| RTC/时序 | rdtsc/HPET 多源时钟一致性:虚拟化下中断注入延迟有规律残差;指令执行周期统计异常 | 极难:需要全栈时序一致性,伪装单一源没用 |
| GPU | 虚拟显卡(无真实厂商 ROM/温度传感器/性能分布),渲染指令延迟分布与真卡不同 | 难:GPU passthrough 可缓但仍留痕迹 |
| 固件/驱动链 | ACPI 表/SMBIOS/设备描述符是模板值;虚拟设备驱动的签名链 | 中:可定制但工作量大,特征库持续更新 |

结论:**研究用物理机**;虚拟机只用于不联引擎云端报告的离线分析(静态+自签测试服)。

- **为什么虚拟机不行**:RTC/时序(反作弊测 rdtsc 一致性/中断时序)、GPU(虚拟显卡指纹+渲染特征)、驱动签名(虚拟设备链)三重暴露;VM 检测原理 → `../04-对抗攻防/检测原理全景.md` 模拟器节(同源);
- 可行研究环境:物理机+独立测试账号+网络隔离(云端证据不出研究网);快照回滚用磁盘级(系统还原点)而非 VM;
- 隔离红线:研究机的驱动/样本不上生产游戏服——预启动模式+云端关联会让测试行为污染正式账号信誉。

### 4.4 手游侧入口

手游反作弊(ACE 手游/网易易盾/ThoughtWork 等)无内核权限,对抗全在用户态+厂商定制 ROM 层,与既有 Android 对抗库完全重叠:模拟器与 root 检测 → `../04-对抗攻防/root与环境隐藏.md`;frida 对抗 → 同目录 frida反检测对抗.md;协议分析 → `../10-纯算法/协议脱机与RPC.md`。本篇不重复展开。

### 4.5 分析报告应含什么(自家游戏测试交付物)

按库报告规范(两张表)裁剪的反作弊测试交付清单:
- **检测覆盖矩阵**:作弊动作(内存改值/加速/注入/协议重放/脚本)× 检测层(客户端/驱动/云端),每格=检出与否+证据路径(日志/上报样本);
- **环境基线**:测试机指纹、游戏版本、反作弊模块版本(引擎热更频繁,版本必须钉死);
- **绕过成本评估**:每个检出面尝试绕过的难度分级与失败原因(给防御方排优先级用);
- **盲区清单**:§4.2 差集法跑出的"无任何上报"动作列表——这是给厂商最值钱的部分。

## §5 公开研究与判例锚点(技术史脉络)

理解各引擎设计为什么长这样,看公开对抗史最省力:

| 事件/研究方向 | 技术含义 |
|---|---|
| TP 时代内核对抗(扫描硬盘/隐藏进程/禁调试器) | "驱动 vs 驱动"军备竞赛起点;现代 ACE 预启动模式是其延续 |
| DMA 外挂兴起(2019-2023 主线) | 纯软件检测失效 → 蜜罐+千人千面加密+硬件指纹三件套成为标配 |
| 公开研究:Vanguard 固件链分析 | 反作弊上探 TPM/Secure Boot:客户端可信根向固件延伸 |
| 反作弊驱动内核漏洞披露(EAC/BE 均有 CVE 史) | 防守方代码也是攻击面:引擎自身漏洞走 SRC/PSIRT 报送 |
| 云手机/云游戏作弊 | 帧率熵+时序指纹检测兴起的服务端根源 |
| AI 作弊(目标检测+辅助瞄准) | 对抗移向"图像侧信道":检测端从系统层转到输入行为统计层 |

研究方法锚:学术论文关键词(aimbot detection/anti-cheat bypass behavioral detection)、引擎官方公开文档(ACE 官网技术专栏讲自家检测面——**防守方自述是最准的检测面清单**)。

## §6 法律与伦理边界(写明)

- **国内**:外挂制作/销售——破坏计算机信息系统罪(刑法 285/286 条)与侵犯著作权罪均有大量判例;"只卖不写"/"只写不卖"均有获刑案例;
- **服务条款**:在线游戏对抗即使不涉刑,封号+设备拉黑是确定结果;研究行为在测试服/私服(自家)/离线环境进行;
- **本库覆盖边界**:反作弊引擎的静态结构/检测原理/授权测试方法论;**不覆盖**:在野游戏的可用绕过件制作、外挂分发渠道、代练/工作室黑产;
- 漏洞价值出口:反作弊引擎漏洞(检测绕过/提权)可走厂商 SRC(腾讯 SRC/ Epic 与 BE 的安全报告渠道 `[待核:BE/EAC 当前漏洞报送入口]`)——这是合法变现路径。

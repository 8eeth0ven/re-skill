# 常用手法速查

这册收的是「最简单最常用」的一层：30 秒定位目标函数、1 分钟打出补丁、一眼认出简单漏洞模式。深层的对抗、降级、壳内操作不在这里，定位到函数后被检测、被干，开 `手法/12-绕过决策/绕过决策手册.md`； hook 层面不够的看 `手法/09-函数全景/`。

## 二、NOP 与补丁速查

字节流一律按文件内的小端原样写：r2 `wx`、hex 编辑器、`printf` 直接粘字节串，不要把指令字按大端倒着写。

### 1. 各架构 NOP 字节

| 架构/模式 | 文件内字节流 | 助记 | 备注 |
|---|---|---|---|
| arm64 | `1f 20 03 d5` | `nop` | 指令字 0xD503201F，小端存盘即 1f 20 03 d5；写反成 d5 03 20 1f 就是无效编码 |
| arm（32 位 ARM 态） | `00 00 a0 e1` | `mov r0, r0` | 经典 nop，指令字 0xE1A00000 |
| thumb | `00 bf` | `nop` | thumb 地址带 bit0（符号值 +1），补丁按实际对齐算 |
| x86 | `90` | `nop` | 1 字节，短跳转两条 90 90 即可盖掉 |
| x86_64 | `90`；盖长指令用多字节 | `nop` / `nopl` | 5 字节 nop = `0f 1f 44 00 00`，按需补足长度 |

arm64 分支指令对照（跳转偏移 imm = (目标地址 - 当前地址) / 4，编码 = 基础字 + imm26）：

| 指令 | 指令字 | 说明 |
|---|---|---|
| `b +n` | `0x14000000` 起 | 无条件跳转，offset 0 时字节流 `00 00 00 14` |
| `b.eq +n` | `0x54000000` 起 | cond=0000；条件码占指令字低 4 位 |
| `b.ne +n` | `0x54000001` 起 | 与 b.eq 只差最低位，小端流里翻第一个字节的 bit0 |

x86 变长指令注意：NOP 前先看原指令总长，盖不满会留下半条残指令，反汇编直接错位。盖「跳转目标地址不变」的指令最稳，盖完 `pd` 回看一眼。

### 2. 强制返回值补丁

| 架构 | 返回 1/真 | 返回 0/假 | 说明 |
|---|---|---|---|
| arm64 | `mov w0, #1; ret` = `20 00 80 52` + `c0 03 5f d6` | `mov w0, #0; ret` = `00 00 80 52` + `c0 03 5f d6` | 32 位返回值用 w0；jlong/指针返回用 x0：`mov x0, #1` = `20 00 80 d2` |
| arm | `mov r0, #1; bx lr` = `01 00 a0 e3` + `1e ff 2f e1` | `mov r0, #0; bx lr` = `00 00 a0 e3` + `1e ff 2f e1` | `mov r0,#1` 是 0xE3A00001，别写成寄存器版 0xE1A00001 |
| thumb | `movs r0, #1; bx lr` = `01 20` + `70 47` | `movs r0, #0; bx lr` = `00 20` + `70 47` | 共 4 字节，最小补丁 |
| x86 | `mov eax, 1; ret` = `b8 01 00 00 00` + `c3` | `xor eax, eax; ret` = `31 c0` + `c3` | 函数序言不用管，直接盖函数头 |
| x86_64 | 同 x86：`b8 01 00 00 00` + `c3` | `31 c0` + `c3` | 写 eax 自动清零高 32 位，够用 |

补丁写在函数头第一条指令位置；jboolean 返回只看 w0 低 8 位，所以返回真给 1 即可。不动函数序言（栈帧那些）就不会碰调用方约定。

### 3. 分支/比较补丁

- **条件跳转改 NOP**：跳到失败块的 `b.cond`（arm64 4 字节）改 `1f 20 03 d5`；x86 短跳 `74/75 xx` 改 `90 90`。适合「校验失败才跳走」的单点分支。
- **eq/ne 互换**：arm64 条件码在指令字低 4 位，小端字节流里就是第一个字节的最低位，b.eq(0)↔b.ne(1) 翻这一个 bit 即可；稳妥做法是 r2 里 `wa b.ne 0x目标地址` 重汇编。
- **恒真跳转**：把条件分支换成无条件 `b`：指令字 = `0x14000000 | ((目标-当前)/4 & 0x3ffffff)`，offset 0 即 `00 00 00 14`。注意别拿 `mov` 替换 `cmp`——`mov` 不改 flags，后面分支测的是残留标志位，这是常见错法。
- **smali 层**：
  - `invoke-*/move-result v0` 之后插 `const/4 v0, 0x1`（复用已有寄存器，不改 `.registers`）；返回判定就改后面 `return v0` 前的值。
  - `if-eqz v0, :fail` 改 `if-nez`，或把跳转目标改成正常分支 label。
  - void 方法里的校验直接删 `throw` 换 `return-void`；带返回值就 `const` + `return`。

改前后对照：

```smali
invoke-static {}, Lcom/x/Check;->isVip()Z
move-result v0
const/4 v0, 0x1          # ← 插这一行覆盖校验结果（复用 v0，不改 .registers）
if-eqz v0, :cond_fail    # 或者：把这行 if-eqz 改成 if-nez
```
- **重打包一条龙**：

```bash
apktool d target.apk -o out/          # 改 out/smali*/
apktool b out/ -o patched.apk
zipalign -p -f 4 patched.apk aligned.apk
apksigner sign --ks debug.keystore --ks-pass pass:android --out signed.apk aligned.apk
adb install -r signed.apk
# 或签名一步到位：java -jar uber-apk-signer.jar -a patched.apk
```

分支补丁在 r2 里实操（重汇编比手算字节稳，尤其带偏移的跳转）：

```bash
r2 -w libcheck.so
s 0x1A2B4
wa b.ne 0x1A2C0       # b.eq 改 b.ne，目标写原来的跳转目标地址
pd 2
q
```

### 4. so 补丁实操流

```bash
r2 -w libcheck.so
iS~.text          # 关键：ELF 文件偏移 ≠ 运行时地址，iS 表里 addr(vaddr)↔paddr(文件偏移) 直接对照
# 程序头级换算：readelf -l libcheck.so | grep -A1 LOAD
#   文件偏移 = vaddr - 段VirtAddr + 段Offset
afl~check         # 找目标函数；s sym.check_root 或 s 0x文件偏移
wx 20008052c0035fd6   # 直写 hex 流（mov w0,#1; ret）
# 或直接写汇编：wa mov w0, #1; ret
pd 5              # 反汇编回来校验
q
```

不想开 r2，命令行直写文件偏移也行（seek 一定是文件偏移，`conv=notrunc` 不能丢，否则文件被截断）：

```bash
printf '\x20\x00\x80\x52\xc0\x03\x5f\xd6' | dd of=libcheck.so bs=1 seek=$((0x1A2B0)) conv=notrunc
```

thumb 两个坑：函数符号地址带 bit0（显示 +1），实际补丁偏移按偶数算；thumb 指令 2 字节对齐，盖 4 字节补丁时别把相邻指令劈成半条。

改完自检三步：

```bash
# 1. 反汇编回看是否预期指令
r2 -q -c 's 0x1A2B0; pd 2' libcheck.so
# 2. 确认真的写进去了（改前后对比）
md5 -q libcheck.so          # Linux 上用 md5sum
# 3. 重打包后确认签名完整
apksigner verify -v signed.apk
```

文件补丁被签名/完整性校验挡住时，用 frida 做内存补丁（so 内偏移同样从 `iS`/符号表来）：

```js
var base = Module.findBaseAddress('libcheck.so');
var addr = base.add(0x1A2B0);              // 函数在 so 内的偏移
Memory.protect(addr, 8, 'rwx');
addr.writeByteArray([0x20,0x00,0x80,0x52, 0xC0,0x03,0x5F,0xD6]); // mov w0,#1; ret
```

### 5. 什么情况用哪个

| 场景 | 用哪个 |
|---|---|
| 条件逻辑太复杂看不懂，只要结果 | 强制返回值补丁（表 2） |
| 分支只是多走一步校验 | 条件跳转 NOP（表 3 第一条） |
| dex 在壳里拿不到、或重打包后签名校验弹 | so 文件补丁 / frida 内存补丁，再往上走看 `手法/02-frida/` 与 `手法/12-绕过决策/绕过决策手册.md` |
| 要长期固化、不想常挂 frida | 文件补丁 + 重打包签名（表 3 末条） |

## 三、简单漏洞模式速查（定位+一句话验证）

探针值规范见 `../../测试值规范.md`：日志前缀 `[RE]`、构造值 `REPROBE-日期-序号`、内存魔法值 `0x52455052`，禁用 deadbeef/0x42 一类高碰撞值。

| 模式 | 定位锚点 | 快速验证方法 |
|---|---|---|
| 硬编码密钥/key | jadx/strings 搜 `AES`、`secret`、`key`；base64 长串正则 `[A-Za-z0-9+/]{20,}={0,2}` | 用 §一快查 ③ hook 出 key/iv，对抓包密文本地解一次验证（命令见下） |
| 默认口令/后门账号 | 搜 `admin`、`test`、`guest`、`123456` 字面量；登录壳里的演示号 | 直接拿 `admin/admin`、`test/123456` 打登录接口，回包业务 code 为成功即中 |
| 弱随机 | jadx 搜 `new Random(`、`Math.random`；重置码/短信码/彩票类逻辑所在类 | 看种子是否 `System.currentTimeMillis()`；hook `java.util.Random.nextInt` 打 `[RE]` 日志，同种子本地可复现同序列即弱随机 |
| ECB 模式 | 搜 `AES/ECB`、`DES/ECB`、`Cipher.getInstance("AES")`（缺省即 ECB） | hook `Cipher.getInstance` 打转换串；或抓两条请求对比：同明文段对应密文块相同即 ECB |
| 单层 md5/sha1 存口令 | 搜 `MessageDigest.getInstance("MD5")`、登录参数构造处 | 抓登录包看 password 字段是否 32 位 hex，与常见弱口令哈希比对（命令见下） |
| 客户端侧校验可绕 | 本地 `if (isVip)`、`isPay()`、授权/内购返回值判断 | 一次性验证：`Check.isVip.implementation = function(){ console.log('[RE] bypass'); return true; };`；要固化就转 §二强制返回值补丁 |
| 越权 id 参数 | 对象接口里的数字型 `id`/`userId`/`orderId` | 改 `id=9100000001` → `id=9100000002`（假段值，见 `../../测试值规范.md`）看是否回他人数据；回包结构一致即横向越权 |
| 可预测 token | token 为纯时间戳、自增、时间戳+md5 | 两次登录对比 token 差值 ≈ 请求间隔秒数；`date +%s` 现算下一个拿去重放 |
| 证书信任空实现 | jadx 搜 `checkServerTrusted`、`TrustManager`，看方法体是不是空的 | 自定义 TrustManager 两个校验方法为空实现 = 信任所有证书，随便配个代理证书就能解明文 |
| 日志泄漏敏感信息 | 搜 `Log.d(`、`Log.i(` 带 token/password/手机号 | 清空 logcat 后正常操作 app 一轮，过滤关键词看吐了什么（命令见下） |

验证命令块（对应上表「命令见下」三处）：

```bash
# 硬编码密钥：hook 出 key/iv 后对抓包密文解一次，解出可读明文即命中
echo '<b64密文>' | base64 -d | openssl enc -d -aes-128-cbc -K <keyhex> -iv <ivhex>

# 单层 md5 口令：抓包 password 与常见弱口令哈希比对
echo -n admin123 | md5sum

# 日志泄漏：清空后操作 app 一轮
adb logcat -c && adb logcat | grep -i -e token -e password
```

ECB/弱随机佐证 hook（转换串一看便知模式，Random 调用一目了然）：

```js
Java.perform(function () {
  var C = Java.use('javax.crypto.Cipher');
  C.getInstance.overload('java.lang.String').implementation = function (t) {
    console.log('[RE] Cipher.getInstance: ' + t);
    return this.getInstance(t);
  };
  var R = Java.use('java.util.Random');
  R.nextInt.overload().implementation = function () {
    var v = this.nextInt();
    console.log('[RE] Random.nextInt = ' + v);
    return v;
  };
});
```

收尾按 `../../测试值规范.md` 走一遍：`grep -r "\[RE\]" 产物目录`、设备上 `ls /data/local/tmp/re_*`，确认零残留。

```

[PASS] arm64 返回0: 00008052c0035fd6 -> mov w0, #0; ret

[PASS] arm 返回1: 0100a0e31eff2fe1 -> mov r0, #1; bx lr
[PASS] thumb NOP: 00bf -> nop
[PASS] thumb 返回1: 01207047 -> movs r0, #1; bx lr
[PASS] x86 NOP: 90 -> nop

[unicorn/arm64] 原函数 x0=0, 补丁后 x0=1

结论: 反汇编 12/12 PASS;arm64/x86 模拟执行 补丁前后行为变化正确
```

两个实测才踩得到的坑（脚本已内置规避）：
1. arm 的 `mov r0,#1` 指令字是 0xE3A00001（立即数版），手滑写成寄存器版 0xE1A00001 就成了 `mov r0,r1`；
2. unicorn 里跑 `ret/bx lr` 必须**先给返回地址**（arm64 设 LR、x86 压栈），否则跳 0 地址直接 FETCH_UNMAPPED。

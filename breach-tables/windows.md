# Vulnerability Validation Table · Windows (Drivers/Kernel/EoP)

> The master index is at `../breach-tables-cve.md` (CVE-worthy = security-policy violation + exploitability proof + impact scope); set up the environment and dual-machine kernel debugging first via `../platforms/01-windows/win-vuln/toolchain-setup.md`; the nine kernel entrances are compared in `../platforms/01-windows/win-vuln/kernel-attack-surface.md` §1. Surfaces absent from the table are still fair game — this table prioritizes high-value validation checks.

| Recognition signal | Validation action | Confirmation criteria | Exclusions and false positives |
| --- | --- | --- | --- |
| A signed .sys (even WHQL) exposing `\Device\` where `IoCreateDeviceSecure` set no SDDL → device DACL missing | Enumerate the surface per `../platforms/01-windows/win-vuln/driver-ioctl-audit.md` §1 (namespace/ACL/SDDL/Access-bit interplay); confirm with WinObj or the access mask that Everyone can open it | An unprivileged user can open the device + at least one bad IOCTL = a full elevation surface | The device ACL allows only SYSTEM/Admin; the device opens but every IOCTL walks a validated path |
| In IOCTL handling, METHOD_NEITHER's `Type3InputBuffer/UserBuffer` used raw without Probe (or Probed once, then used outside the loop) | Checklist per `../platforms/01-windows/win-vuln/driver-ioctl-audit.md` §3.1; decode the CTL_CODE to type it first (§2.2/§2.3 — the four Method semantics); user mode passes a kernel address for a direct write | A user-controllable pointer → kernel arbitrary read/write (only a stable write counts; a BSOD is merely the floor) | Fully Probed + wrapped in try/except; METHOD_BUFFERED with all lengths checked |
| After `ProbeForRead` validation, the user address/length is re-read (double-fetch race) | Two-thread race: one thread mutates the buffer/length, the other fires the IOCTL; WinDbg `!analyze` to compare the two reads; localization identical to the race entries of `../platforms/01-windows/win-vuln/driver-ioctl-audit.md` §3 | The race window hits stably (10+ triggers, same crash point) | Validation happens on a kernel copy (no window); the window is too small to reproduce stably |
| Output-length bugs: the output length taken from a user InputBuffer field without clamping, or an out-of-bounds write into `SystemBuffer` at the declared length | In the handler, trace where OutputBufferLength comes from (`Irp->IoStatus.Information` vs a user field); Method semantics per `../platforms/01-windows/win-vuln/driver-ioctl-audit.md` §2.3; construct "tiny actual buffer + huge declared length" | A kernel-pool out-of-bounds write (output-path overflows are commonly under-audited) | The length comes straight from an Irp field with a minimum check; output goes through safe-copy functions |
| Pool-overflow primitive in hand, choosing the reclaim target (the old play died after Win10+ pool isolation) | Pick spray primitives per the pool backend: pool evolution and the currently-stable surface in `../platforms/01-windows/win-vuln/kernel-pool-cve-patterns.md` §1/§2; overflow → adjacent-object selection by target class in §3.1 | Stably modify an adjacent object's fields (type confusion/list surgery), not a one-shot crash | The target object sits in Secure Pool (dynamic KDP); Win11 pool isolation + delayed reuse scatter the adjacency |
| UAF window in hand, choosing the reclaiming object (a controllable allocation in the same pool, same size as the freed object) | Heap grooming + reclaim-primitive selection per `../platforms/01-windows/win-vuln/kernel-pool-cve-patterns.md` §2/§3; do the object-lifetime analysis first | The UAF becomes controllable type confusion (e.g. a window object reoccupied by attacker data) | The window is too small to reclaim into; reference counting actually protects (don't just look at the free call — look at refs) |
| win32k user-callback reentrancy surface: locks/object state broken during UserModeCallback (the classic UAF engine) | Surface composition, tagWND lifecycle, and localization all in `../platforms/01-windows/win-vuln/kernel-attack-surface.md` §2; stress the reentrancy paths with messaging APIs | Reentrancy triggers a UAF/lock failure that is controllable | The callback paths already de-xxx'd into win32kbase; only rare window states enter the callback |
| ALPC port surface: message-handling type confusion / cancel-routine races / null pointers | Enumeration and historical patterns, fuzz tools per `../platforms/01-windows/win-vuln/kernel-attack-surface.md` §3; send malformed sequences at high-message-rate ports | Kernel corruption with controllable fields (a pure BSOD rates low; further primitivization counts as high) | Only a blue screen, nothing controllable; the port requires specific privileges to connect |
| Print spooler spoolsv (a SYSTEM process): driver-load paths / PointAndPrint / spool directory ACLs | Audit the AddPrinterDriver DLL load path, the spool dir and spool-file ACLs, the RPC-over-TCP surface; enumerate the unauthenticated RPC calls into spoolsv one by one | An unprivileged user loads an arbitrary DLL into a SYSTEM process, or writes spool files beyond authorization | PointAndPrint already tightened; RPC over TCP disabled; the load path has signature checks (note the OS build) |
| Service elevation: unquoted service paths with spaces, or weak ACLs on service binaries/config dirs | `sc qc` to enumerate unquoted paths exhaustively; icacls for writability of the service exe and config; manually re-write to verify (don't trust scanners alone) | Attacker DLL/exe executes as SYSTEM at reboot/service restart | No spaces in the path; correct directory ACLs; the service is disabled and can't be started. Note: for third-party software this surface mostly gets no CVE — go to the vendor PSIRT |
| Scheduled-task and registry execution units: ACLs on `\System32\Tasks` task files, RunOnce/IFEO keys | schtasks /query /v cross-checked against task-file ACLs; a low-privilege writer on a high-privilege execution unit (Image Path pointing into a writable location) is the surface | Low privilege modifies a high-privilege execution unit (elevation) | The task files/keys allow only SYSTEM; mostly a config defect — MSRC usually declines; route to the vendor honestly |
| COM/DCOM hijack: HKCU CLSID overriding HKLM (InprocServer32 → attacker DLL) + a high-privilege COM consumer | Enumerate the CLSIDs loaded by high-privilege processes → find HKCU-writable override points; verify DCOM activation permissions (RunAs/Launching) | A high-privilege process loads the attacker DLL (elevation) | The CLSID lookup chain skips HKCU; the consumer runs in an AppContainer. Microsoft mostly treats these as defense-in-depth, no ID; report only when the default config is exploitable |
| Font-parsing surface: DirectWrite/umfd OTF/TTF/woff2 table parsing (historically high-yield) | Audit the parser functions' bounds table by table; fuzz via `../platforms/01-windows/win-vuln/toolchain-setup.md` statics + WinAFL coverage-guided against dwrite.dll | Memory corruption in the parsing surface (controllable offset under PageHeap) | Requires admin to install the font to trigger (post-Win10 the per-user font area's impact shrank); malformed tables silently rejected |
| Third-party AV/anti-cheat/peripheral vendor drivers (newly signed drivers outside the BYOVD list) | Run the full `../platforms/01-windows/win-vuln/driver-ioctl-audit.md` checklist; add one extra cut: the kernel-callback registration surface of self-rolled process-protection drivers (trusting user data inside object/process callbacks), surface located per `../platforms/01-windows/win-vuln/kernel-attack-surface.md` §4 | A new kernel bug in the signed driver itself (vendor PSIRTs pay well) | Passing off a driver already on the BYOVD list as new; the bug needs an admin to manually install the driver to be reachable (user mode can't install = reduced surface) |
| EDR-bypass surfaces (unload protection / driver disablement / unmapping / handle stripping) — settle the CVE boundary first | Boundary: the **other bug the bypass enables** (e.g. writing into a process after bypassing driver protection) is what counts; pure detection-evasion or containment-evasion violates no boundary | Produces no CVE — the output is attack capability only; fine for red-teaming, don't write reports on such surfaces | Reporting detection-evasion as a bug (guaranteed bounce); burning a week of output on a non-CVE surface |
| LPE chain assembly: info leak (KASLR break) + a write primitive stitched into full elevation | Primitive construction and composition per `../platforms/01-windows/win-vuln/kernel-pool-cve-patterns.md` §3 (leak selection → token/PreviousMode writes); every chain link reproduces before stitching | An end-to-end SYSTEM shell (the PoC's completeness decides the report's tier) | Crashes only, no stable primitive; depends on uncontrollable heap layout (state the success rate in the report) |
| Missing logging/telemetry surfaces (nothing in ETW/events to trace post-attack) | Not a bug to hunt: that's product feedback, not a security-boundary violation; at most a hardening suggestion | Not CVE material — a loss-cutting row | Long reports written on such "findings" waste time |
| Holding only a crash dump (user-submitted / caught by WER); pin the root cause before deciding investment | Symbol server + `!analyze -v` to start: environment per `../platforms/01-windows/win-vuln/toolchain-setup.md` §1; for unsigned third-party drivers, Ghidra symbol/type recovery in `../platforms/01-windows/win-vuln/pe-re-and-symbols.md` §2.3 | The crash point localized to a concrete driver function + a root-cause hypothesis (the entrance to a white-box audit) | Third-party drivers in the dump fully obfuscated; when the stack is smashed, `!analyze` conclusions are not fully trustworthy |
| HVCI (memory integrity) on by default; data-driven attacks (patching executable pages) blocked | Design the chain to avoid code execution: patch function pointers/objects/token data; before target selection check the target machine's HVCI/CFG state and write it into the reproduction environment | An elevation that still works under default HVCI-on configs (impact = all default users) | The exploit only works with HVCI off (impact shrinks; must be stated in the report or it gets returned) |
| .sys packed/obfuscated/unsigned; statics won't go in | Type it + workflow per `../platforms/01-windows/win-vuln/pe-re-and-symbols.md` §1.2/§2 (Ghidra headless + audit scripts at scale); locate handlers via IOCTL-dispatch switch characteristics per `../platforms/01-windows/win-vuln/driver-ioctl-audit.md` §2.5 | The full handler set decompiled in hand | Runtime-decrypted fully-encrypted (VMP class): dump the memory image dynamically first, then back to statics; don't gnaw at the packer head-on |
| Bug located — classify by root cause, then sweep the same driver/vendor-SDK sibling drivers for the same pattern calls | Root-cause method and case cross-reference in `../platforms/11-root-cause/kernel-vuln-root-cause-cases.md` (master case table + per-case root-cause dissection); technique mapping in `../platforms/11-root-cause/root-cause-to-technique-map.md` | One root-cause pattern reproducing across drivers = batch CVEs (incomplete patch = new reports) | Forcibly bundling distinct root causes into one report; the vendor SDK's old versions are EOL (still reportable — mark it) |
| Submitting to MSRC: process and acceptance rate | Channel decision + report template per `../disclosure-cve.md` §1/§4; kernel bugs must carry a PoC + affected versions + reproduction environment; same-root-cause merges expected | An ID + bounty (kernel LPE in high tiers; pure DoS low tier or declined) | No PoC, only a crash description; re-reporting already-fixed bugs; racing the public timeline violates the disclosure terms |
| Impact-scope computation (version matrix): a hard report requirement | Diff a signature function across multiple ntoskrnl/driver builds to bound the version range; hang the work product on the vulnerability-hypothesis list template of `../platforms/01-windows/win-vuln/pe-re-and-symbols.md` §1.4; state the default-config states (HVCI/CFG/feature toggles) | An affected range precise to the build + config preconditions | Writing only "Win10 and above"; including already-fixed builds — triage returns it |
| Syscall info-class delta audit: new classes in NtQuerySystemInformation/NtQueryInformationProcess | Build a class×check matrix: a new class shares internal functions with old ones but old checks don't cover the new branch (watch patch diffs for "added a case" commits); any **auto-increment** is also a full primitive (pick counters/high-bit fields for increment-escalation); such syscalls are mostly absent from renderer-sandbox block lists = a direct browser sandbox escape | A user-mode-triggered kernel arbitrary write/auto-increment (with a sandbox-reachability proof) | The new class has its own complete checks; the increment target has no security semantics |
| Object-manager namespace squatting: a low-privilege user pre-registers `\RPC Control\<a security component's dedicated name>`/a Named Pipe | Pre-register the object name before the EDR/AV user-mode component initializes (scheduled task at top priority + ARSO auto-restart-login guarantees first run); the component crashes at startup = whole-machine protection dead; one principle × the whole EDR vendor list = horizontal batch CVEs | A security-component denial of service that disables protection (vendor side confirms the impact) | The object name already DACL-protected; the component has name-collision recovery logic; mostly unfixable on Microsoft's side — the CVE surface is on the vendor side |

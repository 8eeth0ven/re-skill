# Breach Table: Browser & V8 (Sub-table)

> The master index is at `../breach-tables-cve.md`; this table collects V8 renderer bugs, Chromium sandbox/IPC surfaces, extensions, and service workers. Same four columns as the master: `what to recognize \| where to hit \| what counts as a hit \| false leads`. Root-cause canon: `../platforms/06-binary-vuln/vuln-types-exploitation.md` §2 (the six V8 CVE patterns) + `../platforms/11-root-cause/userspace-runtime-root-causes.md` §1 (JIT root causes and the three typical classes); when environment feasibility stalls, check `../re-to-cve-audit.md` (row F browsers); for submission jump to `../disclosure-cve.md`. Surfaces absent from the table are still fair game.

| What to recognize | Where to hit | What counts as a hit | False leads |
| --- | --- | --- | --- |
| Targeting · version-gap window: Chrome stable trails dev/beta by ~4-7 weeks | Follow the stable announcements (chromereleases) for fix commits → back-search the v8 git for same-pattern call sites (incomplete patch = a new ID; approach as in `general-and-wrapup.md`); a bug fixed in dev but not yet in stable reproduces on stable | Triggerable on the current stable while the fixing ID hasn't landed = a real 0day window; file with the VRP expedited tier | Dev channel already fixed and stable's next release carries the fix (verify the fixed version number first); triggerable only on canary |
| Targeting · first implementations: a new Web API / a new Typer rule's first implementation | Strike the first implementation within 30 days of Intent to Ship / a new feature reaching stable: the first built-in .tq implementation, TurboFan/Turboshaft's first optimization of a new operation (the first version usually copies interpreter semantics — Range/side-effect boundaries are most error-prone) | The new API is on by default in stable and triggers a type/memory error (implementation-period bug density far exceeds mature surfaces) | Origin trial/flag off by default (needs a user-set flag — no impact surface); staged features only behind `--js-staging` |
| Targeting · V8 source-migration surfaces: the Turboshaft replacement of the TurboFan backend, the Maglev mid-tier JIT landing window | Watch the v8 git log for [turboshaft]/[maglev] new phases/new lowerings: "rewrite-check desync" is rampant during rewrites; previously fixed patterns regress when rewritten for Turboshaft; --no-maglev/--turboshaft A/B diffing to attribute | A typing/range error on the new migration path producing a stable OOB in release d8 (migration-era precedent: Maglev CVE-2024-0517 in the wild) | The migration switch isn't enabled by default; only a DCHECK assertion fires (release lacks that check) |
| Targeting · CTF v8 problem sources: CTF patches grant an artificial builtin (e.g. giving Array an OOB read/write) | Treat the CTF patch as an exploitation template for practice (the starctf2019 oob style); for real 0day surfaces find the isomorph: look at the pass/opcode the patch touches, then hunt the same boundary class in the real upstream code | A bug at the isomorphic point in real upstream code (the CTF patch itself is a challenge, not the product) | CTF's `--allow-natives-syntax` is a challenge convenience, off in release; CTF-patch bugs aren't reportable (not product code) |
| Typer type-inference errors: a mis-computed Range / truncation and sign dimensions out of sync | Combine arithmetic chains of Math.max/min/sign, `\|0`, `>>>`, and the boundary values -1/0xFFFFFFFF/2^31-1/2^53 against Range; precedents: CVE-2021-21224 (wrong truncation dimension), CVE-2020-16040 (wrong Signed32 restriction intersection — root-cause chain in `../platforms/11-root-cause/userspace-runtime-root-causes.md` §1.3B); `--trace-turbo` stage-by-stage graph diff to find the first wrong node | A Typer error landing exactly on a dimension covered by a deleted check (index/length/Map) → stable OOB in release d8 | The wrong number lands on no checked dimension (wrong return value but no memory corruption — rated low or declined); needs `%` natives with no hot-loop equivalent trigger (release disables natives) |
| BCE bounds-check-elimination errors: a CheckBounds judged always-true and deleted | Expressions rewritten without recomputing Range (the GoogleCTF2018 JIT pattern: `t+1+1` rewritten to `t+2` without recompute); the length-mutation window after `new Array(len)`; String.indexOf/charCodeAt return-domain assumptions; --trace-turbo to confirm the check node vanished | The check deleted + an actual OOB index: OOB read/write on a float array into adjacent object headers (the §1.4 escalation path holds deterministically) | An OOB that only reads hole/undefined (benign OOB); the OOB first hits a release CHECK and crashes (stops at a DoS rating) |
| Map transition/elements-kind races: mutation racing optimized code re-entry | Mutate inside getter/Proxy/valueOf/iterator callbacks: store a double into a SMI array, change prototype, Object.defineProperty to dictionary mode; CVE-2021-30632 (the deleted store was precisely the migration store); specifically audit builtins that "treat Map-validation and offset-use as atomic" | Old-layout reads/writes under new layout: an object pointer read as double = addrof, the reverse = fakeobj (the 1203122/38001 patterns) | Correct deopt after re-entry (`--trace-deopt` wrong-map bail-out = the safety net works); only the megamorphic slow path is taken (the slow path carries full checks) |
| Elimination passes: LoadElimination/StoreStoreElimination/EscapeAnalysis judging side-effecting stores/loads "redundant" and deleting them | Write the same field twice with a semantics-changing operation in between (a Map change/a GC-triggering call) and see whether the second store is deleted; alias-analysis error scenarios: an object reclaimed after passing through a function — is the "known value" still true | A deleted write = lost state → consumed under stale state = type confusion/OOB (CVE-2021-30632 is this class) | The deletion is correct (the state was genuinely redundant) — pure optimization; `--verify-store-elimination` reports only in debug |
| Maglev mid-tier JIT's own surface: typing out of sync with TurboFan | Crashes with --maglev but not --no-maglev → attribute to Maglev; attack its fast-inference shortcut assumptions (daring to cut checks without TurboFan's full range analysis); tier-up boundaries (feedback re-computed at the Maglev→TurboFan handoff) | A stable release OOB on the Maglev path (in-the-wild precedent: CVE-2024-0517 OOB write) | The wrong value gets backstopped by TurboFan (eventually consistent); only a one-frame misread at tier-up with no memory corruption |
| Torque/CSA builtin surface: .tq type annotations mismatching the runtime | The built-in .tq UnsafeCast/cast annotations; Array/TypedArray/String builtin index types (uintptr vs Smi) at huge lengths/negative indices; cold code bypassing the optimizer is equally reachable (low trigger bar) | Type confusion/OOB inside a builtin (no need for the function to go hot — a single call triggers) | Torque debug assertions fire only in debug builds — release with the same input and no memory corruption = a phantom crash; a pure DCHECK doesn't count |
| WASM GC/threads surfaces: struct/array/rtt and atomics at versions on by default in stable | ref.cast/br_on_cast type-check boundaries, deep subtype chains; GC safepoints (stack maps) and thread races; the new shared-everything surface; precedent: CVE-2024-2887 (wasm type confusion, Pwn2Own) | A wasm-side type confusion → cross-struct OOB read/write (stable on trigger, zero JIT training cost) | Proposals needing `--experimental-wasm-*` (not default-on in stable — no impact surface); exclusive to third-party wasm runtimes (wasm3 etc. — Chrome uses Liftoff+TurboFan) |
| WASM dual-compiler semantic diffs: Liftoff (baseline) vs TurboFan disagreeing on the same module | Write semantically subtle modules (trapping-load OOB semantics, i64 boundaries, multi-return, tail-call) so the two tiers diff; --liftoff-only vs --no-liftoff comparison | The same module behaves differently across the two tiers, one of them corrupting memory (clean attribution, reportable) | The proposal isn't default-on at its tail stage; the diff is only compiled-code performance (semantics identical) |
| The RegExp layer: irregexp bytecode + native compilation | The lastIndex vs GC window (the issue 1307610 SKIP_WRITE_BARRIER pattern — root-cause chain in `../platforms/11-root-cause/userspace-runtime-root-causes.md` §4.1); re-entrancy via replace/split callbacks mutating the input string; backtracking-stack exhaustion paths; u/v-flag unicode boundaries | A dangling lastIndex → UAF; or corrupted backtracking state after re-entry = heap corruption | Catastrophic-backtracking ReDoS (Chrome declines/rates rock-bottom); a path that exists only in d8 with no Chrome counterpart |
| Parser/preparser surface: two-pass lazy-parsing inconsistency | Same-named bindings inside eval/with/arrow-parameter defaults/destructuring; parameter-count boundaries (>65535); nested template strings; unicode-escape vs identifier re-parse differences | The same function parsed twice yields different variable slots = wrong-slot reads (a type-confusion surface) | Differences affecting only error messages; triggers only under `%SetForceSlowPath` (release takes the fast path — no difference) |
| GC/write-barrier surface: SKIP_WRITE_BARRIER missing a cross-generation edge, concurrent-marking races | Grep the source for SKIP_WRITE_BARRIER and verify each site's object-age assumption; WeakRef/finalization-registry timing; missing remembered-set entries after minor-GC moves (the general shape: decouple the reachability graph from the real reference graph) | Old space pointing into reclaimed new space = UAF (the CVE-2021-37975 family — GC bugs often go in-the-wild) | --verify-heap reports only in debug (release: same path, no corruption); the object is still pinned by conservative scanning |
| OOB→addrof/fakeobj chain construction: the object model = unchecked pointers, escalation is deterministic | OOB first rewrites an adjacent JSArray's length for extended reach; flip obj/double via a dual map to derive addrof/fakeobj (the CVE-2021-38001 template); under pointer compression the same version's built-in maps have constant low 32 bits — hardcode offline; templates in `../platforms/06-binary-vuln/vuln-types-exploitation.md` §2.3-2.5 | Stable arbitrary read/write + proof (read out an object header/map) — the report rates a tier above "stopped at crash" | Hardcoded maps without version tags (guaranteed to break across versions); newer ArrayBuffer backing_store goes through the external pointer table — the old template of editing backing_store directly is dead |
| V8 heap-sandbox bypass surface: cage+TPT/CPT/EPT guarding the "arbitrary read/write → code execution" leg | With in-sandbox arbitrary read/write in hand, attack: external pointer table indices that can be edited but must bypass tag checks; the trusted space (wasm instances have moved in) indirect-call surface; code pointer table rewrite entrances | Escaping from JS-layer arbitrary read/write to execution outside the sandbox = the Chrome VRP sandbox-bypass track (pays above ordinary renderer bugs) | A standalone bypass report must carry its own usable memory-corruption primitive (theoretical pairings not accepted); triggerable only under `--sandbox-testing` |
| Renderer→browser Mojo IPC receivers: the high-privilege browser process consuming untrusted messages | Enumerate .mojom interfaces (content/browser, services/); message fields consumed directly as lengths/indices/enums (OOB values, negatives, huge lengths); raw_ptr derived from messages; legacy IPC leftovers; every interface reachable from the sandboxed renderer | A malicious renderer message → browser-process memory corruption = sandbox escape (the second hop of a full chain; the top rating tier) | Only causes a browser CHECK crash (DoS, rated low); interfaces reachable only with another bug first (a theoretical pairing isn't an independent bug) |
| Site-isolation bypass: the one-process-per-site boundary | Process-reuse windows on cross-site navigation (same-site determination, schemeful same-site gaps for new schemes); COOP/COEP bypass; postMessage channel cross-site leaks | Beating isolation = cross-site data readable (Spectre-class information disclosure) | Same-site different-origin data issues belong to the SOP (not a site-isolation bypass); requires the same device/physical assistance |
| Full-chain assembly: a V8 bug + an IPC bug stitched into a complete chain | The 0ctf2020 chromium_rce progression pattern: the V8 bug first yields in-renderer arbitrary read/write → the second hop hits a Mojo receiver; the whole run under default sandbox-on state (approach in `../platforms/06-binary-vuln/vuln-types-exploitation.md` §2.7) | Web-page visit → browser-process code execution (the top rating; in-the-wild evidence appends) | Works only with `--no-sandbox` (a disabled sandbox isn't a bypass); the second hop's interface is unreachable in the default config |
| Extension API abuse: wide manifest permissions + API semantic bugs | MV3 service-worker message-handler parameters flowing into the scripting.executeScript dynamic surface; externally_connectable allowing any site to message; DNR rule injection; nativeMessaging host command concatenation (the surface parallels the extension row of `desktop-and-ecosystem.md`; here specialize in Chrome's own API implementation-layer checks) | An ordinary web page borrowing the extension's privileges to read other sites' cookies/drive the native host (affects every user with the extension) | Requires the user to first install a malicious extension (a store-review matter — takedown, not CVE); the API works as documented = by design |
| Service-worker surface: the SW lifecycle and interception layer | SW update/uninstall racing page fetches (cache poisoning); scope escapes (Service-Worker-Allowed header handling); Cache API key-normalization bypasses mixing cross-origin content; SWs also run on V8 = an extra high-survival trigger surface for ordinary V8 bugs | The SW cache layer breaching same-origin boundaries: cross-site script/data injection | The SW caches only its own same-origin content (no violation); requires server-side header cooperation (a site misconfiguration) |
| Targeting · the 1day main path: fix-commit archaeology + official regression tests | Mozilla/V8/WebKit bug fixes always attach a regression test (js/src/jit-test/tests/wasm/regress/ class) = **the official trigger template**: read the fix diff for the root cause → start from the regression test → check out the fix commit's **parent** to build your own vulnerable tree (more reliable than historical release binaries — avoids BuildConfig drift) → generalize variants once it runs; for XNU isomorphs bisect across opensource.apple.com tag ranges | A deterministic 1day environment + same-surface variants | GN args not aligned (build-parameter drift breaks reproduction); architecture-dependent bugs need cross-builds from the source tree (ARM64-only classes must be noted) |
| The V8 post-sandbox era's three exits: in-cage arbitrary read/write is only half the journey | Exit ① leftover wasm-instance RWX pages; ② an independent SBX-bypass chain (a wasm type-canonicalization confusion + a JSPI-class sandbox bypass combo); ③ deopt-class confusion (externref↔i64 lazy deopt) yielding a **non-compressed 64-bit pointer** that cuts straight through the pointer-compression assumption; the weaponization watershed = flag-free: no natives-syntax (warmup feedback triggers naturally) + zero hardcoded addresses (all leaked at runtime) + hit-rate attached | A complete assessment with the "in-sandbox ARW" and "SBX exit" stages verified separately | Old templates editing RWX pages directly are dead; deopt confusion is GC-sensitive (hit-rate wobble needs retry logic); a PoC depending on `%OptimizeFunctionOnNextCall` stops at d8 |
| Process · PoC minimization: crash → reportable PoC | Build d8 at the matching version (gclient sync, check out the tag); the trio --trace-turbo/--trace-deopt/--print-opt-code to pin the root cause; delete input lines to minimize; back-derive a natural trigger from the natives version: `%OptimizeFunctionOnNextCall` → a 10k-iteration hot loop; follow the CVE-2021-21224 analysis method (find the first wrong node) | A single-file PoC triggering stably in release d8/Chrome with zero flags | Crashes only under debug-d8-only assertions; the PoC depends on `%` runtime functions with no natural equivalent (stops at d8, unreachable in release) |
| Process · stability and submission | Run the PoC 1000 iterations and report the crash rate (>95% = stable); confirm the version matrix (current stable + the two prior); file with Chrome VRP (bughunters): affected versions + the flag-free PoC + the --trace-turbo root cause + an exploitation assessment (how far OOB/AR/AA goes); details in `../disclosure-cve.md` | Triaged + the reward tier confirmed; if found exploited in the wild, expedite immediately | Reporting an already-fixed dev-only bug; the PoC depends on ASAN-specific memory layouts (no crash without ASAN); reporting only a crash with no root-cause localization |

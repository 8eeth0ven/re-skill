# Breach Table — Open-Source C/C++ (CVE Grinding at the Component Layer)

> The master table is at `../breach-tables-cve.md` (the index); this table expands the open-source C/C++ surface, same format as the master. The open-source rhythm: **target selection (parsing surfaces nobody fuzzes) → hotspot localization (fix diffs/complexity/integer arithmetic) → AFL++ runs → ASAN triage → minimal PoC → GitHub SA/email embargo**. CVE-worthy = policy violation + exploitability proof + impact scope (see `../disclosure-cve.md`).

| What to recognize | Where to hit | What counts as a hit | False leads |
| --- | --- | --- | --- |
| A candidate project absent from the OSS-Fuzz coverage list | Clone the oss-fuzz repo, `ls projects/`, check the target name; absent + has a file/network parsing surface = blank zone; start an AFL++ container: `docker run -v $PWD:/src aflplusplus/aflplusplus`. Engine choice in `../platforms/06-binary-vuln/vuln-types-exploitation.md` §7 | ASAN reporting controllable memory corruption + a minimal PoC | The project claims "internal fuzzing" that doesn't cover the target parsing branch (check the CI config for real coverage) |
| The project has a recent security-fix commit (a minor-version bump) | `git log -p --grep="fix\|overflow\|bounds\|CVE-"` for the fix diff; check whether the fixed function's **same-pattern call sites** (`rg "<function name>" -t c`) remain unfixed; a fix that only adds one if is usually a local patch | Incomplete patch: the patch fixes one spot, another same-pattern site still triggers = a new CVE | The fix was a full rewrite (the same-pattern sites are gone); the new bug shares the old root cause and gets merged (state the differences proactively when filing) |
| File-parsing libraries (images jpeg/png/gif/webp/tiff, fonts ttf/otf/woff, archives zip/7z/rar/tar, protocols asn.1/x509/dns) | Corpus start: feed every sample in the project's `tests/`/`examples/` as seeds + fill an AFL dictionary with format magics (`AFL_CUSTOM_DICT` or `-dict`); run 10 minutes first and watch the coverage slope | A crash → ASAN triage (next row) → a reproducible malformed file | Parse-fail silently returns (coverage flat — rewrite the harness from a deeper function); boundaries triggered only by huge files (state the trigger conditions in the report) |
| The maintainer has given up (issues silent for six months/README says unmaintained) | Report anyway: GitHub private advisory + the SECURITY.md email contact, both; 90 days without response → public disclosure (keep the timeline as evidence); where an active fork exists downstream, report the fork too | An ID even with no claimant (GitHub SA can request a CVE directly) | Project dead ≠ publish at will (the embargo still holds); reporting only the fork and forgetting upstream (a fork fix that never lands upstream = upstream still carries the bug) |
| A large parser with no idea where to start: complexity-hotspot localization | `rg "while\|for" --stats` to find overlong loops/deep recursion; prioritize recursive parsers with manual-stack traits (alloca/fixed buffers inside recursive functions); run suspicious functions standalone under frida/Qiling. Stack-surface root-cause patterns in `../platforms/11-root-cause/memory-error-root-causes.md` §1 | A deep-recursion stack overflow/OOB write inside the recursion | Recursion depth unreachable with normal input (compute the minimum trigger depth — if you can't construct it, it doesn't count); the compiler already added stack protection and it's just a __chk_fail crash |
| Length-arithmetic class: the length math before malloc/alloca | `rg "malloc(\|alloca\|realloc" -B3 -t c` and check the length source: packet-field `int` → `size_t`, negative lengths, `len*a+b` multiply-add overflow, `len+1` wrap — allocate small, copy big. Integer-overflow root causes in `../platforms/11-root-cause/memory-error-root-causes.md` (arithmetic section) | Integer overflow → heap overflow (the PoC shows the bypass point with concrete field values) | Without `-fwrapv`, the UB is optimized away outright; the overflow only causes a failed allocation returning NULL, correctly handled |
| Release notes say "rewrite parser"/"new decoder" | A freshly written parser = a fuzz-coverage blank + never exercised by real input; diff the old/new version trees (`git diff --stat vOld vNew`) and attack the new files first | A first-release bug in the new parser (often one bug, many trigger paths) | The "rewrite" is only interface wrapping (the core parse is unchanged — confirm via `git log`); the new code ships with complete fuzzing (check CI) |
| Data-is-program class: bytecode/script parsing engines (regex/lua vm/svg path/wasm/font hinting) | Recognize the "input drives execution flow" surface: dispatch tables inside interpreter loops, stack/register-machine emulation; attack the bounds inside opcode implementations (stack-pointer arithmetic/jump-target validation). Root-cause lens in `../platforms/11-root-cause/injection-logic-root-causes.md` §0 and `../platforms/11-root-cause/userspace-runtime-root-causes.md` | Bytecode-layer memory corruption (engine boundary escape) | Requires the "allow untrusted scripts" config that is off by default; it's just RE DoS (performance issues are generally not accepted) |
| The library compiles for many architectures (a full arch list in autotools/cmake) | One overflow reproduces on amd64/arm/riscv alike (write all architectures into the report); `size_t/int`-truncation classes are 32-bit-only — run those there (they don't trigger on 64-bit); attach the cross-compile reproduction script to the report | A multi-architecture impact surface (faster rating and intake) | Asserting all architectures after verifying only your own (give per-arch reproductions or mark "expected same"); forgetting to state 32-bit-only triggering (the maintainer fails to reproduce on 64-bit) |
| Out-of-tree kernel modules/peripheral drivers (openwrt packages/Raspberry Pi peripherals/industrial cards) | `copy_from_user` length checks, the ioctl dispatch jump table, firmware parsing inside probe; non-mainline = nobody's syzkaller scans it. Kernel-surface playbooks in `../platforms/11-root-cause/kernel-vuln-root-cause-cases.md` | Kernel memory corruption reachable by an ordinary user | The module already hit mainline (report upstream instead — don't snipe the ID); loads only with specific hardware present (state the device preconditions in impact) |
| Build-chain files (configure.ac/CMakeLists.txt/CI yaml) | Command concatenation in autotools m4 macros, CMake `execute_process`/`file(DOWNLOAD)` executing without validation, `curl ... \| sh` in CI; the injection points where one malicious commit into the source repo means RCE | Build-time command injection (must show the malicious input source: tarball filenames/env vars/submodule urls) | The variables all come hard-coded inside the repo (no external input path); only affects the developer's own machine, never ships in the product (low rating) |
| Before reporting: which tag did the fix actually land in | Confirm with `git tag --contains <fix-commit>`; a maintainer who merged to master without tagging a release = "fixed next version" limbo — write the fix commit hash in the report + push for a tag; attach how users judge affected versions by tag | The affected-version range is exact (in tag terms), or the advisory can't ship | Treating the master hash as the affected boundary (users install releases); the fix commit was reverted then re-fixed (go by the last one) |
| Low-star industry libraries (DICOM medical imaging/lib60870 ICS/gnss satellite/marine AIS) | Few stars = a fuzz blank, yet downstream they're inside hospital/power-plant/navigation products; find downstream: GitHub dependency graphs/`rg "<lib name>" lockfiles`/distro package indexes; write impact in terms of the downstream products | An industry-component bug (rating by actual deployment, not by stars) | Downstream never exercises the buggy code path (forked and modified/compile-trimmed); writing "theoretically referenced" as "deployed" |
| Duplicate-report anti-collision: dedup before filing | The project's issues, existing GHSAs (search the advisory database by project name), NVD/CVE searches by function name/trigger filename; if the same function was reported but the trigger path/affected versions differ, you can still file (spell out the differences from the old advisory in the report's first paragraph) | First-to-report rights confirmed after dedup | An advisory for the same bug exists but is embargoed/unpublished (email the maintainer to confirm); the function name collides but the root cause differs (file it — don't self-deter) |
| After the fix ships: patch-bypass re-report | Take the fix diff and back-derive the filtering logic (blacklisted chars/one blocked call site/only a length cap without fixing the copy), re-trigger with bypass input; still crashing on the fixed version = a new report or a revision of the original advisory | The bypass reproduces (ASAN still fires on the fixed version) | The maintainer quickly follows with a second fix (folded into the original advisory — credit but no new ID); the bypass needs an admin config that doesn't exist in reality |
| Before reporting: minimize the PoC | The trio: ASAN output + trigger file + reproduction command (one line); trim malformed files with `afl-tmin` or by hand to the minimum; exploits/chains don't ship with the first report (add in comments later) | The maintainer clones and reproduces immediately (fast receipt, fast fix) | A PoC bundled with a full attack script gets sent back for rewrite; the reproduction command depends on local paths (use relative ones); only a crash video without the input file |
| The GitHub SA flow works | Repo Security tab → Report a vulnerability (private); maintainer confirms → advisory draft → Request CVE ID on the page (GitHub is a CNA); at publish, optionally mark "fixed versions" to drive notifications | The GHSA+CVE dual ID in hand (typically 3-5 business days) | The repo hasn't enabled the Security tab (fall back to the SECURITY.md mailbox/issue path); screenshotting and leaking the draft stage (embargo broken) |
| No GitHub SA surface: email + embargo | The security mailbox in SECURITY.md/README; the email contains: affected version range + the PoC trio + fix suggestions + a proposed 90-day embargo; calendar the embargo expiry; publish per notice if unfixed at expiry | A receipt + a settled timeline (email archive as evidence) | The contact mailbox is dead (keep the bounce record before switching to public disclosure); posting suggestive content on social media during embargo (counts as early disclosure) |
| CVE application channel selection | If the project belongs to a CNA (in the Apache/Red Hat/Google etc. lists), that CNA is fastest; no owner → the GitHub CNA or the MITRE form; one bug, one application channel only | The ID lands in one pass | Multi-head simultaneous applications collide (revocation risk); filing with MITRE and only then discovering the project has its own CNA (check ownership first) |
| Fuzzing starts dry: seeds and dictionaries | Seeds = the project's test samples + real corpora (distro package files/system fonts/captured samples); dictionary = format magics + field-name strings (lifted from the parser's case constants); still flat → move the harness entrance (call the deep parse function directly). See `../platforms/06-binary-vuln/vuln-types-exploitation.md` §7.2/§7.3 | The coverage curve keeps climbing + the first batch of unique crashes | Empty/all-zero seeds (the first 30 minutes wasted); a corpus too big to run (cmin-dedupe first) |
| A pile of crashes: triage before reporting | Re-run each crash under ASAN individually (`ASAN_OPTIONS=abort_on_error=1`, one by one), group by root-cause function + allocation stack; same root cause = one bug reported merged, different functions = split into multiple reports (each with its own minimal PoC) | A grouped list: how many independent bugs + each one's minimal PoC | Passing one bug's multiple paths off as multiple bugs (maintainer bounces it); different trigger paths but the same memcpy (merge first, split per maintainer feedback) |
| Upstream responds extremely fast (fixed same-day) | Watch the release/tag: on the day the fixed version ships, verify + push for the advisory and the CVE; a fix merged but no release and no advisory = note the 90-day clock start (from the report date, not the merge date) | A fast ID (common on the GitHub SA surface) | Treating a merged fix commit as already disclosed (no advisory = users don't know; follow through); publishing your blog first and breaking the embargo |
| The bug lives in the library's CLI tool (not the library API) | Judge reachability: a distro putting the tool in PATH / invoking it from scripts = a real attack surface; a tool that crashes just parsing a malformed file is reportable as-is (the file/xxd ecological niche) | Memory corruption from malformed files on the CLI face (realistically triggerable) | The tool is only a demo in the tests directory (not installed with the package); a tool needing root to run (downgrade the write-up) |
| Double-evaluation/second-parse classes: any engine with measure+write passes or validate-then-compile passes | Find the input-mutable point between the passes: nginx's regex map sharing the `$1` capture buffer (overwritten between the measure pass and the write pass: a big capture = heap overflow + a small capture = uninitialized-heap leak, a dual primitive breaking ASLR); GitLab lint running an already-validated expression through a UTF-8 path **compiled a second time**, bypassing the compile-time size check → integer overflow hijacking the regex VM stack | A dual-primitive pairing (leak first, write second) with a complete exploitation argument | The input is actually frozen between passes (immutable); the second-compile path already validates uniformly |
| Defensive code = new attack surface: when auditing diffs, watch newly added defensive/fault-tolerance branches | "Class-existence checks", "anti-crash fallbacks", "error-recovery logic" — code added to prevent errors introduces new paths of its own (a defensive check loading untrusted input = an RCE surface); cherry-picked commits of this class get a dedicated pass | A new bug introduced by a defensive branch | The defensive code is genuinely harmless (a pure read-only check); the new branch is unreachable (flag off by default) |
| Refactor regressions: type-sign-change commits (size_t→signed/type narrowing) | Good/bad version diffing + `git bisect` to pin the introducing commit + `-fsanitize=undefined` builds to pin the line; the report carries both the introducing and fixing commits (the affected range counts from the introduction); refactors motivated by performance/cleanup are high-yield zones | A regression bug introduced by a refactor (with the exact introducing version) | The refactor has no semantic change (bisect runs dry — cut losses early); the regression is only a behavior change with no memory-safety impact |

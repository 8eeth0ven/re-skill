# Vulnerability Validation Table: Desktop & Ecosystem (Sub-table)

> The master index is at `../breach-tables-cve.md`; this table collects desktop software and ecosystem-supply-chain surfaces. Same four columns as the master: `recognition signal \| validation action \| confirmation criteria \| exclusions and false positives`. When environment feasibility stalls, check `../re-to-cve-audit.md` first (branch C Windows user mode / branch F browsers); for the submission stage jump to `../disclosure-cve.md`. Surfaces absent from the table are still fair game.

| Recognition signal | Validation action | Confirmation criteria | Exclusions and false positives |
| --- | --- | --- | --- |
| Electron desktop apps: registered custom protocols (`setAsDefaultProtocolClient`/manifest `protocol`s entries) | An external page launches `app://`/`myapp://` with `../`, `%00`, double-encoded parameters → check whether the protocol handler feeds the parameters straight into `loadURL`/`shell.openPath`/`BrowserWindow`; verify the `nodeIntegration`/`contextIsolation`/`sandbox` toggles; check whether `webSecurity` is off | A web page launching yields local file read/Node-side RCE under default config (affects all installed users, no config-tampering social engineering needed) | It needs the user to manually enable an unsafe toggle; the protocol parameters only enter the app's own whitelisted router; devtools leftovers don't count |
| Electron preload/contextBridge exposure: a bridge wrapping fs/shell/child_process one layer for the page | `npx asar extract` to unpack and read the preload JS; whether contextBridge-exposed functions concatenate paths/commands directly from arguments (path traversal `..\\`); verify the page's content sources (remote pages/iframes loaded?) | Page XSS or a loaded remote site → bridge calls arbitrary file writes/command execution | The bridge arguments are all enumerated whitelists; the page is fully offline with no remote content |
| CEF desktop apps: leftover `node_integration`/command-line flag forwarding; a CEF version stuck on an old branch | Check build configs and the process command line (can external input reach `--` arguments?); probe `window.require/process` via JS injection surfaces (forms/rich text/webview); leftover `remote-debugging-port` (127 direct connect) | JS on the render surface → Node-side RCE; or an unauthenticated debug port allowing arbitrary page-script injection | Node integration explicitly off; the debug port binds 127 with a random token; flags come only from a local config file (no external input) |
| WebView2 desktop apps (shared Edge runtime): Fixed Version distribution without self-update | Confirm the runtime policy (Evergreen self-update/Fixed frozen); map the Fixed version against same-period Edge security advisories for carried bugs; `AddWebResourceRequested`/`WebResourceRequested` filter bypasses (scheme casing/trailing slash); `postMessage` bridge parsing on the native side | An already-fixed Edge bug triggerable inside the app (impact = the app's entire user base), or bridge messages reaching native command concatenation | Evergreen auto-updates — no version gap; the bug only affects the browser process model, not applicable to WebView2 |
| Updaters embedded in desktop apps: weak update-package checks (length/hash only, or over http) | Capture the update-check request; check the validation order (install-then-verify = useless); signature-check bypasses (the hash travels with the package/signature only on the notice page); feed mutations into the delta-patch parser (bsdiff/homegrown); check whether the rollback interface has a version floor | MITM/malicious mirror → arbitrary code execution (all users); or heap corruption in delta parsing | https+pinning end to end + signature verified before install; the updater only downloads and lets the system's msiexec install (OS-level signature check) |
| MSI/NSIS installers: CustomActions running scripts; loose ACLs on install/data directories | Unpack with 7z/ORCA and inspect CustomActions and `[PROPERTY]` concatenation; after install, `icacls` the directories (a user-writable `Program Files` subdirectory = install-then-elevate); whether the app's startup chain loads DLLs from the current directory/user-writable paths (`LoadLibrary` search-order hijack; the exploitation posture matches `../platforms/01-windows/malware.md` §2.1) | A low-privilege user writes a file → loaded when a service/startup item executes elevated (single-machine elevation) | Self-checks with signatures; correct directory ACLs; all DLLs loaded by absolute path |
| Desktop apps opening local IPC: 127 TCP ports/named pipes/local sockets as RPC without authentication | `lsof -i`/`netstat` to list the 127 surface; send raw commands directly (read files/exec); browser-side launch: loose localhost CORS, DNS rebinding, `file://` page fetch | Any web page or local low-privilege process → high-privilege IPC commands (file read/write/exec); remote-web-page triggering ranks highest | Token/origin checks present; the named pipe verifies the peer's process SID; binds 127 only with rebinding protection on |
| Browser extensions: wide manifest permissions (`<all_urls>`, nativeMessaging, cookies, tabs) | Manifest permission audit; content scripts taking page-controlled input (URL parameters/innerText) executing in the extension context; `background` message-handler parameters flowing into dynamic-execution surfaces; command concatenation on the nativeMessaging host side | Page-controlled input → high-privilege extension actions (read any site's cookies/drive native-host command injection), affecting every user with the extension | Handler whitelisted; MV3 has no dynamic-execution surface; native-host arguments all enumerated |
| IDE/creative-software plugin ecosystems (proprietary plugin formats beyond VSCode/Adobe/IDE): sideloadable plugin packages | Whether the plugin package structure (zip/proprietary) and install chain verify signature/origin; the plugin directory's ACLs (user-writable → a high-privilege host process loading DLLs = elevation, same as the installer row); extract proprietary filter/font/model parsers for AFL | A malicious plugin package silently installs (supply-chain event), or parser memory corruption (an ID obtainable) | Sideloads disabled — official source+signature only; parsing runs in a separate sandbox process; the plugin directory's permissions are locked down |
| Office/document parsing surfaces: document parsers bundled with mail clients/cloud-drive clients/previewers (not delegating to the OS) | Check the bundled parser library version (often a stale fork); feed mutations into docx/xlsx/rtf/ole compound documents/rare formats; replay RTF/OLE historical bug patterns (object splicing/field overwrites) on the bundled parser | Memory corruption on open/preview (default path triggering, no user confirmation dialogs) | Parsing actually delegates to system components (rides the OS's fixes); preview force-converts to an intermediate format before parsing; reachable only in a dead "save as" branch |
| Font rasterization: desktop/design/game software bundling freetype/harfbuzz or a homegrown rasterizer | Lift the bundled library version and match the upstream fixed list; feed mutations into GSUB/GPOS/CFF/variable-font tables; trigger paths: image-embedded fonts/document-embedded fonts/webfonts cached from the web | Rendering a malicious font = a heap overflow (low social-engineering bar: one image) | Uses the system font engine (the bug belongs to the OS); table-length prechecks block everything; fonts pass through subsetting/cleaning first |
| Multimedia decoding: desktop apps statically bundling ffmpeg/homegrown codecs stuck on an old fork | `strings` for `Lavc`/version numbers and match upstream security fixes; feed mutations into containers (mkv/mp4/avi/wav) and rare codecs; locate the demuxer's trusted length fields | Opening a media file/generating a thumbnail = UAF/overflow (thumbnail = zero interaction) | Actually uses the system MediaFoundation; decoding is isolated into an external process; only accepts its own recorded formats (trusted input domain) |
| Qt/GTK image plugins: apps shipping their own imageformats/gdk-pixbuf loaders | List the loaders directory for rare plugins (tga/pcx/ico/psd); write a `QImageReader` harness free of the GUI for direct AFL; diff plugin versions | Overflow on the thumbnail/preview path (crash on receiving an image — file-manager-style default trigger) | Thumbnails go through a system service; the loader honors registered magics only with a size cap; oversized inputs prechecked and rejected |
| Game-engine asset parsing: Unity AssetBundle, Unreal pak/uasset, Godot resource (with mod ecosystems) | Reverse the mod/official-pack formats; fuzz the bundle header and offset tables (length fields trusted raw); aim type-confusion at deserializers (Unity serialized-object type fields, Unreal soft-object-path injection) | Loading a malicious mod/map = code execution (deserialization to arbitrary types) or heap corruption | Mods are signed/sandboxed; deserialization type whitelists; assets import only via manual editor action (high trigger bar) |
| Anti-cheat/cheat drivers: signed kernel drivers resident and exposing `\Device\` | Transplant the full Windows-driver playbook: device DACL + IOCTL code extraction, skeleton in `../platforms/01-windows/win-vuln/driver-ioctl-audit.md` §4; specialize in raw-pointer passing and physical-memory-mapping primitives (cheat drivers usually ship arbitrary read/write); development surface per `../platforms/01-windows/programming.md` §5 | An ordinary user process → kernel arbitrary read/write (this class has produced bugs in batches historically; one bug often files against a whole family of games) | The device ACL restricts to SYSTEM; IOCTLs fully buffered with length checks; returns data only, accepts no pointers |
| VR runtimes (SteamVR/OpenXR/Oculus services): resident system service + drivers + local websocket/jsonrpc | The service process's privileges; driver DLL search paths; the local websocket surface (origin/token checks); gallery/model/controller-config file parsers | A web page → local-service commands; or loading a malicious VR asset = RCE | The websocket carries a token; asset parsing runs in the sandboxed render process; the service runs at ordinary privilege (no elevation payoff) |
| Cross-platform framework version gaps: Tauri (wry)/Electron (Chromium)/Flutter (engine) | Lift the framework version against upstream security advisories (Chromium/WebKit version mapping); Tauri `allowlist` dangerous-API exposure (fs/shell wide open); `asset:` protocol scope traversal; IPC command arguments flowing straight into `Command::new` | Frontend XSS → framework-bridge RCE; or carrying an already-fixed upstream bug (prove by version gap) | The version is current, no gap; the bridge exposes only side-effect-free commands; the asset protocol is locked to the frontend directory |
| Credential-storage design flaws: a client encrypting stored passwords with a hardcoded key / no app-layer isolation above DPAPI | Unpack the client and find the crypto routine: hardcoded key (the same key for all users = one click decrypts every user's credentials)/key stored in the registry beside the data; keychain ACLs shared across app groups; inspect what the "remember password" file writes to disk | App-layer hardcoded-key encryption of credentials (anyone can decrypt) = a reportable design flaw; fully plaintext local credential files (cryptography defeated) | The system mechanism itself (DPAPI CurrentUser-decryptable is by design — that alone isn't a bug); anything premised on already having arbitrary code execution locally is mostly downgraded/not given an ID |
| npm/pypi native extensions: packages carrying node-gyp/C extensions parsing file/protocol input | Strip out the native part → write a harness free of JS and run AFL directly (see `../platforms/06-binary-vuln/`); on the JS side only mark the entry and calling convention (parameter reachability) | Native-layer heap overflow/UAF (supply-chain impact = all dependents; GHSA+CVE dual track) | Pure JS logic bugs (GHSA primarily); parsing inputs all come from fixed files inside the package (no untrusted-input surface); the bug only triggers in devDependency scenarios |
| CI-script command injection: repo workflow/build scripts concatenating shell | Trace input sources: branch names/PR titles/issue bodies/commit author names → `shell=True`/`os.system`/backtick concatenation; workflow `${{ }}` expansion landing directly in `run:` blocks (the default shell-injection surface) | An externally controllable string → command execution in the CI environment (stealing secrets/push permissions). Boundary: mostly handled as supply-chain incidents; CNAs often issue no CVE — state the classification clearly in the report | Inputs come only from the maintainer's own actions; the runner holds no secrets worth stealing and no pushable permissions; fork PRs don't run that workflow by default |
| Mirror and package-source poisoning boundaries: typosquats/dependency confusion/malicious-package events | Classify before acting: malicious packages (a poisoning incident → platform takedown request + security notice, not a CVE)/package-manager client defects (metadata parsing bugs, scheme confusion, http downgrade, signature-check bypasses → that is the CVE surface) | Only exploitable defects in the client/source service itself count as CVEs; poisoned packages go the takedown+notice route — the value is in the response chain, not the ID | Force-filing a plain malicious package as a CVE (rejected); false alarms from self-built test packages (check the uploader and download counts first) |
| Harness-ifying desktop-app parsing surfaces: the parser embedded in the main EXE/DLL, and you want to fuzz | First locate the parsing unit (IDA import tables/error-string back-references); if the DLL exports → stub and call directly; if the EXE is coupled to the GUI message loop → relink extracted functions, or feed files process-wide with WinAFL coverage guidance (see `../platforms/01-windows/win-vuln/toolchain-setup.md` §3) | A stable overflow under PageHeap/ASAN with controllable offset/content | Parsing silently returns without crashing; the parser is reachable only through full GUI interaction (harness cost exceeds payoff — switch entrances) |
| Desktop-app deep links/URL schemes concatenating shell: registry custom schemes | Registry `HKCR\<scheme>\shell\open\command` — check how it takes arguments; `%1` quote escapes (`"`/space truncation) → `ShellExecute`/`subprocess(shell=True)`; the argument path flowing straight into file writes | A web page launching the scheme = command injection/arbitrary file write (zero interaction beyond the launch confirmation) | The argument only routes through a whitelist jump; spawning uses an argument array, no shell; the scheme validates arguments strictly before dispatch |
| IoT hardware downgrade surfaces (one line via serial/debug port): devices leaving UART/JTAG/SWD debug shells | Open the case and find the serial/debug points (interface identification and wiring in `../platforms/07-iot/wireless-hw/hw-interfaces.md` §1 — the four debug-interface master table — and §2 UART); connect at 115200 straight into a shell; on the firmware side verify whether telnetd/hardcoded accounts are reused on the same platform (unpack the firmware first via `../platforms/07-iot/iot/firmware-extraction.md`) | Physical-access root mostly gets no ID (state it clearly); **the same backdoor credential/same debug shell reused by a network surface (remote management/UPnP)** is the high-severity escalation | The serial port needs case-opening + soldering; the bootloader locks writes; a standalone "can get a shell" CVE filing is usually rejected (needs physical + no elevation payoff) |
| Ecosystem wrap-up gate: desktop/ecosystem bugs must pass the three questions for an ID | The affected population is quantifiable (install base/downloads/dependency-tree back-lookup) + reachable under default config (no user toggles required) + exploitability proven (not a purely theoretical DoS); if any of the three is missing, patch it before filing; cross-check `../re-to-cve-audit.md` §3 common breakpoints | The report passes on first submission (the impact-numbers and default-trigger chapters both stand) | "The user can harden it themselves" as a premise; impact written as "all users" with no numbers |

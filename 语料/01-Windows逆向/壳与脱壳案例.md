## 一、压缩壳实战

### UPX 解压缩算法逆向
作者:徐大力。解压核心是两块位流取数指令,最阴处 `SUB ESI,-4` 影响 CF 且紧跟标志位相关加法;C 逆写 32 位即可(压缩级别不同解压算法不同(参数/分支数变),逆出的 C 只能解同级别样本):
```c
int getbit(uint *pd, uint **pp){ int t=(*pd)>>31&1; *pd<<=1;   // 符号位即输出位
  if(!*pd){ *pd=**pp; t=(*pd)>>31&1; *pd<<=1;                 // 位窗口耗尽重取4字节
    *pd+=((uint)*pp>=0xFFFFFFFC ? 0 : 1); (*pp)++; }          // 模拟 SUB ESI,-4 的CF
  return t; }
```
> 同法:UPX脱壳详细分析(cradiator/index09)、UPX 静态脱壳机 0.3 版、UPXFix 源代码、UPX完美脱壳脚本、UPX 4.0.2 源码分析、学习UPX加壳过程、upx原理分析、使用AFL来fuzz upx

### UPX 加壳样本完整脱壳流程(以 notepad 为例)
作者:index09(cradiator)。节特征:UPX0 节 RSize=0(解压数据落点)、UPX1 存压缩数据;入口 `MOV ESI,UPX1首`/`LEA EDI,[ESI+FFFF1000]`(指向UPX0);解压主体 EBX 做位窗口控制操作分支,解压后进入 E8/E9 CALL/JMP 修复循环(特征 `MOV AL,BYTE PTR [EDI]/SUB AL,0E8/CMP AL,1/JA 循环/CMP BYTE PTR [EDI+1],1`);IAT 填充段(两重循环 LoadLibrary+GetProcAddress,`MOV DWORD PTR [EBX],EAX` 写回)处直接读出原 IAT 的 RVA 与大小(本例 RVA=0x10000,size=0x344)留给 ImpREC,比自动搜索准;收尾 VirtualProtect 改 PE 头可写→清 UPX0/1 节 UNINITIALIZED_DATA 属性→恢复→`JMP OEP`(跨节大跳即 OEP)。

### UPX 脱壳后重定位表修复
作者:psycongroo。坑:`upx -d` 脱完仍崩——UPX 不保留原重定位表,而是壳内按"位移表"模拟改写;壳内重定位循环特征码(直接搜二进制定位):`31 C0 8A 07 47 09 C0 74 22 3C EF 77 11 01 C3 8B 03 86 C4 C1 C0 10 86 C4 01 F0 89 03 EB E2 24 0F C1 E0 10 66 8B 07 83 C7 02 EB E2`。算法:edi 指向位移表,每轮取 1 字节(>0xEF 则取后两字节组 16 位),ebx 累加(初值=第一区块 VA-4),遇 0 结束;`pReload&0xF000` 为块 VA、`&0xFFF|0x3000` 为 typeOffset。重建:提取位移表 bin→模拟算法算出全部重定位项→新加节写入→LordPE 改重定位目录指向(StudyPE 的 reloc 修复按钮即此事)。魔改 UPX:DIE 查壳用"文件尾-0x24 处 UPX!"+EP 特征 `E8........EB0E5A585997608A542420E9........60`(3.x loader);去掉 UPX! magic 后部分查壳器仍能靠 EP 特征识别,`upx -d` 拒脱需 patch 特征或手脱。
> 同法:upx脱壳重定位表修复的通用思路同样适用于魔改版 UPX。

### ASPack 脱壳详细分析

### AsPack 2.12 静态脱壳机编写
作者:瘋子。结构:①按 SizeOfImage 申请内存按节读入;②定位壳内保存的"节 RVA+RawSize 结构数组"(壳用 `[ebp+0x57C]` 附近变量遍历),纯算法解压;③解压后原 IAT/重定位表未破坏,定位壳内保存位置改回数据目录;④壳若抽取资源(图标/版本)到壳节则保留壳节;⑤修 OEP、删壳加的导入节、落盘。E8/E9 优化原理(压缩壳通用):压缩前把 `E8/E9 rel32` 的相对偏移改成"目的绝对地址"(rel+当前指令地址)使多处跳同一目标的指令字节一致,再 BSWAP 高低位进一步增冗余约省 5%;解压后必须逆向还原 rel(壳的还原循环见上条 ASPack 笔记);UPX/NsPack/ASPack 全用此优化。

### ASProtect 通用脱壳四步与 OEP 跟踪命令
作者:zombieys[CCG](aspr 脱壳总结)+ikki(译)。四步:找入口→dump→重建 IT→修运行错误,能用 caspr/ASPr 直接脱优先;Anti-Debugger:`BP IsDebuggerPresent` 断在 `MOVZX EAX,BYTE PTR [EAX+2]`,直接把内存 `7FFDF002`(PEB BeingDebugged)改 00;OEP 跟踪:最后一次异常后停在壳 `RETN` 处下断,命令行 `TC EIP<900000`(trace till eip 落程序领空),第一次落在 jmp 跳板区(FF25 表)再 F8+再 TC,第二次落进 GetModuleHandleA 调用包装处即 dump 点(此点已含壳还原好的用户代码)。Stolen Bytes:OEP 前 N 字节被壳偷走,识别=OEP 附近出现错位 NOP/残码、真 OEP=错位起点;按编译器标准头补:`PUSH EBP/MOV EBP,ESP/ADD ESP,-10/MOV EAX,imm`(VC 11 字节或 Delphi 14 字节),EAX 的值在壳内 `MOV EAX,EBX` 等价处取(壳替程序执行了入口)。

### ASProtect 1.23 IAT 无效项手工识别(重定向 API 语义识别法)
作者:ikki(译)。ImpREC Trace Level 1 后剩的无效项,右键 DeasmHexView 看壳模拟函数代码按语义判 API:`push [全局]/pop eax/ret` 返回 OS 标识→GetVersion;带 `cmp [全局],400000("MZP")`/GetModuleHandleA 包装→GetModuleHandleA;GetModuleHandleA 后又 `mov eax,[命令行指针]`→GetCommandLineA;`mov eax,[PID全局]/ret`→GetCurrentProcessId(邻接项→GetCurrentProcess);空壳(push ebp/pop ebp/ret 4)→FreeResource/LockResource 任选一个合法名。原则:壳模拟函数与真 API 语义等价即可随意指认,程序照跑。

### ASProtect 1.3 变形 Stolen Code 还原
作者:tDasm。1.23 的 stolen code 不变形直接照抄,1.3 开始变形;还原:OD 除"内存访问异常"外全忽略,记入口 ESP,最后一次异常 ret 后命令行 `tc ebp>=12ffc0 && ebp<12ffc4` 停在变形 stolen code 处;逐条 F7,把变形代码语义简化后抄回:`PUSH 34/JMP/PUSH FS:[0]/MOV [ESP+4],EAX/LEA ESP,[ESP+4]/MOV FS:[0],ESP` ≡ `PUSH EAX+安装SEH` 组合;`PUSH imm/…/MOV [ESP+4],reg` ≡ `PUSH reg`;最终得到标准入口序列(PUSH EBP/MOV EBP,ESP/PUSH -1/PUSH/PUSH/PUSH FS:[0]…),长度与被偷字节一致。

### ASProtect 1.31 全加密 IAT 重建(自写脱壳代码内联)
作者:佚名(菜鸟啄硬壳系列)。适用:壳删光 INT/IID/IAT 且 API 名堆栈解密即焚,调用全改 `call 壳地址`;预处理:文件尾加 2000h 空节,预置库函数名表/编号转换表/IID、INT、IAT 初始结构,在壳内 5 个 `jmp 00EC58C3`(每次加密一个 API 后的返回汇聚点)处挂自写代码,分别处理五种加密调用方式(al=1..4),把 API 名抓下来重建 INT/IID/IAT 并把 `call 壳址` 改回 `call/jmp dword ptr [IAT]`。关键情报源:API 名在堆栈解密后"弹出未清除",半数以上可从废弃堆栈(如 13FED4)找回;库调用按编号,编号→库名表明文可读。壳"禁区"攻法(call [ebx+30]:每次进副本地址、花指令密、自校验随长度变、断点/单步即死):校验只扫"副本"(地址由壳变量 00EE0500 指定)而"正本"固定 xxxx3704-xxxx3C58——把 00EE0500 改指正本,再改正本校验循环起始(`mov ebx,副本地址/mov esi,ebx`),壳就反复扫描一个不动体,正本内随意下断修改。OEP 定位:地址进 00EExxxx 段后搜 `8D 04 18 5C FF E0`(lea eax/[eax+ebx];pop esp;jmp eax),jmp 目标即 OEP;时间限制 SEH 处 `test ebx,ebx` 临时改 `xor ebx,ebx` 过关后还原。

### ASProtect 2.1x SKE「模拟系统函数」解除
作者:coneco。直接到 OEP dump 会缺壳分配段(VirtualAlloc 内存不在 dump 范围)→运行报 Protect Error;机制:壳复制系统函数头部几条指令到分配段(0x1F/0x20 系地址),改原程序调用为 `call 壳段地址`,壳段尾 `push 真函数内部地址/ret` 回系统函数。解除:在壳改写调用地址处(2DBA97 附近 `sub eax,ebp/sub eax,5/inc ebp/mov [ebp],eax`)设硬件断点,ODbgScript 循环:eax 保存真函数地址→在自己分配段(470000)写入核心代码(照抄改造):`pushad / mov word ptr [ebp],15FF(call dword ptr [xxxx] 前两字节) / mov eax,[470070](之前保存的系统函数真地址) / mov esi,404000(IAT 起点) / cmp [esi],eax;je;add esi,4;cmp esi,4040D0;jb 循环(遍历 IAT 找同值项) / mov dword ptr [ebp+2],esi(后四字节=IAT 项) / popad / jmp 回壳`。

### 各编译器 OEP 特征码表(找 OEP 速查)
作者:hijack汇编。
| 语言 | OEP 特征 |
|---|---|
| VC++ | `55 8B EC 6A FF 68 xxxxxx 68 xxxxxx 64 A1 00000000 50 64 8925…`(push ebp;mov ebp,esp;push -1;两次 push;SEH 安装) |
| VB | `68 xxxxxx`(JMP ThunRTMain 前 push)/`E8 F0FFFFFF`(call jmp &MSVBVM60.#100)两种形态,后跟一串 00 与 `30 00` |
| BC++ | `EB 10` + "fb:C++HOOK" 字串 + `A1 xxxxxx/C1E0 02/A3…/PUSH 0/CALL GetModuleHandleA` |
| Delphi | `55 8B EC 83C4 EC/ADD ESP,-14/53 56 57 33C0…`(push ebx/esi/edi 齐全) |
| 易语言 | 格式一 `E8 06000000/50/E8…(ExitProcess)` 开头 `call $+6`;格式二/5.0 独立编译同 VC 形态 |
| MASM32/TASM32/VC8 | `6A 00/CALL GetModuleHandleA/A3 xxxxxx/6A 00/68 DlgProc…/CALL DialogBoxParamA` |
附:Delphi 快速找 OEP 通用招——运行后 WinHex 开主内存搜文本 "runtime" 向前找最近 `55 8B EC`;VB 搜程序名向前找最近 `68`;VC 无规律(zombieys 法);VC 附加特征:OEP 处 `sub esp,0x58`+下一个 call 多为 GetVersion,搜 "sub esp 0x58" 可定位(21Gun5)。

### 徒手脱壳八法
作者:hijack汇编。①单步跟踪(近 call F7/远 call F8/循环 F4 跳出/见大跳转警觉);②最后一次异常法(数 Shift+F9 次数 n,重载按 n-1 次,看栈 SEH 处理程序跟随单步到大跳转);③两次断点法(资源段 F2 断确认解压完,再 .text F2 断,单步到大跳转);④ESP 定律(pushad 后对 ESP 值下硬件访问断点);⑤直接搜 popad 法(仅 UPX/ASPack 级);⑥模拟跟踪法(命令行 `tc eip<壳节基址`,SFX/输入表节基址以下即用户代码);⑦SFX 法(OD 选项"字节方式跟踪真正入口",慢但全自动);⑧一步到达法(运行后堆栈自下而上找程序领空"返回到"项,排除系统模块,反汇编跟随上翻断首)。

### 脱壳后无法运行的原因分析与对策
作者:佚名(菜鸟啄硬壳系列)。判成功:图标一致+无"初始化失败"警告=大体成功;有警告必是 IID/IAT 错;异常/发错误报告=OEP 错或 IAT 函数张冠李戴;一闪而退=文件校验(文件尺寸变→校验和变)。定位:VC/Delphi 程序不能直接校验内存,通常开自身文件副本读——断所有模块间 CreateFile/ReadFile 调用,当 FileName=自身路径时跟踪 ReadFile(栈上有递减的调用次数计数),读完后必进累加循环(`mov cl,[eax]/add [ebp-14],ecx`),次数到 1 时单步即见 `cmp 校验值/累加值/jnz`,nop 掉比较跳转;副产品:CreateFile 断点顺带暴露壳开的调试器窗口名/反跟踪文件名。

### 反硬件断点(异常回调清 DRx)突破
作者:21Gun5。现象:OEP/IAT 硬件断点全不触发;排查:硬件断点失效只有 SetThreadContext 与异常回调改 CONTEXT 两路,SetThreadContext 不断→是 SEH;定位:OD 全部异常不忽略,数出程序全部异常(如 7 处),逐个在"第 N 个异常点"下硬件断点重跑——异常 4 断不下→清零发生在第 3 次异常的 handler 里;看第 3 次异常堆栈的 SEH handler 地址,IDA 打开(handler 前一刻 dump 的内存)加 CONTEXT 结构体,F5 确认是对 CONTEXT.Dr0-Dr7 赋 0。突破:清零代码段(如 43AF57-43AF72)整体 nop;之后每次设新硬件断点若再被清,断在 handler 入口 nop 即可。配套 IAT 脚本套路:两断点循环——"API 获取点"(寄存器出现 xxx.yyy 函数名,存临时变量)+"IAT 填充点"(mov [edi],eax 处改填临时变量真值),跑完到 OEP dump,按新建 IAT 修输入表。

### DLL 脱壳要点(aspack 示例)
作者:xhK。DLL 脱壳三件:OEP(同 EXE 法)+重定位表+IAT;重定位:找到壳重定位处理模块(断点下在改写处),ESI 即重定位表结束地址,大小=结束-基址-RVA,dump 后 LordPE 修基址为实际加载基址+重定位表;IAT 快捷定位:压缩壳一般不破坏输入表区块——用 PEiD 查原文件输入表 RVA,OD 数据窗口跳到 `基址+RVA`,向下滚动找第一个系统函数指针(如 ntdll.RtlDeleteCriticalSection)=IAT 真实起点,滚到无函数为止=终点,差值即大小;ImportREC 去掉"使用磁盘 PE 头"选项,填 RVA/大小重建。

### 自写 IAT 加密壳通用分析模板
作者:21花生。典型流程:FS:[30]→PEB 取 kernel32 基址→遍历导出表拿 GetProcAddress→VirtualProtect 改属性→代码段解密→IAT 处理:LoadLibrary+GetProcAddress 后把 API 地址异或加密,再 VirtualAlloc 一块内存放解密 shellcode,把内存首地址填进 IAT。脱壳脚本模板(ODbgScript):
```
VAR dwGetAPIAddr / VAR dwWriteIATAddr / MOV dwOEP,00409486      // GetProcAddress 返回下一条 / 写 IAT 下一条
BPHWS dwGetAPIAddr,"x" / BPHWS dwWriteIATAddr,"x" / BPHWS dwOEP,"x"
LOOP0: RUN → eip==GetAPI处: MOV dwTmp,eax(真API) / eip==WriteIAT处: MOV [edi],dwTmp(改填真值) / eip==OEP: 结束
```

### 壳的标准骨架(读壳/写壳两用)
```

重定位: 基址不等时按重定位表改写(压缩壳常用自造位移表)
收尾:  恢复节属性(VirtualProtect)→POPAD→JMP/PUSH OEP/RET
```

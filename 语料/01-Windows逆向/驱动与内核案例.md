### 重载内核 完爆SSDT hook
(IamHuskar)**重载内核走旁路**:本机 ntkrnlmp.exe 复制改名 kernel.dll,R3 注入 DLL 到 CE/OD 后当 DLL 加载,通知驱动把副本拷进内核并重定位;R3 hook ntdll 的 nt 系列函数(服务号从干净 ntdll 取),被 hook 函数把内核副本中函数偏移+参数经 IOCTL 传驱动执行——全程不改真内核一字节、不碰 KiFastCallEntry,所有 SSDT hook 对它无效。限制:要求 ntdll 的 nt 函数本身未被 hook(否则取错服务号)。

(笨笨雄)**驱动逆向方法论第一课**:驱动不直接碰硬件(走 HAL 上的 Native API),分析 RING0 程序≈分析 RING3+熟悉 API 表。识别锚点:①DriverEntry 两参数(DriverObject/RegistryPath=UNICODE_STRING{WORD,WORD,PVOID});②`mov [esi+70h],eax` 类=填 MajorFunction(x86 DRIVER_OBJECT 偏移 0x70 起的函数指针数组,+0x38=IRP_MJ_CREATE,+0x40=CLOSE,+0x78=DEVICE_CONTROL);③IRP 关键偏移:+0x0C SystemBuffer/+0x18 IoStatus.Status/+0x1C Information/+0x60 栈位置(栈内+0x04 OutLen/+0x08 InLen/+0x0C IoControlCode);④IOCTL 分发=一串 `cmp ecx, 83050000h; jz`;⑤**Zw 系函数入口 `mov eax, N` 的 N 即 SSDT 服务号**(hook 时 `[eax+1]` 取号);⑥Native API 成败看返回值最高位(jl)。R3 API↔IRP:CreateFile→IRP_MJ_CREATE、CloseHandle→CLOSE、DeviceIoControl→DEVICE_CONTROL——在分发入口下条件断点(IoControlCode=目标值)定位功能。
> 同法:《驱动逆向附带笔记》《逆向一个直接IO硬盘的驱动》《逆向未知dhook.sys驱动源代码》《逆一个驱动中带Exception的函数》(SEH 对 IDA F5 的干扰)

### ring0层exp原语之滥用GDI
(玉涵,译)**GDI Bitmap 任意读写原语**(一次写漏洞→无限读写):`PEB.GdiSharedHandleTable + (handle & 0xffff)*0x18` 得 GDICELL64,`pKernelAddress+0x18`(BASEOBJECT64)+0x38=SURFOBJ64.pvScan0;建 Manager/Worker 两 bitmap,用漏洞把 Worker 的 pvScan0 改成指向 Manager 的 pvScan0 字段;此后 `SetBitmapBits(hManager)`=设地址,`Get/SetBitmapBits(hWorker)`=读写该地址——偷 token 全程 R3 API;版本相关偏移以 {UniqueProcessId,Token} 预置(8.1x64:0x2e0/0x348;ActiveProcessLinks=UniqueProcessId+8)。

### CVE-2021-3438打印机驱动SSPORT.sys提权(内核写内存)分析
(CIVIL哈)HP 打印驱动 SSPORT.sys:唯一控制码 0x9C402408;输入前 16 字节须匹配 qword_11030 的魔串('AA' 走 3 次 while),不匹配(=读方向)则**从驱动 data 段向用户缓冲区拷 0x1000**(越读=内核信息泄露);匹配(=写方向)则用户缓冲区向驱动 data 段 strncpy——溢出方向只能打用户态侧缓冲区,data 段后不可写区直接蓝。结论:单独利用价值低,需与其他原语组合。**方法论价值:先逆 MajorFunction[14]→唯一码→分方向分析读写溢出面**。

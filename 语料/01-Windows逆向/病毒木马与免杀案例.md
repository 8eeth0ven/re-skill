## 一、文件感染型病毒:感染技术与家族案例
### PE病毒学习笔记初识感染技术
作者:佚名(学习笔记,基于 Billy Belceb Win32 篇)。Win32 感染骨架:FindFirstFile/FindNextFile 搜文件 → CreateFileA+CreateFileMappingA+MapViewOfFile → 两次映射(先按原大小读 PE 头算对齐,再按"文件大小+病毒大小对齐"重映射)→ 改末节 SizeOfRawData/VirtualSize/SizeOfImage、属性 OR 0F0000020h(可读写执行+code)→ EOP 改末节末尾 → rep movsb 拷病毒体 → 尾部 jmp/push+ret 回 OldEP。感染核心五元组(节表+PE头):末节 `[esi+10h]`SizeOfRawData=原值+VirusSize 后 FileAlign 对齐、`[esi+08h]`VirtualSize 同写、`[edi+50h]`SizeOfImage=新 SizeOfRawData+VirtualAddress、`[edi+28h]`EOP=SizeOfRawData+VirtualAddress、`[esi+24h]`属性或 0F0000020h;对齐函数=`div 对齐因子→因子-余数→加回`。对齐错是新手感染失败(「不是有效 Win32 程序」)第一死因;感染正被使用的文件用「改名+新建+下次运行时删除」替换法。两种基本型:**后缀式**(追加最后一节末尾,简单利于加壳变形,现代主流)与**散落式 cavity**(切块插宿主空隙,CIH 发扬,执行时重组;衍生:硬挖代码洞插碎片)。文件感染 vs 进程感染:病毒代码可 CreateThread 与宿主并发,WinNT 下 OpenProcess+VirtualAllocEx+WriteProcessMemory+CreateRemoteThread 做「进程感染」,hook explorer.exe 导入表可监视所有进程创建。
> 同法:xfish《扩展节形式感染》(Win32.FUNCKHACKER 完整汇编,感染标记写在 MZ+2 处 4 字节)、《变形PE头添加节形式感染》(Virus.Lonely,DOS_HEADER 与 NT_HEADER 融合腾节表空间:借 BaseOfData 成员充当 e_lfanew,e_lfanew 改 0Ch)、《搜寻节空隙感染》(Virus.Dream,CIH 同款:遍历节表取 SizeOfRawData-VirtualSize 空隙,新版 OEP=空隙 VA)、iiii《几种少见的PE感染方式》(多文件分散感染 QQ.exe+DLL 组合、链接器 /EXPORT:ftsWordBreak=lpk.ftsWordBreak 转发导出 EAT 劫持)
### Win32平台下感染coff-obj文件方法
作者:neineit。感染编译中间产物 obj(供应链前身思路):obj 无 EOP/头无可操作空间,采用「重构造 .text 段数据」——原 .text 代码+重定位表+病毒 shellcode 追加到文件尾,改节头 ul_sec_size/ul_sec_off 指过去,原 ret 改 jmp 跳过重定位表直达病毒代码;宿主链接(不 rebuild all)时病毒被并入 EXE。坑:只拷代码不拷重定位表→链接器产出错乱(IDA 显示正常但 EXE 混乱)——链接器只认「.text 后紧跟重定位表」的事实布局。感染条件苛刻(机器有编译器+obj+增量编译),最早先例 1993 年 Stormbringer 的 shifter。
### windows平台.lnk文件感染技术研究
作者:neineit。lnk 格式(header Flags 各 bit/Shell Item Id List/File location info/Command line 等)逐字段分析,感染两种姿势:
```
1. COM 接口法(样本 svch0st.exe 实录): CoCreateInstance(CLSID_ShellLink) → QueryInterface(IID_IPersistFile)
   → Load(lnk) → GetDescription=="Once"?(感染标记,已染跳过) → GetPath/GetShowCmd → SetArguments("@@@@*原路径*显示方式") → SetPath("%system%\svch0st.exe") → Save()
   svch0st 运行后 GetCommandLineA+strtok 解析 → ShellExecute 拉起原程序
2. 手工构造 Shell Item Id List: lnk 执行仅依赖该节 unicode 路径串(不依赖 File location info 0x10 偏移), 替换 SHITEMID[7] 文件名或整体重构该节即可换目标
```
样本只感染 flags bit6=1(有自定义图标)的 lnk,避开系统 lnk(系统 lnk 无自定义图标)。检测面:0x34 处目标文件大小字段与实际不符、File locator info 异常偏移、两节目标文件名不一致、指向程序导入 ole32 的 CoCreateInstance 且 rclsid/riid 为 ShellLink 特征值。

### WIN32.parite.a感染的PE文件分析

### PE感染逆向之修复(Serverx.exe专杀工具出炉手记)
作者:achillis。「愤怒天使」Serverx.exe(Angel Angel v3.0)感染机理与专杀思路(感染逆向范本)。感染:末节扩张写入 shellcode(无新区段),改属性为 E0000040 可执行,**同一段 shellcode 连写 10 次**:
```
[shellcode#1][shellcode#2]...[shellcode#10][原始文件]
  尾int3→SEH→ZwContinue跳#2 ... #10尾int3→SEH→原OEP;每段 +0x1B 处 DWORD = 下一段 VA(最后一段指向原 OEP)
```
每段尾 int3 触发异常,SEH 异常处理里以 ZwContinue 跳入下一段,第 10 次才跳回原入口——层层迂回反跟踪。运行:CreateMutex("Angry Angel v3.0")+ERROR_ALREADY_EXISTS 判重复实例(首实例 WinExec 自身命令行再跑一遍,第二实例直接 int3 走回原入口完成「宿主功能照常」),复制 system32\drivers\spcolsv.exe、注册表自启、注入 explorer 保护、遍历感染。专杀五要素链:shellcode 头 8 字节特征 `\x60\x78\x03\x79\x01\xEB\xE8\x74` 从文件尾**向前**搜索→最后一处即原文件末(得原文件大小与截断点),每段 +0x1B 处 DWORD 是下一段跳转目标→最后一段的转移目标即原始 OEP;由截断长度反推末节 RawSize/VirtualSize/SizeOfImage,重写 EOP。修复后与原文件仅差 3 字节(checksum 与节属性)。

作者:cnlgz。源码免杀三步:①预处理加花指令(独立 NOP 函数在敏感 API 调用前插入);②MyCCL 正/反向定位特征码,LoadPE+C32ASM 判特征落在文件头/代码区/字符串/输入输出表/版权信息哪一块;③分块施策——字符串用 wsprintf/sprintf/strcat 运行期拼接、分段加密;代码区改等价指令/调换寄存器;输入表加无关注册函数稀释;版权信息清改。源码免杀优势:重编译自动重定入口,无需手工修 PE。
### 瑞星ServiceMain免杀所想
作者:yugangyi。输出表特征对抗案例:Gh0st 系导出 ServiceMain 必被瑞星杀,新增导出/移动位置均无效——对比系统 svchost 服务 DLL 的 ServiceMain 入口毫无差异却白,说明杀的是「ServiceMain+Gh0st 其他特征」的组合;解法从「改名即免杀」升级到理解查杀是特征向量匹配。现役启示:导出函数名与反射加载入口(profile 改 ReflectiveLoader 名)同属一条对抗线。
### 过所有主流杀软查杀的"免杀壳"编写揭秘
作者:暗夜之刃。免杀壳核心思想=伪装:壳头模拟常见编译器壳的节布局与入口特征,加壳后样本在静态特征维度与正常加壳软件无区分;配合逐字节变形与资源伪造。与《保护篇》外壳编写互为镜像。
### [原创]shellcode免杀框架内附SysWhispers2_x86直接系统调用
作者:快乐鸡哥。四件套框架(GenerateShellCode/EncryptShellCode/FunctionHash/XShellCodeLoader):shellcode 自定义入口+hash 找 API(解析导出表逐函数 hash 比对),.text 抠出即为 shellcode;AES128(WjCryptLib)加密。Loader 落地细节:自定义只读节装密文(**节属性忌 RWX 全开**——内存里可疑;节名用系统常见但本程序未用的如 .edata,#pragma section 方式会把节排最前反而报毒);NtProtectVirtualMemory 用**汇编直接系统调用**改 RW → 解密 → 还原 RX → 执行。三态进环适配:32 位@32 位 sysenter、32 位@64 位 KiFastSystemCall(FS:[0xC0] WOW32Reserved)、64 位@64 位 syscall。SysWhispers2 原理(免维护 SSN 表的标准解):SW2_PopulateSyscallList 找 ntdll 基址→遍历导出表取全部 Zw* 的「函数名 hash+函数地址」入 SW2_SYSCALL_ENTRY 列表→**按函数地址从小到大冒泡排序**(ntdll 内 Zw* 按调用号顺序排列,排序位次即系统调用号)→SW2_GetSyscallNumber 按 hash 查表返回序号;调用桩为「push hash → call GetSyscallNumber → 压参数 → sysenter/syscall」。实测过火绒/360 全线/毒霸静态与执行,卡巴在 Beacon 反射加载环节检出(引出下条)。
> 同法:知识库病毒木马篇 §4.2(syscall 直调原理,此为工程化实现与 x86 适配出处)
### [原创]魔改CobaltStrike:免杀就像便秘一样
作者:快乐鸡哥。CS 三层去特征:①**网络测绘规避**:stager URI 由 MSFURI() 生成 4 字符且 checksum8(ASCII 和 mod 256==92)——测绘扫描即按此算 URI 找 TeamServer;魔改点=改 MSFURI 生成规则与 isStager 校验(定死 URI 或换算法);TeamServer 以 NanoHTTPD 2048 字节分片回传异或 Beacon。②**千人千面 shellcode**:CS 原生 shellcode 本质是 wininet 下载器——自写等价 C 下载器(wininet/winhttp 双实现)再转 shellcode,随手工混淆,从源头消特征。③**Beacon 内存特征**:DOS 头花指令(抗 360/火绒内存扫)、默认 profile、导出名 ReflectiveLoader、IAT——对策分别为自定 profile/改导出名/`set obfuscate "true"`;卡巴对反射注入行为本身的检测需另解(续篇三板斧再锤卡巴)。
### [原创]免杀R77 rootkit之利用X64 PELoader
作者:lxsgbin。R77(用户态 rootkit,隐藏进程/文件/服务/端口)免杀化:JWASM 汇编写 PELoader——取 kernel32 基址→自实现 GetProcessAddr→模拟 LoadLibrary(申请镜像内存/复制 DOS+NT 头/复制节/处理重定位/处理输入表/调 DllMain);注入器从资源取 R77 DLL,VirtualAllocEx+WriteProcessMemory 落目标进程。要点:全部加载行为发生在内存与自写代码里,磁盘无 LoadLibrary 痕迹。

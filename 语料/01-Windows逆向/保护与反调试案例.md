# 保护与反调试案例(Windows)

> 定位:与《平台/01-Windows安全/保护篇》互补——保护篇收通用原理矩阵(PEB/NtQIP/DRx/rdtsc/异常/Anti-OD/花指令原理/VMProtect handler),本库只收**实战案例细节**:具体软件保护方案拆解、检测点的具体实现代码、绕过脚本、组合保护与新型检测点。通用原理不重复,查原理先看保护篇。

## 1. 反调试检测点实例

### 反调试七讲:对象句柄/汇编指令/异常/杂项/调试标志/进程内存/直接与调试器交互
作者:梦幻的彼岸(checkpoint anti-debug 手册翻译系列,七篇一套),手册级覆盖每类检测点的可编译实现,以下为保护篇矩阵之外的关键增量:
- 对象句柄类:`OpenProcess(csrss.exe)`(经 ntdll!CsrGetProcessId 拿 PID 后 OpenProcess(PROCESS_ALL_ACCESS) 成功=调试器用户具备管理员+Debug 权限,EXECryptor 也用这招收 OD);`CreateFile` 独占打开自身 exe(CREATE_PROCESS_DEBUG_EVENT 发生时被调试文件句柄保存在调试器侧,调试器忘记关闭则独占打开失败=有调试器,`GetModuleFileNameA(NULL,szFileName,...); return INVALID_HANDLE_VALUE==CreateFileA(szFileName,GENERIC_READ,0,NULL,OPEN_EXISTING,0,0);`);`CloseHandle(非法句柄)`→EXCEPTION_INVALID_HANDLE(0xC0000008),SEH 捕到=被调试。
- 汇编指令类:INT3 长形式 `0xCD 0x03`(异常时 EIP 指向指令中间(0x03 字节处)而非开头,handler 里不修 EIP 就错位——既是检测点也是反插件点);INT 2D(Windows 对 EAX=1/3/4(Vista+ 还含 5)时把异常地址额外 +1,后面字节被跳过,专打调试器指令对齐);ICE 断点(INT 1/0xF1,无调试器时异常回 SEH);选择器法打单步(`push fs; pop ds` 改段选择器后,单步异常会让 DS 恢复默认值→后续 `xchg [eax],cl` 访问违例,x64 上 DS/SS 都恢复、x86 上 SS 不恢复——用 SS/DS 行为差区分系统位数;变体 `push 3; pop gs; mov ax,gs; cmp al,3; jne being_debugged`);指令前缀(前加 CS 段超越等触发异常,被调试与否行为不同);POPF 置 TF(`push 0x100; popf` 直接触发单步,自己挂 SEH 接=无调试器)。
- 杂项类:`DbgPrint`/`DbgSetDebugFilterState`(有内核调试器时格式化输出显著变慢,配合计时检测);`NtYieldExecution/SwitchToThread`(被单步时返回值异常,连续调用判断);`OutputDebugString`+`SetLastError`(先 SetLastError(12345) 再 OutputDebugStringA,被调试时 GetLastError 不再是 12345)。
- 进程内存类:0xCC 扫描(逐字节扫关键函数体直到 RET(0xC3),误报多);反步过(anti-step-over,检查函数返回地址处首字节是否 0xCC,是则把返回地址 patch 成别的指令——既废断点又改控制流);`NtQueryVirtualMemory` 探 PAGE_GUARD(内存断点痕迹);反附加三板斧(检测/patch ntdll!DbgBreakPoint 与 ntdll!DbgUiRemoteBreakin——附加时远程线程从这里进门,patch 成 RET 附加即断不下来;代码校验和防 patch)。
- 直接交互类:自我调试(子进程 `DebugActiveProcess(父PID)` 抢占调试位,他人再附加失败);`GenerateConsoleCtrlEvent` 发 CTRL+C 给调试器;`BlockInput`;`NtSetInformationThread(ThreadHideFromDebugger)`;`EnumWindows` 找调试器窗口后 `SuspendThread` 其 UI 线程;`SwitchDesktop`;`OutputDebugString`(无调试器时 GetLastError()==ERROR_INVALID_HANDLE)。
> 同法:《反调试:调试标志寄存器》(梦幻的彼岸,PEB/NtGlobalFlag/堆标志的 API+手工双路写法)、《反调试:异常情况》(同作者,SetUnhandledExceptionFilter 未被调用即被调试)。

### 使用NtQuerySystemInformation和DuplicateHandle的系统级反调试
作者:梦幻的彼岸(译 x86matthew)。系统级打击所有用户态调试器(而非检测"自己是否被调"):①`NtQuerySystemInformation(SystemExtendedHandleInformation=64)` 拿全系统句柄表;②找 ObjectTypeIndex 为 DebugObject 的句柄(任意进程持有都算);③`DuplicateHandle(远程进程,该句柄,本进程,NULL,0,FALSE,DUPLICATE_CLOSE_SOURCE)` 直接远程掐掉调试器的调试句柄,调试器静默失效;④循环往复,守卫线程化。难点:DebugObject 的 ObjectTypeIndex 随 Windows 版本漂移——通用解法:先枚举本进程句柄按类型打标→调 `DebugActiveProcess(0)`(PID 非法也会在当前进程内创建内部调试句柄)→再枚举一次,新增的未打标类型即调试句柄类型,取其 ObjectTypeIndex 再 CloseHandle 收尾;不落自己进程标志,纯句柄表视角,常规 ScyllaHide 类隐藏 PEB 的工具不管用。

### 通过滥用一个Windows中的糟糕假设来检测调试器(多字节INT3)
作者:银雁冰(译 triplefault.io)。Windows 内核(nt!KiBreakpointTrap 及异常分发链)处理断点异常时**假设 int3 恒为单字节 0xCC**,把 ExceptionAddress 一律当作指令首地址;执行多字节形式 `CD 03` 时:无调试器→异常回程序自己的 filter,ExceptionRecord.ExceptionAddress 与 ContextRecord.Rip 都指向指令中间(指令首+1);有调试器(用户态/内核态均中)→调试器按"地址=指令首"或递减 EIP 的方式处理,恢复执行的 EIP 与真实落点错一字节,后续指令流损坏,filter 里比较 EIP 与预期值即可判定。同时打 x64dbg/WinDbg/内核调试器,少见的"内核假设级"检测点;内核分析锚点:KiBreakpointTrap 里 `test DebugActive,80h` 分支、Dr7 清零、KiSaveDebugRegisterState 调用时机。

### 从3环调试器工作流程的实现看反调试 + 从异常分发流程的实现看反用户调试器
作者:又出bug了(15PB,两篇一套,另有反双机调试篇)。WRK 源码级:调试器三段式=`CreateProcess(DEBUG_ONLY_THIS_PROCESS)`/`DebugActiveProcess`→`WaitForDebugEvent`(内部 DbgUiWaitStateChange 等 DebugObject->EventsPresent 内核事件)→分发;`DbgUiConnectToDbg` 调 `ZwCreateDebugObject` 创建调试内核对象(DEBUG_OBJECT{EventsPresent,Mutex,EventList,Flags}),**句柄存在 TEB+0xF24**——反调试可遍历 TEB+0xF24 非空判调试(3 环不进内核就能摸到);attach 路径:`NtDebugActiveProcess`→DbgkpPostFakeProcessCreateMessages(伪造进程/线程/模块创建消息)+DbgkpSetProcessDebugObject,**DbgUiIssueRemoteBreakin 在被调试进程创建远程线程跑 DbgUiRemoteBreakin,内含 int3**——"附加断在入口"的原因,patch DbgUiRemoteBreakin/DbgBreakPoint 即反附加;异常分发:`KiDispatchException` 第一次分发先走 `DbgkForwardException`,其先查 `CrossThreadFlags 的 PS_CROSS_THREAD_FLAGS_HIDEFROMDBG` 位(即 ThreadHideFromDebugger 的内核落点),再 DbgkpSendApiMessage→DbgkpQueueMessage 入调试对象队列。

### TLS及TLS反调试和反反调试

## 3. 花指令与SMC实战

### 抗去除花指令(四部)
作者:yangbostar。花指令二分:**可执行式**(PUSHEAX&POPEAX/INC&DEC/NOP,病毒变形引擎用来换特征码)与**不可执行式**(垃圾字节在不可达路径);有效条件:①垃圾字节是某合法指令的一部分②运行时位于实际不可达路径。抗去除进阶层(打 OD 插件的去花特征匹配):1)**多节形式**(多个 `jmp Label/db thunk` 串联,一次特征匹配清不干净);2)**多层乱序**(Label 顺序与物理顺序交错,NOP 填充式去除会破坏真实代码);3)**互补条件跳转**(`jz Label/jnz Label` 代替 jmp,静态可见两条路都到 Label,垃圾字节夹在中间——部分插件不识别);4)**xor-cmp 伪条件跳转**:`xor reg,value1 / cmp reg,value1`(无论 reg 初值 ZF 必不置位)`jnz Label / db thunkcode / Label:`;5)**API 确定值法**(故意传错参数/inc esp 破坏栈对齐令 CreateFile 返回错误码(确定值),或利用"句柄必为 4 的倍数"取模恒 0,后接条件跳转=确定性跳转——形态无穷举);6)**检测被清除**(花被 NOP 后留下 NOP 痕迹,程序自校验这些位置出现 0x90 即发现被去花)。
> 同法:《写花指令》(同思路教程)、《分析花指令》、《识别花指令》(特征列举)。
